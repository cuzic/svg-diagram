# ADR 0033: 免疫マップ(Immunity to Change)は、新しい部品を作らず、既存の部品と skill の手引きで支える

- 状態: 採用(実装済み: `skills/svg-diagram/references/immunity.md` と `examples/immunity-*.ts`)。当初は専用の部品(`immunityMap` ほか)を足す案で、Opus レビューを 3 回まわして収束した(第 3 回は blocker 0 / major 0)。その過程で、既存の部品だけで足りると分かり、方針を改めた
- 日付: 2026-10-17
- 基点: `main`(7d443ac、PR #283 まで)
- 関連: ADR 0025 / 0026(原因分析の図)、ADR 0015 / 0020(TOC)。ADR 0030 は fukan の下書き、0031 は FCIS、0032 は Arbinger が使っているので 0033 とした(当初 0031 と付けて FCIS と衝突し、改めた)

## 背景

Kegan & Lahey『Immunity to Change』(邦訳『なぜ人と組織は変われないのか』)の免疫マップを、面談で進めながら図にしたい。マップは 4 つの欄(改善目標 | 阻害行動 | 隠れた競合目標(不安ボックス付き)| 強力な固定観念)に箇条書きを並べるワークシートで、後半は固定観念の検証と書き直しへ進む。

調べた範囲では、免疫マップを因果ループ図・CRT・連関図・蒸発雲と結びつけた出典は見つからなかった(英語・日本語とも)。ループや雲への対応は、この ADR 側の推論である。

## 決定

1. **新しい band・型・規則は作らない**。マップ、検証、ループ、対立は、既存の `row` / `group` / `table` / `causalLoop` / `cloud` で作れる。
2. **段階ごとに別の図にする**(TOC が現状ツリー・クラウド…と図を分けるのと同じ)。1 枚に詰め込まない。
3. **手引きを skill に書く**: `skills/svg-diagram/references/immunity.md`(SKILL.md の領域別の案内に 1 行)と、動く例 `examples/immunity-{map,tests,loop,cloud}.ts`(golden)。例は `check --strict` を通す。
4. **専用の検査(`immunity-*`)と、図どうしの `from` による id の型検査は作らない**。使われ方を見て、必要と分かってから足す(別 ADR)。

## 理由(Opus レビューで分かったこと)

- 専用の部品を作る案は、層配置の固定(`pin`)や新しい `CauseRole`、図を跨ぐ検査と結びついて重く、`layeredAttempt` を壊す危険があった(blocker)。
- 既存の部品だけでマップは作れる。`grid()` は使えない(行優先に折り返し、`id` / `title` / `reveal` が無い)が、`row([group × 4])` は見出し・空欄の破線・同じ幅・欄単位の `reveal` がそろう。
- 検査で守りたかったこと(欄の欠け、参照の誤り)の多くは、面談の中で人が確かめることで、ツールが意味を判断するものではない。

## skill に書いた罠(レビューで実測したもの)

- `grid()` は使えない。`row + group` を使う。
- 欄の間に矢印は引かない(原典も欄の順に読む)。`connect()` を書くなら `connect('x:left', 'y:right', {route: 'elbow', bend: 'auto'})` の形で、3 本以上なら全部の箱を結ぶ(既定の経路は箱を避けず build の検証で落ちる。孤立の `graph-orphan-node` が出る)。
- 不安の欄は破線・色なしで、文頭に「不安:」。`tone` を付けると `legend-missing` が毎回出る。
- 悪循環ではなく自己調整のループ(B)。`causalLoop` が B1 と表示する。強化(R)は別の図。
- 蒸発雲: 目標と競合目標はニーズ(B / C)、固定観念は `cd` の前提。`injection` に行動実験を入れない(解決策に読まれる。検証は表)。

## 後回し(需要が出たら)

- 専用の検査 `immunity-*`(阻害行動に競合目標が無い、改善目標が 1 つでない、など)と `immunityCheck`。
- マップの id を、検証・ループ・雲の図から型検査つきで参照する仕組み(TOC の `mirrors` に倣う。自分の id と `from` の属性で、anchor id を重複させない)。
- 矢印つきのマップ(層配置。`layeredAttempt` の層の固定は、辺の頭は尾より後ろの層という前提を壊すので、別 ADR で設計する)。
- 図を跨ぐ検査(「試されていない固定観念」)、組織版(主語を「私たち」にする)。
- 日本語版の用語の確認(訳語は未確認。本で確かめる)。

## 却下した案

- 専用の band `immunityMap` と、`CauseRole` 6 種、層の固定、`immunity-*` の検査(上のとおり重く、既存の部品で足りる)。
- `grid()` でマップを作る。
- マップ全体を他の図へ自動変換する(符号やループは作者の判断で、全体を変換すると巨大になる)。
