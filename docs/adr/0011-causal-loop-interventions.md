# ADR 0011: 因果ループ図の介入点(`interventions`)と円環配置(`layout: 'ring'`)

- 状態: 提案
- 日付: 2026-10-13
- 基点: `main`(4e58744、PR #120 まで)
- 関連: ADR 0008(要望の受け方)、ADR 0004 / 0005(deck 側の要望)
- 対象の要望: B4(因果ループ図に、ループの外の介入点)、B5(因果ループ図が円環にならない)

## 背景

TOC・因果の整理の資料で、悪循環の因果ループ図に「介入点」(標準の合意、早期の果実)を足そうとして、図が作れなかった。要望の原文は次のとおり。

- B4(優先度 高): 悪循環のループに介入点を足して 7 ノードにしたら、検査が「ラベル `-` が `R1` と重なる」「線がラベルを貫く」で止まった。5 ノードのループと、箱を別に描いて回避した。提案は `causalLoop` に `interventions: [{id, label, to, polarity}]` を足し、ループの外側に置き、ラベルの衝突は自動で避けること。
- B5(優先度 中): `direction: 'TB'` ではループが縦の鎖になり、戻りの線が長く折れた。既定の `LR` では 5 ノードが横一列になり、戻りの線が下を回った(円環でなく帯)。提案は `layout: 'ring'`(円周に配置し、矢印を弧にする。`cycle()` に近い見た目)。

決めたいのは 3 点。(1) 介入点を、データと図のどこに、どういう意味で置くか。(2) ラベルの衝突は、どこで起きていて、どう避けるか。(3) 円環配置を `causalLoop` に入れるか、`cycle()` に任せるか。

## 現状(コードを読んで確かめたこと)

### causalLoop の実装

`causalLoop(nodes, links, opts)` は `lib/dsl.ts:990` から `causalBand`(`lib/semnet-dsl.ts`)→ `resolveCausal`(`lib/semnet.ts:36`)で `CausalSpec` になり、`ChartBand`(`kind: 'causal'`)として `lib/charts.ts:82` の `layoutCausal`(`lib/semnet.ts:121`)が描く。

- ノードは `{id, label}` のみ。リンクは `CausalLink {from, to, polarity: '+' | '-' | 'same' | 'opposite', delay?, label?}`(`lib/semnet-analysis.ts:65`)。
- `analyzeCausalLoops`(`lib/semnet-analysis.ts:69`)が、有向の単純閉路をすべて 1 回ずつ数え、負リンクの数が偶数なら `R`、奇数なら `B` とする。名前は `R1, R2, B1, …`(種類ごとに 1 から)。純粋関数で、レイアウトを知らない。
- 配置は `networkCanvas`(`lib/semnet.ts:83`)で、`pert` / `dependencyNetwork` と共有の階層型レイアウト(`layoutWithLanes` → `routeLayered`、`lib/layered-route.ts`)。層は右向きの軸で計算し、`direction: 'TB'` はその転置。戻りの辺(ループを閉じる辺)は、層の外側の「車線」を回る直交経路になる。これが B5 の「帯」の正体で、階層型レイアウトに円環の概念はない。
- 辺ごとに `arrow()` で線を引く(`avoid: true`で `c.segs` に登録される)。極性の記号(`+` / `-`)と遅延の記号(`||`)、辺のラベルは、辺の中点の周りの 2〜3 の候補位置から `Canvas.place()` で選ぶ(`lib/semnet.ts:126-128`)。
- ループ名(`R1` / `B1`)は、ループのノードの中心の平均 x の、最も低いノードの下に置く(`lib/semnet.ts:132-135`)。

### 「ラベル `-` が `R1` と重なる」の出所

検査のメッセージは英語で `causal: label "-" overlaps label "R1"`。出所は `lib/charts-verify.ts:26`(全 chart 共通の検査。ラベル同士の重なりを、`overlaps()` で 0.5px 超として報告する)。同じ関数が `a line runs through the label "…"`(`:32`、`plate` なしのラベルを `segs` が貫くとき)も出す。

衝突が起きる原因は `layoutCausal` の最後の段にある。極性の記号は `c.place()`(候補を順に試し、`Canvas.free()` が通った位置に置く)で置くが、ループ名は `c.text()`(`lib/semnet.ts:134`)で**候補なしに固定位置へ置く**。ループ名は記号より後に置かれるので、記号が先にその位置を取っていると、ループ名が記号に重なる。ループ名に衝突を避ける経路がなく、検査だけが後から止める構造になっている。

再現した(作業ツリーは変更していない。スクリプトは使い捨て)。5 ノードのループに、介入点を想定した 2 ノードを、ループの外から内へのリンクとして足した 7 ノードを、極性と遅延を乱数で変えて 60 通り検査した。

| 結果 | 件数(60 通り中) |
|---|---|
| `label "||" overlaps label "B1"` | 2 |
| `label "+" overlaps label "B1"` | 2 |
| `label "-" overlaps label "B1"` | 1 |

つまり B4 の「`-` が `R1` と重なる」は、介入点が原因なのではなく、既存の 5 ノードの図でも起こり得る既存の欠陥である(7 ノードでは、辺が増えて記号が密になるので踏みやすい)。

**「線がラベルを貫く」も再現できた**(レビューの指摘で確認し、同じ手順でこちらでも再現した)。上の掃引は `checkDiagram`(`charts-verify.ts`)だけを通していて、`build` の後に走る `lint-svg --strict` を通していなかった。7 ノード(5 ノードのループ + 外の 2 ノード)を、種を変えて 12 通り `build` し、`lint-svg --strict` を通したところ、1 通り(LR)が `"+" is crossed by a path` で落ちた(終了コード 1。レビュー側の 10 通りでは 3 通り)。検査は `lib/svg-lint.ts:139-155` の規則 5(「文字より後に描かれた線が、その文字の上を通る」)。

原因は**描く順**である。極性の記号は `plate`(ページ色の板)付きなので、`Canvas.free()` も `charts-verify.ts` も、線との重なりを許す。ところが `layoutCausal` は、辺 i の線を引いて記号を置き、次の辺 i+1 の線を引く、という順で SVG に出す。辺 i+1 の線が、先に置かれた辺 i の記号の上を通ると、板の上に線が来て、文字を貫く(板は後から描く線を覆えない)。`layoutDependency` も同じ形で、辺のラベルに同じ欠陥がある。この欠陥は `check`(生成側の検査)では見えず、`lint --strict` でだけ出る。

もう 1 つ、読んで見つけた問題がある。`Canvas.place()` は、候補がすべて塞がっていると**何も描かずに `undefined` を返す**(`lib/charts-base.ts:142`)。`layoutCausal` はその戻り値を見ないので、極性の記号が**黙って消える**ことがある。因果ループ図で `+` / `-` が消えるのは、図の意味が変わる(R が B に見える)ので、衝突で止まるよりも悪い。介入点で記号が増えると、この経路を踏みやすくなる。

### `cycle()` と semnet 系

`cycle(steps, opts)`(`lib/flow-shapes.ts:75`、`layoutCycle` `:232`)は、円周に 3〜8 のノード(円)を等角に置き、隣のノードの間を、円弧の矢印(SVG の `A` コマンド)で結ぶ。意味付き(極性・遅延・R/B の分類)ではなく、辺は「次の段階」だけ。矢印が弧になる、ノードの間隔が一定、中心の文字(`centre`)を持つ、という見た目は、B5 が求める「ループ図らしさ」そのもの。

`pert` / `dependencyNetwork` / `causalLoop` は、3 つとも `lib/semnet.ts` の `networkCanvas` を共有する。`layoutCausal` を触ると、共有の部分(`networkCanvas`、`arrow`、`edgeMid`、`pathOf`)の変更が pert と dependency にも及ぶので、共有の部分は触らず、causal 固有のコードに閉じる。

## 論点

1. 介入点は「ノード」か「別の種類の要素」か。リンクの極性・R/B 分類・アンカーとの関係。
2. 介入点の配置を、既存の階層型レイアウトに任せるか、ループの外側へ別に置くか。
3. 衝突の回避は、`place()` の候補を足す程度で足りるか。置けないときは、黙って消すか、止めるか。
4. B5 を `causalLoop` に入れるか。入れるなら、ループでないノードや、複数のループをどう扱うか。

## 決定

### 1. 介入点は、ループに入らない別の要素にする

`CausalOpts` に `interventions` を足す。リンクの配列に混ぜない(混ぜると、`analyzeCausalLoops` が閉路の候補にし、レイアウトがループの中の層に押し込む。要望者が 7 ノードで詰まった原因もこれ)。

```ts
export interface CausalIntervention {
  id: string;
  label: string;
  /** 作用するノードの id。複数を書くと、それぞれへ矢印を引く(極性と遅延は共通)。 */
  to: string | readonly string[];
  /** 介入を強めたとき、対象が同じ向きに動くか(`+` / `same`)、逆に動くか(`-` / `opposite`)。必須。 */
  polarity: CausalPolarity;
  delay?: boolean;
}
export interface CausalOpts extends SemnetOpts {
  interventions?: readonly CausalIntervention[];
  layout?: 'layered' | 'ring'; // 決定 4。既定は 'layered'(今のまま)
}
```

- 極性は `CausalLink` と同じ語彙(`'+' | '-' | 'same' | 'opposite'`)で表す。意味は「介入を強めると、対象が同じ向きに(`+`)/ 逆に(`-`)動く」。悪循環を断つ介入は、たいてい `-`。必須にする(`CausalLink` も必須で、省略に既定値を持たせると、符号の読み違いが黙って通る)。
- 介入点は**ループに入らない**。入ってくる辺を持てない(ループの外から来るだけ)ので、`analyzeCausalLoops` の入力には渡さず、R/B の分類・ループ名・`CausalLoop` の中身は、介入点があっても変わらない。介入点から介入点への辺と、ノードから介入点への辺は作れない(`to` はノード id だけ。介入点の id を書くと、「介入点は介入点に作用できない」と書いて止まる)。必要になったら別の要望にする。
- id は、ノード・介入点・図の `id` で一意(`checkIds` に全部を渡す)。介入点もノードと同じくアンカー(`band.ids`)になり、`connect()` や `spotlight` の対象にできる。型では、`causalLoop` に型パラメータ `const I extends readonly CausalIntervention[]` を足し、`Declares<… | ChartIds<I>>` と `AnchorsOf<ChartIds<N> | ChartIds<I>>` に入れる(`test/types/semnet.ts` の既存の型検査と同じ形)。`to` が実在のノードかは、実行時に検査する(`CausalLink.from/to` が型で縛られていないのと同じ)。
- 検査(`resolveCausal`): `label` と `id` は空でない文字列、`to` は 1 つ以上で、重複せず、すべて実在のノード、`polarity` は 4 値のどれか、`delay` は真偽。エラーは `causalLoop(): intervention "<id>" ...` の形(`fail()`)。
- alt(`causalAlt`)に、ループの記述の後ろへ `Interventions: 標準の合意 -> 標準なし (-); …`(`id`ではなく表示名で、対象のラベルと極性)を足す。`semnetTexts` に、介入点のラベル(700)と極性・遅延の記号を足す(全ての描く文字を `semnetTexts` に列挙するのが、幅の測定の決まり)。

### 2. 見た目: 破線の箱と破線の矢印

ループのノードと区別するために、**色だけに頼らず**、介入点の箱は破線の枠(`6,4`)、矢印も破線(`6,4`)とし、どちらも accent の色にする(ループの辺は text 色の実線)。極性の記号は、ループの辺と同じ(`+` は accent、`-` は danger、`||` は muted)。ループ名のような凡例は足さない(破線が「外から」を表す。alt に `Intervention` と書く)。`nodeBox`(`lib/semnet.ts:98`)は破線の引数を持たないので、causal 専用のコードで `c.rect` を直接呼ぶ(`nodeBox` の共有は変えない)。

### 3. 配置: ループを先に置き、介入点は帯を 1 辺に固定して置く

介入点を層の計算に混ぜない。第 1 段は簡素にする(辺の自動選択はしない)。

1. **帯は 1 辺に固定**する。LR は上、TB は左、ring は外周。ループのレイアウトに渡す矩形を、帯の厚み(`箱の高さ 48 + 矢印の長さ 40 + 余白`)の分だけ、その辺から縮める(`networkCanvas` に省略可能の `inset`。省略時は今と同じ)。介入点がなければ縮めない。
2. **ループの配置**(階層型または ring)。出力は、ノードの位置と、経路。
3. **帯の中の位置**。介入点を、対象の中心(複数の対象なら平均)の座標の順に並べ、最小の間隔(16px)で左から右へ、次に右から左へ押し離して重ならないようにする。箱は幅 = 文字の幅 + 28、高さ 48。
4. **矢印の経路**。箱の対象側の辺から、対象の箱の辺までの直交の折れ線。対象の幅に収まるなら直線。複数の対象には 1 本ずつ。経路がノードの箱を貫く、箱が他のラベルに重なる、図からはみ出す、ときは、帯の厚みを 8px ずつ増やして最大 3 回やり直し(`height` 未指定なら図が伸びるだけ)、それでも駄目なら、どの介入点のどの矢印が何に当たるかと直し方(`height` を上げる、`to` を減らす、ラベルを短くする)を書いて止まる(`fail()`)。ループの戻りの線との交差は許す(線が線を横切るのは正当)。
5. **アンカー**。介入点の箱は `c.rect(..., {id})` で描き、ノードと同じアンカー(`anchors`)と solid になる。`connect()` と `spotlight` の対象にできる。

辺の自動選択(交差の最少化)は、第 1 段では持たない。帯の置き場が固定の辺で足りない実例が出たら、別の要望にする。

### 4. 描く順と衝突の回避: 線を全部描いてから、記号とラベルを描く(2 段)

**描く順を 2 段にする**(決定の中心)。

- **第 1 段: 線と箱をすべて描く**。ループの辺の線(矢じりを含む)、介入点の矢印、ノードと介入点の箱を、先に全部描く。この段で `c.segs` が確定する。
- **第 2 段: 記号とラベルをすべて描く**。極性の記号、遅延、辺のラベル、介入点の矢印の記号、ループ名を、確定した `segs` と箱を見ながら `Canvas.place()` で置く。文字は常に線より後に描かれるので、線が文字の上を通る(`lint-svg` の規則 5)ことが、構造上起きない。

`layoutCausal` を 2 段にする。`layoutDependency` も同じ欠陥(辺のラベルを辺ごとに引きながら置く)なので、同じ 2 段にする(実装計画の A に含める。`pert` は辺にラベルを置かないので対象外)。

置く順: 辺の記号 → 介入点の矢印の記号 → ループ名(記号の意味の方が大きいので、ループ名が避ける)。

- **ループ名**を `c.text()` から `c.place()` に替える。候補は、今の位置、ループのノードの上、ループの重心の順。ring では中心を先頭にする。どれも塞がっていれば、8px の刻みで外へ探す。
- **記号の最後の逃げ道**。`place()` の候補がすべて塞がったときは、まず同じ候補を辺の上の別の点(中点から両側へ)の脇でも試し、それでも塞がっていれば、辺そのものの上(`plate` で線を隠す)に載せる。第 2 段なので、板は線を覆える。ただし線を隠してよいのは、**板の両側に同じ線分が 6px 以上残る場所だけ**(短い辺で辺のほとんどを隠さない)で、板は文字箱より左右 2px 広いので、板ごとほかのラベル・箱・矢じりに当たらないこと(矢じりは `c.path` で登録されず `free()` に見えないので、図ごとに矢じりの箱を渡す)。極性と遅延が、これでも置けないときは、黙って消さず、`causalLoop(): the polarity "-" of <from> -> <to> has no room (the figure is too dense around this link: ...)` で止まる。**止めるのは極性と遅延(意味が変わるもの)だけ**で、辺の自由文のラベルは置けなければ省く(依存ネットワークのラベルと同じ)。ラベルは極性・遅延・ループ名のあとに置く。なお、`height` を上げても `width` を上げても余白は増えない(`networkCanvas` は高さを下に足すだけ、幅は倍率 1 で頭打ち)ので、案内は「リンクかノードを減らす、ノードのラベルを短くする」にする。
- 検査(`lib/charts-verify.ts`)は変えない。生成側で衝突が起きないようにし、検査は最後の砦のまま。ただし、検査(`check`)だけでなく、**`lint-svg --strict` を通ることを受け入れにする**。

**実装した A での補足(2026-10-14 改訂)**: (1) 第 1 段は「線 → ノードの箱と文字」、第 2 段が「極性 → 遅延 → ループ名 → 辺のラベル」の順(箱の文字も線の後)。(2) 依存ネットワークの辺のラベルにも同じ逃げ道を持たせたが、**置けないときは止めず、従来どおり省く**(止めると、既存のテスト `semnet.test.ts` の長い凡例の図が止まる。今動いている図が、ラベルを省いた形で通っている)。ラベルが無くても図の向きは変わらないので、止めるのは別の要望にする。(3) 逃げ道は、板が矢じり・箱の縁・辺のほとんどを隠さないことを条件にする。最初の版(辺の上 8 点、条件なし)は、依存ネットワークの合成 120 図で、矢じりが半分以上板に隠れた件数が 10 → 25、箱の縁にかかる板が 28 → 36 と、**悪化**した(`lint-svg` の規則 5 は線が隠れると成り立つので見つからない)。改訂後は 0 / 2。掃引テストが `plateDamage` でこの 2 つの件数を修正前以下に縛る。(4) 共有の部品(`arrow`、`networkCanvas`、`nodeBox`、`placeEdgeLabel` など)は `lib/semnet-common.ts` に分け、`semnet.ts` と `semnet-causal.ts` の相互 import をなくした。(5) 掃引ヘルパーは `test/helpers/semnet-sweep.ts`、テストは `test/semnet-causal-layout.test.ts`。

**止める変更の影響を、実装の前に測る**。記号が置けず止まるようになる変更は、今は黙って記号が消えて通っている図を壊しうる。実装の前に、`examples/` の因果ループ図と依頼者の図で、何件が止まるかを測る(0 件でなければ、止める代わりに `warn` にして `check --strict` の扱いを決める)。**測定(A、2026-10-14 改訂。測る図に辺ラベル・遅延が付いた密な図を足した)**: `examples/` の因果・依存 4 図は 0 件。合成の因果ループ(5 ノード + 外の 2 ノード、60 種 × LR/TB)は 0 件。合成の密な因果ループ(3〜6 ノード、リンクは約 2 倍、40% に遅延、40% に `短期的な効果` のラベル。150 種 × LR/TB = 300 図)は、**修正前は止まる図が 0 でも、記号が黙って消える図があり、ラベルは 394 件が消えていた**。最初の版(止める対象にラベルを含め、辺の脇は中点のみ)は 205 / 300 図が止まった(ラベル 194)。改訂後(止めるのは極性と遅延だけ、脇の候補を辺に沿って増やす)は **4 / 300 図が止まり**、ラベルの省略は 182 件(修正前の 394 件より少ない)。依存ネットワーク(5〜7 ノード 60 種 × LR/TB)は、ラベルの省略が 46 件(修正前は 38 件)で、止まる図は 0。

### 5. B5: `layout: 'ring'` を `causalLoop` に入れる(`cycle()` には任せない)

`cycle()` は、極性・遅延・R/B の分類・辺のラベル・介入点を持たない。`cycle()` に足すと、意味付きの機能が 2 箇所に分かれる。`causalLoop` に配置の選択肢として入れる。

- 既定は `'layered'`(今のまま。差分なし)。`'ring'` は、ノードを楕円の円周に等角に置き、ループの辺を円弧(楕円の弧)で結ぶ。
- **ring の条件**: 第 1 段では、**ノードがちょうど 1 つの単純ループ(長さ 2〜8)の上にあり、閉路がそのループ 1 つだけの図**に限る。ループの辺以外の辺(弦)を持たない。自己ループ(あるノードからそのノード自身への辺)は閉路の数に数えず、外向きに小さく描く(既存の `pathOf` の形)ので許す。「全ノードを通る閉路が存在する」(ハミルトン閉路)だけでは足りず、閉路が複数ある図(**8 の字**: 2 つのループが 1 ノードを共有する形、弦のある図)は、ハミルトン閉路を持っていても満たさない。満たさない図は止まる。「最長ループを円周に置き、残りのノードを外側に置く」ことは、配置規則が増えるので第 2 段に回す。条件を満たさないと、`causalLoop({layout: 'ring'}): the graph must be one loop (found N loops / "x" is not on it; use layout: 'layered'; an outside node is an intervention)` で止まる。**ループの外のノードは介入点に回す**、という使い分け。
- 弦は、第 1 段の条件で存在しない(あると止まる)。
- 順序は、そのループの辺の向きに従って時計回りに置く(`cycle()` の `direction: 'cw'` と同じ向き)。先頭は上(-90°)から。ループ名は円の中心に置く(決定 4)。
- **半径の決め方**: 幅は帯の幅から求める(`rx = (幅 − 最大のノードの幅 − 16) / 2`)。`ry` は 60px から 8px ずつ増やし、隣り合う箱の間の隙間が 36px(矢印の長さ + 記号の幅)以上で、隣り合わない箱が重ならなくなる最初の値にする。`height` を指定していて足りなければ、必要な高さを書いて止まる(他の chart と同じく、直し方を書く)。指定がなければ `2·ry + 箱の高さ + 余白`。
- 円弧は、点列(約 6° ごと)の折れ線として `arrow()` に渡す。そうすれば、既存の `c.segs`(ラベルの回避)と矢じりの向きの計算を、そのまま使える。箱の縁との交点は、弧の上の点を二分探索して求める。
- ring では `direction` は意味を持たない。`layout: 'ring'` と `direction` の両方を書いたら止まる(`direction` の既定が `LR` なので、`resolveCausal` に渡る生の値で判定する)。
- 適用外: `pert` / `dependencyNetwork` には足さない(`layout` は `CausalOpts` だけ)。

## 代替案

| 案 | 採らない理由 |
|---|---|
| 介入点を、ノードと `links` に混ぜる(要望者がやったこと) | 層に押し込まれて図が崩れる。閉路の探索の対象になり、アンカーの意味もぼやける。7 ノードで詰まった原因そのもの |
| `interventions` を 4 番目の引数にする | 既存の引数は変えたくない。`opts` の他の項目(`direction`、`height`)と同じ階層の方が見つけやすい |
| 介入点の極性に既定値(`-`)を持たせる | 符号の読み違いが黙って通る。`CausalLink` が必須なのと揃えて必須にする |
| 介入点を階層型レイアウトの中の「層 0」のノードとして置く | 介入点の数だけ層が増える・ループの形が崩れる。外側の帯の方が「ループの外」を表せる |
| 衝突を `check` に任せる(今のまま)で、候補だけ増やす | 候補が塞がると、記号が黙って消える経路が残る。消えるより、止まる方が良い |
| ring を `cycle()` の拡張として作る | 極性・遅延・R/B・介入点が必要になり、`causalLoop` と二重になる。`cycle()` は意味なしの安い図として残す |
| ring で、ループ外のノードを内側や外側へ自動配置する | 配置規則が複雑になり、どこに置くべきかの議論が増える。まず「ループ外は介入点へ」で止め、要望が出たら足す |
| 弦を曲線(内側へ膨らむ弧)にする | 記号の置き場の予測が難しい。直線から始め、塞がる実例が出たら考える |

## 影響

- **既存の因果ループ図・依存ネットワークの SVG は、要素の順が変わる**(2 段にするため。線が先、記号とラベルが後)。見た目は同じか、衝突を避けた分だけ記号の位置が動く。したがって「衝突がない図は byte 同一」は成り立たない。`pnpm golden` で golden を更新し、**`diff-svg` で「要素の順だけが変わった(見た目は同じ)」と説明する**(PR に貼る)。見た目が変わった図は、個別に理由を書く。U0 の整理だけは、byte 同一を保つ(動作を変えないので)。
- 記号が黙って消えていた図は、止まるようになる(破壊的だが、図の意味が壊れていた場合に限る)。止まったら、`height` / `width` を足す。実装前に件数を測る(決定 4)。
- 公開 API の追加: 型 `CausalIntervention`、`CausalOpts` の 2 項目。`dsl-exports.json`(関数名の一覧)は変わらない(新しい関数がない)。`lib/dsl.ts:1940` の型の再エクスポートに `CausalIntervention` を足す。
- `pert` / `dependencyNetwork` と共有のコード(`arrow`、`edgeMid`、`pathOf`)は、書き換えずに export して使う。`networkCanvas` だけは、C が省略可能の引数 `inset` を足す(省略時の出力は変わらない)ので、0016 U4 の書き換えと衝突する。そのため C は 0016 U4 の後に入れる(下の順序)。
- 検査(`charts-verify.ts`)・`Canvas`(`charts-base.ts`)は変えない。
- **ADR 0012(id のスコープ化)との関係**: 介入点の id は `band.ids` に入り、ノードの id と同じ扱いになる(スコープの修飾の対象、`spotlight` / `reveal` の照合も同じ)。0012 が決める「帯の出力のアンカーの素の名前への戻し」と同じ経路を、介入点もそのまま通る。`causalLoop` のオーバーロード(`lib/dsl.ts:990`)と `CausalOpts`(`lib/semnet.ts:14`)は、0011 と 0012 の両方が変える。0011 が先にマージされ、0012 の型の変更は、その上に足す(下の順序)。
- **ADR 0016 との順序**: 0016 は `networkCanvas` / `layoutLayered` の呼び出しを書き換える。**0011 の U0 と A を先にマージし**、そのあとで 0016 を入れる。0011 の C(`inset`)と 0016 の変更が `networkCanvas` で衝突するので、C は 0016 U4 の後に回す。各 PR の「byte 同一」の比較は、その PR の直前の `main` を基準にする。

### 未決・限界

- 介入点から介入点への依存、リンク(辺)への介入(リンクの強さを変える)、測定点(ループからの出力)は扱わない。
- 弦が多い ring、8 を超えるノード、ループ外のノードを持つ ring は、止まる。
- 要望者の 7 ノードの元ソースは、まだ受け取っていない。受け取ったら、同じ図が `lint --strict` を通ることを、受け入れに加える(上の再現は、同じ形の合成の図)。

### 順序と統合

全 ADR を通したマージ順は、**0013 と 0012-E(独立)→ 0011 の U0 と A → (0016 の共通 PR)→ 0016 → 0010 → 0012 の A〜D** 。0011 の残り(B、D、C)は、U0 と A のあと、B・D を並列に進める。**C(`networkCanvas` に `inset` を足す)は、0016 U4(`networkCanvas` の呼び出しの書き換え)の後**にマージする。型(`types.ts`・`dsl.ts` のオーバーロード)の変更は最後に寄せ、各 ADR は `opts` の項目を足すだけにする、という方針の**例外が B**(`dsl.ts` の `causalLoop` のオーバーロードに型パラメータを足す)で、B は **0012 より先に入れる**(0012 の型の変更は、その上に足す)。

A・B・D は、触るファイルの重なりが `lib/semnet-causal.ts` の別の関数だけなので、各自が自分の関数を新ファイルに切り出し(`placeLoopNames`、`resolveIntervention`、`layoutRing`)、`layoutCausal` の本体には 1 行の呼び出しだけ足す。各ユニットは、別の worktree・ブランチ・PR。「byte 同一」の比較は、各 PR の直前の `main` を基準にする。`main` の更新が速いので、マージ前に `git fetch` して rebase する。
