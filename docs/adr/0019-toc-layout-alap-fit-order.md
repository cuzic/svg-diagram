# ADR 0019: TOC の因果ツリーの層・大きさ・並び(ALAP の層決め、幅と高さの同時の探索、交差の自動探索)

- 状態: 実装済み(U0〜U5 は PR #206・#205・#214・#215・#216・#217。`maxDisplayHeight` の好み扱い(throw しない)への換算は未対応)
- 日付: 2026-10-15
- 基点: `main`(479c188、PR #194 まで)
- 関連: ADR 0016(層の決定 `tighten`、`layeredAttempt`、点数 (交差, 折れ)、D11 / U13 の AND の並走)、ADR 0010(`fitWidth` / `fitLayout`、`fold`、`heightBudget`)、ADR 0015(`tree`、`tocCheck`、`cause-parallel` / `cause-crossing`)。要望の原文は `medius-research/docs/svg-diagram-feature-requests.md` の H 節のうち H1・H2・H3(依頼元の優先度は「高」の 3 件)
- 範囲外: H4・H5(NBR・TT の描き方)、H6、H8(`tocCheck` の追加規則)。H7(中核バッジ)・H9(`goal`)は不具合として別 PR(#199・#198)で直した。H10・H11 は ADR 0017・0018 の側

## 背景

FRT・NBR・PRT・TT を TOC の標準に合わせて作り直したところ、3 つが「線が長い・図が大きすぎる」を生み、毎回手作業の調整になっている。

| ID | 要望 | 実例 |
|---|---|---|
| H1 | 入力しか持たない節(障害・行動・前提条件)を、出力先の 1 つ手前の層に置く(ALAP) | PRT で、後ろの中間目標につながる「行動」「障害」も最初の層に置かれ、図の端から端まで長い線が走る。FRT の前提条件も同じ |
| H2 | 幅と高さの両方に収まる `maxNodeW` の自動探索。収まらないときは図を分ける位置の提案 | `maxNodeW` を 100〜190 で手で試し、幅が足りないと throw、広げると高さが 1080px を超える(PRT 1556〜1936px、TT 1216〜1276px) |
| H3 | 交差・並走の順序 | FRT に `cause-parallel`(e3→e4 と i5→e4)、`cause-crossing`(e6→e7 と e2→e7)が残る。直し方は「順序を替える」だが、替える方法がない |

**ユーザー決定**(依頼元セッションからの伝達。2026-10-15): 手動の整列ヒント(`straight` / `order` / `rank`)は実装しない。H3 の「`order` / `rank` のヒント」案は採らず、自動探索だけを入れる。ADR 0016 の D5 / U10 への書き戻しは PR #204 で行われた。

## 現状(事実。コードとレビューでの実測で確かめた)

**層(H1)。** `layoutLayered`(`lib/graph-layout.ts`)は最長経路で層を決める。入る辺が無い節は層 0。`LayeredOpts.tighten`(`:154`)は、入る辺が無く `start` でもない節を「最も近い行き先の層 - 1」まで引き寄せる(1 パス)。**動くのは入る辺が無い節だけ**なので、入力側が 2 段の連鎖(障害 → 行動 → 中間目標、前提条件 → 行動 → 効果 = TT の 3 入力)は、先頭の節が動かず(行き先の行動が層 1 のまま)、長い矢印が残る(実測: `r→i1→i2→i3→i4→g` と `o→x→i4` で、`tighten` 後も `o:0, x:1, i4:4`)。`tighten` を使うのは states・classes・semnet(`AttemptOpts.tighten` 経由で整列案にだけ)と bpmn(`layoutOpts` 経由)。`causeTree`(`lib/toc.ts`)は渡さない。

**幅と高さ(H2)。** `fitLayout`(`lib/fit-width.ts:144`)は `dir` と `maxNodeW`(`NARROWING = [200, 160, 130, 110]`、`:98`)の組を順に試し、`causeTree` は軸を変えず、最後に `fold`(ADR 0010 D7)を試す。**高さの予算は `first` モードでも効く**(`fitWidth` の `:55` が、`mode` の分岐(`:56`)より前に高さを判定する。予算は `layout-handlers.ts:560` の `canvas.height ?? maxDisplayHeight`)。`fit-width.ts:25` のコメント(「best mode」)が古い。問題は 3 つ:

1. 格子が**狭める方向だけ**(200 → 110)で、狭めると箱の行数が増えて**高さは増える**。高すぎる図は、格子の全部と fold を試して(どれも更に高い)throw する。
2. throw の文面は幅しか知らない(`fitFailure`、`widerThan`)。実測: 幅 88px・高さ 436px の図が、予算 386px で「does not fit 900px」「widen the figure (diagram({width: 140}))」と出る。**高さの失敗が幅の失敗として報告される**。依頼元の「幅が足りないと throw」の一部は、これの可能性がある。
3. `maxNodeW` を数値で書くと、その 1 通りしか試さない(だから手でループした)。`dir` を明示した図は、`maxNodeW` を書かなくても狭めない(`:149`)。

**並び(H3)。** `layoutLayered` は重心法の掃き出しを `sweeps`(既定 4)回。`transpose: true`(整列案が使う)は、見た中で交差が最少の並びを残し、隣の入れ替えで交差が減る間だけ入れ替える(ADR 0016 D2)。点数は (交差, 折れ)。`cause-parallel` / `cause-crossing` は `lib/verify-handlers.ts:153-181` の検査で、**AND の弧が描かれた結果へ入る矢印どうし**の交差・並走だけを見る(`andTo` は `band.ands` から作る。`toc.ts` は弧が描けない AND を `ands` から外して `loose` に入れ、`loose` は検査の error)。ADR 0016 D11 / U13 は、`cause-parallel` を**経路の問題**(長い矢印の最後の折れが、直接の矢印の折れより行き先に近い。`layered-route.ts` の経路)と診断し、「並走は経路の中ほどの話なので、ずらしで直る問題ではない」としている。U13(`runsTogether` の共有)は未実装。

## 論点

1. H1 で、入力側の連鎖(2 段)まで直すには、`graph-layout.ts` に層の決め方を足す必要がある。
2. H1 の既定を変えると、`tree` を書いた図の出力が変わる。`tree` は ADR 0015 D2 では検査の指定だったが、配置の指定にもなる。
3. H2 は既存の `fitLayout`(`first` モード)で足りるか。`best` は要るか。
4. H2 で収まらないとき、「分ける位置」は幅の失敗と高さの失敗で意味が違う。
5. H3 は ADR 0016 D11 / U13(経路での並走の解消)と重なる。どちらが何を持つか。

## 決定

### D0: 準備(U0): `tree: 'prt' | 'frt' | 'tt'` の例を先に足す

`examples/` の `toc-*` に `tree` を使う例が無く(grep で `tree:` があるのは `test/toc-rules.test.ts` の `'crt'` だけ)、D1 の既定が golden の対象にならない。D1 の前に、PRT・FRT(正のループと前提条件を含む)・TT の例を 1 つずつ足し、いまの出力を baseline にする(`pnpm golden` が、D1 の差分をこの 3 つに限って見せる)。

### D1: `layer: 'alap'`。入力側の連鎖を含めて、行き先の 1 つ手前へ(H1)

`causeTree` に `layer?: 'asap' | 'alap'` を足す。`'alap'` のとき、`layoutLayered` に新しい指定 `alap?: {keep: readonly string[]}` を渡す(`tighten` は変えない。`tighten` を変えると、それを使う states・classes・semnet の出力が動く)。

- **動かす節の集合 M**: 入る辺が全部 M の節から来ている節(= 入る辺が無い節と、そこから入る辺だけで作られた節の連鎖)のうち、`keep` に無いもの。順方向の不動点で求める(反転した辺は、層決めの向きで数える)。「入力側」の連鎖がまるごと M になる。M に無い節(途中に、M の外から入る辺を持つ節)は動かさない。
- **動かし方**: M の節を、逆の位相順(行き先から)に、`層 = 行き先の層の最小 - 1` へ移す(最長経路の層より後ろにだけ動く。層が減ることはない)。実測の例: `o→x→i4`(`i4` は層 4)は `x:3, o:2`。
- **`keep`**: `causeTree` が、役割 `root`・`injection`(そこから因果が始まる)・`start` の節の id を渡す。**`layoutLayered` の `start` は使わない**(`start` は DFS による循環の切り方も変える。実測: 辺 b→c, c→b, a→b, d→c で、`start=[d]` にすると層が `a:0 b:1 d:1 c:2` から `d:0 c:1 a:1 b:2` に変わる。FRT の正のループ(宣言しない循環は warn)の層が、`keep` のせいで変わるのは筋が違う)。
- **経路は `layered-route.ts` に触らない**: `tighten`・`alap` は `layeredAttempt` の第 3 引数 `layoutOpts`(`LayeredOpts`)に入れれば、素の配置と整列案の両方に届く(`:317`、`:319`)。`AttemptOpts.tighten`(整列案にだけ)の意味は変えない。
- **既定**: `layer` を書かなければ、`tree` が `'prt'`・`'frt'`・`'tt'` なら `'alap'`、それ以外(`'crt'`、`tree` 無し、pdpc・relationDiagram・arrowDiagram)は `'asap'`(いまと同じ)。**これは ADR 0015 D2 の変更**(`tree` は検査の指定だったが、配置の指定にもなる)。理由: PRT・FRT・TT の「入力」は、行き先の手前に置くのが標準の読み方で、`tree` を書いた図は TOC の標準に合わせたい図だから。`layer: 'asap'` で戻せる。`'nbr'` は H4 の ADR で `tree` の値を足すときに既定の対象へ入れる(いまの型に無い)。
- **`asap` に戻したら元の図**: `'asap'` では `alap` も `keep` も渡さない(渡さなければ、層も循環の切り方も、いまと同じ)。
- **PRT・TT では M が図全体になる**: PRT・TT には root・injection・start の節が無いので、`keep` は空で、M は「入る辺が全部 M から来る節」= 事実上すべての節になる。つまり PRT・TT では、D1 は図全体の ALAP(各節を、行き先の層 - 1 まで後ろへ)である。節を前へ動かすことも、層を増やすこともない(層は最長経路より後ろへ動くだけで、図の高さは変わらない)。U0 の例に、**行き先が 2 つある図(sink が 2 つ)**と、**`back: true` の戻り辺を持つ図**を含める。
- **後退辺(`back: true`)**: 反転した辺の先が、DAG の入る辺を失って M に入りうる。実装で、`back: true` を持つ FRT で確かめる(外周のレーンの形は層に依存する)。テストは、層の番号ではなく**反転した辺の集合**(`breakCycles` の結果)が `asap` と同じことを比べる。
- **PRT の「最下段が行動」(H8 の①)との関係**: ALAP で行動が中間目標の手前に寄り、最下段が行動だけでなくなる図がある。H8 の ADR で、規則を「行動を持たない枝の末端が `action` でない」で書き直す。
- **`graph-layout.ts` に触る**(層の決め方の追加。手順 2 の最後、`tighten` の隣に 30 行ほど)。依頼元の担当(ADR 0016 の `graph-layout.ts` の列)との調整が要る: 着手前に調整する(未解決を見よ)。

### D2: `maxNodeW: 'auto'` ― 広い方から、`first` モードで、幅と高さの両方に収まる最初の値(H2)

`best` は使わない(レビューの指摘: 点数(交差, 折れ)は `maxNodeW` ごとに偶然に動き、100px の細長い図が「折れが 1 つ少ない」だけで勝つ。同点は早い方が勝つので、昇順の格子では小さい値が勝つ。`best` の中では fold が、収まる案と点数で競ってしまう)。

- **`'auto'` の意味**: 格子を**広い方から狭い方へ**(260, 250, …, 100)並べ、`first` モードで、**幅と高さの予算の両方に収まる最初の案**を取る。広い方が行数が少なく、高さが低く、箱の中の折り返しが少ない。幅と高さは `maxNodeW` に対してほぼ単調(幅は増え、高さは減る)なので、収まる案は 1 つの区間をなし、先頭が最も読みやすい。多くの図は数回で止まる。
- **`dir` を明示した図にも効く**(`maxNodeW: 'auto'` と書くのは、幅の軸を自動にする宣言。`dir` は変えない)。`fold` は、格子が全部だめなときの最後の手段(`dir` 明示でも `'auto'` では許す。ADR 0010 D7 の `fold: true` と同じ扱い)。
- **予算**: 幅は `w`。高さは 2 種類に分ける。(a) `canvas.height` は SVG の座標での**固定の上限**で、そこから**バンドの上端 `y` を引いた値**(タイトル・出典行・上にある別のバンドの分。下の凡例は考えない)を、収まる条件にする(超えれば不採用。全部だめなら throw)。(b) `maxDisplayHeight` はスライドに**縮小して置いたときの表示の高さ**で、SVG が高くても縮むだけで溢れない。これは SVG の単位に換算して**好み**として使い、**それで throw はしない**(好みを満たす案があればそれを選び、無ければ (a) だけを満たす最初の案を選ぶ)。**近似**であることを `maxNodeW: 'auto'` の説明に書く(同じ制約が states / classes / tree にもあるが、広告するのは `'auto'` が最初)。
- **`fitApplied`**: `from` は、数値の `maxNodeW` か既定 200(`widths[0]` ではない)。`describeApplied` の「縮めた」/「変えた」は**向き(`from` と `to` の大小)だけ**で選ぶ。**`mode`(warn か note)は項目ごとに決める**: `maxNodeW: 'auto'` と書いた図の `maxNodeW` の変更は note(書き手が頼んだ)。`dir` を省略した図の `dir` の変更は、いまのとおり warn。`plan.mode` は `dir` から決まるだけなので、`FitApplied.mode` を項目の側に持たせる。**`fold` は、`maxNodeW: 'auto'` と `dir` 明示の組み合わせで `'written'` と記録されて warn になってしまう**(`'auto'` が頼んだ折り返しなので note にする)。`auto-fit-applied` の文面(`lib/rules.ts:600-605`)に `maxNodeW` の枝を足す。**幅の失敗の文面は変えない**(`test/fit-width.test.ts:65`・`:73` が文面を固定している。高さの失敗の文面だけを足す)。
- **型と検査**: `lib/dsl/diagrams.ts:118` の `maxNodeW >= 80` の検査、`types/diagrams.ts:139`、`dsl-exports` の fixture に `'auto'` を足す。
- **throw の文面の修正(これは H2 の不具合で、`'auto'` と独立に先にやる)**: 高さの予算で落ちたことを文に出す。`tried` に、幅の超過か高さの超過かを持たせ、「does not fit 900px」を「does not fit 900x386px (width 88px; height 436px over the 386px budget)」の形にする。直し方も、幅の超過なら幅を広げる、高さの超過なら図を分ける(D3)か `canvas` の高さを増やす、と分ける。`widerThan` は、幅の失敗のときだけ使う。`fit-width.ts:25` の古いコメントも直す。

### D3: 収まらないときの分け方の提案は、失敗の種類で変える(H2)

throw の文面に、直し方を 1 つ足す(自動で分けない。ADR 0010 D1 の「直し方は 1 つ指す」を踏襲)。

- **高さの失敗**(層が縦に積まれるので、層と層の間で切ると効く): 層 `k` と `k+1` の間で切る案のうち、**両側の高さが予算に収まる**案だけを残し、その中で、境界をまたぐ辺の数が最少、同数なら両側の節数の差が最小のもの。収まる案が無ければ「3 つ以上に分ける」と言う。またぐ辺の端の節は、両方の図に出す(文に書く)。後退辺は、またぐ辺に数えない。
- **幅の失敗**(1 つの層が広いので、層の間で切っても効かない): 最も広い層の名前(節の id)を挙げ、「この層の節を、枝(出ている先の連結成分)ごとに 2 つの図へ分ける」と言う。
- **分析に使うレイアウト**: `Fitted` の `ok: false` に、分析に使う案の結果 `R`(層・辺・大きさを持つ)を 1 つ載せる(`lay` だけでなく、高さ・幅の判定に要る大きさも要るので、`R` ごと)。**どの案か**: 高さの失敗では、**幅に収まった最初の案**(最も広い格子の中で幅が収まるもの。最も狭い `maxNodeW: 100` の案は、行数が増えて最も高く、切る位置の判断を歪める)。幅の失敗では、最も狭い格子の案(fold の前)。fold で層の番号が振り直される(`graph-layout.ts:393`)ので、fold の案は使わない。
- 既存の「`wider > 1400` なら図を分ける」という一般的な文は、位置を言える場合はこの提案で置き換える。

### D4: 交差の再探索は、`cause-crossing` だけ。`cause-parallel` は ADR 0016 の経路の側(H3)

- **持ち分け**: `cause-parallel`(並走)は、ADR 0016 D11 / U13 の経路の仕事とする(並走は並べ替えで直らない、という 0016 の診断を採る)。本 ADR は、**AND の結果へ入る矢印どうしの交差(`cause-crossing`)を減らす並びの再探索**だけを入れる。並走を減らす経路の変更は、U13 の担当に任せ、`runsTogether`(共有関数)の定義は U13 のものを使う(本 ADR は、交差の判定だけを検査から共有する)。
- **点数**: `(loose の数, AND の結果へ入る矢印どうしの交差の数, 交差, 折れ)` の辞書式。**`loose` が先**(並べ替えで AND が描けなくなった図は、検査の対象から外れて違反が 0 になるので、そのままだと勝ってしまう)。さらに、`layeredAttempt` が整列案に課す門番(新しい箱の貫通が無い、幅と高さに収まる)を、再探索の案にも課す。
- **起動と範囲**: `causeTree` だけ(`band.base === undefined`。pdpc・relationDiagram は共有の `layoutCauseBand` を通るが、対象にしない)。最良の案に、AND の結果への矢印の交差が 1 つ以上あるときだけ、**幅の判定を終えた後に 1 回**走らせる。0 なら、今の結果のまま(出力は不変)。再探索が幅・高さを超えない案だけを採る(`fitApplied` は、再探索を記録に足さず、再探索で並びが変わったことを info で知らせる)。
- **並びの変え方**: `layoutLayered` に新しい入力は足さない(`order` の口は、手動ヒントの却下(2026-10-15)に合わせて取り下げ。ADR 0016 PR #204 で同じ決定を書き戻し済み)。`layeredAttempt` を、**掃き出しの回数を増やし(`sweeps` 12)、入力の節の並びを決定的に変えて**呼び直すだけにする。入力の並び: (1) 逆順、(2) 結果から見た深さ優先、(3) 1 つずつずらした並び(最大 `min(節数, 6)`)。**節の配列を並べ替えると、循環の切り方・fold の行の切り方・非連結成分の番号も変わる**ので、再探索は、**宣言しない循環が無く、`fold` していない、つながった 1 成分の図**に限る(それ以外は今の結果のまま)。どの並びでも、**同じ AND の原因が隣り合う**制約(`toc.ts:99-101`)を、並べ替えの後に掛け直す。合計 8 回まで。乱数は使わない。
- **費用**: 起動したときだけ 1 回の探索(最大 8 回の `layeredAttempt`)。測定(レビュー): 50 節で `layeredAttempt` 1 組が約 136ms なので、起動したときの上乗せは約 1 秒。D2 の中(`build`)には入れない(D2 × D4 だと約 25 秒)。
- **手動のヒントは作らない**(ユーザー決定)。

### D5: 検証

- **byte 同一**: `tree` を書かない図、`layer` / `maxNodeW: 'auto'` を書かない図、AND の交差が無い図は、SVG を変えない(`pnpm golden` の差分ゼロ。D0 で足した 3 つの例だけが D1 で動く。その before / after を PR に載せる)。pdpc・relationDiagram・arrowDiagram・states・classes・semnet は、`graph-layout.ts` への足し(`alap`)を使わない限り、出力が変わらない。
- **テスト(フォント依存の絶対値は避ける)**:
  1. `alap`: 入力側が 2 段の連鎖(`o→x→i4`)で、`x` が行き先の層 - 1、`o` が `x` の層 - 1。`keep` の節(root・injection・start)は層 0 のまま。`start` を渡したときと違い、宣言しない循環のある図の層が、`asap` と同じ(`keep` が循環の切り方を変えない)。
  2. `maxNodeW: 'auto'`: 予算が緩いときは最大の値(260)、予算を厳しくすると、収まる範囲で最大の値(単調)。`dir` を明示した図でも効く。収まる値が無いときは、幅の失敗と高さの失敗が、別の文面で throw される。
  3. 高さの失敗の文面が、幅を広げるよう勧めない(88px の図の実測の再現)。
  4. D3: 高さの失敗で、両側が収まる切り方だけが出る。幅の失敗で、最も広い層の節が出る。
  5. D4: 実例(FRT の `e6→e7` と `e2→e7`)で違反が 0 になる(または、何が残るかを書く)。AND を描けなくする並び(`loose` が増える案)が、違反が 0 になっても採られない。違反が無い図では、再探索が呼ばれない(呼び出しの回数は、`layoutCauseBand` の再探索の関数を数える)。
- 依頼元の PRT・FRT・TT の実例の高さ・折れ・違反数の before / after を PR に載せる(測定の再現コード付き。値は固定しない)。

## 代替案

| 案 | 採らない理由 |
|---|---|
| `tighten` を、入力側の連鎖まで動かす形に変える | states・classes・semnet の出力が動く。新しい `alap` を足して、`causeTree` だけが使う |
| `start` に root / injection を渡して固定する | 循環の切り方まで変わる(実測)。`keep`(除外)にする |
| 全図で ALAP を既定にする | CRT の「根本原因は最下段」と汎用の因果図の出力が変わる |
| `order` / `rank` のヒント(H3 の案) | ユーザー決定(手動の整列ヒントは実装しない) |
| `maxNodeW: 'auto'` を `best` で選ぶ | 点数が偶然に動き、狭い図が勝つ。同点は早い方が勝つ。fold が点数で競う(D2) |
| 並走(`cause-parallel`)も並べ替えで直す | ADR 0016 D11 の診断どおり、経路の問題。U13 の仕事 |
| 分ける位置を自動で図にする | 受け渡しの節の置き方は書き手の判断 |
| 並びの全探索(順列) | 節が 10 を超えると組合せが爆発する |

## 影響

- **変わる出力**: `tree: 'prt' | 'frt' | 'tt'` の図の層。ADR 0015 D2 を、「`tree` は検査の指定」から「検査と、層の既定の指定」に改める(`layer: 'asap'` で戻せる)。

## 実装での補足

実装(PR #205・#206・#214〜#217)と、この ADR の書き方との食い違い・補足。

- **U0(#206)**: `tree: 'prt' | 'frt' | 'tt'` の例 `toc-prt`・`toc-frt`・`toc-tt` を baseline として先に足した(コード変更なし)。#214 で `toc-prt` を、2 段の入力連鎖が出る形に直した。
- **U1(#205)**: 高さの失敗が幅として報告される不具合は、単独で直した(幅 88px の図で「does not fit 900px」「widen the figure (width: 140)」と出ていた)。高さの失敗は別の文面にし、直し方を「図を分ける・`canvas` の高さを増やす」にした。幅の失敗の文面と `fit-width.ts` の古いコメントも直した。
- **U2(#214, D1)**: `graph-layout.ts` の `LayeredOpts` に `alap: {keep}` を足した(`tighten` は変えない。`tighten` は 1 パスで、2 段の連鎖に効かない)。`keep` と `start` は最初の層に残り、層は増える方向にだけ動き、循環の切り方は変わらない(`start` を使わないため)。`causeTree({layer: 'asap' | 'alap'})` は、`tree` が `prt`・`frt`・`tt` のとき既定 `alap`、それ以外は `asap`(出力不変)。`root`・`injection`・`start` の役割の実体は `keep`。影響の実測(`layer: 'asap'` と比べて): prt 940x636 → 940x656(長い線が消え、図は 1 行分高い。経路のセグメント数 31 → 29)、frt 940x576 のまま 44 → 42、tt 940x460 のまま 32 → 32(節の位置が動く)。後退辺(`back: true`)を持つ FRT は `toc-frt` の例で確かめた。
- **U3(#215, D2)**: 広い方から 260 → 100 を 10px 刻み、`first` モード。`dir` を書いた図にも効き、収まらなければ `fold`(`'auto'` でも許す)。`fitApplied` の `maxNodeW` / `fold` の `mode` は `'auto'`(info)で、`from` は既定の 200、`describeApplied` は大小で「縮めた / 広げた」。`auto-fit-applied` の文面は「`dir` / `maxNodeW` を `'auto'` にしたため…」。`'auto'` は余裕のある図でも 260px まで広げる(「収まる最も広い値」。意図した挙動)。**高さの予算**は、`canvas.height` があればバンドの上端 y を引いた値(近似)。**`maxDisplayHeight` だけのときは従来どおりで、この ADR が書く「好み扱いで throw しない」への換算は未対応**(スライドの縮小率の取り込みが要るので別途)。数値の `maxNodeW` と省略の図は不変(`pnpm golden` 差分ゼロ)。
- **U4(#216, D3)**: 失敗のメッセージの末尾に `split:` の 1 行を足す(図は分けない)。高さの失敗は、幅に収まった最初の案の層を、両側が高さの予算に収まる境界のうち、またぐ矢印が最少、同数なら両側の節数の差が最小で選ぶ(戻り辺は数えない。なければ「3 つ以上に分ける」)。幅の失敗は、最も狭い案(折り返し前)で最も広い層とその節を挙げて「節を 2 つの図に分ける」。`Fitted` の失敗に各案の結果 `results` を持たせ、`LayoutPlan.layoutOf` を足した(`causeTree` だけが渡す。`states` / `classes` / `tree` の文面は不変)。新ファイル `lib/fit-split.ts`。
- **U5(#217, D4)**: `order` の口は、**ADR 0016 D5 の決定(手動の整列ヒントは実装しない)で取り下げた**とおり、入力の節の並びを決定的に変えて呼び直すだけ。ADR の本文は「掃き出し 12、最大 8 回、再探索は宣言しない循環が無く `fold` していないつながった 1 成分の図に限る」と書くが、実装は**最大 7 回の再レイアウト**(逆順、1〜6 個ずらし)で、採る条件は「点数(AND の矢印の交差, 交差, 折れ)の辞書式で厳密に良い」かつ「層が同じ(循環の切り方・折り返しが変わった案は採らない)・図が高くならない・AND が描けなくなった(`loose`)案でない・`fitApplied` が増えない」。起動は AND の矢印の交差が 1 つ以上あるときだけで、無い図・`pdpc` / `relationDiagram`(`base` あり)は 1 回のレイアウトのまま(出力不変。テストで `deepEqual`)。実測(ランダムな AND つき FRT 150 図。固定幅のモックフォント): 交差のある図 30 → 9(交差の総数 10)、`loose` 0。`cause-parallel` は ADR 0016 D11 / U13 の経路の仕事なので触らない。交差・並走の判定は `lib/cause-clash.ts` に切り出して、検査と探索で共有した(警告の文面と順序は不変)。
- **不具合の修正(別 PR)**: H9(#198): FRT の最終の `role: 'goal'` を、`toc-parts` が `de` と同じに数える(メッセージにも書いた)。H7(#199): `coreDriver` の「中核」バッジを箱の外に置き、`coreDriver` のある図だけ、矢印の向きの軸の両端に `BADGE_H + 2` の余白を取る(`toc-core` は 940x480 → 940x528)。
- **未解決の項目**: 「`graph-layout.ts` の `alap` は ADR のマージ後に着手」は、ADR(#203)のマージ後の PR #214 で入った。D2 の格子の下限 100・上限 260 が日本語の見出しに妥当かは、依頼元の図での測定を待つ。D4 は、節の並びを変えるだけで交差が減ることを実例(上の実測)で確かめた(取り下げずに実装)。
