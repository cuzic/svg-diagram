# ADR 0033: 人間関係の力学の図(ドラマの三角形 + 変わらない土台 + TED*)を描く(U0 の結果しだいで chart の種類 `dramaTriangle` を足す)

- 状態: 決定(帯も chart も作らない。例 `examples/drama-triangle.ts` とレシピで描く。ユーザーの判断 2026-10-18。下の設計は、手書きが 3 つ以上の図で出たときに chart を検討する際の草案として残す)
- 日付: 2026-10-17
- 基点: `main`(85e468e)
- 関連: ADR 0011(因果ループ。`causalLoop` が chart の種類であることを借りる)、ADR 0025/0026(検査の重大度の付け方)、ADR 0027(PPTX)、ADR 0031(FCIS。新しい `lib/` は core)、ADR 0032(決定済み・帯は作らない。`cycle` / `causalLoop({layout: 'ring'})` + レシピ `relationship.md` で賄う。先例と境界は D1・D6)

## 背景

コーチング・コンサル・カウンセリングの資料では、クライアントの人間関係を、Karpman のドラマの三角形(Drama Triangle。迫害者・救済者・犠牲者。1968)で説明し、Emerald の TED*(創造者・挑戦者・コーチ)を出口として対置することが多い。説明の読みどころは次の 3 点で、今の帯では描きにくい**見込み**(U0 で測る)。

- **役割は場面ごとに入れ替わる**(犠牲者→救済者→迫害者→犠牲者…)。三角形の頂点どうしを行き来する軌跡が主役。
- **入れ替わっても、土台の「犠牲者の構え」は変わらない。** 役割を替えただけでは「態度を変えた」ように見えるが、実は同じ構えのまま。これを読み手が誤解なく受け取れる見せ方が要る。TED* は役割の名前を替える図ではなく、**土台が創造者の構えに替わる**図として見せる。
  - 出典の書き分け: Karpman(1968)の主題は役割の**入れ替わり**。「3 役割すべての下に犠牲者の構え(victim orientation)がある」という読み方は Emerald(2005)の枠組みで、Karpman の原論文の主張ではない。ADR と DSL の語はこの区別を保つ。
- クライアント自身の**実際の発言・行動**(「どうせ私には無理」)を、各場面に添える。

`causalLoop` は +/− の増減と R/B の判定を描く図で、役割の遍歴も、変わらない土台も持たない。

## 論点

1. 作らない(既存の図 + レシピ)か、chart の種類にするか。独立した帯にはしない。
2. 入力の形(役割の遍歴、土台、相手)。
3. 土台を、3 頂点に等しく効く形でどう置くか。
4. 検査とその重大度の置き場。書き出し。ADR 0032 との境界。

## 決定

### D1. 先に「既存の図 + レシピ」で足りるかを U0 で測る。足りなければ chart の種類 `kind: 'drama'` にする(独立した帯にはしない)

ADR 0032 は、同じ人間関係の領域で「既存の帯で足りる」と測って帯を作らないと決めた。本 ADR も同じ順で判定する。

| 案 | 配線 | 描画の部品 | PPTX | alt | 検査 |
|---|---|---|---|---|---|
| **既存の図 + レシピ**(`causalLoop({layout:'ring'})` に 3 ノード、`cycle`、`step:`、`legendLabels`、`group`。0032 と同じ) | 無し | 既存 | 既存 | 既存 | 無し |
| 独立した帯 | `Band`/`LaidOutBand`、`CHILD_BANDS`/`STACK_WIDTH`、`LAYOUT_HANDLERS`、`MEASURE_HANDLERS`、`EMIT_HANDLERS`、`FIT_HANDLERS`、`REVEAL`、`VERIFY_HANDLERS`、`lib/rules.ts` の 3 か所、`lib/dsl.ts`、`lib/pptx/bands.ts` ほか | 自前(`arrow()`/`place()` は使えない) | 帯ごとに分類 | 帯ごとに分岐 | `lib/rules.ts` |
| chart の種類 | `ChartKind`(`lib/charts-base.ts`)、`ChartSpec`(`lib/charts.ts`)と switch 2 つ(`chartTexts`/`layoutChart`)、`charts-dsl.ts`、`lib/dsl/charts.ts`、`dsl-exports.json` | `Canvas` の `arrow()`/`place()` を使える | chart は `'image'` に自動 | chart の `alt` | `lib/rules.ts` の分岐 + `relationCheck` の配線(`DiagramData`/`lib/types/core.ts` 2 か所、`lib/dsl/render.ts` 2 か所、重大度の関数、`RelationFinding` の型) |

- `causalLoop` は独立した帯ではなく chart の 1 種類(`lib/charts.ts` の `ChartSpec`)。描画に使いたい `arrow()`(`lib/semnet-common.ts`)と `Canvas.place()`(`lib/charts-base.ts`)は chart の上でしか動かないので、独立した帯は退ける。
- **U0 の判定の観点**: 既存の図で足りないものを数える——(1) 三角形の向きの固定、(2) 番号つきの軌跡、(3) 3 頂点に対称な土台、(4) 吹き出し(`scene` + `says`)、(5) 同じ辺の繰り返し(V→R→V→R で同じ向きの辺が重なる。`ring` は 1 つのループのノードを楕円に並べる配置なので、そのまま渡せるか)。足りる(レシピで済む)なら**作らず**、例とレシピを `relationship.md` に足す。足りないなら chart の種類にする。
- chart の制約: 描く文字列は全部 `*Texts()` に挙げる(strict-width)。入力の欄(`core`/`path`/`ted`/`labels`)は `band.spec` の中に入るので、`withHandle` の欄名の罠(`top/left/right/bottom/center/at`、`anchors`)には当たらない。帯の根に欄を足すときだけ注意。
- `analyzeCausalLoops`(`lib/semnet-analysis.ts`)は使わない(D2 の注)。

### D2. 入力(案)

```ts
dramaTriangle({
  core: {                                        // 変わらない土台(常に描く)
    label: '犠牲者の構え',                        // 任意。既定の語は U0 の出典照合で決める
    says: '「自分には状況を変える力がない」',     // 任意
  },
  path: [                                        // クライアントが場面ごとに取った役割(時系列。2〜6 手)
    {role: 'victim',     scene: '締切を詰められた',   toward: '上司',   says: '「どうせ私には無理です」'},
    {role: 'rescuer',    scene: '後輩の仕事を肩代わり', toward: '後輩',   says: '「私がやっておくよ」'},
    {role: 'persecutor', scene: '後輩に当たる',       toward: '後輩',   says: '「なぜ自分で考えないの」'},
    {role: 'victim',     scene: '疲れ果てる',         says: '「結局、私ばかり」'},
  ],
  ted: {                                         // あれば 2 枚(既定は上下。幅が足りれば左右)。なければ DDT 1 枚
    core: {says: '「何を実現したいか、自分で選ぶ」'},
    path: [ {role: 'creator', scene: '…', says: '…'}, … ],     // 任意。0〜6 手。'creator' | 'challenger' | 'coach'。連続した同じ役割は throw
  },
  labels: {…},                                   // 役割名の訳の上書き(TED* の 3 役割のキーも含む)
}, {id: 'dt1'})
```

- **頂点は役割名だけ**を表示する。人(上司・後輩)は頂点に置かず、各手の `toward`(その場面の相手)として吹き出しか矢印のラベルに出す(役割 = 人ではなく、場面ごとの立ち位置)。**`who` は持たない。**
- `path` は 2〜6 手の時系列。同じ役割が離れて何度出てもよい。**同じ役割が連続したら throw**(自己ループは描かない。1 手にまとめる)。`scene` は吹き出しの見出し、`says` は本文。
- `core` は**常に描く**(DDT は既定で犠牲者の構え、TED* は創造者の構え。ラベルの語は U0 の出典照合で決める。Emerald の語は orientation 寄り)。任意にするのは `core.label`(上書き)と `core.says`。
- `mode` は持たない。`ted` があれば `both`。TED* だけの図は需要が出てから。
- `moves`(相手との矢印)と `analyzeCausalLoops` の再利用は**入れない**。役割の入れ替わりには増減の極性が無く、3 頂点の完全有向グラフの閉路 R1/B1 は読み手に新しいことを伝えない。「最初の役割に戻る」ことは `path[0].role === path.at(-1).role` の純粋関数で判定すればよい。相手の軌跡を 2 本目の `path` で描く需要は未決。
- **アンカー**: 各頂点(例 `dt1.victim`)と各手(`dt1.step1`…)に id を付け、`connect()` で外の注記から線を引けるようにする(`ChartBand.ids`)。名前の前に `opts.id` を付け、`opts.id` が無いときは登録しない(ADR 0026 の `whyWhyTree` と同じ作法。モジュールの変数で連番を数えない)。1 枚の図に 2 つ置いても(「以前」と「今」)衝突しない。
- `toward` の置き場(吹き出しの中か、矢印のラベルか)は U0 で決める。吹き出しに入れると 1 手が 3 要素(相手・場面・発言)で幅が厳しく、矢印のラベルに置くと同じ 2 頂点の間を何度も通る弧でラベルが混む。
- 手ごとの出し分けは D5(chart は要素ごとの `reveal` を持てない)。

### D3. 配置: 三角形、軌跡、そして「3 頂点に等しい土台」

- 頂点: DDT は**広く描かれる向き**として逆三角形(迫害者・救済者が上の左右、犠牲者が下)。TED* は創造者を頂点に置く。**向きの出典は U0 で原典に当たって確認する**(確認前の断言はしない)。
- **土台(`core`)は、帯でも、特定の頂点に接するものでもなく、3 頂点を全部含む領域**にする。
  - 案(a)(U0 で比べる): 三角形全体を囲む地の領域(角丸の塗りと枠)に 3 頂点を置き、領域の見出しに `core` のラベルを書く。
  - 案(b): 重心に `core` を置き、3 頂点から等しい破線を引く。
  - 案(c): 各手の吹き出しに `core` の小さな印を付け、「どの手も同じ土台から」を繰り返す。
  - 約束: どの案でも、**土台は 3 頂点に対して対称に効く**こと(どの頂点にも同じ近さ・同じ印)。逆三角形の下に帯を敷くと、帯に接する犠牲者の頂点だけが土台に見えるため。領域の見出しを左上に置くと迫害者の頂点に寄って見えるので、見出しは**上の中央か領域の下の中央**に置く。案(c)は距離ではなく、印の同一性で約束を満たす。色だけに頼らず、ラベルと端の印も付ける。
- 軌跡: 手と手の間の遷移(n 手なら n−1 本)を矢印で引き、番号は**頂点の側**に置く(① ④ が同じ頂点に重なるときは、番号を並べる)。同じ 2 頂点の間を何度も行き来するときは、n 回目の弧の膨らみをずらす(半径 + k·n。規則は U0 で決める)。弧は `semnet-ring.ts` の `arc()` と同じく**折れ線(`Pt[]`)で作って `arrow()` に渡す**(`Canvas.segs` に入り、`place()` がラベルを弧から避ける。SVG の `A`/`Q` の path で描くと `segs` に入らず、ラベルが弧に乗る)。並走のずらしだけ自前で足す。
- 吹き出し: 頂点の外に置き、`Canvas.wrap(s, maxW)` で**図の `wrap` の設定に従って**折る(chart の中では `bunsetsu-soft` を指定できない。図全体の配置が失敗したときの `phrase` への後戻りは、幅が足りないときに throw させればその仕組みに乗る)。最大幅(`maxNodeW` 相当)を持つ。`scene` + `says` で 1 手 2 行以上になるため、**`both` の既定は上下に積む**(900px では左右に並ばない見込み)。左右に並べるのは幅が足りるときだけ。
- `both` のとき、DDT の土台から TED* の土台へ「構えが替わる」太い矢印を 1 本だけ引く。役割どうしの対応線は引かない(役割名の対応は、TED* の頂点名の添字にとどめる)。

### D4. 検査(`relationCheck` は本 ADR 単独の設定にする)

`rcaCheck` は原因分析の図用で、`RcaFinding` は `severity?: 'info'` があればその規則は常に info、無ければ `rcaCheck` に従う。人間関係の図の規則を混ぜると、RCA の資料で `rcaCheck: 'strict'` を付けたときに無関係の規則まで warn に上がる。ADR 0032 は帯を作らず検査も足さないので、**共通にする相手はいない**。検査が全部 info なら、新しい設定を作らず常に info でよいかを U3 で併せて検討する(設定を作る費用は D1 の表の chart の行を参照)。作る場合は、既定 info、`'strict'` で warn。

| 規則 | 条件 | 重大度 |
|---|---|---|
| `dt-core-says-missing` | `core.says` が無い(土台の中身が読み手に伝わらない) | info |
| `dt-says-missing` | `path` の手の半分以上に `says` が無い(クライアントの実際の言葉が無い) | info |
| `dt-ted-core-same` | `core.says` が**両方あって同じ文** | info |

- DDT の `path` は 2〜6 手で、連続した同じ役割は throw なので、必ず 2 種類以上の役割を含む。**`dt-path-one-role` は書かない**(発火しない)。
- `dt-path-no-return`(最初の役割に戻らない `path`)は**入れるか未決**。戻らない `path` も正しい説明でありうる(場面を 3 つだけ見せる、など)ので、U3 で例を 3〜4 枚描いてから決める。
- 「役割は違うのに土台が犠牲者のまま」は**正しい図**なので、これを警告する規則は書かない。
- 色だけの区別は、既存の検査(`gray-tone-collision` は `box` と `table` の行の `tone` だけ、`a11y-color-only-emphasis` は `em` の語だけ)の範囲外。**色以外の手がかりを型で強制する**(土台にはラベルが必ず付く。端の印の形は DDT と TED* で固定)ことで足りると決め、新しい検査は書かない。

### D5. 書き出しと、手ごとの出し分け

- chart の種類にしたなら、PPTX は `chart: 'image'` に自動で決まる(`lib/pptx/bands.ts`)。HTML は chart の既定でよい(`<text>` が div に変わる影響だけ確かめる)。
- 題と説明(`alt`): 軌跡の要約を出す(例「犠牲者→救済者→迫害者→犠牲者。土台: 自分には状況を変える力がない」)。
- **手ごとの出し分け(スライドで ①→②→③ を順に出す)**: chart は要素ごとの `reveal` を持てない(`lib/reveal-handlers.ts` の `chart: plain`。chart が持つのは帯全体の `reveal`/`until` だけ)。**決定: 全体の `path` を渡したまま、`upTo: k`(k は 1〜n)で描く手を k 手までに絞る。** 配置・高さは常に全体の `path` で決まるので、途中までの図が全体の図の部分集合になることが構造で保証される(`path.slice` で切ると、1 手だけの段が `path` の 2 手未満の throw に当たり、後の手の矢印が先に `segs` に入ると前の吹き出しの位置が変わる)。描かない手の id も登録したままなので、`connect()` は壊れない。著者はスライドごとに `upTo` を変えて並べる。(代案: `dimIds` で未出の手を薄く描く——同じ配置を共有できる。chart の要素ごとの `reveal` を作る——別の ADR。)
- SKILL.md には、使い分けの 1 節を `references/` 側に足す。

### D6. ADR 0032 との境界

- 0032 は「帯を作らず、`cycle` / `causalLoop({layout: 'ring'})` + `legendLabels` + `step:` と、レシピ `skills/svg-diagram/references/relationship.md` で賄う」と決めた。**本 ADR の図とレシピの使い分け**を、U0 の後に決める: 二人の当事者の循環はレシピ、一人のクライアントの役割の遍歴と変わらない土台は本 ADR の図(U0 でレシピで足りれば、本 ADR も作らず `relationship.md` に例を足す)。
- 概念の側の重なり: 0032 の「同じ行動、違う心の向き」(氷山)と本 ADR の「違う役割、同じ土台」は、同じ「行動の層」と「その下の構えの層」の 2 層構図を裏返したもの。構えの層の見た目(水面の線か、地の領域か)をそろえるかは、0032 の例と見比べて U0 で決める。

## U0 の結果(2026-10-18)

### (1) 出典の確認(Web 検索。二次資料のみ。原典は未確認)

- 確認できた: TED* は Creator / Challenger / Coach の 3 役割で、Creator が Victim、Challenger が Persecutor に対応する(Coach が Rescuer に対応するのは、検索結果に明示がなく、含意にとどまる)。書名は *The Power of TED\* (The Empowerment Dynamic)*、土台の移行は「Victim Orientation から Creator Orientation へ」と書かれている(出版社の紹介文)。
- **確認できなかった**: TED* の三角形の向き(公式の図が見つからない)。日本語の標準訳(邦題・Rescuer の訳語)。**どちらも原典か訳書に当たるまで断言しない。** 図の向きは「DDT は逆三角形が広く描かれる」止まりで、TED* は利用者が選べるようにするか、当たるまでは DDT と同じ向きにそろえる。

### (2) 既存の部品での試作(`group` + `row` + `spacer` + `box` + `connect` + `table`。コミットしない `proto/dt-p3〜p5.ts`)

| 観点 | 結果 |
|---|---|
| (1) 三角形の向きの固定 | ○ `row`(上 2 + 下 1、`justify: 'center'`、`width`)と `spacer(64〜72)` で逆三角形になる。`spacer` が小さいと、`connect` のラベルが箱と重なってビルドが止まる(72px 未満)。 |
| (3) 対称な土台 | ○ `group` が 3 頂点を全部含む地の領域になり、`title`(`titleAlign: 'center'`)が上の中央に座る(D3 の案(a)で足りる)。 |
| (2) 番号つきの軌跡 | △ `connect(..., {label: '①', chip: true})` で描ける。同じ頂点に出入りする矢印は `@t`(`vic:top@0.7` と `@0.3`)で手で分ける。 |
| (5) 同じ辺の繰り返し | △ 同じ 2 頂点の間を 2 回通ると、チップが重なる(`text-overlap`)。`labelAt` と `@t` を手で散らせば通るが、矢印どうしが交差しないよう利用者が順序を知っている必要がある。 |
| (4) 吹き出し(場面 + 発言) | ✗ `callout` は箱ごとに 1 つ。同じ頂点が複数回出ると置き場がない。**手ごとの `scene` / `says` は図の下の `table`(番号 | 場面 | 言葉)に置くと読める**(試作 p5)。 |
| `both`(TED* の並置 + 構えが替わる矢印) | ○ `row([group, group])` と `connect('dg:right', 'tg:left', {chip: true, weight: 'heavy'})` で描ける。ただし間隔が 80px だとラベルが矢印を覆う(`connect-label-covers-arrow`)ので 160px 以上。TED* 側の箱は矢印が無く、`graph-orphan-node` / `graph-disconnected` が出る(`accept` に理由を書くか、軌跡を持たせる)。 |
| `upTo`(手ごとの出し分け) | ✗ 手で組み直す。 |

### 判定

D1 の観点のうち (1)(3) と `both` は既存の部品で足りる。(2)(5) は手作業の調整が要り、(4) は表に分ける書き方で足りる。ADR 0032 の基準(「同じ配置の手書きが 3 つ以上の図で出たら帯を検討」)に照らすと、**まず例とレシピで足りる**。chart(`kind: 'drama'`)に進む場合の動機は、`@t` と `labelAt` の手調整の自動化、同じ辺の繰り返し、`upTo`、alt の自動生成の 4 つに絞られる。

### 決定(2026-10-18)

- 帯も chart も**作らない**(ADR 0032 と同じ判断)。`examples/drama-triangle.ts`(説明用の架空の例。以前=ドラマの三角形、以後=TED*、同じ 3 人・同じ場面)を足した。頂点(役割)は固定して**人だけを動かし**、変わらない構えは外枠の見出しで見せ、下に「人 × 場面」の表を置く。同じ 3 人が役割を回す見せ方は、場面ごとの三角形を並べる形(マップ1)を採った。1 つの三角形に人ごとの線を引く形は、番号のチップが重なって読めず、人ごとのレーンは三角形が消えるため退けた。
- レシピの文章は `relationship.md`(ADR 0032 のブランチ。未 push)に書く。0032 の PR が先に入った後に足す。
- 未確認のまま残るもの: TED* の三角形の向き(例では作図上の配置と明記した)、役割・構えの日本語の標準訳。

## 実装の順序

- **U0(先にやる)**: (1) 原典の確認: DDT・TED* の三角形の向き、役割と構えの語の標準訳(Rescuer の訳は「救援者」「救助者」「救済者」と揺れる)。(2) **既存の図で試作**(`causalLoop({layout:'ring'})` に 3 ノード + `step:`・`legendLabels`・`group`、`cycle`)して、何が足りないかを D1 の観点(向きの固定・番号つき軌跡・対称な土台・吹き出し)で数え、0032 と同じ表で判定する。足りれば作らない。(3) 足りない場合に限り、chart の試作で D3 の土台の案(a)(b)(c)、弧のずらし、吹き出しの幅、`path.slice(0,k)` の部分集合性を実測する。D1〜D3 はここで書き換える。

- U2: `ted` と `both`(上下に積む形、構えが替わる矢印)。

新しい `lib/` のファイルは core で、`pure-exports` の ratchet に当たる(関数ごとにテストを同じ PR に入れる)。

## 退けた案

- **独立した帯にする**: 描画の部品が使えない(D1)。
- **最初から chart を作る**: 0032 が既存の図 + レシピで足りると測った先例があるので、U0 で測ってから決める(D1)。
- **`causalLoop` に `preset: 'drama'` を足す**: ノードが自由な図の配置と、頂点が固定の配置が混ざる。
- **`analyzeCausalLoops` で R/B を付ける**: 役割の入れ替わりに極性が無く、情報が増えない(D2)。
- **土台を三角形の下の帯にする**: 帯に接する犠牲者の頂点だけが土台に見える(D3)。
- **現在の役割を 1 か所だけ強調する(`client`)**: 入れ替わりと変わらない土台が出ない。
- **頂点に人を置く(`who`)**: 本人が役割を移る軌跡と矛盾する(D2)。
- **DDT と TED* を別々の chart にする**: 構えが替わる矢印と、場面の入力が二重になる。
