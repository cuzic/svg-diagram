# ADR 0065: ACT / CBT のワークを描く — quadrant の actMatrix と centre、concentric の sectors と marks、cycle の links と frame

- 状態: 提案(実装済み、未レビュー)
- 日付: 2026-11-15
- 基点: `main`(PR #364 まで)
- 関連: ADR 0046(valueChain)、ADR 0054(PowerPoint のグループ)、ADR 0034(`data-node`)。番号は、別ブランチで 0056〜0064 が使われているため 0065 にした。

## 背景

ACT / CBT のワーク(ACT Matrix、Values Bullseye、CBT の 5 領域モデル)を、AI が聞き手になって枠を埋め、JSON spec で図にしたい。今の部品と照らし合わせると、次が足りない。

- ACT Matrix は 2 × 2 の象限図で `quadrant` で描けるが、軸と 4 つのマスの決まった言葉を毎回書くことになり、十字の交点に「気づいている自分」を置く手段がない。
- Values Bullseye(と技術レーダー)は、同心円を扇形に分け、扇形と距離で印を置く図。`concentric` には扇形の区切りも印もない。週ごとの比較には、印の前回の位置からの動きが要る。
- CBT の 5 領域モデル(Padesky の hot cross bun)は、外枠(状況・環境)の中に 4 つの要素を対称に置き、全部の組を両向きの矢印で結ぶ図。`relationDiagram` は配置が自動で、教科書どおりの対称形にならない。`cycle` は一方向の輪。

最初は新しい band(`target`、`interplay`)として作ったが、「新しい band にせず既存の band の機能追加で足りる」というレビュー(依頼者)を受けて、`concentric` と `cycle` のオプションにした(下の「検討したほかの案」)。

## 決定

- D1. `quadrant` にプリセット `actMatrix` を足す(`QUADRANT_PRESETS` と spec の enum)。
  - 縦軸 `y: {title: 'どこで起きるか', low: '心の中（内）', high: '五感で感じる（外）'}`、横軸 `x: {title: '行動の向き', low: '離れる（away）', high: '向かう（toward）'}`、2 × 2、`crosshair: true`。縦軸の見出しは最初「体験」にしたが、意味があいまいだという指摘で改めた。
  - マス(見た目の順、上の行から): 左上「離れる行動 / つらさを避けるためにすること」(muted)、右上「向かう行動 / 大切なものに近づくためにすること」(accent)、左下「内側の体験 / 考え・感情・衝動」(plain)、右下「大切な人や物事 / 価値」(accent)。
  - 英語(`lang: 'en'`)の扱いはほかのプリセットと同じ: 日本語で入るので、英語の図では x・y・cells・centre を書く。
- D2. `quadrant` に `centre?: string` を足す。2 × 2 で `crosshair: true` のときだけ書ける(それ以外と、`regions` との併用はエラー)。`actMatrix` は既定で「気づいている自分」を置き、`centre: ''` で外す。描き方は矢印のラベルと同じ白い下地(`chips`)と太字の accent の文字で、SVG と PowerPoint の書き出しは変えない。交点の言葉は下の行に半分はみ出すので、下の行のマスの見出しをその分下げる。言葉の箱は見出しと同じ障害物で、項目は避ける。
- D3. `concentric` に `sectors`・`marks`・`fromLegend` を足す。
  - `sectors` は 12 時から時計回りに 1〜8 個。見出しは輪の外、扇形の真ん中の向きに置く。区切り線を中心から外周まで引く(`centre` の言葉があるときは、言葉が全体を表すので、いちばん内側の輪の縁から。輪が 1 本なら言葉のすぐ外から)。扇形どうし・輪どうしで同じ見出しは使えない(印は見出しで扇形・輪を指す)。
  - `sectors` があるとき、`rings` は数(1〜6、名前なしの輪)でもよい。輪の名前は 12 時の区切り線のすぐ右に書く(`labels: 'side'` と、輪の `description` は使えない)。
  - 印 `{label, sector, ring | r, tone, id, from}`: `sector` は番号(1 から)・見出し・id、`ring` は `rings` に書いた順の番号(`order` に従う)か名前、`r` は 0(中心)〜1(外周)。どちらか 1 つ。
  - 輪の幅: 内側ほど少し広い(外縁を半径の ((i + 1) / n)^0.75 に置く。中心近くの印にも見出しの場所がある)。`centre` の言葉がそれより大きいときは、いちばん内側の輪をその言葉の大きさまで(半径の 45% まで)広げ、残りの輪で外までを等分する。
  - 印の置き方: 同じ扇形の同じ距離の印は扇形の中に等間隔に並べ、そこから近い順に点の位置を探す(輪に沿って両側へ、輪の印は輪の幅の 3 割まで、`r` の印は半径の 8% まで内外にも)。点はほかの点・文字・前の印の移動の矢印と、別の扇形から移った印の前回の位置(扇形の真ん中の決まった場所なので、先に取っておく)に当てない。前回の丸と移動の矢印も、ほかの印の点と見出しに当てない(当たらない場所がなければ、線をまたぐ場合と同じく緩めて置く)。見出しは右・左・上・下・斜めの順(中心から離れる側が先)に試し、文字・点・自分の移動の矢印に当たらず、輪の線と区切り線をまたがない場所を選ぶ。1 行で見つからなければ 2 行に折り返して探す。それでも見つからなければ線をまたぐ場所に置き(1 行、だめなら 2 行。さらにだめなら、輪の印は輪の幅いっぱい、`r` の印は半径の 20% まで内外に、扇形の端から端まで点の位置を広げて探す)、`crossings` に残して、lint の規則 `concentric-label-crossing`(warn)が印の名前付きで知らせる。規則にしたので、JSON spec でも findings に印の場所(`parts[0].marks[2]`)付きで出る(検査の warnings だけだと spec には出ない)。線をまたいでもほかの文字・点に当たらない場所がなければ、重ねて描くことはせず、印の番号と見出しを書いたエラーにする(その場所の印を減らす、見出しを短くする、ほかの輪・扇形に分ける。spec では `parts[0].marks[3].label` の誤りとして返る)。
  - `from: {ring | r, sector?}` は前回の位置。点線の丸を置き、今の点へ矢印を引く。印に `from` があるときは、図の下に同じ描き方(点線の丸と言葉、矢印、点と言葉)の凡例を付ける。言葉は `fromLegend: [前回, 今回]`(既定 `['前回', '今回']`、spec の `lang: 'en'` は `['Last time', 'Now']`)、`false` で凡例を消す。
- D3b. `concentric` の扇形に `layout: 'circle' | 'stack'` を足す(既定 `circle`。扇形がないときはエラー)。`stack` は同じデータ(扇形・輪・印・`from`)を、扇形ごとの列に輪の箱を積み重ねた形で描く(依頼者が 3 案から選んだ形)。同じ JSON から円と積み重ねのどちらも描ける。
  - 列は扇形(左から書いた順)、段は輪で、いちばん内側の輪が最上段(技術レーダーなら Adopt が上)。`centre` の言葉は列の上の見出し、扇形の名前は列の下、輪の名前(あるとき)は段の左に書く。外枠は角丸の `rect`、段と列の境は細い線。
  - `ring` の印はその段の箱に、`r` の印はその段の中の高さに置く。`r` を輪に分ける境は円の既定(外縁を ((i + 1) / n)^0.75)と同じ。円で `centre` の言葉のためにいちばん内側の輪が広がるときは、境の近くの `r` が円と積み重ねで別の段になりうる。
  - 段の高さは、いちばん込んだ箱の見出しが縦に並ぶだけ(見出しの高さ + 20px ずつ)で、上限はない。輪の名前の高さも入れる。下限は 64px、印か `from` に `r` があれば 88px(段の中の高さで遠さを表し、段の中の移動に矢印の長さが要る)。
  - 列の幅は 96px 以上。足りない帯では、要る幅を書いたエラーにする(円なら同じデータを描ける)。
  - 印の置き方は円と同じ手順(`placeMarks`)を共有する: 点は箱の左から(同じ輪の印は縦に並べ、同じ `r` の印は横に並べる)段に沿って列の幅いっぱいまで探し、上下にもずらす(輪の印は段の 3 割、`r` の印は段の 15% まで。それで見つからなければ段の中のどこでも、近い順に。`r` の印も輪は変わらない)。見出しは自分の箱の中(外枠の内側)で、文字・点・移動の矢印に当てない。段が見出しの数だけ高いので、ふつうは線をまたぐことはない。それでも場所がなければ箱の外の段・列の線をまたいで置き、`concentric-label-crossing` で知らせる。外枠の中に文字・点に当たらない場所がなければ(1 行でも 2 行でも)、外枠の外(図の帯の中)まで広げて探し(ほかの文字には当てない。これも同じ規則で知らせる)、それでもなければ円と同じくエラーにする。
  - 探す点の数: 段は見出しの数だけ高くなるので、8px 刻みで段の高さ × 列の幅を全部試すと、込んだ箱では 1 つの印に数万か所になる。試す数(段の高さ ÷ 8 × 列の幅 ÷ 8)がおよそ 6000 か所を超える箱では刻みを粗くし、それでも 1 段階で 6000 か所を超えたら次の段階へ進む。ほかの点・文字・矢印は 32px のます目に分けて持ち、当たりの判定は近くのものだけを見る(1 列に `r: .1`・`from: {r: .95}` の印 24 個で 2 分かかっていた)。
  - `from` は同じ列なら列の中の上下の矢印。別の列からは、円の「前の扇形の真ん中」と同じ考えで、前の列の真ん中のその高さから引く(その場所は先に取っておき、ほかの点は 24px 以上離す)。前回の丸の近くにほかの印の点があると、その印が動いたように読めるため。移動の矢印は全長にわたって 12px ごとに取っておくので、列をまたぐ長い矢印の上にもほかの点は来ない(円も同じ。今の例の出力は変わらない)。
  - 円の図の出力は変わらない(印の置き方と描き方を関数に分けただけ)。
- D4. `cycle` に `links` と `frame` を足す。
  - `links: 'all' | [{from, to, label?, direction?: 'both' | 'forward'}]`(番号・id・見出し)。あるときは循環の矢印の代わりに、要素を正多角形(偶数は上が平ら、奇数は頂点が上、4 個は正方形)の頂点に置き、組ごとに直線で結ぶ。正多角形のまま広げも縮めもしない(縮めると円が重なる)。帯の幅が足りないときは、要る幅を書いたエラーにする。`'all'` は 6 個まで(全部の組)。同じ組の 2 本・自分への線・`direction`(cw / ccw)との併用はエラー。
  - 円の大きさは、見出しと `sub` がそれぞれ 1 行に入る最小(48〜76px、4px 刻み)。1 行に入らなければ折り返して入る最小(〜84px)。
  - 両向きの線は、真ん中から両端へ向かう 2 本の矢印として描く(`marker-start` は使わず、`marker-end` だけで描ける)。
  - `centre` は中心の円(plain の地)に書き、中心を通る線はその円の下をくぐる。
  - 線のラベルは、線の真ん中(なければ 35%・65%・25%・75% の位置)の両側を試し、ほかの線・円・中心の円・先に置いたラベルに当たらない最初の場所に置く(4 個の対角線のように線が真ん中で交わるときも、ラベルが相手の線の上に乗らない)。
  - `frame` は図を囲む角丸の枠と左上の名前。幅は中身(円と文字)に合わせ、名前より狭くはしない。`links` がない cycle にも使える。
- D5. どちらも flowShapes(`lib/flow-shapes.ts`)の図形(polygon / circle / rect / path)と文字だけで描く。SVG、PowerPoint、`data-node`、spotlight、reveal、検査の登録は変えない。矢印の印の定義(`dsl-arrow`)は、cycle と同じく矢印のある concentric でも出す。
- D6. JSON spec は既存の `concentric`(`lib/spec-parts/r5.ts`)と `cycle`(`lib/spec.ts`)の部品にオプションを足す。印の `sector` / `ring` と線の `from` / `to` が実在しないときは、その場所(`parts[0].marks[2].ring` など)の誤りとして返す。名前が 2 つに当たるとき(ある扇形の見出しが別の扇形の id と同じ、同じ見出しの要素を線が名前で指す)も、最初のものに黙って決めず、DSL と spec の両方で誤りにする。quadrant の `centre` の検査は、格子と十字線の既定を quadrant() と同じ関数(`quadrantDefaults`)で求める(`positioning` は既定で十字線があるので `centre` を書ける。3 × 3 のプリセットでは `parts[0].centre` の誤り)。帯の幅が足りないエラーは、図(diagram)の幅で言う(その図の `width` が帯を狭めているときは、その `width` を言う)。spec には幅がないので、その部分を除き、扇形を減らす・円にするなどを勧める。`lang: 'en'` は全部の concentric に凡例の言葉を足すので、扇形のない concentric では組み立ての時に捨てる。
- D7. ADR 0054 のグループ: concentric は輪(`ring`)・扇形の見出し(`sector`)・印(`mark`。点・前回の丸・矢印・見出し)・凡例(`legend`)、cycle の links は要素(`step`)・線(`link`。2 本の矢印とラベル)・枠の名前(`frame`)をまとまりにする。枠の線と区切り線はどこにも入れない(`rect` の図形は part を持たない)。

## 結果

- 例: `examples/quadrant-act-matrix.ts`、`examples/concentric-values-bullseye.ts`、`examples/concentric-tech-radar.ts`、`examples/concentric-values-stack.ts`、`examples/concentric-tech-radar-stack.ts`(積み重ね版)、`examples/cycle-cbt-five-areas.ts`。どれも `build`(lint --strict)を警告なしで通る。
- テスト: `test/act-cbt.test.ts`(扇形の印の置き方、見出しが線・文字・点に重ならないか報告されること、`from` と凡例、links の多角形と枠、spec、strict lint)、`test/quadrant.test.ts`(actMatrix と centre)。
- resvg: resvg-js 2.6.2 は `orient="auto-start-reverse"` を無視して、すべての矢印の頭を右向きに描く(両向きの線だけでなく、どの図の矢印も)。svg-diagram の PNG の経路(`svgToPng`、`preview` / `show` / `contact`、PowerPoint の画像の帯)は `resvgMarkers()` で印を書き換えてから resvg に渡すので正しい。SVG を直接 resvg-js に渡す外のコードは、同じ書き換えが要る。
- 確かめていないこと: PowerPoint 実機での見た目。1 つの扇形の内側の輪に長い見出しの印が多いと、線をまたぐ印が残る(警告が出る)。

## 検討したほかの案

- 積み重ね版を別の部品(`valuesGrid` など)にする: データは concentric と同じで、描き方だけが違う。同じ JSON から両方を描けるよう、`layout` にした。
- 新しい band `target` と `interplay`(最初の実装): 部品の数が増え、`concentric` / `cycle` と使い分けを覚えることになる。扇形と印は同心円の上の追加、多角形の相互作用は「要素を円周に並べる」cycle の配置の変種なので、オプションにした。
- interplay を `relationDiagram` の配置オプションにする: 意味は最も合うが、自動配置(層・交差の最小化)の仕組みに固定の多角形を入れることになり、手間と影響が大きい。
- 中心の言葉を避けて矢印を曲げる: 4 個の正方形で 2 本の対角線が大きく曲がり、読みにくかった。中心の円の下をくぐらせた。
- 線をまたぐ見出しに白い縁取り(ハロー)を付ける: SVG と PowerPoint の両方の文字の描き方を変えることになる。場所を探し、見つからなければ警告にした。

## レビュー(Opus、2026-11-15)で直したこと

- 別の扇形から移った印の前回の丸が、そこにいる別の印の点に重なり、その印が動いたように見えた → 前回の位置を先に取っておき、前回の丸と矢印をほかの印に当てない。
- 4 個の対角線のように真ん中で交わる線のラベルが、相手の線の上に乗った → ラベルはほかの線・円・ラベルに当たらない位置を探す。
- 狭い帯で links の cycle の多角形が縮み、円が黙って重なった → 縮めず、要る幅を書いたエラーにする。あわせて横に広げるのもやめ、「4 個は正方形」を本当にした。
- 輪が 1 本で中心の言葉があると、区切り線の長さが 0 になった → 言葉のすぐ外から引く。
- spec の検査の抜け: cycle の自分への線と同じ組の 2 本、quadrant の `centre`(2 × 2 と十字線)、扇形・輪の同じ見出しを、組み立て前に場所付きで返す。`actMatrix` で格子や十字線を変えたときのエラーは `centre: ''` を勧める。空白だけの `centre` は無いものとする。扇形のある concentric で輪の `description` を書いたときの文言を直した。
- (積み重ね版のレビュー)最後の手として図のどこにでも置いた見出しが外枠や輪の名前の上に出て、知らされなかった → 見出しは外枠の内側だけ。込んだ箱で見出しが重なった(段の高さに上限があり、横は列の 150px ほどしか探さず、同じ `r` の印は上下にほとんど動けなかった) → 段の高さは見出しの数だけ(上限なし)、横は列の幅いっぱい、最後は段の中のどこでも。列をまたぐ長い移動の矢印の上にほかの点が来た → 矢印を全長にわたって取っておく。狭い帯で意味のわからない例外 → 要る幅を書いたエラー。長い輪の名前が段からはみ出した → 段の高さに入れる。

## レビュー(2026-11-16、PR #367)で直したこと

- `layout: 'stack'` の印の置き場所探しが、込んだ箱で段の高さ × 列の幅を 8px 刻みで全部試し、そのたびにすべての点・文字・矢印と当たりを調べていた(1 列に 24 個で 153 秒、MCP サーバーの CPU を止める) → ます目で当たりを調べ、試す数に上限を置いた(見出しの長い 24 個・輪 3 本で、spec の描画と検査まで 122 秒 → 2 秒。込んだ箱では点の位置が前と少し変わる。例の出力は変わらない)。
- 最後の手として、見出しを最初の候補の右にほかの見出しと重ねて置き、検査が ok: false になっていた(「線をまたいで置き、警告」と書いたのと違った) → 外枠の外まで広げても重ならない場所がなければ、印を名指しするエラーにした。
- spec の quadrant の `centre` の検査がプリセットの既定(格子・十字線)を見ていなかった。名前が 2 つに当たる参照が最初のものに決まっていた。帯の幅のエラーが図の幅でなく帯の幅を言っていた → D6。
