# ADR 0036: `diagram({density: 'compact'})` — 層状の図の間隔を詰めて、同じ図を小さい面積に収める

- 状態: 実装済み(PR #301)。Opus の読み取りレビュー 2 巡目(1 巡目: 高 2・中 3・低 3、2 巡目: 高 0・中 3・低 4)までを反映した版
- 日付: 2026-10-18
- 基点: `main`(PR #293 = ADR 0035 まで)
- 関連: ADR 0016(経路 `layered-route.ts`)、ADR 0019(`maxNodeW` の格子)、ADR 0031(FCIS。`WrapEnv` / `LayoutCtx` を純粋な層へ渡す口)、ADR 0010(幅・高さに収める `fitLayout`)
- 範囲外: 箱の中の余白(`PAD`)、文字の大きさ、図の幅の決め方(`width: 'fit'` は層状の図を狭くしない。既存の挙動)、層状でない図(表・グラフ・チャート・ワイヤーフレーム)、`pert` / `dependencyNetwork` / `causalLoop` / `semnet`(`density` を渡していない)

## 背景

利用者から「もっと密度を上げてほしい」と求められた。聞き直した結果、意味は次のとおり:
- **図を小さくまとめる**: 箱と箱、層と層の間隔を詰めて、同じ内容をより小さい面積に収める。線の本数と交差は変えない。
- **対象は図の種類を問わず全部**(層状の図)。

層状の図の間隔は、図の種類ごとに別々の定数が持っている(実測。`lib/` の定数):

| 図 | 兄弟の間隔 | 層の間隔 | 線のレーン・スタブ |
|---|---|---|---|
| 因果ツリー(`toc.ts`) | `GAP = 28` | `LEVEL = 64`、`gapFor(...)` | `layered-route.ts` の `STUB = 18`、`LANE = 14` |
| 状態遷移(`states.ts`) | `GAP = 28` | 72 / 64 / `widest + STUB + ARROW + 8` | 同上 |
| クラス図(`classes.ts`) | `GAP = 36` | `LEVEL_GAP = 72` | 同上 |
| ツリー(`tree.ts`。組織図・マインドマップ) | `GAP = 24` | `LEVEL_GAP = 44` | — |
| 故障の木(`fta.ts`) | `GAP = 24` | `LEVEL_GAP = 36` | — |
| BPMN(`bpmn.ts`) | — | `COL_GAP = 52 / 36` | `STUB = 16` |

定数を直接書き換えると、既存の図(golden)が全部変わる。図ごとの間隔を 1 つの指定で変える口が要る。

## 決定

### D1: `diagram({density: 'normal' | 'compact'})`。既定は `'normal'`(今のまま)
- `DiagramOpts.density` / `DiagramData.density`。検証は `diagram()` で(`'normal'` か `'compact'` 以外は throw: `diagram({density}) must be 'normal' or 'compact'`)。
- `'compact'` は間隔の倍率 **0.75**(`spaceOf`、`lib/layout.ts`)。倍率は値で書かせない(`density: 0.6` のような自由な数は、図が壊れる下限を利用者に背負わせるので入れない。段階が要るなら語を足す)。
- 書かない図の SVG は 1 バイトも変わらない(`pnpm golden` の差分ゼロ。実測)。

### D2: 倍率は `WrapEnv.space`(省略可、既定 1)で、既にレイアウトまで届いている env に載せる
- `WrapEnv` は `layoutBands` が作る `LayoutCtx`(`extends WrapEnv`)が、そのまま各レイアウト関数に `env` として渡している(`layout-handlers.ts` の `layoutBpmn(..., ctx)` など)。`space` を足すと、純粋な層(`toc.ts` など)に**新しい引数を足さず**に届く。`space` は省略可なので、`{wrap, keepWords}` の literal を作るテストは変わらない。
- 純粋な層はモジュールの状態を持たない(`core-purity.test.ts`)ので、定数を差し替えるのではなく、使う場所で `Math.round(定数 * (env.space ?? 1))` と掛ける。
- `layered-route.ts` は、`STUB` / `LANE` を `stubOf(space)` / `laneStepOf(space)`(`Math.round`)で関数にし、`routeLayered` の先頭で局所の `STUB` / `LANE` として**同名で隠す**(関数の中の約 12 か所の参照を書き換えない)。`gapFor(n, chip, space)`、`layoutWithLanes(..., chip, space)`、`AttemptOpts.space` が受ける。

### D3: 詰める対象と、詰めない対象
詰める(`env.space` を掛ける):
- 因果ツリー(`causeTree` / `pdpc` / `relationDiagram`): `GAP`、`LEVEL`、`gapFor(degree)`、レーンとスタブ(`AttemptOpts.space`)。`PORT = 22`(AND の矢じりの間隔)は詰めない(矢じり 12px が離れる最小のため)。
- 状態遷移(`stateDiagram`)と**アロー・ダイヤグラム(`arrowDiagram`。`StatesBand` を返す)**: 兄弟の間隔(自己ループの無いとき)、層の間隔の基本値、`gapFor`、レーンとスタブ。**遷移ラベルの幅は詰めない**(`dir: 'right'` の層の間隔は `widest + スタブ + 矢じり + 余白`。ラベルの幅まで 0.75 倍にすると、層の間にラベルが入らず、ラベルが矢印の線に載る: Opus レビュー #1。スタブだけ縮む)。自己ループのある行間(`GAP + LOOP + …`)も詰めない(ループの腕の置き場)。
- ツリー(`tree.ts`): 組織図(縦向き・`dir: 'right'` とも)と、`mindmap` の `right` / `left` / `down` / `up` / `radial`(`layoutTree` / `layoutBalanced`)の `GAP` と `LEVEL_GAP`。**`mindmap` の `org` / `list` / `brace` / `fishbone` / `timeline` は詰まらない**(別の配置を使う。実測: バイト一致)。
- 故障の木(`fta.ts`): `GAP` と `LEVEL_GAP`。
- BPMN: 列の間隔 `COL_GAP`。ただし**ラベルのあるフローの図では、列の間隔をラベルの幅が決める**(`gap = max(COL_GAP, widestFlow + flowRoom)`)ので、`COL_GAP` を詰めても変わらない(実測: `examples/bpmn.ts` はバイト一致)。効くのは、ラベルの置き場を取らない段(`fit: 'shrink'` の `flowRoom: null`)だけ。レーンの高さ(`PAD_Y`)・`flowRoom` は詰めない。BPMN は帯が全幅なので、効いても見た目の差は列が左へ寄るだけ。

詰めない:
- **クラス図の兄弟の間隔(`GAP`)とレーン・スタブ**。多重度のラベル(`1`、`1..*` など)を矢印の端に置くので、詰めるとラベルどうしが重なる(実測: `GAP` を詰めると `classes: label "1" overlaps label "1..*" by 1x6px`、スタブを詰めても同じ)。クラス図は**層の間隔の基本値だけ**詰める(縦向きのクラス図では、層 = 行なので、行の間隔は詰まる。横向きでは詰まる向きが列になる)。
- 箱の中の余白(`PAD_X` / `PAD_Y`)と文字の大きさ(`roles`)。範囲外。

### D4: 効く範囲(事実を書いておく)
- **間隔を詰めても、SVG の幅は変わらない**。図が狭くなって中央に寄るだけで、**`width: 'fit'` と組んでも狭くならない**(`fitWidthOf` が帯の全幅を返すため。層状の帯の描画範囲を測るのは別の変更になる。実測: Opus レビュー #3)。`density` が減らすのは**高さ**で、効き方は図の向きで違う: 兄弟が縦に並ぶ図(縦向きの因果ツリー・PDPC・組織図・`dir: 'right'` の組織図)は高さが減る。兄弟の間隔も層の間隔も横方向にしかない図(横一列の状態遷移・BPMN)は高さが変わらない。
- **高さは、ほとんどの図で減るが、すべてではない**。`maxNodeW: 'auto'` の段(通常では 130px、compact では 150px で収まる、など)や、並びの探索が別の答えを選ぶと、配置が別物になって高くなる図がある(ランダムな因果ツリー 176 図中 4 図、最大 +14%。D6 の戻しの図も高さが戻る)。**`dir` を省略した図では、compact で別の向きが収まるようになり、向きが変わって高さが約 2 倍になることもある**(ランダムな状態遷移 200 図中 1 図: 218 → 448px。通常は `maxNodeW` を縮めて横向きのまま収まるが、compact では縦向きが高さの予算に収まり、収める手順が向きの変更を先に選ぶ。手順の順番は既存のもの)。向きを変えたくない図は `dir` を書く(書いた `dir` は変わらない)。「収まりやすくなる」も、戻しのある図では常には成り立たない(幅や高さの予算に収まるのが compact だけの図は、戻しで作り直せず、compact のまま残る: D6)。

### D5: 検査は変えない
`edge-bends`・`cause-crossing`・箱の貫通など、図の検査は変えない。詰めた結果、ラベルが重なる・矢印が箱に触れる、など検査が失敗するときは、その図で `density` を使わない(D3 のクラス図が例)。**因果ツリーと状態遷移は D6 の戻しがある**。

### D6: 因果ツリーは、詰めた図が箱を通る矢印を作るときだけ、その帯を通常の間隔に戻す
- 実測(Opus レビュー #2): ランダムな因果ツリー(実フォント、幅 1800、176 図)で、compact だけが `cause: arrow X -> Y runs through "Z"`(ビルドが失敗する)を出す図が、通常 6 図に対して **21 図**。原因は層の間隔(`LEVEL` / `gapFor`)を詰めること(層の間隔だけ詰めなければ 6 図 = 通常と同じ。GAP・レーン・スタブだけ詰めても増えない)。倍率を 0.9 にしても、増える図が 5 図残った。
- 決定: `layoutCauseBand` が、詰めた(`space !== 1`)図に**検査と同じ判定**(`routesThroughNodes`、`verify-base.ts`)で箱を通る矢印を数え、1 本でもあれば、`space: 1` で作り直す。作り直した図のほうが通る矢印が**少ない**ときだけ採る(同数なら詰めた図)。詰めて問題の無い図(大多数)は、追加のレイアウトをしない。
- 実測(同じ 200 図、実フォント): compact だけが失敗する図は 18 図 → **0 図**(通常より問題が多い図は無い。通常と問題の数が同じで、箇所が別の矢印に移る図が 2 図ある)。
- **作り直しが例外を投げるとき**(通常の間隔では幅・高さに収まらない)は、詰めた図のまま返す。検査が、本当の問題(箱を通る矢印)を言う(2 巡目 #1: 戻しの作り直しを `try` で囲んでいなかったため、「幅に収まらない」と別の理由を言っていた)。
- **状態遷移にも同じ戻し**(2 巡目 #2): `layoutStatesBand` が、詰めた図に検査と同じ判定(`statesProblems`。`verify-base.ts` に取り出し、検査 `checkStates` と共有する)で、箱を通る遷移・ラベルが箱・他のラベル・他の矢印に載る数を数え、通常の間隔のほうが少ないときだけ作り直す。実測(ランダムな状態遷移 88 図、実フォント): compact だけで問題の出る図が 3 図(すべて `dir: 'down'`。ラベルの重なり)あり、この戻しで直る。
- 戻しは、**黙って**通常の間隔で描く(利用者に知らせる `info` は無い。未解決)。
- クラス図・BPMN には入れていない(ランダムな図で測っていない。クラス図は未測定、BPMN は効かない図が大多数)。出るようなら同じ形で足す。

## 検証(実装 PR での実測。`examples/` の同じ図を normal と compact で並べた)

SVG が変わった図(Opus レビューの全 169 図の比較。それ以外はバイト一致):

| 図 | 通常 | compact |
|---|---|---|
| 因果ツリー(15 節の図 / `toc-crt` / `toc-frt`) | 732 / 596 / 616px | 636 / 524 / 544px |
| `toc-prt` / `toc-nbr` / `toc-tt` / `toc-hop` / `toc-core` / `toc-crt-loop` | 716 / 612 / 520 / 544 / 528 / 652px | 644 / 558 / 466 / 472 / 474 / 568px |
| PDPC(`qc-pdpc`)/ `qc-relation` / `qc-systematic` | 848 / 1202 / 492px | 740 / 1055 / 456px |
| 故障の木(`fta` / `fta-inhibit`) | 702 / 418px | 675 / 400px |
| 組織図(`org-chart` / `org-chart-right`)/ マインドマップ | 312 / 576 / 316px | 290 / 528 / 292px |
| クラス図 | 688px | 664px |
| アロー・ダイヤグラム(`qc-arrow` / `qc-arrow-long`) | 283 / 1159px | 276 / 1033px |
| 状態遷移・BPMN(`state-diagram` / `bpmn`) | 268 / 500px | 同じ |

- 型検査、全体テスト(既知のフォント差 2 件を除いて通る)、全例の `golden`(`density` を書かない図は差分ゼロ。Opus が独立に確かめた)。
- テスト(`test/density.test.ts`、25 件): 主な層状の図 14 例で、compact が新しい問題を足さず高くならないこと、因果ツリー・PDPC・組織図・故障の木が 2〜10% 低くなること、`'normal'` と書かない図が同じ SVG、クラス図の同じ層の箱の間隔が変わらないこと、状態遷移の層の間隔がスタブ分(8.5px)しか減らないこと(元のコードでは落ちる)、数・`'tight'` は throw、因果ツリーの箱を通る矢印を戻すこと(レビューの実在の失敗図 c43・c123、状態遷移 s61。それぞれ、戻しや `try` を外すと落ちることを確認)。
- **ランダムな因果ツリー 200 図(実フォント、幅 1800)**: compact だけが失敗する図は 18 図 → 0 図(D6)。

## 未解決の項目
- **倍率 0.75 の根拠は目視**(箱の高さ 36〜55px に対し、レーン 14 → 11px、スタブ 18 → 14px)。因果ツリーの 15 節の図で、間隔を 0.55 倍にしても読めたが、AND の矢じりが近づく図・ラベルのある図では、ランダムな図のビルドで確かめただけ。層の間隔を詰める割合は、D6 の戻しで安全側にしてある(詰めても問題が増えない)が、「戻る図」の割合は測っていない。
- **対象外の層状の図**: `pert` / `dependencyNetwork` / `causalLoop` / `semnet`(同じ `layoutLayered` を使うが `density` を渡していない。実測: examples の `semnet-*` と immunity-loop はバイト一致)。
- **`width: 'fit'` は層状の図を狭くしない**(既存の挙動。層状の帯の描画範囲を測れば効くが、既存の図の `width: 'fit'` も変わるので別の変更)。
- **`.svg-diagram.json` では `density` を設定できない**(`wrap` / `keepWords` はできる)。プロジェクト全体を compact にしたい利用者は図ごとに書く。意図的に入れていない(既存の図が全部変わる指定を設定ファイルから入れるのは別の判断)。
- **クラス図・BPMN の戻し**(D6)は入れていない。クラス図はランダムな図で測っていない(状態遷移と同じく、ラベルが関わる)。
- **戻しを利用者に知らせる `info`** が無い(`density: 'compact'` が黙って通常の間隔で描かれる)。`maxNodeW` の `auto-fit-applied` と同じ形が候補。
- **検査の追加**: 詰めすぎで `edge-bends` が増える図があるかを、実在の図(`medius-research` の因果ツリー 33 本など)で測っていない。
- **迂回経路**(ADR 0035 の `route-search.ts`)の出だしは、`routeLayered` のスタブ(倍率つき)に合わせた。迂回経路の終わりの余地(26px)は倍率を受けない。
