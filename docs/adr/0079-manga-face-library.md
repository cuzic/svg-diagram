# ADR 0079: パラメトリックなマンガ風の顔のライブラリ — パーツのスロット、表情のプリセット、`CharacterManifest` の出力

- 状態: 提案(Draft。2026-11-22。決める人の確認待ち。Q1〜Q10 は未決。設計と小さなスパイクで、`lib/` は変えていない)
- 日付: 2026-11-22
- 基点: `main`(74816524。ADR 0078 U0a まで)
- 関連: ADR 0074(`comic()`、`CharacterManifest`、`loadCharacter`、D6 の紙の色)、ADR 0076(D1 マンプ、D4 パレットとキーラインと `recolor`)、ADR 0069(`partCatalog`)、PR #444(Open Peeps など素材の調査。`spike/comic-assets`)
- 範囲外: 3/4 や横向きの顔、全身、アニメーション(表情の補間は「将来」に書くだけ)、絵師の素材そのもの、顔を選ぶ画面(Artifact 側)
- 例のデータはすべてこの ADR のための作り話。ふきだしの文言は中立なもの(「ここが変更点です。」「要確認ですね。」)だけ

## 背景

`comic()`(ADR 0074)の内蔵の顔は、`lib/comic/face.ts` の約 60 行で、表情 8 種、髪 2 種。目は点か円で、機能は足りるが絵としては粗い。絵師の素材は `CharacterManifest`(箱、頭・口・上のアンカー、表情ごとの SVG 断片、ライセンス)で受けられるが、素材を用意するのは人の手間になる。

PR #444 の調査では、Open Peeps(CC0)が同じ型で動き、内蔵の顔よりずっと良く見えた。決める人の依頼は、**日本のマンガ風の顔を SVG で描く枠組みを作る**こと。Open Peeps のパーツのスロット構造(頭と髪、表情、小物、色のスロット)を構造の参考にする。

Open Peeps の構造(DiceBear の定義 `open-peeps.json`。PR #444 の `spikes/comic-assets/source/` と README)は次のとおり。

- キャンバスにパーツのスロット(頭・髪、表情、アクセサリ、ひげ、マスク)がある
- 各パーツは path・circle・ellipse の集まりで、変換で置く
- 色は名前のついたパレットの鍵(肌、髪の濃い所、服、輪郭)

この ADR は、その構造を**パラメータで動かせる形**にし、手描きの固定の path は髪のような「形そのものが絵」の所に絞る。

## スパイク(`spikes/manga-face/`。`lib/` は触っていない)

| `gallery.ts` | `out/gallery.svg`(表情 8 × 髪 2 × 肌 2)、`out/extras.svg`(追加の表情 4) |
| `run.ts` | 読み込み・大きさ・決定性・アンカー・4 コマの `comic()` の測定 |

| 4 コマの `comic()`(`2x2`、6:5、素材 2 人を `cast.asset` で) | 検査の結果は問題なし(`verdict.ok`)。人物の断片が 4 コマに 8 個出た。SVG 53.5 KB(顔 1 つあたり約 6.7 KB) |

**見た目の正直な評価**(`out/gallery.png`、`out/comic-sample.svg` を見ての感想。好みは決める人が決める)。

- 良い所: 内蔵の顔よりはっきり「マンガ・アニメ風」に読める。大きな目(二重の虹彩、2 つのハイライト、上まぶたの太い線とまつげ)、眉の傾き、口の形で、**笑い・怒り・悲しみ・驚き・考え中**が原寸のギャラリーで見分けられる。肌色と髪の濃淡の差し替えも効く。決まった色のスロット(肌・髪・服・虹彩)から、影と明るい所の色を混ぜて作れる
- 弱い所 1: **汎用的で、子どもっぽい**。丸い頬、大きな目、小さな口で、どの表情でも幼く見える。大人の顔(長い顔、小さめの目、細い眉)は、形のパラメータ(D2)で出せるはずだが、スパイクでは試していない
- 弱い所 2: **髪が「ヘルメット」に見える**。髪の影(境目の太い線の内側)と 1 本のハイライトの帯だけで、毛束の流れが無い。ボブは濃い髪が輪郭の線と同じ暗さで、塊に見える(ADR 0076 D4 の「髪と服の境目のキーライン」を髪にも使うと分かれる見込み。スパイクでは付けていない)
- 弱い所 3: `surprise` と `think` は差が小さい(目の大きさと視線だけ)。`neutral` は平板
- 弱い所 4: **舞台の大きさでは細部が消える**。頭の円が半径 36px(縮尺 0.36)なので、輪郭の線は約 1.7px、下まぶたの細い線は約 0.9px になる。まつげとハイライトは小さな点になり、表情は**眉と口と目の形**で決まる。コマの中では、あほ毛がふきだしのしっぽに隠れることがある(`top` のアンカーが頭の上の余白を広げるため、しっぽは髪に当たる)
- 総括: 「手描きの Open Peeps の方が洗練されている。パラメトリックな顔は、Open Peeps が持たない自由さ(表情の連続的な調整、乱数での量産、色の差し替え)と、権利の簡単さの代わりに、絵の完成度を払う」。**v1 の見た目の水準は、このスパイクの出来(良い試作)から上がる余地がある(D7 のレビューの往復で上げる)が、プロの手描きには届かない**と考える。受け入れるかどうかは決める人の判断(Q2)

## 決定

### D1. 範囲と境界 — 別パッケージにして、`CharacterManifest` で渡す

**推奨: 別のパッケージ(仮の名前 `manga-face`。別のリポジトリ、または、この monorepo の別のパッケージ)。出力は `CharacterManifest` の JSON。svg-diagram は何も依存しない。** どちらでも、`comic()` は今のまま(スパイクで確認済み: `comic(sheet, {characters: {id: manifest}})` が変更なしで受ける)。

| 観点 | 別パッケージ(推奨) | `lib/manga-face/`(モジュール) |
|---|---|---|
| 純粋さ | どちらも純粋に書ける。別パッケージなら svg-diagram の純粋のテスト(`test/core-purity.test.ts`)の外に出られ、制約を負わない | `lib/` の純粋の規則と、`typecheck` / `biome` に従う。出来るが、絵の調整のたびに core の CI に乗る |
| Artifact のバンドルの大きさ | Artifact は `svg-diagram/browser`(jsDelivr)を読む。顔の生成を入れると約 20 KB(ソース。圧縮前)が全員に載る。別パッケージなら**必要な人だけ**。普通は、生成済みの JSON(1 人分 48.7 KB、gzip で 3.5 KB)をページに貼る | エントリを分ければ避けられるが、`package.json` の `exports` と bundle の管理が増える |
| 出す周期 | 絵の調整(髪の形、目の比率)は頻繁で、見た目に好みが入る。core の golden(`examples/out/`)は顔を使うので、**顔が変わると core の golden が動く**。別パッケージなら動かない | 顔の調整が core のリリースと golden の更新に結びつく |
| 絵のライセンス | 絵(パーツの形)を CC0、コードを MIT のように**絵だけ別に宣言できる**。core の LICENSE(MIT)に絵の権利の説明を混ぜない | 同じパッケージ内に絵が入る。ファイルごとのライセンス表示が要る |
| 試す速さ | 先に出して試せる。決める人の見た目の確認と直しの往復が core の PR に乗らない | PR ごとにレビューが core と同じ重さ |

- svg-diagram 側の変更は**ない**(U7 で、例とドキュメントと、マニフェストの検査用の fixture だけを足す)。型は、別パッケージが `CharacterManifest` と同じ形を自前で宣言する(`import type` の依存は持たない)。ずれは U7 のテスト(別パッケージの出力を `loadCharacter` に通す)で検知する。
- `lib/manga-face/` を選んだ場合の差分: エントリは `svg-diagram/manga-face` の独立した export にし、`svg-diagram/browser` には入れない。U1〜U7 のファイルの置き場所が変わるだけで、D2 以降は同じ。
- どちらでも、**出力は `CharacterManifest`**(D5)。`comic()` に型や分岐を足さない。

### D2. パーツのモデル — スロットとパラメータ

座標は箱 `[0, -40, 300, 400]` の中、頭の中心は `(150, 140)`、頭の円の半径は 100(スパイクの値。D5 でアンカーに使う)。顔の幅は約 170、あごは中心の下 約 96。舞台の頭の半径 36px に合わせると、縮尺は 0.36。

```ts
interface MangaCharacter {
  id: string; name: string;
  head: {cheek: number; chin: number; jaw: number; ratio?: 'normal' | 'chibi'};   // 頬の幅、あごの深さ、あごの丸さ(0 尖る〜1 丸い)
  eyes: EyeParams;  brows: BrowParams;  mouth: MouthKind;  nose: 'none' | 'dot' | 'line';
  hair: HairParams;
  palette: {skin: string; hair: string; top: string; iris: string};   // 名前つきの鍵、または後述のスロット
  mirror?: boolean;
}
```

| スロット | パラメータ | 方式 | 理由 |
|---|---|---|---|
| 顔の輪郭 | 頬の幅 `cheek`、あごの深さ `chin`、あごの丸さ `jaw`。頭身 `ratio`(`normal` / `chibi`) | **パラメトリック**(3 次ベジェの制御点を数から出す) | 数が少なく、連続で変えられ、輪郭が必ず閉じる。`chibi` は頬を広げ、あごを浅くし、胴を縮め、目を下げる(v1 は `normal` だけ。`chibi` は U2 で試して決める) |
| 耳・首・胴 | 位置は輪郭から出る。服の色 `top` | パラメトリック(固定の形を数で置く) | 形の自由度が要らない |
| 目 | 幅 `w`、高さ `h`、傾き `tilt`、虹彩の大きさ `iris`、視線 `lookX` / `lookY`、ハイライト 1〜2、まつげ。**種類 `kind`**: `open`、`arc`(`^^`)、`arcDown`、`cross`(`><`)、`dot`、`half`(半目) | **パラメトリック**(上まぶたと下まぶたの曲線を `w`・`h`・`tilt` から出し、虹彩は clipPath で切る) | 目はマンガ風の顔の印象の大半を決める。連続の調整が効く所 |
| 眉 | 角度 `angle`(内側が下がる=怒り、上がる=困り)、太さ `thick`、上下 `dy`、左右の上げ `raise` | パラメトリック(先の細い塗りつぶしの形。筆のような太さの変化) | 表情を決めるのは眉の傾きが大きい。左右の差が要る(考え中、ドヤ) |
| 口 | 種類(`flat` / `smile` / `open` / `o` / `frown` / `wave` / `omega`(ω) / `grit`(食いしばり)/ `tri`(▽))と幅 | **形のライブラリ**(種類ごとに幅から path を出す) | 口は種類で形が変わるので、連続の変形にはしない。幅だけ動かす |
| 鼻 | `dot` / `line` / `none` | 小さな固定の形 | マンガ風では省くことが多い |
| 髪 | `template`(`short` / `bob` / …)、前髪の毛束の数 `strands`、分け目 `parting`(−1〜1)、あほ毛 `ahoge`、ハイライトの帯 `highlight` | **テンプレート(固定の外形)+パラメトリックな前髪**。外形(頭のてっぺん、側面、後ろ髪の塊)は固定の path、前髪の毛先は `strands` と `parting` から出す | 髪は「形そのものが絵」で、輪郭をパラメータで滑らかに作ろうとすると不自然になる。外形は固定の手描きが勝つ。**毛束の数と分け目だけパラメータ**にして、同じテンプレートから見た目を変える |
| 効果 | 頬の斜線(`blush`) | 顔の一部として描く | 頬の斜線は顔の上に重なる細い線で、表情のプリセットに属する |
| 汗・怒りマーク・落ち込みの線 | — | **描かない。ADR 0076 D1 のマンプ(`marks`)に任せる** | 位置の置き方(頭のアンカー、ぶつかりの検査)が 0076 にある。顔の断片に混ぜると二重になり、検査も効かない |

- **固定の形が良い所**: 髪の外形、胴の肩の線、耳。**パラメータが良い所**: 目、眉、口の幅、輪郭、毛束の数、色。判断の目安は「連続して動かして不自然にならないか」。
- 表情は D3、色は D4、アンカーは D5。

### D3. 表情はプリセット

**表情 = 目 + 眉 + 口 + 頬の斜線の組**(`Preset`)。スパイクで 12 個が動いた。1 つの表情は、顔のパラメータ(輪郭・髪・色)に**かぶせるだけ**で、人物の見分けは変わらない。

| ADR 0074 の `ComicExpression` | プリセット(目 / 眉 / 口) | スパイクでの見え方 |
|---|---|---|
| `neutral` | `open` / 水平 / `flat` | 平板。無表情として読める |
| `smile` | `open`(やや細め)/ 少し上がる / `smile` | 穏やか |
| `laugh` | `arc`(`^^`)/ 上がる / `open`(舌つき)+ 頬の斜線 | はっきり笑いに読める |
| `surprise` | `open`(大きく、虹彩を小さく)/ 上がる / `o` | 目で分かるが、`think` との差が小さい |
| `worry` | `open`(垂れ目)/ 内側が上がる / `wave` | 困りに読める |
| `angry` | `open`(つり目、細め)/ 内側が下がる / `grit` | はっきり怒りに読める |
| `think` | `open`(視線を横上へ)/ 片眉を上げる / `flat`(小さい) | 弱い。視線の差だけ |
| `sad` | `open`(垂れ目、大きな虹彩)/ 内側が大きく上がる / `frown` | はっきり悲しみに読める |

**追加の表情**(ADR 0074 にはない。スパイクで動いたのは最初の 4 つ。残りは U4 で作る):

| 名前 | 日本語 | 内容 |
|---|---|---|
| `shy` | 照れ | 視線を下げた目、困り眉、`omega` の口、頬の斜線 |
| `smug` | ドヤ | 半目、片眉を上げる、`omega` の口 |
| `deadpan` | ジト目 | 半目で虹彩を小さく、水平の眉、`flat` の口 |
| `clench` | 食いしばり | `><` の目、内側が下がる眉、`tri` の口 |
| `cry` | 号泣 | `arcDown` の目、困り眉、`open` の口。涙は**描かず**マンプに任せる |
| `sleepy` | 眠い | 半目、眉は下がる、`o` の小さい口 |
| `blank` | ぽかん | `dot` の目、水平の眉、`o` の口 |
| `smirk` | にやり | 細い目、片眉を上げる、口の片側だけ上がる(`omega` の変形) |

**ADR 0074 の `ComicExpression` との関係(0074 を壊さない)**:

1. 出力のマニフェストの `expressions` のキーは、**今の 8 種だけ**(`loadCharacter` は 8 種以外のキーを拒む)。
2. 追加の表情は、人物ごとの**割り当て** `expressionMap`(`{think: 'deadpan', sad: 'cry'}` のような、8 種のキーからプリセットの名前への対応)で出す。たとえば、ある人物では `think` が「ジト目」になる。**割り当てはライブラリの側で解決**し、マニフェストには 8 種のキーに解決済みの断片だけが入る。`comic()` は何も知らなくて良い。
3. 追加の表情を `comic()` の台本(`ComicStage.expression`)から直接名指ししたい場合は、`ComicExpression` を広げる(後続の ADR。欠けた表情の扱いは現在の挙動に従い、無ければ `neutral` に落とす)。Q8。

### D4. スタイル — 線、影、ハイライト、パレット

- **線の重みは 1 つの体系**(箱の単位。縮尺 0.36 で舞台の px にすると約 0.36 倍):
  - 輪郭(顔、髪、胴、首): 4.6(約 1.7px)
  - 目鼻口と眉の細部: 3.4〜3.6(約 1.3px)
  - 髪の毛筋、下まぶたの線: 2.4(約 0.9px)
  - 上まぶた: 7(約 2.5px)。ここだけ太くして目を締める
- **線(ストローク)と塗り(ブラシ風)の使い分け**: 輪郭は**一定幅のストローク**(丸い端と角)。眉、まつげの跳ね、上まぶたの端は**先の細い塗りつぶしの形**(幅が変わる、ブラシ風)。ストロークだけにすると記号のように見え、塗りだけにするとデータが大きくなるので、この 2 つに分ける。
- **影は 1 色**(セル塗りの 1 段): 肌の影(肌の色を一定の割合で赤みの色へ寄せる)を、前髪の下と首にだけ置く。髪の影は髪の色をインクへ寄せた色で、前髪の境目の内側の帯。グラデーションは使わない(サイズと決定性のため)。
- **ハイライトの規則**: 目に 2 つ(大きな楕円と小さな円。左上と右下)。`surprise` と `angry` は 1 つ。髪は帯 1 本(明るい色)。
- **パレットのスロット**: `skin`、`hair`、`top`、`iris`。ほかの色(肌の影、頬の赤み、髪の影・ハイライト、虹彩の濃淡、服の影)は、**この 4 つからコードで混ぜて出す**。ADR 0076 D4 の `recolor`(`{skin, hair, top}`)は「素材の中のこの色の文字列を置き換える」ものなので、**派生の色も宣言しないと置き換わらない**。そのため:
  - 通常は、色の変更を**ライブラリで再生成**する(`faceManifest({...character, palette})`)。`comic()` は色を知らなくて良い
  - 0076 の `avatars`(`renderComic` で上書き)を効かせたい場合は、マニフェストの `recolor` に**派生の色も含めた対応の表**を出す。0076 の `recolor` は 3 つのキーなので、キーの追加(例: `skinShade`)は 0076 A13 の変更になる(U7、Q9)
- **キーラインと紙**: インクは固定の暗い色(`#2b2530`。紙の白に対して約 15:1)で、インクの線は 3:1 以上。ADR 0076 D4 の 3 層(紙のキーライン・インク・紙のキーライン)を、**髪が服や首にかかる境目**に付ける(スパイクでは未実装。ボブで髪が塊に見える原因の候補)。外側の輪郭は 1 本のまま。
- **ダークモードと紙の色**: 断片の色は `#rrggbb` で書き、`characterSvg` が `rgb()` に直す(ダークの再配色を受けない。ADR 0074 D6。**紙の上に載せる**)。白目は `#ffffff` で、紙の色には依存しない。コマの背景が `bg.tint` で変わっても、顔は同じ。

### D5. 決定性と API

```ts
faceManifest(character: MangaCharacter, opts?: {expressions?: readonly string[]}): CharacterManifest
randomCharacter(seed: string | number, constraints?: Constraints): MangaCharacter
mirrorCharacter(m: MangaCharacter): MangaCharacter     // mirror の反転
presets: Record<string, Preset>
```

- **同じパラメータからバイト単位で同じ SVG**(スパイクで確認)。出す座標は**0.1 に丸める**(ADR 0076 の座標を丸める方針に合わせる)。三角関数は、角度を決まった刻みに丸めた表から引く(エンジンによる最後の桁の違いが出力を変えない)。パラメータの表示順、数の丸め、`Object.entries` の順序を固定する。テストは Node の版を変えて同じ出力になるか(CI の matrix)を見る。
- **乱数の人物**(`randomCharacter`): シードから決める。`xmur3` のハッシュと `mulberry32` の乱数(外部に依存しない小さな実装)。値は**刻みの決まった集合**から選ぶ(連続の値を細かく出さない)。制約(髪のテンプレート、肌の範囲)を渡せる。**同じシードは必ず同じ人物**(スナップショットのテスト)。
- **鏡像(`mirror`)は、ライブラリのオプション**(`comic()` のオプションにしない)。理由: (1) 反転は絵の一部(分け目、あほ毛、左右非対称のパーツ)で、`CharacterManifest` の中身として完結する。`comic()` を変えずに済む。(2) アンカー(口の x、頭の円の中心)の反転はマニフェストの側で計算でき、`comic()` が反転した絵のアンカーを推測しなくて済む。(3) 正面の顔は左右がほぼ対称なので、v1 では差が小さい。顔を向き合わせたいときは、同じ人物の `mirror` 版を別の id(`mf-b-flip`)として `characters` に渡す。3/4 の顔を入れる版では、`comic()` の舞台の `flip` が要るので、**そのときに決め直す**。実装は `<g transform="translate(300 0) scale(-1 1)">`(`loadCharacter` を通ることを確認済み)。
- **アンカー(パラメータから計算する)**:
  - `head`: 頭の円 `{cx: 150, cy: 140, r: 100}`。箱の規約として固定。顔の輪郭は円の内側に収める(あごは中心の下 96〜100)
  - `mouth`: `[150, 210]`(口の位置のパラメータから。表情で口の中心は動かしても、マニフェストには 1 つ。しっぽは口を向くので、表情によらず同じ点)
  - `top`: 髪のテンプレートの上端(あほ毛があればその先)から計算した値。8 表情の絵の最上端より**上**(安全側)。スパイクの測定(Chromium の `getBBox` +インク幅の半分)で確認
  - `hand`: v1 は出さない(胴に手が無い)。マンプの小道具(0076 D1)は `hand` が無いとき、決まった位置に落ちる
  - `bubbleSides`: `['top-left', 'top', 'top-right']`
- マニフェストの `license` は CC0(D6)で、`author` に原作者(このプロジェクト)、`url` にリポジトリ。

### D6. 権利

1. **絵はすべて独自**。特定の作品、作家、キャラクターに似せない(「○○風」の指示を作らない、参考画像を写さない)。Open Peeps と DiceBear は**構造(スロットと色のスロット)の参考**にとどめ、パーツの形(path)は使わない。DiceBear の Adventurer(CC BY 4.0)の絵は写さない。Lorelei(CC0)も形は写さない。
2. **ライセンス**: 絵のパーツ(path の形)と生成物を CC0、コードを MIT(Q6)。マニフェストの `license.spdx` は `CC0-1.0`。`loadCharacter` が空の `license` を拒むので、ライセンスを必ず書く。
3. **AI による部品の下書き(OmniSVG 系など)**: **v1 では入れない**(推奨。Q4)。理由: 学習データ(MMSVG-2M には出所が混ざる)と生成物の権利が不明確で、既存の作品に似るおそれを検査できない。許す場合の条件(あとで決める):
   - 生成物を**そのまま入れない**。人が見て、パラメトリックなコード(D2)として**描き直す**(下絵として使う)
   - `PROVENANCE.md` に、部品ごとの作者、日付、道具、指示(プロンプト)、似た作品が無いかの確認を記録する
   - モデルの利用条件が、生成物の CC0 での公開を許すものだけ
4. 部品を足す PR は、出所の記録(`PROVENANCE.md` の行)が無いと通さない(U6 のテスト)。

### D7. 品質のリスクと見直しの往復

手続きで魅力のある顔を作るのは難しい。**検査できることと、好みで決まることを分ける**。好みは決める人の判断で、ライブラリは「受け入れの目安」を機械で検査し、見た目は人が見る。

**見直しの往復**:

1. **ギャラリー**: `gallery.svg`(表情 × 髪 × 肌)、`random.svg`(シード 64 人)、`stage.svg`(舞台の大きさ(頭の半径 36px)で、表情 8 種を並べた行)、4 コマのサンプル。PNG にして確認する(スパイクのとおり)。
2. **決める人の確認点**: U2(顔・目・眉・口)の後、U3(髪)の後、U4(プリセット)の後に、ギャラリーを見てもらう。各回は「OK / 直す点の一覧(セルの位置で指す)」。**U2 で OK が出るまで、U3 以降へ進まない**。
3. **golden の SVG**: ギャラリーの代表 6 セル(表情 3 × 髪 2)を golden にし、**意図した見た目の変更**のときだけ更新する(PR の説明に前後の画像)。

**受け入れの基準(検査できるもの。好みは含まない)**:

| 基準 | 内容 | 目安 |
|---|---|---|
| 読み込み | 乱数のシード 1000 人 × 全表情で `loadCharacter` が受ける | 全部通る |
| アンカー | 頭の円が箱に収まる。`top` は 8 表情の絵の上端より上で、箱の上端以下(`getBBox` +インク幅)。口のアンカーは口の形の中。ミラー版も | 全部通る |
| 自己交差 | 塗りの path をベジェから折れ線にして、自己交差が無い(髪の毛先、輪郭) | 0(前髪の毛先の数 × 分け目の全組で) |
| 大きさ | 断片 1 つ、マニフェスト 1 人分、gzip 後 | 断片 ≤ 8 KB(スパイク 4.9〜5.8 KB)、1 人分 ≤ 64 KB(48.7 KB)、gzip ≤ 6 KB(3.5 KB)、path ≤ 60(33) |
| コントラスト | インクと紙が 3:1 以上(約 15:1)。目鼻口の線と肌の色(全部の肌の候補)が 3:1 以上。髪と肌・服と肌は保証しない(ADR 0076 D4 と同じ)。境目のキーラインで見分けられる | インクの線の比 |
| 決定性 | 同じパラメータで 2 回、別の Node の版で、同じバイト列 | 一致 |
| 見分けやすさ | 舞台の大きさ(頭の半径 36px)で描いた表情 8 種の組(28 組)の画素の差が、閾値以上 | 閾値は U4 で、スパイクの値から決める(今は `surprise` と `think` が近い) |
| 禁止要素 | `<text>` / `<use>` / filter / 名前つきの色を含まない(`loadCharacter` が検査) | 0 |

**好み(決める人が決める)**: 全体の印象、年齢の見え方、髪の形、目の大きさ、線の太さ。機械の検査は「壊れていない」までで、「魅力がある」は保証しない。

### D8. 将来(この ADR の範囲外。メモ)

- 表情の補間: プリセットが数の組なので、2 つの間を補間できる。VectorTalker の口パクにも使える。
- 顔の共通部分の共有: マニフェストは表情ごとに胴と髪も持つので、重複が大きい(gzip で約 14 倍に縮む)。共通の層と表情の層を分ける形は、ADR 0074 の変更(Q7)。
- 3/4 の顔、全身。

## 代替案

| 案 | 採らない理由 |
|---|---|
| Open Peeps を同梱して使う | 構造は良いが、日本のマンガ風ではなく、手描きの固定の絵で、パラメータで動かせない。PR #444 で変換は可能と確認済みなので、**並べて使う**(排他ではない) |

## 影響

- svg-diagram 本体の `lib/` は変えない(U7 は例とドキュメントとテストの fixture)。
- 別のパッケージを作る場合は、リポジトリ、CI、リリースの設定が要る(U1)。
- 顔の生成はブラウザでも動かせる(純粋)。Artifact は、生成済みの JSON を貼る(1 人分 48.7 KB、gzip 3.5 KB)。

## テスト方針

- 純粋(`fs` / `child_process` なし)。Chromium を使う検査(アンカーの `getBBox`、PNG)は、別の実行で分ける(playwright-chromium は optional)。
- 決定性は、2 回の実行とパラメータの深いコピーと、Node の版(CI の matrix)。
- golden は、ギャラリーの代表の SVG。更新は意図した見た目の変更のときだけで、人が見て受け入れる。

| Q6 | 絵とコードのライセンス | 絵は CC0、コードは MIT | 素材の再配布に支障がなく、権利の説明が単純(D6) |

| Q8 | `ComicExpression` に追加の表情(照れ、ドヤ、ジト目など)を足すか | 後で(U8)。v1 は `expressionMap` で 8 種のキーに割り当てる | 0074 を壊さない。欠けた表情の扱いを決めてから |
| Q9 | ADR 0076 の `recolor` を、派生の色(影、ハイライトなど)も宣言できるように広げるか | 広げる(0076 A13 の拡張。U7)。または、色の変更はライブラリで再生成する運用にして、`avatars` は素材には効かないと明記 | `avatars` を素材の顔でも使いたいなら前者が要る |
| Q10 | 舞台の頭が小さい(半径 36px で、細部が消える)ことをどう扱うか | 受け入れる。細部(まつげ、ハイライト)は大きく描いたときだけ効く装飾と考え、表情は眉・口・目の形で決める。コマの頭を大きくする案は `comic()` の別の ADR | 舞台の寸法を変えると 0074 の全部の配置に影響する |
