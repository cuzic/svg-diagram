# ADR 0079: パラメトリックなマンガ風の顔のライブラリ — パーツのスロット、表情のプリセット、`CharacterManifest` の出力

- 状態: 提案(Draft。2026-11-22。Opus レビュー 2 回分(1 回目 Major 8、2 回目 Major 3)と、決める人の方針(別リポジトリ + ADR 0080 のプラグイン)を反映。Q2〜Q10 は未決。設計と小さなスパイクで、`lib/` は変えていない)
- 日付: 2026-11-22
- 基点: `main`(74816524。ADR 0078 U0a まで)
- 関連: ADR 0074(`comic()`、`CharacterManifest`、`loadCharacter`、D6 の紙の色)、ADR 0076(D1 マンプ、D4 パレットとキーラインと `recolor`)、ADR 0069(`partCatalog`)、PR #444(Open Peeps など素材の調査。`spike/comic-assets`)、**ADR 0080(バンドのプラグインの仕組み。PR #455 で起草中。**この ADR は 0080 の確定を待って D1 の接続を決め直す**。0080 のダークモードの規則は改訂中で、色は既定でテーマのトークン、要素ごとに紙の色へ外せる、という方向)

## 背景

`comic()`(ADR 0074)の内蔵の顔は、`lib/comic/face.ts` の約 60 行で、表情 8 種、髪 2 種。目は点か円で、機能は足りるが絵としては粗い。絵師の素材は `CharacterManifest`(箱、頭・口・上のアンカー、表情ごとの SVG 断片、ライセンス)で受けられるが、素材を用意するのは人の手間になる。

PR #444 の調査では、Open Peeps(CC0)が同じ型で動き、内蔵の顔よりずっと良く見えた。決める人の依頼は、**日本のマンガ風の顔を SVG で描く枠組みを作る**こと。Open Peeps のパーツのスロット構造(頭と髪、表情、小物、色のスロット)を構造の参考にする。

Open Peeps の構造(DiceBear の定義 `open-peeps.json`。PR #444 の `spikes/comic-assets/source/` と README)は次のとおり。

- キャンバスにパーツのスロット(頭・髪、表情、アクセサリ、ひげ、マスク)がある
- 各パーツは path・circle・ellipse の集まりで、変換で置く
- 色は名前のついたパレットの鍵(肌、髪の濃い所、服、輪郭)

この ADR は、その構造を**パラメータで動かせる形**にし、手描きの固定の path は髪のような「形そのものが絵」の所に絞る。

**見た目の評価**(`out/directions.png`、`out/gallery.png`、`out/comic-sample.svg`。好みは決める人が決める)。

- 良い所: 内蔵の顔よりはっきり「マンガ・アニメ風」に読める。眉が前髪の上に出て、舞台の大きさでも笑い・怒り・悲しみ・驚き・考え中は読める。肌の濃い人物でも特徴の線が残る。前髪は毛束の幅と長さが分け目からの距離で変わり、規則的なギザギザではなくなった。側面の切れ込み(耳の張り出し)は無くした
- **まだ弱い所 1: 短い髪は、まだ「おかっぱ」に近い**。外形が 1 つの塊で、流れが無い。毛束を減らして幅を変えたが、帽子のように見える。髪のテンプレートを作り込む U3 で直す
- **まだ弱い所 2: 黒い髪の人物では、眉のキーラインが白い「ステッカー」に見える**(眉が前髪に重なる所に紙の線を敷くため)。暗い肌のキーラインの「落書き」感は、基準を 3:1 にして、**brown では無くなった(`dark` だけに残る)**。線の幅も 6 から 4 に減らした。ただし、黒い髪 × 眉は残るので、髪の側の毛束を一段明るくする、眉の下にだけ敷く、などの調整が U3 に残る
- **弱い所 3: 成熟した方向は、舞台の大きさでは、若い方向との差が小さい**。顔を縦に、あごを平らに、目を小さく・虹彩を小さく・上まぶたを細く・まつげなしにしたが、舞台(`directions.png` の最初の段)で見分けるのは、目の大きさと眉の太さ程度。年齢感は髪が決めるので、成熟した方向専用の髪のテンプレートが要る(U3)。あごの深さは頭の円(`chin ≤ 98`)で上限があり、「縦に長く」する余地は小さい
- **弱い所 4: 舞台の大きさでは細部が消える**。輪郭の線は約 1.7px で、まつげとハイライトは小さな点になる。表情は眉・口・目の形で決まる
- 総括: 「手描きの Open Peeps の方が洗練されている。パラメトリックな顔は、Open Peeps にない自由さ(表情の連続調整、乱数での量産、色の差し替え、権利の簡単さ)の代わりに、絵の完成度を払う」。**受け入れるか、どちらの方向に進めるかは決める人の判断**(Q2。**`out/directions.png` の最初の段(舞台の大きさ)を見て決めてほしい**)

## 決定

### D1. 範囲と境界 — 別リポジトリ(`cuzic/manga-face`)。svg-diagram には ADR 0080 のプラグインでつなぐ

**決める人の方針: 顔のライブラリは別のリポジトリ `cuzic/manga-face` に置く。** svg-diagram とは、一般的な**バンドのプラグインの仕組み(ADR 0080。PR #455)**でつなぐ。**0080 は起草中で、この ADR は 0080 を「未確定の前提」として参照し、接続の細部は 0080 の確定後に決め直す。**

- **manga-face が提供するもの**(どれも svg-diagram の `lib/` を変えずに出す):
  1. **人物の提供**(`comic()` 向け): `faceManifest(character)` が `CharacterManifest` を返す。`comic()` はそれを `characters` に渡して今のまま使う(スパイクで確認済み)。0080 に「人物の提供元」の形があれば、それを実装する。
  2. **バンド**(0080 が決める形で): 例として、顔の一覧(表情 × 人物の格子)や、アバターの並びを描くバンド。顔の見た目を決める人が、ギャラリーを svg-diagram の図の一部として描ける。
  3. 生成済みの JSON を出す CLI(`manga-face build params.json > character.json`)。Artifact は、JSON を貼るか、ブラウザで動く ESM を読み込んで人物を作り直す(0076 のアバターの選び直し)。
- **svg-diagram 側の変更は、ADR 0080 の仕組みだけ**。この ADR の U7 は、例とドキュメントとテストの fixture を足す。
- **ダークモードと色(0080 との境目)**: manga-face の断片は、インクと紙を `#22201b` と `#ffffff` の 16 進で書く。これは `PALETTE.text` / `PALETTE.bg` と同じ値で、**0080 の既定(色はテーマのトークン)に任せると、ダークモードでインクと紙が反転する**。顔は紙の上に載る絵なので(ADR 0074 D6)、**バンドも人物の提供も、断片を `characterSvg` と同じ変換(`#rrggbb` → `rgb()`)を通して出すか、0080 の「要素ごとに紙の色へ外す」指定で外す**ことを、manga-face の約束にする。0080 の改訂版の規則が確定したら、その名前に合わせる。
- **型のずれの防ぎ方**。manga-face は `svg-diagram` を **peer の範囲(`^`)つきの devDependency** に持ち、**`import type`** で `CharacterManifest` を使う(型の変更で manga-face の `typecheck` が落ちる)。実行時の依存は持たない。CI は**公開済みの svg-diagram の `loadCharacter` に出力を通す**(最新と、peer の範囲の下限の 2 版)。
- **ブラウザで動く ESM を出す**(依存なし。0076 のアバターの画面が、人物を作り直せるように)。純粋に書く(`fs` を使わない)ので、バンドルは作れる。jsDelivr から読めること。
- **権利**: 絵(出力)は CC0-1.0、コードは MIT(D6、Q6)。core の LICENSE(MIT)に絵の説明を混ぜない。
- 別リポジトリにする理由は、**出す周期**(絵の調整が頻繁で、好みが入る)、**絵のライセンスを別に宣言できる**こと、**決める人の見た目の確認と直しの往復が core の PR に乗らない**こと。
- `comic()` の `characters` に渡す形は変えない(0074 のまま)。

### D2. パーツのモデル — スロット、範囲、不変条件

座標は箱 `[20, 16, 260, 344]`(絵の幅 20〜280 と、髪の上端 約 23 に切る。0074 の助言)の中、頭の中心は `(150, 140)`、頭の円の半径は 100。顔の幅は約 170、あごは中心の下 約 96。舞台の頭の半径 36px に合わせると、縮尺は 0.36。

```ts
interface Base {   // 人物の基本の形。表情はこれに差分をかぶせる(D3)
  head: {cheek: number; chin: number; jaw: number; chinW: number};
  eyes: {w: number; h: number; tilt: number; iris: number; y: number; gap: number; lashes: boolean; lidW: number};
  brows: {thick: number; dy: number};
  mouth: {w: number; y: number};
  nose: 'none' | 'dot' | 'line';
  hair: {template: 'short' | 'bob'; strands: number; parting: number; ahoge: 'none' | 'left' | 'right'; highlight: boolean; sideLen: number};
}
interface MangaCharacter extends Base { id: string; name: string; palette: Palette; mirror?: boolean }
type Palette = {skin: SkinKey | `#${string}`; hair: HairKey | `#${string}`; top: TopKey | `#${string}`; iris: IrisKey | `#${string}`};   // ADR 0076 の名前つきの鍵(既定)と、上級者向けの 16 進
```

**パラメータの表**(スパイクの値。`normalize` が範囲に丸め、刻みに合わせる。丸めたあとで不変条件を検査する):

| 項目 | 範囲 | 刻み | 既定(若い方向) | 意味 |
|---|---|---|---|---|
| `head.cheek` | 74〜96 | 2 | 86 | 頬の半幅 |
| `head.chin` | 90〜98 | 1 | 96 | あごの深さ(頭の円に収める) |
| `head.jaw` | 0〜1 | 0.05 | 0.65 | あごの丸さ(0 は尖る)。既定は 0.6 以上 |
| `head.chinW` | 0〜16 | 2 | 4 | あごの先の平らな幅(あごの角度と頬の張りを別にする) |
| `eyes.w` / `eyes.h` | 18〜28 / 13〜26 | 1 | 25 / 23 | 目の半幅 / 半高 |
| `eyes.lidW` | 4.5〜7.5 | 0.5 | 7 | 上まぶたの線の太さ(成熟した方向は 5.5 で細い) |
| `eyes.tilt` | −8〜10 | 1 | 0 | 外側の目尻の上がり(負は垂れ目) |
| `eyes.iris` | 0.6〜1.2 | 0.05 | 1.0 | 虹彩の大きさ |
| `eyes.y` / `eyes.gap` | 14〜28 / 36〜48 | 1 | 20 / 42 | 目の高さ(中心から)/ 左右の中心の間隔の半分 |
| `brows.thick` / `brows.dy` | 4〜9 / −20〜8 | 0.5 / 1 | 6 / 0 | 眉の太さ / 上下 |
| `mouth.w` / `mouth.y` | 10〜48 / 58〜70 | 1 | 16 / 64 | 口の基本の幅 / 高さ(`mouth.y ≤ chin − 30`) |
| `hair.strands` | **1〜9(整数)** | 1 | 5 | 前髪の毛束の数 |
| `hair.parting` | −1〜1 | 0.25 | 0.5 | 分け目の位置。**髪の量は、髪が落ちる側(分け目の反対)に寄る** |
| `hair.sideLen` | 16〜40 | 2 | 36 | 短い髪の側面の長さ(成熟した方向は 20) |
| `hair.ahoge` | `none` / `left` / `right` | — | **`none`** | 側面の小さな房(中央の長いあほ毛は、`top` を広げて差し替えの互換を壊すので既定でなし。D5) |

**依存する制約**(範囲の箱の中でも、有効でない組がある。**粗い格子(頬 5 × あご 3 × 毛束 3 × 分け目 3 × テンプレート 2 × 方向 2 = 540 点)で、この制約を入れる前は 70% が無効だった**: 口があごに届く 50%、目が顔から出る 30%、顔が頭の円から出る 3%)。`normalize` が範囲に丸めたあとに適用する:

| 制約 | 式 |
|---|---|
| 顔が頭の円の中 | あごの丸さ → 頬の順に下げる(円の中に入るまで) |
| 目の間隔 | `eyes.gap ≤ 顔の半幅(目の高さ) − 4 − まつげ(11) − 1 − 1.08 × 18` |
| 目の幅 | `eyes.w ≤ (顔の半幅(目の高さ) − 4 − まつげ − gap − 1) / 1.08`(いちばん幅の広い表情 `surprise` が ×1.08) |
| 口の高さ | `eyes.y + 28 ≤ mouth.y ≤ chin − 30`(`laugh` の口が 26 下がるため) |
| 口の幅 | `mouth.w ≤ (顔の半幅(口の高さ) − 6) × 2 / 2.6`(`laugh` が ×2.6) |

これでも残るもの(範囲が両方の下限を満たせない、眉と目の間など)は、`validate` が報告する。

**不変条件**(`validate` がパラメータと全表情のあと、**幾何として**検査する。`loadCharacter` は絵の幾何を検査しないので、ライブラリが責任を持つ。落ちたら `toManifest` が例外を投げ、違反の一覧を出す):

1. 範囲の中で、`hair.strands` は 1 以上の整数。パレットの値は、名前つきの鍵か `#rrggbb`(それ以外は拒む。`loadCharacter` は色の文字列を検査しない)。
2. 顔の輪郭が自己交差しない。あご・頬が**頭の円の中**にある(頭の上部は髪が覆うので、円の外でよい)。
3. 毛束・髪の塊の外形が自己交差しない。
4. 目が顔の輪郭の中(その高さの顔の幅 − 4 以内)にあり、左右の目が中央で触れない。**まつげは外側(左目は左、右目は右)に付くものとして測る**(2 回目のレビューで、左目の内側に付けて誤判定していた)。
5. 眉の下端が目の上端より上(重ならない)。眉が頭の円の上に出ない。
6. 口が顔の中にあり、あごに届かない。口の `x` のアンカーが口の幅の中。目から離れている。
7. **すべて全表情(プリセット適用後)で検査する**。

**スロットの方式**:

| スロット | パラメータ | 方式 | 理由 |
|---|---|---|---|
| 顔の輪郭 | `cheek`、`chin`、`jaw`、`chinW` | **パラメトリック**(こめかみ → 頬骨 → あごの角 → あご先の 3 区間の 3 次ベジェ。数から出す) | 数が少なく、連続で変えられる。あごの角度と頬の張りが別。1 回目の「V の尖ったあご」を直す |
| 耳・首・胴 | 位置は輪郭から出る。服の色 `top` | パラメトリック(固定の形を数で置く) | 形の自由度が要らない |
| 目 | 基本の `w` / `h` / `tilt` / `iris` / `lashes`。種類 `open` / `arc`(`^^`)/ `arcDown` / `cross`(`><`)/ `dot` / `half`(半目)。**プリセットで**視線、まぶたの下がり(`lid`)、下まぶたの持ち上げ(`squint`)、左右の高さの差 | **パラメトリック**(上まぶたと下まぶたの曲線を数から出し、虹彩は clipPath で切る) | マンガ風の顔の印象の大半を決める。連続の調整が効く |
| 眉 | 基本の `thick` / `dy`。**プリセットで**角度(`angle`。内側が下がる=怒り。整数)、上げ、左右の上げ。**前髪の上に、インクで描く**(透け眉)。髪の暗い所(インクとの比 3:1 未満)に重なるので、紙のキーラインを敷く(D4) | パラメトリック(先の細い塗りつぶし) | 表情を決める眉の傾きが、前髪に隠れない(1 回目の根本原因) |
| 口 | 基本の幅。種類 `flat` / `smile` / `open` / `o` / `frown` / `wave` / `omega` / `grit` / `tri`。プリセットで幅の倍率、深さ、横のずれ | **形のライブラリ**(種類ごとに幅と深さから path を出す) | 種類で形が変わるので、連続の変形にはしない |
| 鼻 | `dot` / `line` / `none`(**インク**) | 小さな固定の形 | マンガ風では省くことが多い |
| 髪 | `template`(`short` / `bob`)、毛束の数 `strands`、分け目 `parting`、側面の房 `ahoge`、ハイライト | **テンプレート(固定の外形)+ パラメトリックな毛束**。外形(頭のてっぺん、側面、後ろ髪)は固定の path で、分け目の反対側に量を寄せる(左右対称にしない)。**前髪は毛束ごとの先の細い塗り**(インクの線で区切る)で、**毛束の幅・長さ・傾きを分け目からの距離から出す**(分け目から遠いほど幅が広く、長い。長さに決まった周期の揺れを足す。規則的なギザギザにしない) | 髪は「形そのものが絵」で、外形をパラメータで滑らかに作ると不自然。毛束だけ数で変える。ハイライトは冠に沿った折れ線(天使の輪) |
| 効果 | 頬の斜線(`blush`) | 顔の一部 | 表情のプリセットに属する |
| 汗・怒りマーク・落ち込みの線・涙 | — | **描かない。ADR 0076 D1 のマンプ(`marks`)に任せる** | 置き方(頭のアンカー、ぶつかりの検査)が 0076 にある |

固定の形が良い所は髪の外形・胴の肩の線・耳、パラメータが良い所は目・眉・口の幅・輪郭・毛束の数・色。判断の目安は「連続して動かして不自然にならないか」。

### D3. 表情はプリセット(人物の基本に対する差分)

**表情 = 目・眉・口・頬の斜線の差分の組**(`Preset`)。差分は、人物の基本の目・眉・口に**倍率と加算**でかぶせる(`h × 1.2`、`iris × 0.62`、`tilt + 3`、`dy + 4`。眉の `angle` は絶対値)。範囲に丸めてから不変条件を検査する(D2)。**人物ごとの目の形(`eyes.w` など)が、全表情で保たれる**(1 回目は絶対値で、全員が同じ目になった)。

| ADR 0074 の `ComicExpression` | プリセット(差分) | 舞台の大きさでの見え方 |
|---|---|---|
| `neutral` | 差分なし | 基準 |
| `smile` | 目を低く(×0.78)、上まぶたを下げ(`lid` 0.8)、**下まぶたを持ち上げる(`squint` 0.6)**、眉を上げる(−7°、−4)、口は広く深い笑い(幅 ×2.1、深さ ×2.8)、**頬の斜線** | neutral と別の群に出る |
| `laugh` | `^^` の目、眉を上げる、`open`(舌つき、幅 ×2.6)、頬の斜線 | はっきり |
| `surprise` | 目を大きく(×1.25)、虹彩を小さく(×0.62)、眉を大きく上げる(−16)、`o` の口 | はっきり |
| `worry` | 目を低く(×0.9)、まぶたを少し下げ(`lid` 0.85)、垂れ目(−6)、虹彩を小さく(×0.9)、視線を横へ、眉の内側を上げる(−28°、太く、−5)、`wave` の口(幅 ×2) | sad と別: **目は開いたまま、口は波** |
| `angry` | つり目(+9)、目を低く(×0.74)、眉の内側を下げる(20°、太く)、`grit` の口 | はっきり |
| `think` | **左右非対称**: 左目を低く(×0.55)、視線を横上へ、片眉を大きく上げる(26、太く)、口を片側へずらす(+7、幅 ×1.2) | 非対称が舞台でも読める |
| `sad` | **まぶたを下げる(`lid` 0.6)**、大きな虹彩、視線を下へ、眉を大きく下げる(−32°、太く)、`frown`(幅 ×1.4、深さ ×2.2) | worry と別: **目が伏せ、口が深い** |

1 回目の診断を直す: 実際に近かったのは **worry と sad、neutral と smile** で(surprise と think は近くなかった)、原因は眉が前髪の下に隠れていたこと。眉を前髪の上に出し、smile の下まぶたと頬の斜線、sad のまぶた、think の非対称で分けた。**表情の差を強めると別の組(smile–laugh、smile–worry)が下がる**ことを 2 回目で確かめた(D7 の分布)。涙・汗は**描かず**マンプ(0076)に任せる。

**追加の表情**(ADR 0074 にない。スパイクで動くのは `shy` 照れ、`smug` ドヤ、`deadpan` ジト目、`clench` 食いしばり(`><`)、`cry` 号泣、`blank` ぽかん):

| 名前 | 内容 | 差し替えてよい `ComicExpression` |
|---|---|---|
| `shy` 照れ | 視線を下げた目、困り眉、`omega` の口、頬の斜線 | `smile` |
| `smug` ドヤ | 半目、片眉を上げる、`omega` の口 | `smile` |
| `deadpan` ジト目 | 半目で虹彩を小さく、水平の眉、`flat` の口 | `think` |
| `clench` 食いしばり | `><` の目(左目が `>`、右目が `<`)、内側が下がる眉、`tri` の口 | `angry` |
| `cry` 号泣 | `arcDown` の目、困り眉、`open` の口(涙はマンプ) | `sad` |
| `blank` ぽかん | `dot` の目、水平の眉、`o` の口 | `surprise` |

**ADR 0074 を壊さずに出す**:

1. マニフェストの `expressions` のキーは、**今の 8 種だけ**(`loadCharacter` は 8 種以外のキーを拒む)。
2. 追加の表情は、人物ごとの `expressionMap`(8 種のキー → プリセット名)で出す。**同じ意味の変種だけ**(上の表の右の列)を許し、`think → cry` のように意味が変わるものは拒む(スパイクで確認)。割り当てはライブラリの入力で、**マニフェストには記録しない**(0074 の型を変えない)。0076 D5 の場面生成が頼んだ意味(`think`)と、描かれる意味が食い違わないため。v1 は、割り当て先のある追加の表情だけを出す。
3. 追加の表情を台本(`ComicStage.expression`)から直接名指しする拡張は、後続の ADR(Q8)。

### D4. スタイル — 線、影、ハイライト、パレット、キーライン

- **線の重みは 1 つの体系**(箱の単位。縮尺 0.36 で舞台の px にすると 0.36 倍。**開いた線は 2.8 単位(舞台で 1.0 px)以上**に決める。それより細くなる細部は、太くするか外す):
  - 輪郭(顔、髪の塊、胴、首): 4.6(約 1.7px)
  - 目鼻口と眉の細部、毛束の区切り: 3.0〜3.6(約 1.1〜1.3px)
  - 上まぶた: 7(成熟した方向は 5.5。約 2.0〜2.5px)。ここだけ太くして目を締める
- **線(ストローク)と塗り(ブラシ風)の使い分け**: 輪郭は**一定幅のストローク**。眉、まつげの跳ね、前髪の毛束は**先の細い塗りつぶしの形**。
- **色は基本の 3 つ(肌・髪・服)+ 虹彩。影・ハイライト・頬は、基本色の上の透明度つきの重ね**。肌の影は、薔薇色を 28% の不透明度で肌の上に。髪の影はインクを 28〜45%(ボブの後ろ髪は 25%)。ハイライトは白を 42〜50%。頬の斜線は 65%。`fill-opacity` / `stroke-opacity` は断片の許可リストにある(`lib/icon-store.ts`)。**マニフェストに出る色の文字列は、基本の 3 つ(と、インク・紙・白・口の色)だけ**。したがって **ADR 0076 の `recolor`(`{skin, hair, top}`、文字列の置き換え)がそのまま効き、キーを足す必要はない**。3 つの基本色が、ほかの色と**重複しない**ことを不変条件にする(重複したら 1 だけずらす。**`000000`〜`ffffff` の内側で**。`#ffffff` が `#1000000` になる不具合を直した)。虹彩の色は 0076 の `recolor` の対象外。
- **影は 1 色**(セル塗りの 1 段): 前髪の下の肌、首、毛束の先。グラデーションは使わない。
- **ハイライトの規則**: 目に 2 つ(大きな楕円と小さな円)。`surprise` と `angry` は 1 つ。髪は冠に沿った帯 1 本。
- **特徴の線はインク**(眉、鼻、口、下まぶた、`^^` `><` 点の目)。髪の色の影にしない。インクは**コマのインクと同じ**値(`#22201b`、`PALETTE.text`)、紙も同じ(`PALETTE.bg`)。
- **コントラストとキーライン(選んだ方針: キーラインを敷く。パレットは絞らない)**:
  - **基準は 3:1**。特徴の線は文字ではなくグラフィックなので、WCAG 1.4.11 の 3:1 を使う(1 回目は文字の 4.5:1 を使っていた)。肌とインクの比が 3:1 未満の肌(ADR 0076 の 6 種では **`dark` 2.0 だけ**。`brown` は 3.3 で付かない)では、特徴の線の下に**紙の線を敷く**(線より両側に 2 単位だけ太い。1 回目は 3 単位)。**目の種類(`open` 以外の `^^` `><` 点も)すべて**、口(閉じた形も)、鼻に付ける。**下まぶたの線は目の白に接するので付けない**。
  - **眉は、髪にも重なる**: 眉は前髪の上に描くので、**髪の色とインクの比が 3:1 未満**(black 1.0、navy 1.6、brown 1.4、chestnut 2.2。明るい髪 blond 7.2、gray 5.5 は付けない)のときも、眉に紙の線を敷く。0076 の 6 色のうち 4 色が対象。**黒い髪の眉は白い「ステッカー」に見える**ことは、見た目の弱点として残る(スパイクの評価)。
  - **全肌 × 髪の組で検査する**。検査は**ピクセル**で行う(D7): 恒真だった「`contrast ≥ 基準 || キーラインが必要`」は使わない。
  - **塗りどうし(髪と肌、服と肌)の比は保証しない**(0076 D4 と同じ。36 通り中 19 通りが 3:1 未満)。
- **境目のキーライン**: **髪と顔**(毛束と塊の縁の、顔の側)、**顔と首**(あごの線。**首の輪郭の中に切る**。1 回目は ±30 で、首より外の後ろ髪に白い弧が出た)に、紙の線を敷く。外側の輪郭(紙に接する縁)には付けない。**髪と肩のキーラインは付けない**(2 回目のレビューで、髪の先が肩に届かず、外しても 0 px しか変わらないと分かった。必要なら、ボブの髪の先を肩まで下げる U3 の仕事)。
- **ADR 0076 A2 との関係**: A2 は「2 つの塗りの境目すべてに、両側に紙のキーラインを付ける」で、内蔵の顔に適用する。manga-face の顔は、**髪の側(暗い塗り)には付けず**(毛束の間の区切りが白くなるため)、**顔の側だけに付ける**。0076 より狭いので、**A2 は内蔵の顔に、素材の顔(manga-face を含む)は 0079 D4 に従う**と、ここで決める(0076 の改訂は不要だが、U7 で 0076 の本文に 1 行の注を足す)。
- **ダークモードと紙の色**: 断片の色は `#rrggbb` で書き、`characterSvg` が `rgb()` に直す(ダークの再配色を受けない。ADR 0074 D6)。**0080 のバンドや人物の提供も、同じ変換を通すか、紙の色へ外す指定を使う**(D1)。白目は `#ffffff`。コマの背景が `bg.tint` で変わっても、顔は同じ。

### D5. 決定性と API

```ts
faceManifest(character: MangaCharacter, opts?: {expressions?: readonly ComicExpression[]; expressionMap?: Partial<Record<ComicExpression, string>>}): CharacterManifest
validate(character: MangaCharacter): string[]                 // D2 の不変条件の違反(空なら有効)
randomCharacter(seed: string | number, constraints?: Constraints): MangaCharacter
type Constraints = {template?: 'short' | 'bob'; skin?: readonly SkinKey[]; hair?: readonly HairKey[]; ahoge?: boolean; style?: 'young' | 'mature'}
presets: Record<string, Preset>
```

- **同じパラメータからバイト単位で同じ SVG**(Node と Chromium で確認済み)。出す座標は**0.1 に丸める**(ADR 0076 の座標を丸める方針に合わせる)。**`Math.cos` / `sin` / `pow`(`**`)/ `hypot` を使わない**: 整数の角度 −45〜45° の `[cos, sin]` と、sRGB → 線形の 256 個の値を、ソースに**定数の表**として書く(起動時に計算しない)。距離は `Math.sqrt`(IEEE で正しく丸められる)。**出力を分ける判定(キーラインの有無、検査の合否)が、エンジンの最後の桁の違いで変わらない**ようにするため(2 回目のレビュー)。テストは、Node の版(CI の matrix)に加え、**Chromium・Firefox・WebKit(playwright)でも同じバイト列か**を見る(生成がブラウザでも動くため)。
- **乱数の人物**(`randomCharacter`): `xmur3` のハッシュと `mulberry32`(外部に依存しない小さな実装)。**項目ごとに別の流れ**(`xmur3(世代 : シード : 項目名)`)を使い、テンプレートや項目を足しても、ほかの項目の値が変わらない。
  - **作りで有効にする**: 値は範囲の中の、**依存する制約(D2)も満たす範囲**から選ぶ(`normalize` が適用する)。目標は**最初の抽選の有効率 99% 以上**(スパイク: 1000 / 1000)。
  - **落ちたら、落ちた群だけ直す**: `validate` が報告した群(目、眉、口、頭、髪)だけを、`項目#k` の別の流れで引き直す(k = 1〜4)。それでも落ちる群は、若い方向の既定値に置き換える。**ほかの群の値は変えない。全部を引き直さない。常に有効な人物を返す**(例外を投げない)。
  - **世代番号 `GENERATOR`(いま 2)は、範囲・依存する制約・乱数の作り・`validate`・プリセットのどれかを変えたら上げる**。**シードが安定なのは同じ世代の中だけ**。固定のシードの組(0〜2 など)のスナップショットを、テストに置く(世代を上げ忘れると、スナップショットが落ちる)。
  - 制約(`Constraints`)で髪のテンプレート、肌・髪の候補、あほ毛の有無、方向を絞れる。
- **鏡像(`mirror`)**: 正面の顔は左右対称なので、**鏡像が意味を持つのは、左右非対称の部品(分け目、あほ毛の房、片方だけの要素)か、3/4 の顔が入ってから**。いまは `parting` と視線の符号を反転するのと変わらない。ライブラリには `mirror` を残すが、**v1 の約束には入れない**(口のアンカーは正面では `x = cx` で、アンカーの反転の試験は空になる)。`cast` は 1 つの素材に対応するので、向きを**コマごとに**変えるには別の `cast` id(同じ人物の `mirror` 版)が要る。**向きは `stage.at` に合わせて `comic()` が決めるのが筋**(`facing` の項目。3/4 の顔と一緒に決める)。
- **アンカー(パラメータから計算する)**:
  - `head`: 頭の円 `{cx: 150, cy: 140, r: 100}`(箱の規約)。顎・頬は円の中(D2)
  - `mouth`: `[150, 口の高さ + 6]`(表情で口の中心は動いても、マニフェストには 1 つ)
  - `top`(**y 座標**。`[箱の y, cy − r]` の範囲): 髪の外形の上端と房の上端から、**線の太さの半分と 0.5 の余裕を引いた値**を式で出す。ラスタ(8 表情を 4 倍で描く)で、最初に色の付く行より**上**であることを許容なしで検査する(スパイク: 宣言 23.2、ラスタ 23.5)。**`top ≥ cy − r − 17 = 23`**(内蔵の顔との差し替えで、ふきだしの帯の余裕を 17px 以上減らさない。D7 の差し替えの互換)。
  - `hand`: v1 は出さない
  - `bubbleSides`: `['top-left', 'top', 'top-right']`
- **あほ毛**: 既定でなし(`none`)。あるときは**側面**の小さな房(中央から外れる)で、`top` が上の限界を超えない。1 回目の中央の長いあほ毛は、`top` を −24 にして 1×2 の 2 つ積みのふきだしの検査(`comic-bubble-zone`)を落とし、ふきだしのしっぽが先に当たった。
- マニフェストの `license` は `CC0-1.0`、`author` は `manga-face contributors`、`url` は manga-face のリポジトリ(D6)。

### D6. 権利

1. **絵はすべて独自**。特定の作品、作家、キャラクターに似せない(「○○風」の指示を作らない、参考画像を写さない)。Open Peeps と DiceBear は**構造(スロットと色のスロット)の参考**にとどめ、パーツの形(path)は使わない。DiceBear の Adventurer(CC BY 4.0)の絵は写さない。Lorelei(CC0)も形は写さない。**「似ていないか」の確認は、道具によらず全パーツに、決める人の確認点で行う。**
2. **AI の扱いは「道具」でなく「方法」で線を引く**(1 回目のレビュー M7。このスパイク自体が、コード生成の AI(コーディングアシスタント)で書かれている):
   - **許す**: 幾何を**コードとして**、**幾何の説明から**、**参考画像なしで**書くこと。人が書いても、コーディングアシスタントが書いてもよい。どちらかを `PROVENANCE.md` に記録する。
   - **v1 では許さない**: 画像・SVG の**生成モデルの出力**(OmniSVG 系を含む)を絵として入れること。**トレース**(既存の絵をなぞる)。**参考画像に合わせる**調整。
   - 将来、生成モデルの出力を許す場合は、別の ADR で条件(学習データと生成物の権利、モデルの利用条件、似た作品の検査)を決める。
3. **`PROVENANCE.md` は U1 から始める**。部品(顔の輪郭、目、眉、口、髪のテンプレート)ごとに、書いた人、日付、方法(人 / コーディングアシスタント)、参照したもの(なし、または幾何の説明)、似た作品が無いかの確認を 1 行で残す。**部品を足す PR は、行が無いと通さない**(U1 のテスト)。
4. **ライセンス**: 生成物(マニフェスト、SVG)は **CC0-1.0**。ソースコードは **MIT**(絵の形がコードの中にあるので、2 つを分けて書き、互換にする。MIT-0 にしてもよい。Q6)。マニフェストの `license` は `{spdx: 'CC0-1.0', author: 'manga-face contributors', url: <リポジトリ>}`。`loadCharacter` が空の `license` を拒むので、ライセンスは必ず書く。

### D7. 品質のリスクと見直しの往復

手続きで魅力のある顔を作るのは難しい。**検査できることと、好みで決まることを分ける**。好みは決める人の判断で、ライブラリは「受け入れの目安」を機械で検査し、見た目は人が見る。

**見直しの往復**:

1. **ギャラリー**: `gallery.svg`(表情 × 髪 × 肌)、`random.svg`(シード 64 人)、**`stage.svg`(舞台の大きさ(頭の半径 36px、DPR 1)で表情 8 種を並べた行。これを各確認点の主な見方にする)**、4 コマのサンプル。PNG にして見る。原寸のギャラリーだけでは、舞台で消える細部を見落とす(`comic()` は舞台の大きさしか使わない。0076 Q7)。
2. **決める人の確認点**: U0.5(見た目の方向)、U2(顔・目・眉・口)の後、U3(髪)の後、U4(追加の表情)の後。各回は「OK / 直す点の一覧(セルの位置で指す)」。**各回で、舞台の大きさの `stage.svg` も見る。** 表情の**ブラインドの確認**(下)を毎回行う。**U2 で OK が出るまで U3 へ進まない**。
3. **golden の SVG**: ギャラリーの代表 6 セル(表情 3 × 髪 2)を golden にし、**意図した見た目の変更**のときだけ更新する(PR の説明に前後の画像)。

**受け入れの基準(検査できるもの。好みは含まない)**:

| 基準 | 内容 | 目安 |
|---|---|---|
| 読み込み | 乱数のシード 1000 件 × 全表情で `validate` が空で、`loadCharacter` が受ける。**最初の抽選の有効率(修復なし)と修復の割合を別々に報告する** | 全部通る。**最初の抽選の有効率 ≥ 99%**(スパイク: 100%、修復 0 件) |
| 不変条件 | D2 の不変条件(輪郭・毛束の自己交差、顔の中の目・口、眉と目の間、頭の円)を全表情で検査 | 違反 0 |
| アンカー | `top` が 8 表情のラスタの上端以上に上(許容なし)、`top ≥ 23`、頭の円が箱に収まる。ミラー版も | 全部通る |
| 差し替えの互換 | **内蔵の顔を、マンガの顔に替えても、通っていた `comic()` の例が落ちない**。`examples/comic-*.ts` と、台詞の長さ 8〜66 字の 1×2(ふきだし 2 個を積む)など | 内蔵で通るもの = マンガで通る(スパイク: 27 / 30 で同じ、退行 0)。**内蔵の顔を置き換える決定(Q5)の条件** |
| 大きさ | 断片 1 つ、マニフェスト 1 人分、gzip 後 | 断片 ≤ 10 KB、1 人分 ≤ 96 KB、gzip ≤ 6 KB、path ≤ 70(スパイク: 8.5 KB、79 KB、4.2 KB、57) |
| コントラスト(ピクセル) | 舞台の 3 倍で描き、**特徴の線(眉・鼻・口・`^^` `><` 点の目)のインクの縁**のうち、周囲 2〜4 px に紙か、インクと 3:1 以上の塗りが見える割合を、肌 6 × 髪 3 × 全表情で測る。キーラインを外した**負の対照**で、検査が落ちることも確かめる | 1 件ごとに 95% 以上(スパイク: 252 件中 235 件。最悪 89.6%、`brown` の肌。負の対照は最悪 3.4%)。髪と肌・服と肌の塗りどうしは保証しない |
| キーラインの効き | 境目のキーライン(髪と顔、顔と首)を外すと、絵が 100 px 以上変わる(**効かないキーラインを残さない**) | 髪と顔 971〜1196 px、顔と首 152〜159 px |
| 最小の線幅 | 開いた線のすべてが、舞台の縮尺で 1.0 px 以上(2.8 単位) | 最小 2.8 単位 |
| 決定性 | 同じパラメータで 2 回、別の Node の版、Chromium・Firefox・WebKit で、同じバイト列 | 一致(Node と Chromium は確認済み) |
| 見分けやすさ(機械) | 舞台の大きさ(頭の半径 36px、94×124 px、DPR 1)で描いた表情 8 種の、**頭の円の外接する正方形(箱の座標で x ∈ [cx−r, cx+r]、y ∈ [cy−r, cy+r])**の平均の差(灰色)の、28 組の最小。**手で決めた人物だけでなく、乱数 64 件と、パレットの両端(肌 6 × 髪 black / blond × 方向 2)でも測り、分布を報告する** | **手で決めた人物: すべて ≥ 6**(スパイク: 10.1 / 8.8 / 6.3)。**乱数とパレットの両端: 最小が 3.5 以上(退行の防止)で、分布を報告する**(スパイク: 乱数の最小 4.2、中央値 6.3、6 未満 24 / 64。両端の最小 3.7、中央値 6.7、6 未満 9 / 24)。**閾値 6 を全部で満たすことは、表情の差を強めても達成できなかった**(別の組が下がる。明るい髪 × 濃い肌の輝度の差が小さい)ため、**要望の「全部 ≥ 6」の代わりに、手で決めた人物の ≥ 6 と、乱数・両端の最小 ≥ 3.5 と、人のブラインド確認を門にする**。決める人が閾値を決め直してよい(Q10) |
| 見分けやすさ(人) | **ブラインドの確認**: 舞台の大きさの 8 表情をシャッフルして並べ、決める人が名前を当てる | **8 つ中 7 つ以上**。各確認点で行う |
| 禁止要素 | `<text>` / `<use>` / filter / 名前つきの色を含まない(`loadCharacter` が検査) | 0 |

**好み(決める人が決める)**: 全体の印象、年齢の見え方、髪の形、目の大きさ、線の太さ、キーラインの目立ち方。機械の検査は「壊れていない」までで、「魅力がある」は保証しない。

### D8. 将来(この ADR の範囲外。メモ)

- 表情の補間: プリセットが差分の数の組なので、2 つの間を補間できる。VectorTalker の口パクにも使える。
- 顔の共通部分の共有: マニフェストは表情ごとに胴と髪も持つので、重複が大きい(gzip で約 17 倍に縮む)。共通の層と表情の層を分ける形は、ADR 0074 の変更(Q7)。
- 3/4 の顔、全身。向き(`facing`)を `comic()` に足す。

## 代替案

| 案 | 採らない理由 |
|---|---|
| Open Peeps を同梱して使う | 構造は良いが、日本のマンガ風ではなく、手描きの固定の絵で、パラメータで動かせない。PR #444 で変換は可能と確認済みなので、**並べて使う**(排他ではない) |
| 固定の手描きのパーツを大量に作って組み合わせる(Mii 風・Picrew 風) | 絵の手間が大きく、探しにくい(芸術科学会論文の指摘) |
| 全部パラメトリック(髪も) | 髪の外形が不自然になる(D2)。外形は固定、毛束だけパラメータ |
| 生成モデルで部品を作る(OmniSVG など) | 権利が不明確で、似た作品の検査ができない。v1 は入れない(D6) |
| `lib/manga-face/` に入れる、または、この repo の workspace にする | 決める人の方針で、別リポジトリ(D1)。出す周期と、見た目の確認の往復を core の PR から分けるため |
| 顔の `mirror` を `comic()` のオプションにする | 正面の顔では効果が無い。3/4 と一緒に、`stage` の向きとして決める(D5) |
| 肌のパレットを絞って、全部の肌で 3:1 にする | 肌の表現の幅が狭まる。キーラインで全部通せる(D4) |

## 影響

- svg-diagram 本体の `lib/` は、この ADR では変えない。ADR 0080 のプラグインの仕組みが入れば、manga-face がそれにつながる。U7 は例とドキュメントとテストの fixture。
- 別リポジトリ `cuzic/manga-face` の用意(CI、リリース、ライセンス、`PROVENANCE.md`)が要る(U1)。
- 顔の生成はブラウザでも動かせる(純粋)。Artifact は、生成済みの JSON を貼るか、ESM を読み込む。

| U7 | svg-diagram との接続(**ADR 0080 の確定後**): バンドと人物の提供元の実装、例(`examples/comic-manga-face.ts`)、ドキュメント、fixture のテスト(manga-face の出力を `loadCharacter` に通す。最新と下限の 2 版)、内蔵の顔を置き換えるか(Q5)。**ADR 0076 U4(`recolor` と `avatars`)と、ADR 0080(PR #455)の確定に依存**(まだ `lib/` に無い)。0076 の本文に、A2 は内蔵の顔向け、素材の顔は 0079 D4 に従う、の 1 行の注を足す | 例が描ける。`recolor` を宣言した人物に `avatars` が効く(基本の 3 色だけで足りる)。**core の golden は変わらない**(内蔵の顔を置き換えない場合) | 例のビルド。fixture のテスト。golden が動かない |

## テスト方針

- 純粋(`fs` / `child_process` なし)。ブラウザを使う検査(アンカーのラスタ、見分けやすさ、決定性)は、別の実行で分ける(playwright は optional)。
- 決定性は、2 回の実行とパラメータの深いコピーと、Node の版と、Chromium・Firefox・WebKit。
- golden は、ギャラリーの代表の SVG。更新は意図した見た目の変更のときだけで、人が見て受け入れる。

## 決める人への質問

| # | 質問 | 推奨 | 理由 |
|---|---|---|---|
| Q1 | (決定済み)別リポジトリ `cuzic/manga-face`。svg-diagram とは ADR 0080 のプラグインでつなぐ | 決める人の方針どおり。接続の形は 0080 の確定後に決め直す | D1。型のずれは `import type` と、公開済みの `loadCharacter` に通す CI で防ぐ |
| Q2 | **見た目の方向を選ぶ**: `out/directions.png` の最初の段(舞台の大きさ。実寸と 2 倍)の「若い」(丸い目・広い頬)と「成熟した」(縦に長い顔・小さな目と虹彩・細い上まぶた・まつげなし・平らなあご先)。正面、バストアップ、一定幅のインク輪郭 + 先の細い塗りの眉・毛束、セル塗りの影 1 段、スクリーントーンなし。3/4 は第 2 版 | **「成熟した」を既定の方向にして、若い方向を `style: 'young'` で選べるようにする**(U0.5)。ただし**いまのスパイクでは、舞台の大きさでの差は小さい**。年齢感は髪が決めるので、成熟した方向には専用の髪のテンプレート(U3)が要る。短い髪の「おかっぱ」感と、黒い髪の眉のキーラインの「ステッカー」感は残る。方向が決まらなければ、動かす項目(目の大きさ、顔の長さ、髪の流れ)を指示してほしい | 若い方向は子どもっぽく、業務のコマには落ち着いた方が合うと考える。ただし**好みの判断**なので、舞台の大きさの見え方で決めてほしい |
| Q3 | v1 の髪のテンプレートの数 | **4 種**(短い、ボブ、長い、くせ毛の短い)。ただし、**2 種を良くしてから**増やす(おかっぱの塊を直すのが先。U3) | 部品を増やすと探しにくい(先行研究)。スパイクは 2 種 |
| Q4 | AI を使った部品を許すか | **コードとして、参考画像なしで書くこと(人またはコーディングアシスタント)は許し、`PROVENANCE.md` に記録する。生成モデルの出力、トレース、参考画像に合わせる調整は v1 では許さない**(D6) | 方法で線を引く。このスパイク自体がコーディングアシスタントで書かれている |
| Q5 | `comic()` の内蔵の顔の既定を置き換えるか | **v1 では置き換えない**。置き換えるのは、(1) 見た目を決める人が認め、(2) **差し替えの互換の試験**(内蔵で通る `comic()` の例が落ちない)を満たしたとき | 置き換えると core の golden が全部動く。先に別リポジトリの出来を確かめる |
| Q6 | 絵とコードのライセンス | 生成物は CC0-1.0、ソースは MIT(または MIT-0) | 素材の再配布に支障がなく、2 つが互換(D6) |
| Q7 | マニフェストの表情間の重複(胴と髪が表情ごとに入る。いま 71〜79 KB、gzip で 4.2 KB)を、共通の層に分けるか | 後で(U8 の別 ADR)。いまは gzip で約 17 倍に縮むので許す | `CharacterManifest` の形の変更になり、ADR 0074 に触る |
| Q8 | `ComicExpression` に追加の表情(照れ、ドヤ、ジト目など)を足すか | 後で(U8)。v1 は `expressionMap` で、**同じ意味の変種だけ**を 8 種のキーに割り当てる | 0074 を壊さない。意味が変わる割り当ては拒む |
| Q9 | 舞台の頭が小さい(半径 36px で、細部が消える)ことをどう扱うか | 受け入れる。**設計を舞台の大きさで先に行い**(最小の線幅 1.0 px、表情は眉・口・目の形で決める)、大きく描いたときだけ効く細部は装飾と考える。コマの頭を大きくする案は `comic()` の別の ADR | 舞台の寸法を変えると 0074 の全部の配置に影響する |
