# ADR 0035: 因果ツリーの交差の見せ方と折れの削減(`hop: 'all'`、並びの探索の拡張、長い矢印の経路探索、箱の辺に 1 本だけの矢印の直線化)

- 状態: 実装済み(PR #293)。Opus の読み取りレビュー 1 巡目(高 2・中 7・低 5)を反映した版。再確認待ち
- 日付: 2026-10-17
- 基点: `main`(a236a8c、PR #291 まで)
- 関連: ADR 0016(経路 `layered-route.ts`、点数 (交差, 折れ)、D3 の直線化)、ADR 0019(D4 交差の再探索)、ADR 0028(`hop: true` の飛び越し弧)、ADR 0015(`cause-crossing` / `cause-parallel`)
- 範囲外: `states` / `classes` / `bpmn` / `semnet`(同じ `routeLayered` を使うが既定のまま)、`pdpc` の外周レーンの選び方、AND の弧、PPTX のネイティブ変換(ADR 0027)

## 背景

利用者から、因果ツリー(未来現実ツリー・現状ツリー)が読みにくいという 2 つの指摘があった。

1. **交差が多く、交差と合流の区別が付かない**(14 節の FRT)。線は箱の上下から出て、ゴールの手前で数 px 間隔の縦線が束になる。直交する交差でも、弧や矢じりが無いので「すれ違い」か「合流」か分からない。
2. **折れが多く、ムダにカクカクする**(15 節の CRT)。実測:
   - 層を 2 つ以上またぐ矢印が、各層の隙間の中点を通る折れ線になり、図の端まで出て戻る(`a3 → u2` は折れが 4 つ)。原因は `elbows`(`layered-route.ts`)が、層ごとの中継点の間を「中点で折れる H-V-H」でつなぐこと。
   - 隣り合う層の箱が少しずれているだけで、小さなジョグが出る(`a4 → u3`)。原因は、直線化(ADR 0016 D3)の候補が「箱の辺に矢印が 2 本以上ある場合」(`slotOf` の `list.length > 1`)に限られること。1 本だけのポートは中央に固定され、箱の中心がずれていれば直線にならない。
   - 並びの探索(ADR 0019 D4)が、固定の 7 通り(書いた順の逆、1〜6 個の巡回)しか試さず、避けられる交差が残る。FRT で、AND の弧の間に別の節が挟まれていた(`cause-crossing`)。

## 決定

### D1: `hop: 'all'`(`CauseOpts.hop?: boolean | 'all'`)
`hop: true`(ADR 0028)は、戻りの矢印の「層を横切る区間」だけが他の線を飛び越す。`'all'` は、**どの矢印でも**層を横切る区間(レイアウトの軸に直交する区間)が、他の線を飛び越す。
- 規則は ADR 0028 のまま(層の流れに逆らう側へ膨らむ、D3 の「付けない箇所」の表も共通)。変わるのは対象の絞りだけ。`causeCrossings` に引数 `everyRun`(既定 false)を足し、`over.reversed` の条件を外す。`reversed` の意味は変えない(`'all'` でも本当に反転した辺だけが `reversed`)。
- 層を横切る区間どうしは平行なので交わらない。交差は「層を横切る区間 × 流れに沿う区間」になり、**前者が飛び越す**。2 重の弧にはならない。
- **全部の交差に弧が付くわけではない**。折れ(`corner`)・矢じりの根元(`arrowhead`)・AND の弧(`and-arc`)・別の交点(`neighbour`)・平行な線(`parallel`)が近い交差は、ADR 0028 D3 の表どおり弧を付けない。実測(Opus レビュー): 実フォントの `toc-hop-all` では交差 7 か所のうち 3 か所に付き、`corner` 2・`neighbour` 2 が残る(`neighbour` は近い 2 か所の**両方**を飛ばす)。「ゴールの手前で縦線が束になる」場面ほど弧が付かない。固定幅の計測では 6 か所すべてに付く。
- 既定は off(書かない図は変わらない)。`tree` の既定にはしない(既存の図が全部変わる。未解決)。
- 検査は変えない(ADR 0028 D5 と同じ)。

### D2: 並びの探索の拡張(ADR 0019 D4)
固定の 7 通りに加え、**固定のシードの擬似乱数による並び**(最大 `min(24, 3n)` 通り)と、**最良の並びの隣の入れ替え**を試す。重複は除く。上限は `MAX_ORDERS = 60`、打ち切りは「最後の改善から `PATIENCE = 30` 通り(AND の交差が 0 になったら `PATIENCE_QUIET = 14` 通り)改善が無い」(捨てた案も数える。1 通りが 1 回のレイアウト)。シードは節の数だけで決まる(LCG): 同じ図は同じ結果。
- **探索は経路探索(D3)を切った図で採点する**(経路探索は 1 回が重く、探索は最大 60 回のレイアウトを作る)。探索の枠(層・高さ・`loose`・`fitApplied`)も、経路探索なしの最初の図(`base`)と比べる。経路探索ありの図は枠が低いことがあり、それと比べると、交差の少ない並びを高さで捨てる(Opus レビュー M3)。
- **最後に**、最良の並びを経路探索ありで 1 回作り直し、「最初の図(`first`)」「その作り直し」「経路探索なしの最良」のうち、点数 (AND の交差, AND の並走, 交差, 折れ) が**最も厳密に良い**ものを採る(同点は先のもの)。枠は上の `base` と同じ。
- **`straighten: false` は従来の 7 通りだけ**(乱択・入れ替えをしない)。実測(40 図): main と同一。
- 採る条件・探索に入る条件は ADR 0019 D4 のまま。点数の最優先は AND の交差なので、AND の交差を 0 にするために全体の交差が増える図がある(実測 58 図のうち 3 図が main より交差が多い。AND の交差は 0 になっている)。
- 入れ替えの段階(隣の入れ替え)は、AND の交差が 0 の図では「全体の交差も 0」のときにだけ省く(それ以外は走る)。実測では、入れ替えの段階まで進む図は少ない(Opus レビュー M5: 40 図中 2 図)。**書いてあるほど効いてはいない**。

### D3: 長い矢印の経路探索(`lib/route-search.ts`、`routeLayered` の `detour`)
層を 2 つ以上またぐ矢印(`e.points.length > 2`)のうち、**折れが 3 つ以上のもの**について、**箱に `margin = 8` 以上離れ、帯の中に収まり、長さ・折れ・交差・他の矢印の線に沿う区間の重み付き和が最小の道**を、格子上の A* で探す。
- 格子の線: すべての箱の ±margin、始点の STUB 先、終点の手前 26px(矢じりと AND の弧の余地)、帯の縁から margin(1/64 px に丸める)。状態は (列, 行, 向き)。向きの切り替えに `BEND = 30`、他の矢印の直交する線との交差に `CROSS = 25`、他の矢印の線に 4px 以内で沿う区間に `ALONG = 200`、**他の矢印の先端から `HEAD_REACH = 22` 以内の縦の線に `HEAD = 300`**(矢じりの中を横切ると、合流に見える。`hop` もそこは飛ばす)。箱との衝突は、箱 ±margin の辺が格子の線であることから、点と歩の中点の判定を**前計算**する。
- **終了条件**: 終点の格子点に着いた状態を取り出しても打ち切らない。最後の曲がり(縦で着いたとき)と最後の区間 `g → end` の費用を足した合計で最小を選び、見積り(残りの長さ)がその合計以上になったら止める(Opus レビュー M1)。交差が格子の線の上に来るとき(箱の辺と他の矢印の縦の線が同じ x)も、歩の**終わり側**で数える(M2)。
- **採る条件**: その矢印だけが変わるので、その矢印の交差・折れの前後の差で全体の (交差, 折れ) を更新し、**厳密に良く、かつ「他の矢印の先端の近くの交差」(`headCrossings`)が増えない**ときだけ。入れる順は辺の順で、先に決めた経路は後の探索の「他の矢印」になる。
- **打ち切り**: 1 回の探索に歩数の上限 `budget = 60000` を置く(超えたら迂回しない)。
- **対象外**: AND に入る矢印(`groupOf` が定義されている。弧の位置が経路の終端から決まるため)、外周のレーンの戻り(`outer`)、後ろ向き(終点の x ≤ 始点の x)の矢印、self ループ、折れが 2 つ以下の矢印。
- **対象の候補**: BK 座標の候補(`coord: 'bk'`)だけ。素の候補は従来のまま。BK の候補は、素の候補と折れで競る側なので、迂回の効果はそこで比べられる。
- **`build()` との関係**: 経路は `detours` に保持し、`aside` の再構築でも消えない。始点・終点は `build()` の最新の値で差し替える(配列は新しく作る。保持した経路を書き換えない: Opus レビュー L1)。
- 呼び出しは `layoutCauseBandOnce`(`causeTree` / `relationDiagram` / `pdpc`。いずれも `cause` の帯)。`straighten: false` のときは使わない。

### D4: 箱の辺に 1 本だけの矢印の直線化(`detour` と一緒に)
ADR 0016 D3 の `direct` の候補に、`slotOf` の `list.length > 1` の条件を外した矢印を加える(`detour` のとき)。ポートを両端の箱が重なる高さへ動かす手順(`align`)と、「厳密に良いときだけ採る」条件は同じ。
- 影響: 既存の図で直線化される矢印が増え、箱の位置(BK の座標)が変わる図がある(`why-why` の x が 4px ほど動いた)。

### D5: 速度のための変更(`crossingsOf` の書き直し)
`crossingsOf`(`polyline-metrics.ts`)は、折れ線ごとの水平・垂直の区間を 1 度だけ作ってから、組ごとに数える形に書き直した。**数は変えない**(`polyline-metrics.test.ts` が通る)。`crossingsWith`(1 本と残りとの交差)を足し、経路探索の採否を「その矢印だけの差」で数える。

### D6: 既定は変えない。出力が変わる範囲
- `hop` は off が既定のまま。D2〜D4 は `causeTree` / `relationDiagram` / `pdpc` で既定 on(`straighten !== false`)。**出力が変わる既存の例は 6 つ**(`qc-relation` / `toc-blocks` / `toc-hop` / `toc-prt` / `why-why` と新しい `toc-hop-all`)で、前後を並べて目視した。どれも折れが減る方向で、悪化は無かった。
- 外部の図は、再生成で線の形が変わる(SVG のバイトは変わる)。`straighten: false` で戻せる(D2 も戻る)。

## 検証(実装 PR での実測)
- 型検査、全体テスト(既知のフォント差 2 件を除いて通る)、全例の `golden`(差分ゼロ。上の 6 つを作り直した後)。
- 14 節の FRT: `cause-crossing` の警告が消える。15 節の CRT: 最大の折れ 4 → 2、合計 26 → 16(固定幅の計測)。
- **ランダムな因果ツリー 58 図(固定幅、8〜19 節、AND 0〜2 個、`dir` 4 方向)**を main と比べた(Opus の再現スクリプト):

| | main | 本 PR |
|---|---|---|
| 交差の合計 | 331 | 309 |
| 折れの合計 | 2256 | 2000 |
| 箱の貫通 | 0 | 0 |
| 他の矢印の先端 16px 以内の交差 | 1 図 | 0 図 |
| 時間の合計 | 5〜8 秒 | 10〜21 秒(計測のたびに揺れる。約 2〜2.5 倍) |

  交差が main より多い図が 3 図ある(AND の交差を優先した結果。D2)。
- **最悪時間**(28 節・`dir: 'right'`・`maxNodeW: 'auto'`): Opus の 1 回目の計測は 334 秒だった。経路探索を探索の中で走らせないこと(D2)、A* と前計算(D3)、折れ 3 つ以上の矢印だけ(D3)、BK の候補だけ(D3)、`crossingsOf` の書き直し(D5)で、**4.6〜11 秒(main は約 5 秒。他のエージェントの負荷で揺れる)**になった。実フォントの 17 節の図(`maxNodeW: 'auto'`)は未再計測。

## 未解決の項目
- **時間は main の約 2〜2.5 倍**(小さな図は同じ程度)。`maxNodeW: 'auto'` や `fold` と組む大きな図では、探索が格子の案ごとに走る。実在の因果ツリー 33 本(`medius-research`)での計測は未了。
- **`hop: 'all'` の既定化**: `tree` を書いた図に既定で付けるか。既存の図が全部変わるので、別の決定にする。弧の付かない交差(D1)を `check` の情報で知らせるかも未決。
- **`neighbour` の規則**: 近い 2 か所の交差の両方に弧が付かない(束ねた線の手前で弧が消える)。片方だけでも付ける規則にするかは、図で確かめてから。
- **`qc-relation` の並走**: 長い矢印 2 本が 12px で並んで走る(変更前も同じ)。`ALONG` の閾値(4px)を超える間隔なので、探索は避けない。
- **AND に入る長い矢印・外周レーンの戻り**は、経路探索の対象外のまま。他の矢印の出だし(始点の STUB の手前)を迂回路が横切る可能性は、枝分かれに見える推測のまま(実測していない)。
- **探索の格子の粗さ**: 線は箱の辺からだけ取る。レーンの空き(`LANE = 14`)を使った探索はしない。
- **PPTX**: 因果ツリーは今も画像として入る(ADR 0027)。ネイティブにするとき、弧と経路探索の結果をどう渡すかは別。
