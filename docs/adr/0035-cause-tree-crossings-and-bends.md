# ADR 0035: 因果ツリーの交差の見せ方と折れの削減(`hop: 'all'`、並びの探索の拡張、長い矢印の経路探索、箱の辺に 1 本だけの矢印の直線化)

- 状態: 実装済み(PR 本文を参照)。Opus の読み取りレビューを受ける
- 日付: 2026-10-17
- 基点: `main`(a236a8c、PR #291 まで)
- 関連: ADR 0016(経路 `layered-route.ts`、点数 (交差, 折れ)、D3 の直線化)、ADR 0019(D4 交差の再探索)、ADR 0028(`hop: true` の飛び越し弧)、ADR 0015(`cause-crossing` / `cause-parallel`)
- 範囲外: `states` / `classes` / `bpmn` / `semnet`(同じ `routeLayered` を使うが既定のまま)、`pdpc` の外周レーンの選び方、AND の弧、PPTX のネイティブ変換(ADR 0027)

## 背景

利用者から、因果ツリー(未来現実ツリー・現状ツリー)が読みにくいという 2 つの指摘があった。

1. **交差が多く、交差と合流の区別が付かない**(14 節の FRT)。線は箱の上下から出て、ゴールの手前で数 px 間隔の縦線が束になる。直交する交差でも、弧や矢じりが無いので「すれ違い」か「合流」か分からない。
2. **折れが多く、ムダにカクカクする**(15 節の CRT)。実測:
   - 層を 2 つ以上またぐ矢印が、各層の隙間の中点を通る折れ線になり、図の端まで出て戻る(`a3 → u2` は折れが 4 つ)。原因は `elbows`(`layered-route.ts`)が、層ごとの中継点の間を「中点で折れる H-V-H」でつなぐこと。
   - 隣り合う層の箱が少しずれているだけで、小さなジョグが出る(`a4 → u3`)。原因は、直線化(ADR 0016 D3)の候補が「箱の辺に矢印が 2 本以上ある場合」(`slotOf` の `list.length > 1`)に限られること。1 本だけのポートは中央に固定され、箱の中心がずれていれば直線にならない。
   - 並びの探索(ADR 0019 D4)が、固定の 7 通り(書いた順の逆、1〜6 個の巡回)しか試さず、避けられる交差が残る。FRT で、AND の弧の間に別の節が挟まれていた(`cause-crossing`)。

## 決定

### D1: `hop: 'all'`(`CauseOpts.hop?: boolean | 'all'`)
`hop: true`(ADR 0028)は、戻りの矢印の「層を横切る区間」だけが他の線を飛び越す。`'all'` は、**どの矢印でも**層を横切る区間(レイアウトの軸に直交する区間)が、他の線を飛び越す。
- 規則は ADR 0028 のまま(層の流れに逆らう側へ膨らむ、D3 の「付けない箇所」の表も共通)。変わるのは対象の絞りだけ。`causeCrossings` に引数 `everyRun`(既定 false)を足し、`over.reversed` の条件を外す。`reversed` の意味は変えない(`'all'` でも本当に反転した辺だけが `reversed`)。
- 層を横切る区間どうしは平行なので交わらない。交差は「層を横切る区間 × 流れに沿う区間」になり、**前者が飛び越す**。2 重の弧(両方が飛ぶ)にはならない。
- 既定は off(書かない図は変わらない)。`'all'` を `tree` の既定にはしない(既存の図が全部変わる。D5 の未解決)。
- 検査は変えない(ADR 0028 D5 と同じ)。

### D2: 並びの探索の拡張(ADR 0019 D4)
固定の 7 通りに加え、**固定のシードの擬似乱数による並び**(最大 `min(24, 3n)` 通り)と、**最良の並びの隣の入れ替え**を試す。上限は `MAX_ORDERS = 80`。
- **決定性**: シードは節の数だけで決まる(LCG)。同じ図は同じ結果。
- **打ち切り**: 最後の改善から `PATIENCE = 30` 通り(AND の交差が 0 になったら `PATIENCE_QUIET = 10`)改善が無ければ止める。実測: 14 節の FRT で最良は 8 通り目、探索は 44 → 19 通り(約 10 秒 → 3.5 秒)。
- **採る条件は ADR 0019 D4 のまま**(点数 (AND の交差, AND の並走, 交差, 折れ) が厳密に良く、層が変わらず、高さが増えず、AND が描けなくならない)。探索に入る条件(どれかの交差があるとき)も変えない。
- 探索は図 1 つにつき 1 回ではなく、`maxNodeW` の格子の案ごとに走りうる(`fitLayout`)。1 回の 1 案あたり最大 80 回の `layoutCauseBandOnce` なので、最悪は約 80 倍。**実測の最悪は未計測**(未解決)。

### D3: 長い矢印の経路探索(`lib/route-search.ts`、`routeLayered` の `detour`)
層を 2 つ以上またぐ矢印(`e.points.length > 2`)について、**箱に `margin = 8` 以上離れ、帯の中に収まり、折れ・交差・他の矢印の線に沿う長さの重み付き和が最小の道**を、格子上の Dijkstra で探す。
- 格子の線: すべての箱の ±margin、始点の STUB 先、終点の手前 26px(矢じりと AND の弧の余地)、帯の縁から margin。状態は (列, 行, 向き)。向きの切り替えに `BEND = 30`、他の矢印の直交する線との交差に `CROSS = 25`、他の矢印の線に 4px 以内で沿う区間に `ALONG = 200`。
- **採る条件**: 候補を入れた全体の (交差, 折れ) が厳密に良いときだけ(ADR 0016 D3 の「図は悪くならない」と同じ)。入れる順は辺の順で、先に決めた経路は後の探索の「他の矢印」になる。
- **対象外**: AND に入る矢印(`groupOf` が定義されている。弧の位置が経路の終端から決まるため)、外周のレーンの戻り(`outer`)、後ろ向き(終点の x ≤ 始点の x)の矢印、self ループ。
- **`build()` との関係**: 経路は `detours` に保持し、`aside` の再構築でも消えない。始点・終点は `build()` の最新の値で差し替える。
- 呼び出しは `causeTree` だけ(`AttemptOpts.detour`)。`straighten: false` のときは使わない(従来の図に戻す指定)。

### D4: 箱の辺に 1 本だけの矢印の直線化(`detour` と一緒に)
ADR 0016 D3 の `direct` の候補に、`slotOf` の `list.length > 1` の条件を外した矢印を加える(`detour` のとき)。ポートを両端の箱が重なる高さへ動かす手順(`align`)と、「厳密に良いときだけ採る」条件は同じ。
- 影響: 既存の図で直線化される矢印が増え、箱の位置(BK の座標)が変わる図がある(`why-why` の x が 4px ほど動いた)。

### D5: 既定は変えない。`hop` と `detour` の関係
- `hop` は off が既定のまま。`detour`(D3・D4)は `causeTree` で既定 on(`straighten !== false`)。**出力が変わる既存の例は 6 つ**(`qc-relation` / `toc-blocks` / `toc-hop` / `toc-prt` / `why-why` と新しい `toc-hop-all`)で、前後を並べて目視した。どれも折れが減る方向で、悪化は無かった。
- `causeTree` を使う外部の図は、再生成で線の形が変わる(SVG のバイトは変わる)。`straighten: false` で戻せる。

## 検証(実装 PR での実測)
- 型検査、全体テスト(2011 件のうち 3 件が落ちた: 既知のフォント差 2 件と、新しい経路探索で前提が崩れたテスト 1 件。後者は `straighten: false` の図で検証するよう直した)、全例の `golden`(差分ゼロ。上の 6 つを作り直した後)。
- 14 節の FRT: `cause-crossing` の警告が消え、避けられない約 3 本の交差が弧で見える。15 節の CRT: 最大の折れが 4 → 2。

## 未解決の項目
- **最悪時間**: `maxNodeW: 'auto'`(ADR 0019 D2)や `fold` と組むと、探索が格子の案ごとに走る。実在の因果ツリー 33 本(`medius-research`)で、時間と交差・折れを測っていない。
- **`hop: 'all'` の既定化**: `tree` を書いた図に既定で付けるか。既存の図が全部変わるので、別の決定にする。
- **`qc-relation` の並走**: 長い矢印 2 本が 12px で並んで走る(変更前も同じ)。`ALONG` の閾値(4px)を超える間隔なので、探索は避けない。
- **AND に入る長い矢印・外周レーンの戻り**は、経路探索の対象外のまま。
- **探索の格子の粗さ**: 線は箱の辺からだけ取る。レーンの空き(`LANE = 14`)を使った探索はしない。
- **PPTX**: 因果ツリーは今も画像として入る(ADR 0027)。ネイティブにするとき、弧と経路探索の結果をどう渡すかは別。
