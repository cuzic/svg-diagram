# ADR 0032: 「箱」の人間関係の図(`collusion` / `boxIceberg` / `imageMap` / `wayOut`)を足す

- 状態: 提案(草案。Opus レビュー前)
- 日付: 2026-10-17
- 基点: `main`(85e468e)
- 関連: ADR 0025(故障の木。新しい帯を足す手順と、検査の重大度の付け方を借りる)、ADR 0027(PPTX 書き出し。帯の分類を足す)、ADR 0031(FCIS。`lib/` は core、`ToneEnv` を通す)

## 背景

Arbinger Institute の『自分の小さな「箱」から脱出する方法』(Leadership and Self-Deception)と『平和の解剖』(The Anatomy of Peace)は、人間関係の問題を**行動の技術ではなく、相手を見る心の向き**の問題として説明する。説明は少数の図に決まっていて、研修資料や要約スライドでは同じ図を何度も描き直す。

今の帯で描こうとすると、次の点で合わない。

- 因果ループ(`causalLoop`)は 1 つの系の増減の向き(+/−)を描く。本の図は**二人の当事者**が持つ段階(促し・裏切り・正当化・見方・行動)が**交差して**互いを回す構図で、ノードの種類が決まっている。
- 氷山は「見える行動」と「見えない心の向き」の 2 層。`row` / `box` で描けるが、**水面の位置と、同じ行動の対比**に意味があり、手書きだと毎回ずれる。
- 「箱の中/外」は色だけで描き分けると、白黒印刷と色覚の違いで読めない(既存の「色だけの区別」の検査に当たる)。

用語は訳書で揺れる(自己裏切り/自己背信、正当化/正当化のイメージ、など)。**この ADR の用語は DSL の欄の名前を決めるためのもので、書籍の定義の再掲ではない。** 書籍との照合は実装前に 1 度やる(U0)。

## 論点

1. 何を帯にするか。既存の帯(`causalLoop`・`row`・`table`・`flow`)で足りる部分はないか。
2. 「箱の中/外」「当事者」の共通の語彙を、帯をまたいでどう持つか。
3. 二人の循環の入力の形と、矢印の交差の配置。
4. 検査(検査で何を止めるか)と、PPTX・HTML への書き出し。

## 決定

### D1. 帯は 4 つ。ただし U0 の試作で既存の帯で足りたものは作らない

| 帯 | 描くもの | 既存の帯で足りない点(U0 で実測して確かめる) |
|---|---|---|
| `collusion` | 当事者 1〜2 人の循環(促し → 自己裏切り → 正当化 → 相手の見方 → 行動)。二人なら行動が相手の見方に入る | 二人の段階の**交差**と、段階ごとの固定の見た目 |
| `boxIceberg` | 水面の上=行動、下=心の向き。同じ行動で心の向きが違う事例を並べる | 水面の位置の揃えと、事例どうしの行の揃え |
| `imageMap` | 自己正当化のイメージの型(例: 優れた人・善良な人・被害者・必要とされる人)と、それが相手に向ける見方 | 型の固定の語彙と、`collusion` の当事者からの参照 |
| `wayOut` | 箱の中の状態から、気づき → 相手を人として見る → 行動、と、箱に戻る矢印 | 戻りの矢印と、技術では出られないという注記の置き場 |

U0 は `examples/arbinger-proto-*.ts` を既存の帯だけで 4 枚描き、足りなかった点を数えて、この表の右列を実測で書き換える。**足りて見えた帯は作らない**(帯を増やす費用は、配線の表 8〜10 か所、検査、PPTX の分類、SKILL.md の説明に及ぶ)。

### D2. 共通の語彙(`lib/box-vocab.ts`)

```ts
type Heart = 'in' | 'out'          // 箱の中 / 外
type ImageKind = 'better-than' | 'i-deserve' | 'must-be-seen' | 'worse-than' | 'other'
```

- `Heart` は**色と形の両方**で描き分ける: 中=閉じた枠(実線の角丸)、外=開いた枠(四隅だけの括弧)。ラベルにも「箱の中/外」を入れる(色だけの区別にしない)。
- `ImageKind` の型の名前は欄の値で、表示の文言は `label` で上書きできる(書籍の訳語に合わせるため)。`'other'` は型に当てはまらない場面用。
- どちらも `ToneEnv`(ADR 0031)を通す。モジュールの状態は持たない。

### D3. `collusion` の入力は「当事者の配列」。段階は固定の欄

```ts
collusion({
  parties: [
    {name: '私', heart: 'in',
     prompt: '子どもを迎えに行くべきだった',      // 促し(任意)
     betrayal: '行かなかった',                    // 自己裏切り(heart:'in' のとき)
     image: {kind: 'better-than', label: '忙しい自分は仕方ない'},
     view: '相手は怠けている',                    // 相手をどう見るか
     act: '黙って不機嫌になる'},
    {name: '妻', heart: 'in', view: '…', act: '…'},
  ],
}, {id: 'c1'})
```

- 1 人なら自己欺瞞の循環(行動の結果が自分の「見方」に戻る)。2 人なら**各自の `act` が相手の `view` に入る**矢印が交差する。3 人以上は throw(図が読めなくなる。必要なら 2 人ずつの図を並べる)。
- `heart: 'out'` の当事者は `betrayal` / `image` を持てない(持てば throw。箱の外にいる人に自己正当化は無い、という約束を型で守る)。
- 配置: 2 人は左右 2 列、段階は上から下。矢印は `act` → 相手の `view` の 2 本だけが列をまたぐ。既存の `routes`(ポート指定の折れ線)を使い、**新しい経路探索は書かない**。

### D4. `boxIceberg`

```ts
boxIceberg({act: '資料を渡す', cases: [
  {heart: 'out', sees: '同僚という人', result: '協力が生まれる'},
  {heart: 'in',  sees: '邪魔な物',     result: '反発が返る'},
]})
```

- 水面は帯全体で 1 本。`act` は水面の上に 1 つ(事例で共通)、事例ごとに水面の下の列を持つ。事例は 2〜4。`act` を事例ごとに変えたい場合は `cases[i].act`。
- 事例の幅は ADR 0010 の幅の決め方に従い、足りなければ `maxNodeW` と同じく警告を出して縮める。

### D5. `imageMap`

- 型ごとの行: `kind`、イメージの文(`image`)、相手に向ける見方(`view`)、典型の行動(`acts`、複数可)。行は 1〜5。
- `collusion` の `image.kind` と同じ `ImageKind` を使い、**同じ id の `imageMap` と `collusion` が同じ図にあれば**、`collusion` 側の型の行へ薄い参照線を引く(U3 で任意の機能にする。無くても帯は成り立つ)。

### D6. `wayOut`

- 状態の列(`states: [{heart, label}]`)と、各遷移(`trigger?`)。`heart: 'in'` から `'out'` へ進む向きを既定とし、**逆向き(戻り)は点線**で描く。
- 「技術では出られない」という趣旨の注記は、帯の `note` に自由に書く(固定の文言は入れない。書籍の主張を DSL が代弁しない)。

### D7. 検査(重大度は ADR 0025 の仕組みを借りる)

| 規則 | 条件 | 重大度 |
|---|---|---|
| `box-heart-slot` | `heart: 'out'` の当事者が `betrayal` / `image` を持つ | 型で throw(検査ではない) |
| `collusion-no-link` | 2 人で、どちらの `act` も相手の `view` に届かない(`view` が空) | warning |
| `collusion-all-out` | 全員が `'out'` なのに循環を描いている | info |
| `iceberg-one-heart` | `boxIceberg` の事例がすべて同じ `heart` で、対比になっていない | info |
| `box-color-only` | `Heart` の描き分けが形を失った(`ToneEnv` の上書きなど) | 既存の「色だけの区別」の検査に任せる(新規に書かない) |

### D8. 書き出し

- 4 つの帯は SVG が主。`lib/emit-html.ts` の `kindOf` は既定が `'svg'` なので変えない(HTML では `<text>` が div に書き換わる点だけ確かめる)。
- PPTX: `lib/pptx/bands.ts` に分類を足す(ADR 0027)。形の描き分けが PPTX で落ちるなら**画像として貼る**分類にする。
- SKILL.md に 1 節を足す(型の選び方の表。使用頻度の実測を踏まえ、本体ではなく分割した参照ファイルに置く)。

## 実装の順序(小さい PR に分ける)

- U0: 既存の帯で 4 枚を試作し、D1 の表の右列を実測で書き換える。書籍との用語の照合。**ここで ADR を改訂してから U1 へ**。
- U1: `box-vocab.ts` と `collusion`(配線の全箇所 + 例 + golden)。
- U2: `boxIceberg`。U3: `imageMap`。U4: `wayOut`。
- U5: PPTX の分類・SKILL.md・検査の仕上げ。

配線の箇所は ADR 0025 D1 と wordart の記録に従う(`Band` / `LaidOutBand`、`CHILD_BANDS` / `STACK_WIDTH`、`LAYOUT_HANDLERS`、`MEASURE_HANDLERS`、`EMIT_HANDLERS`、`FIT_HANDLERS`、`REVEAL`、`VERIFY_HANDLERS`、`lib/dsl/`、`dsl-exports.json`)。新しい `lib/` のファイルは core で、`test/pure-exports.test.ts` の ratchet に当たる(各関数のテストを同じ PR に入れる)。

## 退けた案

- **`causalLoop` に当事者の欄を足す**: ループの +/− の意味と、段階の固定の見た目が混ざる(ADR 0025 D1 と同じ理由)。
- **帯を 1 つ(`arbinger({type: …})`)にする**: 型ごとに入力の形がまるで違い、`type` の分岐で型が効かなくなる。
- **書籍の文言を既定で入れる**: 訳語の揺れと著作物の引用の問題がある。型の名前は欄の値に留め、文は利用者が書く。

## 未決(U0 のあとに決める)

- 『平和の解剖』の図(「平和の心/戦争の心」の対比)を `boxIceberg` の `heart` に載せるか、別の値を足すか。
- 3 人以上の関係(チーム)を扱う需要があるか。あれば `collusion` ではなく別の帯にする。
- `imageMap` の参照線は、アンカーの仕組み(ADR 0007)で書けるか。
