# ADR 0058: デッキのスライドを段組みにする(`columns`)

- 状態: 実装済み(2026-11-15。利用者が設計を承認)
- 基点: `feat/deck-serve`(14a135a、ADR 0056 の実装まで)
- 関連: ADR 0055(デッキの JSON と PowerPoint 書き出し)、ADR 0056(`serve`)、ADR 0050(DSL の `row`)、ADR 0054(PowerPoint のグループ)

## 背景

デッキのスライドに置ける図は 1 つで、中の部品は縦に積むだけ。横に並べられるのは TS の DSL の `row`(ADR 0050)だけで、デッキの JSON にはない。nov18 のデッキ(42 枚)で、次のように 2 つを左右に並べたいスライドが出てきた(利用者の要望、2026-11-15)。

1. バリューチェーン(事業者の目) | ジャーニーマップ(お客さんの目)。ずれを見せる。
2. 「AI のチャットで作る」スライドで、Claude への指示文 | 返ってきた図。
3. 面談の対話の表 | 埋めていくジャーニーマップ。
4. 何のため・いつ使うかの表 | 小さな例の図(2 枚を 1 枚にまとめる)。
5. 同じ図の変える前 | 変えた後。

## 決定

- D1. **入力**: スライドに `columns` を足す。`figure` とは同時に書けない(両方あれば誤り。どちらが勝つかを決めない)。

      {"title": "…", "lead": "…",
       "columns": [
         {"caption": "事業者の目", "figure": {…spec…}},
         {"caption": "お客さんの目", "figure": "journey.json", "width": 2},
         {"text": "・1 行目\n・2 行目"}
       ],
       "columnScale": "same",
       "callouts": […], "source": "…", "notes": "…"}

  - 段は 2 つか 3 つ。
  - 1 つの段には、`figure`(spec そのもの、または `.ts` / `.json` のパス。今の `figure` と同じ)か `text`(短い文。改行で行を分ける。`・` や `- ` で始まる行は箇条書きとして字下げする)のどちらか 1 つ。表は `figure` の `table` 部品で置く。
  - `caption`: 段の上の小さな見出し(1 行、太字)。
  - `width`: 段の幅の比(1〜3 の整数、既定 1)。
  - `columnScale`: `"each"`(既定。段ごとに収まる最大の倍率)か `"same"`(図の段をすべて同じ倍率にする。変える前と後を比べるとき)。
  - スライドには `title` か `figure` か `columns` のどれかが要る。
- D2. **配置**(`lib/deck-layout.ts`): 見出し・リード・強調の枠・出典は今と同じ。残った領域を、段の間を 24 px あけて、`width` の比で横に分ける。
  - 段の中は、上に `caption`(16 px、太字)、その下が中身の領域。
  - 図はその領域に収まる倍率(上限 1.25。`same` なら図の段の倍率の最小)で縮め(図は、まず段の幅で配置し直す。ADR 0059)、段の中で左右の中央、**上に揃える**(左右の見比べでは、上が揃っているほうが読みやすい)。
  - `text` は 19 px(リードと同じ大きさ)で段の幅に折り返す。領域に入らなければ、そのスライドの誤り(`slides[i].columns[j].text`)にする。
  - 図が領域に収まらない(倍率が 0 か、高さが 48 px 未満)ときも誤り(`slides[i].columns[j]`)。
- D3. **小さい文字**: 9pt 未満の警告(ADR 0055 D4)は段ごとに出す。場所は `slides[i].columns[j].figure`。
- D4. **誤りの場所**: 図の検査の誤りは `slides[i].columns[j].figure.parts[k]…` の形で返す。
- D5. **PowerPoint**(`pptx-deck` と `svg-diagram/pptx/deck/edge`): 段の図は、今の 1 枚の図と同じく、図形 1 つ 1 つを倍率で置く(編集できるネイティブの図形のまま。ADR 0054 のグループもそのまま)。
  - 図形の id は、2 つ目からの図をずらして重ならないようにする。コネクタの `stCxn` / `endCxn` も同じだけずらす。
  - 画像の帯の `r:embed` は、スライドの中の通し番号で振り直す。
  - `text` の段は、リードと同じ書式のテキストボックスにする。`caption` はテキストボックス。
- D6. **`serve`**(ADR 0056): 段の図を、それぞれ入れ子の `<svg>` で置く。文字はすべて輪郭にし、許可リスト(D3 of 0056)に当てる。
- D7. **MCP のプラグインの `render_deck`**: 入力の schema は core の `deckSchema` を写しているので、`columns` は自動で入る。プラグインのビューアの 1 枚ごとの絵(`svg-diagram/slides`)と、1 回の重さの見積もり(図の数を数えるところ)は、プラグインのリポジトリで直す(この ADR では core だけ)。
- D8. `figure` だけのスライドの出力は変えない(今の .pptx とバイト単位で同じことをテストで確かめる)。

## 実装で決めたこと(2026-11-15)

- **`text` の段**: 段落(入力の 1 行)ごとに 1 つのテキストボックスにする。箇条書きは `・` を別に置き、2 行目からを本文の位置にそろえる。PowerPoint でも、段落ごとのテキストボックスになる。文字の色は本文の濃い色(`1F2328`)で、リードの灰色にはしない。
- **段の見出し**: 16 px の太字。全部の段の中身は、いちばん高い見出しの下から始める。
- **SVG での id**(D6): 1 枚の SVG に図が 2 つ以上入るので、段の図の id には `c1-`・`c2-` の接頭辞を付ける(`prefixSvgIds`、ADR 0012)。付けないと、矢印の `marker` などが別の図のものを指す。
- **PowerPoint での番号の振り直し**(D5): `renumberShapes` は、図形の `cNvPr` の id、コネクタの `stCxn` / `endCxn`、画像の `r:embed`(`rId12` から)を動かす。1 つ目の図はそのまま、2 つ目からは前の図の最大の id の後ろにずらす。
- **入力の確かめ方**: `.ts` の図を段に書いたときは、確かめる間だけ `text: '-'` を代わりに置く(スライドの `figure` で見出しの代わりを置くのと同じ)。`.ts` の図は `figureKey(i, j)`(`"i:j"`)で覚える。
- **`serve` の覚え直し**(ADR 0056 D5): 段の図に `.ts` があるスライドは、覚えずに毎回描く。
- **確かめたこと**: `figure` だけの 42 枚の nov18 のデッキで、.pptx が前とバイト単位で同じ。段のデッキの .pptx で、図形の id が重ならず、コネクタと画像の参照が切れていない。`serve` で、2 段・テキストと図・3 段が想定どおりに並ぶ(Chromium で見た)。テストは `test/deck-columns.test.ts`。
- **まだのこと**: PowerPoint で開いて見ることは、この機械ではできない(LibreOffice も xmllint の schema もない)。プラグインのビューアの 1 枚ごとの絵と重さの見積もり(D7)。`deck`(図を並べる HTML、ADR 0018)はデッキの JSON を読まないので、段組みも関係しない。

## 検討したほかの案

- **spec の中に横並びの部品を足す**(DSL の `row` の JSON 版): 図の中で並べることになり、2 つの図がそれぞれの凡例・題・検査を持てない。左右に別の図を置いて見比べる今回の使い方には、スライドの段のほうが合う。
- **段を入れ子にする**(段の中に段): 今の 5 つの使い方には要らない。複雑さに見合わない。
- **`figure` と `columns` を両方書いたら `columns` を優先**: 黙って片方を捨てると、書き手が気づかない。誤りにする。

## 結果(見込み)

- nov18 の 5 つのスライドが、外のツールなしで左右に並べられる。PowerPoint でも図形は編集できる。
- `figure` のスライドは今のまま。

## まだやらないこと(今後)

- **段の幅を中身から自動で決める**(利用者の要望、2026-11-15。初版には入れない。→ ADR 0061 で実装済み)。`width` を省くか `"auto"` にしたとき、段の中身に合わせて幅を分ける。
  - 案 A: 各段の図のいちばん小さい文字の大きさ(pt)が、なるべく等しくなるように分ける。
  - 案 B: すべての段で、いちばん小さい文字が 9pt 以上になる分け方を探し、なければ最も小さい段が最大になる分け方にする。
  - 決めることは次のとおり。
    - `text` の段の扱い。文字の大きさは固定なので、折り返した行が領域に入る最小の幅を求めて割り当てるか。
    - `columnScale: "same"` との組み合わせ。
    - 探し方。図の倍率は幅に対して単調なので、二分探索で足りるか。
    - 段が 3 つのときの計算量。
    - 一部の段だけ `width` を書いたときの意味。
  - 初版の `width`(1〜3 の整数の比)はそのまま残す。自動は、それを書かない段に効かせる形にする。
  - 図の配置の幅を空きに合わせて探すこと(ADR 0060 の `fit: "fill"`)は実装済み。段の幅の自動決めは、それを段の幅の比の候補ごとに行って比べる形になる(ADR 0060 の「段の幅の自動決めとの関係」)。
  - 段の図を段の幅で描き直すこと(ADR 0059)は実装済み。自動決めはその上に乗り、候補の幅ごとに図を描き直して比べる(ADR 0059 の「段の幅の自動決めとの関係」)。
