# ADR 0076: マンガのワークシートの拡張 — マンプと小道具、選択肢とヒント、時間の札と大ゴマ、自分のアバター、LLM の場面生成と検査

- 状態: 提案(Draft。決める人の質問は末尾の表)
- 日付: 2026-11-22
- 基点: `main`(f32571ed、ADR 0074 が入った時点)
- 関連: ADR 0074(コマ・ふきだし・人物・穴。この ADR はその型を**広げる**だけで、作り直さない)、ADR 0072(source locations。`where` の path)、ADR 0071(JSON Schema)、ADR 0069(`partCatalog` と MCP の `list_diagram_parts`)、ADR 0057(spec の `canvas`)、ADR 0007(Ports)
- 範囲外: 縦書き(ADR 0074 の第 2 版)、絵師の素材そのもの、印刷用の文字の輪郭化、`chat()` の見た目の変更(ここで足す要素は `chat()` では静かに落とす)
- 例のデータはすべてこの ADR のための作り話。ADR 0074 の例(「週に一度は早く帰る」、「最近、{change}ね」)と、オフィスや日常の一般的な場面だけを使う

## 背景

ADR 0074 は、台詞に穴のあるマンガの土台を決めた。`comic()` の帯、`bubble()`、パラメトリックな簡単な顔、穴(`slot`)、`renderComic` / `update`、幾何の地図(`geometry`)、検査。実装は `lib/comic/` で U1 から始まっている。

決める人は、その次に効く拡張を 5 つ選んだ。優先の順に:

1. マンプ(漫符。汗・怒りマークなど)と小道具。
2. 穴の選択肢とヒント。
3. 時間の札(「1 か月後」)と、大きなコマ・コマ数の変化。
4. 自分のアバター(髪型・眼鏡・服の色・肌の色)。
5. LLM が場面を出しやすくすることと、読む順などの検査。

**方針は 3 つ。**

- ADR 0074 の型の**任意の項目を足す**。`version: 1` のまま。足した項目が無いデータは、今までと同じ SVG になる(golden を変えない。テストで確かめる)。
- 意味が先(ADR 0074 の方針)。データに座標や大きさを置かない。位置は幾何の地図と決まった規則から出す。
- 決定的で、SVG だけ(`<text>` と `<use>` とフィルタを使わない)。`update` で値が変わっても、足した要素の位置は動かない。

## 決定

### D1. マンプ(漫符)と小道具

**データ(ADR 0074 の `ComicPanel` に任意の項目を足す)**

```ts
interface ComicPanel {
  /* 0074 の項目 */
  marks?: Mark[];     // 頭につく記号(汗、怒りなど)
  props?: Prop[];     // 持つ・置く物(PC、コーヒーなど)
}
type MarkKind = 'sweat' | 'anger' | 'sparkle' | 'question' | 'exclaim' | 'heart' | 'sigh' | 'idea' | 'gloom' | 'zzz';
type HeadAnchor = 'top-out' | 'top-in' | 'top' | 'side-out' | 'side-in';
interface Mark { id?: string; kind: MarkKind; on: string; at?: HeadAnchor; size?: 's' | 'm' }
type PropKind = 'pc' | 'coffee' | 'calendar' | 'clock' | 'documents' | 'phone';
type PropAnchor = 'hand' | 'floor' | 'wall-out' | 'wall-in';
interface Prop { id?: string; kind: PropKind; on: string; at?: PropAnchor; alt?: string }
```

- `on` は、そのコマの `stage` にいる人物の id。`id` は省略でき、省略すると `<panel>.<on>.m<n>`(マンプ)、`<panel>.<on>.o<n>`(小道具)になる。ADR 0074 の id の文法に従う。
- データに座標はない。`at` は意味の名前(頭の上の外側、など)で、**希望**であり強制ではない(下の「置き方」)。
- 種類は閉じた `enum`(Schema で止める)。第 1 版はマンプ 10 種(汗・怒り・きらきら・はてな・びっくり・ハート・ため息・ひらめき・落ち込み・ぐうぐう)と小道具 6 種。足すのは `enum` と 1 つの断片だけで、型は変わらない。

**アンカーの模型(規範)。** 人物の `points[<panel>.<id>].head = [cx, cy, r]`(ADR 0074)と、人物の `at` から決める。

- **頭のアンカー**は、頭の円から 8px 離れた位置に、記号の半分の大きさを足した距離を取る。`out` は、コマの中央から離れる側(`left` の人物なら左、`right` なら右。`center` は右)、`in` は中央へ向かう側。
  - `top-out`: 真上から 52°(外側へ傾ける)、`top-in`: 内側へ 52°、`top`: 真上、`side-out`: 水平から 8° 上の外側、`side-in`: 内側。
- **手のアンカー** `hand`: 素材があれば `anchors.hand`(ADR 0074 D3)を倍率をかけて使う。パラメトリックな人物は、頭の中心から**内側へ 58px、コマの下から 30px** の位置(胸から下は枠で切るので、手は枠の際に出る)。
- `floor`: 頭の中心から内側へ 108px、コマの下から 30px。`wall-out` / `wall-in`: 頭の中心から外側 / 内側へ 76px、コマの上から 40px。
- 素材に `hand` が無いとき、`hand` を指定した小道具は `floor` に落ちる(助言 `comic-anchor-missing`)。頭のアンカーは `head` の円だけから出るので、素材に追加の印は要らない。

**置き方(規範。決定的)。**

1. ふきだしを先に置く。**マンプと小道具はふきだしを動かさない**(文字が先)。
2. 候補の並びは、(a) 書き手の `at`、(b) 種類ごとの既定の好み(`sweat` は `top-out` → `side-out` → `top`、`anger` / `question` / `exclaim` は `top-in` から、`sigh` は `side-in` から、など。表は U1 で固定する)、(c) 残りの頭のアンカーを `top`・`top-out`・`top-in`・`side-out`・`side-in` の順に。重複は除く。小道具は `at`、`hand`、`floor`、`wall-out`、`wall-in` の順。
3. 先頭から、**ぶつからない最初の位置**を採る。1 つ置くごとに、その箱を障害物に足す(書く順に決まる)。
4. 1 つも置けなければ、そのマンプ(小道具)は**描かない**。`comic-mark-no-room` / `comic-prop-no-room`(助言)を返す(Q2)。ふきだしの帯が積みきれていて(`comic-bubble-zone`)置けないときは、その原因の報告だけにして、これらは出さない(1 つの誤りは 1 回だけ報告する。ADR 0074 と同じ)。

**ぶつかりの検査(ADR 0074 の検査を広げる)。** 置く箱(マンプは 20px か 28px、小道具は 40px の正方形)が、次のどれにも重ならないこと。余白の数は、スパイクで動いたもの。

| 障害物 | 余白 | 理由 |
|---|---|---|
| ふきだし | 4px | 文字を覆わない(ADR 0074 の頭との余白と同じ) |
| しっぽ(三角形) | 2px | 話し手の線を切らない |
| 頭の円(自分も含む) | 2px | 顔を覆わない |
| 先に置いたマンプ・小道具 | 2px | 重ねない |
| コマの縁 | 8px | 枠線に触れない |
| 番号の札(24px)の四角 | 4px | 左上 |

**ADR 0074 の幾何の地図に足すもの(加えるだけで、既存の項目は変えない)**: `tails: Record<string, [x, y][]>`(ふきだしの id → しっぽの三角形の 3 点。いまはスパイクが式を持ち、地図には無い)と、`marks` / `props: Record<string, Rect>`。しっぽの三角形は、ADR 0074 の「しっぽの向き(規範)」の式から出す。

**層の順(規範)**: コマの紙と背景 → 壁と床の小道具 → 胴 → 顔 → 手の小道具 → マンプ → しっぽ → ふきだし(枠、文字、穴)。ふきだしは**いつも一番上**に出る。ぶつかりの検査があるので、マンプがふきだしに覆われることは起きない。層の順は DOM の順で決める(`z-index` は使わない)。

**SVG だけ・決定的。** マンプと小道具は、固定の箱(24px / 40px)で描いた `<path>` / `<circle>` / `<rect>` の断片で、`lib/comic/` が文字列で持つ。`<text>`・`<use>`・フィルタ・外部参照を使わない。フォントに依存しない。ADR 0074 D3 の `sanitizeBody` を通る形にそろえるので、あとで絵師の素材として同じ形で足せる。色は `lib/tokens.ts` から取り(スパイクは決め打ち)、**どの部品も 2px 前後のインク色の輪郭を持つ**(紙に対し 16:1 なので、非テキストのコントラスト 3:1 を満たす)。

**アクセシビリティ。** マンプは気持ちを重ねるだけの飾りで、意味は `expression` と台詞が持つ。マンプは `aria-hidden="true"` にし、`<title>` を付けない(読み上げを増やさない)。小道具は場面の情報(PC がある、など)なので `<title>` に日本語の名前(「パソコン」)を入れ、書き手が `alt` で上書きできる。

**`chat()`(ADR 0074 D7)では、`marks` と `props` を静かに落とす**。

**代替案**

- **マンプを `expression` の一部にする**(`worry-sweat` のような組み合わせ)。表情 8 × マンプ 10 の組み合わせが増え、Schema の `enum` が膨らむ。却下。
- **自由な `x` / `y`**。ADR 0074 の「データに座標を置かない」に反し、LLM の出力の位置が安定しない。却下。
- **絵文字の文字にする**。フォントと環境で見た目が変わり、輪郭化と色の統一ができない。却下。

### D2. 選択肢とヒント

**データ(ADR 0074 D4 の穴の定義に任意の項目を足す)**

```ts
interface SlotDef {  // 0074: {max?, prompt, fallback?, choices?, strict?}
  choices?: string[];  // 0074。ページがチップか選択欄で出す。自由入力も許す(strict でなければ)
  hints?: string[];    // 新規。最大 3 つ。例として見せる答え。選ばせるのでなく「たとえば」
}
```

`choices` と `hints` の違い: **`choices` は「この中から選ぶ」候補、`hints` は「こう書けばよい」という例**。`choices` が無く `hints` だけなら、ページは入力欄の下に例を小さく出し、押すと入力欄へ入れる(押して値になるのは `choices` と同じ)。`choices` があって `strict` でなければ、チップと自由入力を両方出す(「どちらでも」)。`strict: true` なら選ぶだけ。新しい `mode` の項目は足さない(`choices` と `strict` から決まる)。

| 規則 | 内容 |
|---|---|
| `comic-slot-hints` | `hints` が 4 個以上、重複、1 行でない、制御文字を含む(問題) |
| `comic-slot-hint-length` | `hints` の 1 つが `max` 字を超える(問題)。ヒントを押して入れても、必ず穴に入るようにする |
| `comic-slot-choices` | `choices` が 9 個以上、重複(問題)。チップの数は 8 まで |
| `comic-slot-hint-dup` | `hints` が `choices` の候補と同じ(助言) |

**`max` との関係(D4 の規則を保つ)。** `max` が無いときの既定は、ADR 0074 のとおり**`choices` のいちばん長い候補**(`hints` は数えない。ヒントの長さで、ふきだしの箱を変えさせない)。ヒントは `max` に合わせて書く。ふきだしの箱の大きさは、今までどおり `max` だけから決まる(穴を埋めても、選択肢やヒントが増えても、配置は動かない)。`choices` と `hints` は幾何に影響しない。

**`update` との関係。** チップを押すことは、普通の値の変更と同じ(`update({...values, [id]: choice})`)。選択肢のための特別な経路は作らない。`seq` と `stale`(ADR 0074 D5)の規則はそのまま。ヒントの取得(下)が遅れて戻ってきたときの古さは、ページが `seq` で見る(下)。

**幾何の地図に足すもの**: `slotOrder: string[]`(穴の id を読む順に。キーボードの順序、読み上げの順)と、穴ごとの `inputRects[id]`(穴の矩形を、幅・高さとも **44px 以上**になるよう外へ広げ、コマの中に収めた矩形)。穴の矩形は高さ 22px で、タッチの標的としては小さい(WCAG 2.5.8 は 24px 以上、2.5.5 は 44px)。ページはこの矩形に入力欄かチップの置き場を重ねる。`geometry` は ADR 0074 のとおり値で変わらない(テストで `deepEqual`)。

**LLM に追加のヒントを聞く、ページ側の手がかり。** ライブラリは**どこにも送信しない**(利用者の入力を外に出さないため)。ライブラリが出すのは、データの形と 2 つの純粋な関数だけ。

```ts
// ページが LLM に渡す材料を作る(ライブラリは送らない)
slotContext(sheet, slotId, values): {
  slot: string; panel: string; speaker: string; prompt: string; max: number;
  sentence: string;                 // 他の穴を値で埋め、この穴を「＿＿」にした台詞
  choices: string[]; hints: string[];
  seq: number;                      // この時点の最新の update の seq
}
// ページが LLM から受け取った案を、値として入れてよいか見る
acceptValue(sheet, slotId, text): Finding[]   // 1 行・制御文字なし・max 字以内・strict の候補外 を ADR 0074 D4 の値の規則で見る
```

ページ側の型(ライブラリは持つだけで呼ばない):

```ts
type HintProvider = (ctx: ReturnType<typeof slotContext>, signal: AbortSignal) => Promise<string[]>;
```

古さの扱い: ページは要求を出すときの `ctx.seq` を覚え、答えが戻ったとき、その穴の値や `update` の `seq` が進んでいれば捨てる(ADR 0074 D5 の `stale` と同じ考え方)。戻った案は `acceptValue` を通ったものだけを出す。ヒントはデータ(`hints`)に書き戻さない(静的なヒントと、その場の案を混ぜない)。

**アクセシビリティ(見本が示す。規範は SVG でなく入力欄の側)。** 入力欄は `<label>` を台詞の文(`titles[ふきだしの id]`、穴を `＿＿` にしたもの)にし、案内(`prompt`)を `aria-describedby` で結ぶ。チップは `role="listbox"` の中の `role="option"`(または普通のボタンの並び)で、**44px 以上**、キーボードで矢印と Enter。選んだあと、`update` の戻りの `titles` を `aria-live="polite"` の領域で読み上げる。Tab の順は `slotOrder`。色だけに頼らない(穴の埋めた状態は強調色と**太字**で伝える。ADR 0074 のとおり)。

**代替案**

- **チップを SVG の中に描く**。IME と選択の操作は HTML のほうが確か(ADR 0074 の Q3 と同じ理由)。却下。
- **ヒントの長さから既定の `max` を出す**。ヒント 1 つで全員のふきだしが広がる。却下(Q3)。
- **ライブラリが LLM を呼ぶ**。鍵・送信先・同意はページの仕事。却下。

### D3. 時間の札と大きなコマ

#### 3a. 時間の札(キャプション)

「1 か月後」のような札は、`Dialogue.kind` に `'caption'` を足して表す(新しい型を作らない。`chat()` も同じ `Dialogue` の列を使うので、`chat()` では中央の細い区切りの文字になる)。

```ts
type DialogueKind = 'say' | 'think' | 'shout' | 'narration' | 'caption';   // 'caption' を足す
// 例: {id: 'c1', who: '', kind: 'caption', tpl: '{period}後', slots: {period: {max: 4, prompt: '期間'}}}
```

- 札は 1 コマに 1 つまで。**`dialogue` の先頭に置く**(読む順で最初。先頭でなければ `comic-caption-order`(助言))。`who` は使わない(`narration` と同じく、話し手の検査の対象外)。
- 見た目: コマの左上、番号の札の右(x はコマの左から 32px、上から 8px)に、インク色の塗りに白い文字(14px 太字、行の高さ 20px)の四角。しっぽなし。1 行、**穴を最大で数えて 10 字まで**(`comic-caption-wide`、問題)。穴(`{period}`)は使える(ADR 0074 D4 の規則のまま。札の中の穴も 1 コマの穴の数に数える)。
- **ふきだしの帯を縮める。** 札のあるコマは、ふきだしを積む帯の上端が **32px 下がる**(札 28px + 隙間 4px)。ADR 0074 の帯は、7:5(1 コマ 300px)で 168px、6:5(350px)で 218px だった。札があると **136px / 186px**。ふきだしの高さは 1 行 48、2 行 72、3 行 100(隙間 6px)なので、**7:5 では 2+2 行(150px)が入らず、1+2 行(126px)まで。6:5 では 3+2 行(178px)が入る**。これは ADR 0074 の数字からの計算(U3 で測って確かめる)。`comic-bubble-zone` と `comic-text-budget` は、札のあるコマではこの狭い帯で見る。
- 札が数字の札と重ならないこと、頭の円に触れないことは、D1 のぶつかりの検査に載せる(障害物として最初に足す)。札の位置は固定なので、マンプは札を避けて置かれる。

#### 3b. コマの割り(格子、スパン、コマ数)

ADR 0074 D1 は、名前つきの割り(B)を選び、自由な格子(C)を避けた。ここでは、**名前つきの割りを格子の枠にしたまま、小さなスパンだけを足す**(Q5)。

- **割りに `2x3`(2 列 3 行、6 コマ)を足す**。`1x2`、`1x3`、`1x4`、`2x2` は 0074 のまま。コマ数 2 / 4 / 6 は、`1x2` / `2x2` か `1x4` / `2x3` で表せる。
- **コマに `span?: {cols?: 1 | 2; rows?: 1 | 2}`**(既定 1×1)を足す。`cols: 2` は 2 列の割りの 1 行ぶんの幅いっぱい(全幅)、`rows: 2` は 2 行ぶんの高さ(`2 × 高さ + 溝 16px`)。1 列の割りでは `cols` は 1 のみ。
- **置き方(規範。決定的)。** コマを `panels` の順に、**空いている最初の升(左上から行ごとに左から右)**へ置く。スパンは升の矩形を取る。順に置いて、全部の升が埋まり、はみ出さなければ成立する。成立しなければ `comic-grid-fill`(問題。0074 の `comic-panel-count` を、升の合計の検査に置き換える。スパンが無ければ同じ意味)。
- **読む順 = `panels` の順**。置き方が先頭の空き升から埋めるので、コマの左上の升は、行ごとに左から右の順に並ぶ(`rtl` を第 2 版で入れるときは、列を鏡にする。スパンは列の番号で決まっているので、そのまま鏡にできる)。
- **コマの大きさ。** 幅 = `cols × 升の幅 + (cols - 1) × 溝`、高さ = `rows × 升の高さ + (rows - 1) × 溝`。升の幅は `canvas` の幅から(ADR 0057)、升の高さは `aspect`(Q8)から。
- **コマの中の規則は、コマの幅と高さに合わせる**。人物の位置(`left` / `right` は左右の縁から 104px)、頭の高さ(下から 76px、半径 36px)は ADR 0074 のまま。ふきだしを積む帯は、コマの高さに応じて伸びる。**穴の数の上限は 1 コマ 2 個 × `cols`**(広いコマは 4 個まで)。ふきだしの行数の予算(積んだ 4 行まで)は積みの単位なので変えない(同じ高さに並ぶふきだしは積まない)。
- **大きなコマで人物を大きくするか**(寄りの絵)は、第 1 版では**しない**(Q7)。広いコマは「左右の人物の間が広がり」、高いコマは「上に余白が増える」。余白はマンプ・壁の小道具・札で使える。人物の拡大は、頭の円の半径とアンカーを倍率で決めればよい(すべてアンカーから出す構造なので、足せる)が、見た目の測定が先。

#### 3c. 場面の切り替えのコマ(間奏)

`ComicPanel.kind?: 'scene' | 'interlude'`(既定 `scene`)を足す。**間奏は、格子の升を使わない、全幅の帯**で、`panels` の順に、コマの行の間へ入る。人物はなく(`stage` は空)、`dialogue` は `caption` が 1 つだけ。高さ 96px、淡い色味(`bg.tint`)、札の文字は 24px 太字を中央に。ふつうのコマが行の途中のとき(升が半端に埋まっているとき)に間奏が来たら `comic-grid-fill`。`chat()` では中央の区切りの大きな文字になる。

代わりに「全幅で高さが半分のコマ」を格子に入れる案は、升の高さが半分になり、置き方の規則が崩れる。帯にして格子の外に出すほうが単純(Q6)。

#### 3d. 検査(コマの割りに合わせた変更)

| 規則 | 重さ | 内容 |
|---|---|---|
| `comic-grid-fill` | 問題 | スパンを置くと升が余る・はみ出す、間奏が行の途中に来る(`comic-panel-count` の一般化) |
| `comic-span-invalid` | 問題 | `cols` が割りの列数を超える、`rows` が 2 を超える |
| `comic-caption-wide` | 問題 | 札が穴を最大で数えて 10 字を超える |
| `comic-caption-order` | 助言 | 札が `dialogue` の先頭でない |
| `comic-interlude-content` | 問題 | 間奏に人物やふきだしがある(`caption` 以外) |
| `comic-slots-per-panel` | 問題 | 上限が `2 × cols`(ADR 0074 は 2 個) |

### D4. 自分のアバター

**データ。** ADR 0074 の `Cast.face = {hue, hair?}` を**そのまま広げる**(新しい `avatar` の入れ物は作らない)。

```ts
interface Face {   // 0074: {hue: number; hair?: 'short' | 'long'}
  hue?: number;                                       // 0074。あれば髪と服の色の元(従来の見た目)
  hair?: 'short' | 'long' | 'bob' | 'none';           // 髪型。0074 の 2 種に 2 種を足す
  hairColor?: 'black' | 'brown' | 'chestnut' | 'blond' | 'gray' | 'navy';
  skin?: 'fair' | 'light' | 'medium' | 'tan' | 'brown' | 'dark';
  glasses?: 'none' | 'round' | 'square';
  top?: 'navy' | 'blue' | 'teal' | 'green' | 'yellow' | 'orange' | 'red' | 'purple' | 'gray';   // 服の色
}
```

- 色は**名前のついたパレットの鍵だけ**(`#rrggbb` は受け取らない)。肌 6、髪の色 6、服 9。値は `lib/tokens.ts` に置く(スパイクの `palette.ts` に候補)。名前を固定するので、同じデータは同じ SVG で、色の組み合わせはテストで列挙できる。
- **既定(古いデータの見た目を変えない)**: `skin` は `fair`(ADR 0074 の肌 `#ffe3c8`)、`hair` は `short`、`glasses` は `none`。`hairColor` と `top` が無ければ、従来どおり `hue` から出す(髪 `hsl(hue 35% 28%)`、服 `hsl(hue 45% 62%)`)。`hue` も `hairColor` も無いときの扱いは ADR 0074 のまま(Schema の必須の規則に従う)。
- **同じ人物 id なら全コマで同じ**。`stage` は `who` で `cast` を引くので、アバターは `cast` に 1 度書くだけで全コマに及ぶ。表情はコマごとに変わり、アバターは変わらない。
- **自分のアバターはページが決める。** `renderComic(sheet, {avatars: {me: {...}}})` で `cast[id].face` を**項目ごとに上書き**する(素材の `characters` と同じく、1 回の描画ごとに渡す。大域の状態にしない)。ライブラリは保存しない(保存はページ。`Face` は JSON なので `localStorage` などに書ける)。アバターを変えても幾何は変わらない(頭の円は固定)ので、変更の反映は `renderComic` をもう一度呼ぶ(V1。`update` のような差分の経路は、測って遅ければ足す)。

**読みやすさ(スパイクの結果から)。** パレットの色同士のコントラストは、保証できない(髪と肌の 36 組のうち 19 組が 3:1 未満、服と肌の 54 組のうち 17 組が 1.5:1 未満)。そこで**色の差でなく輪郭で見分ける**。

1. **すべての部品(髪・顔・胴・眼鏡の枠)にインク色の輪郭**(2.5px)を付ける。ADR 0074 のスパイクは、髪に輪郭が無かった。輪郭はインク `#222` で、紙(`#fffdf6`)に対し 16:1。
2. **眼鏡のレンズは白に近い塗り**(肌がどの色でも 3:1 以上になるものを、パレットのテストで確かめる)にして、暗い肌でも見えるようにする。
3. 人物を見分ける助けを色だけにしない。髪型と眼鏡の違いでも見分けられるようにする(下の検査)。
4. 検査: `comic-cast-similar`(助言) — 同じ `cast` の 2 人が、`hair`・`hairColor`(または `hue`)・`skin`・`glasses`・`top` のすべてで同じ。話し手の取り違えを避ける。パレットのテスト: 眼鏡のレンズと全部の肌の組が 3:1 以上、全部の色とインクの輪郭が見える(輪郭は線なので、塗りとの比は問わない)。

**絵師の素材(ADR 0074 Q2)との両立。** パラメータは**パラメトリックな顔だけ**を動かす。素材の人物では、次のものだけ効く。

- 素材の `character.json` に、`recolor: {skin: '#f1c8a0', hair: '#3a2a1a', top: '#4a6fa5'}` を**任意**で書ける。意味は「この素材の SVG のこの色の文字列が、肌・髪・服を表す」。読み込みのとき、これらの色の文字列を、パレットの色に**文字列として置き換える**(`fill` / `stroke` の属性値だけ。`<style>` は ADR 0074 のとおり使えない)。決定的で、サニタイズの規則は変わらない。
- `hair`(髪型)と `glasses` は、素材の絵そのものなので効かない。パラメータが指定されていて素材が受けられないとき、`comic-avatar-ignored`(助言)を返す。
- アンカー(`head` / `mouth` / `hand`)はこの ADR の影響を受けない。マンプと小道具(D1)の位置も素材のアンカーから出るので、素材に差し替えても動く。

**代替案**

- **`#rrggbb` を受け取る**。コントラストの検査が要り、見た目が不揃いになる。名前だけのパレットのほうが、LLM の出力も安定する。却下。
- **`avatar` を別の入れ物にする**。`face` と二重になる。却下。

### D5. LLM が場面を出しやすくし、直す往復を決める

#### 5a. LLM が出しやすい形にする

`comic` は spec の部品なので、ADR 0069 の `partCatalog()` から MCP の `list_diagram_parts` に自動で出る(`{type, description, schema, example}`)。そこに次を載せる。

- **`description`**(英語。部品の説明の言語と同じ)に、書き方の規則を数行で: 1 コマに話し手は 2 人まで、1 つのふきだしは 3 行まで、穴は 1 コマ 2 個まで(広いコマは `2 × cols`)、`tpl` の 1 行は 9 字前後、台詞は意味で書く(座標を書かない)、穴の `max` は 1〜9、人物の id は短い英字。
- **Schema の各項目に `description`**。`kind` の `enum` には、意味を 1 行ずつ(`sweat`: 困っている・焦っている、など)。
- **`example`** は小さな 2 コマ。`spec-kit` の「`partCatalog()` の例はすべて問題なく描ける」というテスト(`lib/spec-kit.ts` のコメント)に載る。
- **作り話の例 3 つ**(テストの fixture と `docs` の例): (1) 会議の前に資料を確認する 2 コマ(穴 `{what}`)、(2) 昼休みに同僚へ相談する 4 コマ(札「{period}後」あり)、(3) 日常の買い物で選ぶ 4 コマ(穴に `choices` と `hints`)。製品の手順の名前や特定の手法は使わない。

#### 5b. 出す → 検査 → 直す の往復の契約

使うツールは、**既存の `render_diagram` と `check_diagram`**(Q12。新しい `render_comic` は作らない)。理由: (1) `comic` は spec の部品として入るので、ツールは増えない。(2) MCP の経路には値が無い(ADR 0074 D5)ので、描かれるのは空のワークシート(紙に手で書く用や、図の確認用)で、`render_diagram` の出力と同じ。(3) 値を持つ描画は `renderComic`(ブラウザ)だけで、MCP に出す理由が無い。

**往復の規則(LLM への指示の一部。`list_diagram_parts` の description に 3 行で書く)**

1. spec を出す。`check_diagram` を呼ぶ。
2. `verdict` が `ok` でなければ、**問題(`severity: 'problem'`)の各件**について、`where` の id(`p2.d1`)か path(ADR 0072 D7。`parts[0].panels[1].dialogue[0]`)の**そのコマだけ**を直す。ほかのコマ・id は変えない。
3. 直したら 1 に戻る。**3 回で止める**。止めたときは、残る問題を人に伝える。
4. 助言(`severity: 'advice'`)は、問題がなくなってから、1 回だけ直してよい。

**検査の結果に足すもの(`RULE_DOCS` に静的に持つ。件ごとには持たない)**

```ts
RULE_DOCS['comic-text-budget'] = {
  /* 0074 の説明 */
  fix: 'Shorten the line or split it over two bubbles; at most 3 lines per bubble and 4 stacked in a panel.',  // 命令形の 1 文(英語)
  scope: 'dialogue',        // どこを直すか: 'dialogue' | 'panel' | 'sheet'
  auto: 'edit',             // 'edit': その場の書き換えで直る / 'regen': コマの作り直しが要る / 'advice': 直さなくてもよい
};
```

各規則の分類(第 1 版)。`edit` は機械的に直せる、`regen` はコマの構成を作り直す、`advice` は直さなくてもよい。

| 規則 | 重さ | `auto` | `scope` | 直し方のヒント(`fix`) |
|---|---|---|---|---|
| `comic-text-budget` | 問題 | edit | dialogue | 台詞を短くする、または別のふきだしに分ける |
| `comic-bubble-zone` | 問題 | regen | panel | ふきだしを減らす、または台詞を別のコマへ移す |
| `comic-slots-per-panel` | 問題 | edit | panel | 穴を 1 つ、普通の語に置き換える |
| `comic-slot-max` / `comic-slot-prompt` / `comic-slot-hints` / `comic-slot-hint-length` | 問題 | edit | dialogue | 数を範囲に収める |
| `comic-speaker-unknown` | 問題 | edit | dialogue | `who` を `stage` にいる人物にする、または `stage` へ足す |
| `comic-at-collision` | 問題 | edit | panel | 一方の `at` を変える |
| `comic-grid-fill` / `comic-span-invalid` | 問題 | regen | sheet | スパイクを外すか、コマの数を合わせる |
| `comic-caption-wide` | 問題 | edit | dialogue | 札を 10 字以内にする |
| `comic-bubble-wide` / `comic-orphan-line` / `comic-follower-split` | 助言 | edit | dialogue | 言い回しを変えて行の切れ目を動かす |
| `comic-mark-no-room` / `comic-prop-no-room` | 助言 | advice | panel | 無くてもよい。残すなら別のアンカーか別の人物に |
| `comic-reading-order` / `comic-tail-cross` / `comic-speaker-unclear` | 助言 | regen | panel | 台詞の順を左から右へそろえる、話し手の人物を入れ替える |
| `comic-face-repeat` | 助言 | edit | sheet | どこかのコマの `expression` を変える |
| `comic-cast-similar` | 助言 | edit | sheet | 髪型か眼鏡か服の色を変える |

「機械的に直せる」は、**同じ規則の別の件が同時に出ても、対象のコマの外を読まずに直せる**という意味。`regen` は、コマの台詞と人物の配置を作り直して、`where` のコマだけ差し替える。

#### 5c. 新しい検査

ADR 0074 の `comic-reading-order`(`anchor` の上書きが読む順に反する)は、**幾何の地図を読む検査**に広げる。ふきだしの置き方が決まった規則(ADR 0074 D1)のうちは、これらは出ない。出るのは、`anchor` の上書き、広いコマ(D3)、第 2 版の縦書きのとき。スパイクの実際の幾何では 0 件で、複製を壊すと 6 件出た(上の表)。

| 規則 | 重さ | 内容 |
|---|---|---|
| `comic-reading-order`(広げる) | 助言 | コマの中のふきだしの**読む順**が、`dialogue` の順と違う。読む順は、縦の範囲が重なるふきだしを 1 行として、行を上から下へ、行の中を水平なら左から右へ(`dir: 'rtl'` は右から左へ。縦書きは列を右から左へ、列の中を上から下へ)。`dir` を引数にして、第 2 版で同じ関数を使う |
| `comic-tail-cross` | 助言 | しっぽが別のしっぽと交差する、または別のふきだしの箱を通る。しっぽの三角形(D1 で地図に足す `tails`)の辺で判定する |
| `comic-speaker-unclear` | 助言 | (a) しっぽが話し手でない人物の頭の円(+4px)の近くを通る、(b) ふきだしの中心が、話し手より別の人物のほうに(8px 以上)近い。話し手を取り違える見た目になる |
| `comic-face-repeat` | 助言 | 同じ人物が、**登場する連続する 3 コマ**で同じ `expression`。表情が変わらず単調になる。3 コマ未満のワークシートでは出さない(閾値は Q15) |
| `comic-cast-similar` | 助言 | D4 |

すべて助言(`verdict` を止めない)。理由: ふきだしの置き方が決まっているので、問題にすると LLM の往復が止まりやすく、見た目の好みに近いものを問題にしないほうがよい(Q14)。

## 代替案(全体)

- **5 つを別々の ADR にする**。型を広げる場所(`ComicPanel` / `SlotDef` / `Face` / `Dialogue.kind`)と検査の表が重なるので、1 つにまとめた。実装の単位(U1〜U6)は別の PR にする。
- **ADR 0074 の `version` を 2 にする**。足したものはすべて任意で、無ければ従来の出力になる。上げない。
- **マンプ・小道具・アバターを `lib/comic/` の外の別の帯にする**。しっぽ・頭の円・穴の矩形との関係(ぶつかりの検査)を持てなくなる。却下。

## 影響

- 型の追加(すべて任意): `ComicPanel.marks` / `props` / `span` / `kind`、`Dialogue.kind: 'caption'`、`SlotDef.hints`、`Face` の項目、素材の `recolor`。割りに `2x3`。`Geometry` に `tails` / `marks` / `props` / `slotOrder` / `inputRects`。`renderComic` の `avatars`、純粋な関数 `slotContext` / `acceptValue`。
- Schema(`schema/comic.schema.json` と `spec.schema.json`)の項目が増える。`layout` と `panels` の数の対応(`if` / `then` の `minItems` / `maxItems`)は、スパイクがあると升の合計で決まるので、`maxItems` だけ Schema に残し、`comic-grid-fill` に任せる。
- ADR 0074 の `comic-panel-count` は `comic-grid-fill` に置き換わる(スパンが無ければ同じ意味)。`comic-slots-per-panel` の上限が `2 × cols`。
- **golden は変えない**(足した項目が無いデータは同じ出力。テストで確かめる)。足した要素を使う例は、新しい golden として足す。
- `chat()`: `marks` / `props` / `span` / `kind: 'interlude'` を静かに落とし、`caption` は中央の区切り、間奏は大きな区切りの文字に変える(ADR 0074 U5 の範囲に入れる)。
- 検査の規則が約 20 増える(表のとおり)。`RULE_DOCS` に `fix` / `scope` / `auto` の 3 項目を足す(ほかの規則は任意のまま)。
- ADR 0074 U1〜U4 が入る前に、この ADR の単位は始められない(依存は下の表)。

## 実装計画

どの単位も `main` に入れる PR を 1 つとし、Opus のレビューで Blocker と Major がなくなってから入れる。優先の順(1 から 5)に U1〜U6。

| 単位 | 前提(ADR 0074) | 内容 |
|---|---|---|
| U1 | U1(配置・ふきだし)、U3(幾何の地図) | マンプと小道具 |
| U2 | U3(穴、`update`) | 選択肢とヒント |
| U3 | U1(割り)、Q10 の測定 | 札、スパイク、`2x3`、間奏 |
| U4 | U2(顔と素材) | アバター |
| U5 | U4(Schema と検査) | LLM 向けの記述と往復の契約 |
| U6 | U1、U3、この ADR の U1・U3 | 読む順などの検査 |

### U1: マンプと小道具

- 範囲: D1 のすべて。`lib/comic/` に `marks.ts`(断片の表)、`anchors.ts`(アンカーの式)、`place-extras.ts`(置き方とぶつかりの検査)。幾何の地図に `tails` / `marks` / `props`。規則 `comic-mark-no-room`、`comic-prop-no-room`、`comic-anchor-missing`、`comic-mark-target`(`on` が `stage` にいない。問題)。
- 完了の基準: (1) スパイクと同じ場面(マンプ 6、小道具 5)で、置く結果が一致する。(2) どの置かれた箱も、ふきだし・しっぽ・頭・ほかの箱・コマの縁・番号の札と重ならない(性質のテスト)。(3) 空・埋めた・飛ばし・長すぎるの 4 状態で、置いた位置が同じ(`deepEqual`)。(4) 2 回置いて SVG が同じ。(5) ふきだしの帯が積みきれていないコマでは `comic-mark-no-room` を出さず、`comic-bubble-zone` だけ。(6) マンプと小道具のないデータの SVG が、U1 の前と**バイト単位で同じ**(golden)。(7) 素材の `anchors.hand` を使う小道具が、素材の位置に出る。
- テスト: 種類 16 × 人物 8 の網羅(置けるか、置けないなら理由が `comic-*-no-room`)、候補の順、層の順(DOM の順)、`aria-hidden` と `<title>`、断片が `<text>` / `<use>` / フィルタを含まない、輪郭のコントラスト(紙に対し 3:1)。`chat()` では落ちる。

### U2: 選択肢とヒント

- 範囲: D2 のすべて。`hints`、規則 4 つ、`slotOrder`、`inputRects`、`slotContext`、`acceptValue`。見本(`examples/artifact/`。ADR 0074 U6)にチップとヒントと a11y を足す部分は、U6 のあとに足す。
- 完了の基準: (1) `choices` と `hints` を足しても `geometry` が `deepEqual`。(2) `max` が無いとき、既定は `choices` の最長で、`hints` を足しても変わらない。(3) `hints` の 4 個目、`max` 超え、重複が期待の規則で止まる。(4) `inputRects` が 44px 以上で、コマの外へ出ない。(5) `acceptValue` が ADR 0074 D4 の値の規則と同じ結果。(6) `slotContext` の `sentence` が `titles` と同じ文。(7) ライブラリのコードがネットワークや `fetch` を使わない(束ねたあとの確認)。
- テスト: 規則ごとの単体、`slotOrder` が読む順、`update` の `seq` / `stale` が選択肢でも変わらない。

### U3: 時間の札、スパン、`2x3`、間奏

- 範囲: D3 のすべて。`caption`、帯の縮み、`span` と置き方、`2x3`、`interlude`、検査 6 つ。**この単位の頭で Q10(縦横比の既定)の測定をする**(札のあるコマの 7:5 と 6:5 で、ふきだしの組み合わせが入るか)。
- 完了の基準: (1) 札のあるコマの帯が 32px 縮み、7:5 で 2+2 行が `comic-bubble-zone`、6:5 で 3+2 行が通る。(2) 2×2 に全幅のコマ + 2 コマ、`2x3` に高さ 2 のコマを入れた図が、升が余らずに置かれ、読む順が `panels` の順。(3) 升が余る・はみ出す・間奏が行の途中、で `comic-grid-fill`。(4) 全幅のコマで穴が 4 個まで通り、5 個で止まる。(5) スパイクや札のないデータの出力が変わらない(golden)。(6) 4 状態で `geometry` が `deepEqual`(札の穴を含む)。
- テスト: 置き方の網羅(小さな格子の全パターン)、幾何(コマの大きさの式)、札の位置が番号の札と重ならない、`chat()` の区切り。

### U4: 自分のアバター

- 範囲: D4 のすべて。`Face` の項目、パレット(`lib/tokens.ts`)、髪型 4 種・眼鏡 2 種の描画、輪郭、`avatars`、素材の `recolor`。`comic-cast-similar`、`comic-avatar-ignored`。
- 完了の基準: (1) `hue` だけのデータが、U4 の前と**バイト単位で同じ**(golden)。ただし髪の輪郭を足す変更は ADR 0074 の golden を動かすので、**輪郭は新しい項目がある人物にだけ付ける**。(2) 同じ `cast` の人物が全コマで同じ見た目。(3) `avatars` で上書きしても、幾何が `deepEqual`。(4) 眼鏡のレンズと全部の肌が 3:1 以上(パレットの網羅)。(5) 素材に `recolor` があれば、パレットの色が文字列で置き換わる。なければ `comic-avatar-ignored`。
- テスト: パレットの網羅(肌 6 × 髪 6 × 服 9 × 髪型 4 × 眼鏡 3 のうち、ふちの組み合わせで SVG を作り、決定的であること、すべての部品に輪郭があること)、`recolor` の置き換え、`#rrggbb` を Schema が拒む。

### U5: LLM 向けの記述と往復の契約

- 範囲: 5a と 5b。部品の `description`・Schema の `description`・`example`・fixture 3 つ。`RULE_DOCS` の `fix` / `scope` / `auto` と、`check_diagram`(プラグイン側。コアの出力の形)へ出す形。MCP のプラグインへの取り込みの手順は、ADR 0069 と同じ。
- 完了の基準: (1) `partCatalog()` の `comic` が `list_diagram_parts` に出て、`example` が問題なく描ける。(2) fixture 3 つが Schema と検査を通る。(3) わざと壊した 8 例(穴が 3 個、話し手が舞台にいない、など)が、期待の規則と `fix` / `scope` / `auto` つきで返る。(4) 台本の往復(LLM を使わない固定の「直した版」)で、`edit` の件を直すと次の `check_diagram` で消える。(5) 規則が増えたのに `fix` の無いものが 0(テストで、`comic-*` の全規則に `fix` があること)。
- テスト: 規則ごとの `fix` の有無、Schema の説明の欠けがないこと、fixture の描画。LLM の品質そのものは測らない(ここでは契約だけ)。

### U6: 読む順・しっぽの交差・話し手の不明・同じ顔

- 範囲: 5c。`comic-reading-order` の広げ、`comic-tail-cross`、`comic-speaker-unclear`、`comic-face-repeat`。`dir` を引数にした読む順の関数。
- 完了の基準: (1) 実際の幾何(ADR 0074 のサンプル 4 コマ)で 0 件。(2) 壊した複製(ふきだしの入れ替え、反対側への移動)で、期待の件数(スパイクと同じ: 読む順 1、しっぽの交差 2、話し手の不明 3)。(3) 同じ表情が 3 コマ続くデータで `comic-face-repeat`、2 コマでは出ない。(4) 左から右の `dir` で正しく、`rtl` の引数で順が鏡になる(単体)。(5) 4 コマで 5 ms 未満。
- テスト: 上のとおり、規則ごとの単体と、スパイクの複製の固定。

## テスト方針

- ADR 0074 と同じ: 配置は純粋な関数で、測定は関数で渡す。足した要素の位置は幾何だけから決まるので、フォントに依存しない。
- 「足した項目が無いデータの出力は変わらない」を、ADR 0074 の golden ですべて取る。
- 「値で位置が動かない」を、状態の組ごとの `deepEqual` で、マンプ・小道具・札・入力欄の矩形にも広げる。

## 質問と推奨(決める人へ)

| # | 質問 | 推奨 |
|---|---|---|
| Q1 | データの項目の名前。`marks` か `manpu` か | `marks`。`manpu` は英語を話す LLM に通じにくい。説明(`description`)に「漫符(comic symbols)」と書く |
| Q2 | マンプや小道具が置けないとき | 描かずに助言(`comic-mark-no-room`)。飾りなので、置けないことで保存を止めない。必須にしたい小道具が出てきたら `required: true` を足す |
| Q3 | `hints` を `max` の既定に数えるか | 数えない。ヒントの長さでふきだしの箱が変わるのを避ける。代わりに、ヒントは `max` 字以内(問題として止める) |
| Q4 | LLM への追加のヒントの取得 | ライブラリは材料(`slotContext`)と受け入れの検査(`acceptValue`)だけを出し、送信はページの仕事。利用者の入力を外へ出すかはページが決める |
| Q5 | スパイクを入れて、ADR 0074 D1 の「自由な格子はやらない」を一部見直すか | 見直す。ただし `cols` / `rows` は 1〜2、置き方は決まった規則、成立しなければ `comic-grid-fill`。大コマの要望(全幅・倍の高さ)にだけ応える |
| Q6 | 場面の切り替え(間奏)を、格子の外の全幅の帯にするか | する。升の高さが半分のコマを入れると置き方が崩れる |
| Q7 | 大きなコマで人物を大きくするか(寄り) | 第 1 版はしない。広い・高いコマは余白が増えるだけ。余白をマンプ・壁の小道具・札で使い、寄りは見た目を測ってから別の単位で決める |
| Q8 | 縦横比の既定(ADR 0074 Q10)を、札のあるコマも考えて決める | 6:5。札のあるコマは 7:5 で 2+2 行が入らず、6:5 なら 3+2 行が入る(ADR の計算)。U3 の頭で測って確定 |
| Q9 | アバターのパレットの数 | 肌 6・髪の色 6・服 9・髪型 4・眼鏡 3。足すのは表を足すだけで、型は変わらない |
| Q10 | 自分のアバターの保存 | ライブラリは保存せず、`renderComic({avatars})` で渡す。保存先(`localStorage`、サーバー)はページの仕事 |
| Q11 | 素材の人物にアバターを効かせる範囲 | 素材が `recolor` を宣言した色(肌・髪・服)だけ。髪型・眼鏡は効かず、助言を出す |
| Q12 | MCP に `render_comic` を足すか | 足さない。`render_diagram` / `check_diagram` と `list_diagram_parts` をそのまま使う。MCP の経路には値が無いので、出る図は空のワークシートで同じ |
| Q13 | 検査の結果へ `fix` / `scope` / `auto` を足す形 | `RULE_DOCS` に規則ごとに静的に持つ(件ごとに持たない)。`fix` は英語の命令形の 1 文 |
| Q14 | 新しい検査(読む順・交差・話し手の不明・同じ顔・似た人物)の重さ | すべて助言。往復が止まりやすくなるので、問題にしない。使ってみて必要になったものだけ、あとで問題に上げる |
| Q15 | `comic-face-repeat` の閾値 | 3 コマ続けて。2 コマ続きはふつうの会話で出てしまう |
| Q16 | ADR 0074 の golden を変えずに、髪へ輪郭を付けるか | 付けない(新しい項目がある人物にだけ付ける)。全人物に付けるなら ADR 0074 の golden を更新する別の PR にする |

## スパイクの再現

```
node spikes/comic-extensions/run.ts [outdir]        # マンプと小道具: 衝突、候補、決定性、大きさ(out/scene-*.svg)
node spikes/comic-extensions/run-checks.ts          # 読む順・しっぽの交差・話し手の不明(実際の幾何と壊した複製)
node spikes/comic-extensions/palette.ts             # アバターのパレットのコントラスト
```

`spikes/comic-extensions/out/` に、解決後(`scene-resolved.svg`)と、最初の候補だけ(`scene-first-choice.svg`)を置いた。これらは `lib/` の外で、ADR 0074 のスパイクと同じく、U1 の PR で `lib/comic/` に置き換えて消す。
