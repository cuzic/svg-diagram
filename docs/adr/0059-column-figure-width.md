# ADR 0059: 段の図を段の幅で描き直す(spec の `width`)

- 状態: 実装済み(2026-11-15。利用者の決定に従う)
- 基点: `feat/deck-serve`(0c18562、ADR 0058 の段組みまで)
- 関連: ADR 0058(段組み)、ADR 0057(spec の `canvas`。別のブランチ `feat/spec-canvas`)、ADR 0055 D4(9pt の警告)

## 背景

JSON spec の図は、必ず幅 940px で配置される(DSL には `diagram({width})` があるが、spec にはない)。段組み(ADR 0058)で 1:1 に分けると、段の幅は約 572px なので、どの図も 61% に縮み、文字は 6.4pt になる。表や段階のように文字を折り返せる図でも、折り返さずに縮むだけになる。図を縦長に書き直しても幅は 940px のままなので変わらない。nov18 で測った図は、バリューチェーン 940×304、ジャーニーマップ 940×321、対立解消図 940×408、現状ツリー(上向き)940×664、マインドマップ(組織図)940×660 で、すべて幅 940 だった。

## 決定(利用者の決定、2026-11-15)

- D1. **spec の最上位に `width` を足す**(px、整数、320〜940、既定 940)。そのまま `diagram({width})` に渡る。図は、その幅で配置される(箱や表の文字は折り返し、文字の大きさは変わらない)。
  - 940 より広くはできない。広い図は ADR 0057 の `canvas` で描く。ADR 0057 の D3 は「spec に自由な `width` を出さない」と決めていた。理由は、幅を広げても文字は 14px のままで、見せる側が縮めると文字が小さくなる(`doc-width` が警告する状態になる)からだった。この ADR の `width` は狭めるだけなので、その心配は起きない。`feat/spec-canvas` を取り込むときに、ADR 0057 の D3 を「940 を超える自由な `width` は出さない(狭める `width` は ADR 0059)」と書き直す。あわせて、`width` と `canvas` を同時に書けないようにする。
- D2. **段の図は、`width` を書いていなければ、段の幅で配置する**。配置の幅は「段の幅 ÷ 0.86」(`COLUMN_FIGURE_SCALE`)で、spec の範囲(320〜940)に収める。こうすると、14px の文字はスライドで約 9pt になる。
  - 縮めるのは、段の高さに収まらないときだけになる(倍率は今と同じ計算で、上限 1.25)。
  - 段が 940 ÷ 0.86 ≒ 808px 以上あるときは、そのまま 940 で描く。
  - `.ts` の図は、DSL の中で幅を決めているので変えない。
  - 図が `width` を書いていれば、それを使う。
- D3. **段の幅に収まらない図は、940 で描いて縮め、警告する**(利用者の決定。誤りにはしない)。
  - 警告は、場所 `slides[i].columns[j].figure` で、次の内容にする: 「段の幅(例 665px)に収まらない(図の理由。例: `mindmap(): the figure does not fit 625px.`)。940px で描いて縮めた。段を広げる、文字を減らす、収まる配置にする、または図に `width` を書く」。
  - 黙って 940 に戻すことはしない。
  - 940 でも描けない図は、今までどおり誤りにする。
- D4. 3 つの経路(`pptx-deck`、`svg-diagram/pptx/deck/edge`、`serve`)で同じにする。段の幅は `columnWidths`(`lib/deck-layout.ts`)で、配置の前に決まる。描き直す spec は `columnSpec`(`lib/deck-spec.ts`)が作る。

## 段の幅の自動決め(ADR 0058「まだやらないこと」)との関係

ADR 0058 の「まだやらないこと」に書いた、段の幅を中身から決める案は、この ADR の上に乗る。

- この ADR は「段の幅が決まっているとき、図をその幅で描き直す」。
- 自動決めは「段の幅そのものを、中身から決める」。
- 自動決めでは、候補の幅ごとに図を描き直し、いちばん小さい文字の大きさを比べて幅を選ぶことになる。図の配置は幅に対して単調ではない(折り返しの位置で高さが跳ぶ)ので、二分探索ではなく、少数の候補(たとえば 1:2、1:1、2:1)を描いて比べる形が現実的。
- 段の幅を変えるたびに図を配置し直すので、描画の回数が候補の数だけ増える。`serve` は、スライドごとに覚える仕組みで 2 回目からは軽くなる。

## 結果

- nov18 のデッキ(37 枚、うち段組み 5 枚)を書き出すと、9pt 未満の警告はなくなった。表と箇条書きは段の幅で折り返される。
- 段の幅で収まらない図(三段の中の対立解消図。5 つの箱には 580px が要る)は、940 で描かれ、そのことが警告で分かる。
- 試した図(段の幅 665px と 440px):
  - 収まる: バリューチェーン(665×331、440×482)、ジャーニーマップ(665×380、440×556)、表、段階、シェブロン。
  - 対立解消図: 665px には収まり、440px には収まらない。
  - 現状ツリー(右向き)とマインドマップ: どちらの幅にも収まらない。
