# ADR 0054: PowerPoint 書き出しで、1つの部品の図形を入れ子のグループにまとめ、名前を付ける

- 状態: 提案(レビュー2回を反映)
- 日付: 2026-11-13
- 基点: `feat/mcp-compare`(f33c344)
- 関連: ADR 0027(PowerPoint 書き出し)、ADR 0034(SVG のノード名 `data-node`)、ADR 0050(組み合わせられる帯)

## 背景

PowerPoint 書き出し(ADR 0027)は、図のすべての部品を編集できる図形にする。図形は帯(部品)ごとに1つのグループにまとめているが、
その中はほとんど平らに並ぶ。ギャラリーの72図を調べると(プラグインの docs/pptx-grouping-survey.md)、見た目で1つの部品が複数の図形に分かれていた。

- 二重枠の箱(CRT の根本原因、PDPC の開始と到達点、なぜなぜの真因、連関図の主要因、状態遷移図の終了状態): 外の箱と内側の枠が別。
- クラス図のクラス: 箱にはクラス名だけで、区切り線と属性・操作の各行は別の図形。
- BPMN のゲートウェイ(ひし形、×印、問いの文字)、FTA の事象とゲート記号、ハーベイボール(円と扇)、シーケンス図の参加者(頭とライフライン)、
  ガントの進み具合のある棒、タイムラインの出来事(点、名前、日付)、同心円の引き出し(点、線、説明文)。
- グラフ: 凡例の1項目(見本と名前)、折れ線の系列(線と点)、値のラベル、軸(目盛り線と目盛りの文字)。
- 親和図のグループとビフォーアフターのパネル: 枠、見出し、カードが別の帯(ADR 0050)なので、部品のグループすらない。
- CRT と FRT の AND: 弧と、弧が束ねる矢印が別々。

既にまとまっているもの: 箱とその番号バッジなど(`bands.ts` の `box-parts`)、四象限の項目(`quadrant.ts` の `item:`)、カスタマージャーニーの
感情の線(`emotion-curve`)。

図形の名前もほとんどが `shape-12`、`line-8` で、PowerPoint の「選択」ウィンドウでどれが何か分からない。

SVG から変換する帯(グラフ、クラス図、BPMN、FTA、ガント、シーケンス図、スイムレーン、ボウタイ、PERT ほか、`lib/pptx/svg-shapes.ts`)は、
SVG の最上位の要素を平らに読む。SVG には意味のまとまりが残っていない。しかも描く側の多くは、まとまりごとではなく図形の種類ごとに描く
(FTA は線、ゲート、印、バッジ、箱、文字の順に、それぞれ全部を描く。`emit-fta.ts`)。1つのまとまりの図形は、描く順で連続していない。

## 決定

### D1. 階層

PowerPoint のグループは入れ子にできる。帯のグループの中を、次の2段までにまとめる。

1. 意味のまとまり(以下「まとまり」): クラス、ゲートウェイ、系列、凡例、軸、レーン、参加者、出来事など。
2. まとまりの中の項目: 凡例の1項目だけ。軸の目盛り1つずつのような細かいグループは作らない(クリックが増えるだけで得が小さい)。

段の数は帯の中で数える。帯の外側(D5 のパネル、`row`)や、今ある `box-parts` の段は数えない。
図形が1つしかないまとまりはグループにせず、その図形にまとまりの名前を付ける。

### D2. SVG から変換する帯: 描く側が要素に `data-part` を書く(ADR 0034 と同じ作り)

- `emitSvg` に `parts?: boolean` を足す。`parts` のとき、帯に `parts: true` を付けて描く(`withNodeIds` と同じく、レイアウトの結果を写して印を付ける)。
  `parts?: true` は、すべての帯の型が持てる共通のフィールドにする(帯の種類ごとの switch はいらない)。`renderBand` は帯を丸ごと渡すので、描く関数の引数は変えない。
- まとまりの持ち主が、描く時点で分からない要素がある: ガントの文字(`GanttText`)、`plane` の文字(`PlaneText`)、クラスの各行、
  FTA のゲート・印・バッジ(ノードとは別の配列)。今は `renderClasses` が文字の持ち主を位置で推測している。レイアウトがこれらに持ち主
  (ノードや系列の添字)を記録する(型に `owner?: number` などを足す)。グラフは、`Canvas.text`、`place`、`lines` に `part` を渡せるようにし、
  `charts-*.ts` の各呼び出し側が渡す。
- 描く側は、帯の `parts` が真のときだけ、まとまりに属する要素に ` data-part="…"` を書く。値はまとまりの道筋で、外から内へ段を `/` で区切る。
  各段は `種類:キー|見出し`。キーはまとまりを区別する安定した値(ノードの添字や id)、見出しは名前に使う文字。
  例: `legend:0|凡例/entry:2|B 社`、`class:3|注文`。段の中の `/`、`|`、`%` は `%2F`、`%7C`、`%25` に置き換える。属性値は `escapeAttr` で書く。
  書く関数は `emit-common.ts` の `partAttr(on, ...steps)` 1つにする。
- `parts` が偽なら何も書かないので、`examples/` の SVG、ウィジェットの SVG、HTML は作りの上で変わらない(テストでも確かめる)。
- `bandPicture`(`lib/pptx/image-band.ts`)は `parts: true` で描く。画像に戻る帯の SVG(`svgBlip`)にも属性が残るが、描画は変わらない。
- グラフは `ChartItem` に `part?: string` を持たせ、`charts-emit.ts` が書く。`plane`(折れ線、バーンダウンほか)、`curve`、`bars` は別の描く関数なので、
  それぞれに同じ属性を足す。グラフの「下地」(文字の後ろの白い矩形、`charts-base.ts` の `Canvas.text`)、半透明の矩形の下に敷く
  ページ色の矩形(`charts-emit.ts`)、薄く描く(dim)ときの矩形も、そのまとまりに入れる(入れないと、まとまりを動かしたときに白い矩形が残る)。
- `svg-shapes.ts` の読む属性(`KNOWN`)に `data-part` を足す。

### D3. 変換(`svg-shapes.ts`)

- 要素の `data-part` を読み(`data-node` と同じく、読む属性に足す)、図形ごとにまとまりの道筋を覚える。`<g>` は今と同じく読まない。
- まとまりの図形は、描く順で飛び飛びでもよい。変換は、道筋ごとに図形を集めて1か所(置き場所)にまとめて書く。まとめると重なりの順が変わり、
  それはスライドの見た目に出うる(例: `plane` の軸のまとまりを目盛りの文字の位置に置くと、格子線がすべての系列の上に来る)。置き場所は次の規則で選ぶ。
  - 図形の描く順の番号は、その図形を受け取った図形のもの(箱に入った文字は箱の番号、線が受け取った矢じりは線の番号)。
  - まとまりの図形の番号を i1 < … < ik として、置き場所を最後、最初、間の各番号の順に試す。
  - 置き場所が使えるのは、動く図形 p のどれについても、p と置き場所の間に描かれる、まとまりの外の図形が p と交わらないとき。
    線は線幅の分だけ太らせた線分として調べる(折れ線を囲む矩形はプロット全体を覆うので使わない)。0.5px 以下の接触は無視する。
  - 同じ種類のまとまり(系列と系列、クラスとクラス)は、互いの順を入れ替えてよい。交わる2本の折れ線のどちらが上かは変わりうるが、
    PowerPoint のグラフも系列を1つずつ(線と点を続けて)描くので、それと同じ見た目になる。まとまりの外の図形(格子線、軸)との順は守る。
    (実装で、2系列の折れ線の線と点がまとまりから外れたことから足した。)
  - 使える置き場所がなければ、交わる図形をまとまりから外して(平らな図形のまま元の位置に置いて)、残りをまとめる。
  これで、重なりの順が変わっても見た目は変わらない。軸は「最初」(目盛りの文字はプロットの外)になり、交わる系列は線と点だけ、あるいは外れる図形が出る。
  D6 の図で外れる図形が出ないことをテストで確かめる(出るものは、理由を書いて許可の一覧に入れる)。
- 今の3つの処理(文字を箱へ、線の端の印を矢じりへ、線の端を箱に接続)は、図全体で今と同じに行う。文字を箱に入れる規則だけ、次を足す。
  まとまりを持つ文字は、別の、空でないまとまりを持ち、自分のまとまりの外側でも内側でもない箱には入らない(クラスの属性の行は、他のクラスや
  背景のまとまりの箱に入らない)。まとまりのない箱や文字は今と同じ。これは将来の図のための守りで、今のギャラリーでは結果を変えない
  (`parts` の有無で、どの文字がどの箱に入るかが変わらないことを、全ギャラリーで確かめる)。
- グループの位置と大きさは、中の図形の元の座標(箱の矩形、線の点、文字の推定の幅)を囲む矩形。曲がったコネクタは `rot` 付きで書かれ、
  `a:xfrm` からは囲む矩形が分からないので、`a:xfrm` は読まない。大きさは最低 1 EMU(一直線に並ぶ線だけのまとまりで 0 にしない)。
  子の座標はそのまま(`chOff`/`chExt` を `off`/`ext` と同じにする。今の `groupXml` と同じ)。

### D4. 図形を直接作る帯

レイアウトから図形を直接作る帯(`cause.ts`、`states.ts`、`flow.ts`、`legend.ts`)は、作るときに `groupXml` で入れ子にする。`cause.ts` は既に
ノードごとに箱・内側の枠・バッジを、矢印ごとに線と棒を続けて書いているので、並べ替えはいらない。`states.ts`、`flow.ts`、`legend.ts` で
図形の種類ごとに書いているところは、まとまりごとに書く順へ並べ替える(D3 と同じく、間の図形と交わらないことを確かめる)。
薄く描く(dim)帯は今と同じく SVG から変換するので(`bands.ts`)、ここのまとまりはできない。

- CRT・FRT・なぜなぜ・PDPC・連関図(`cause.ts`): 二重枠の箱は、箱と内側の枠。中核の原因のバッジは、下地の図形が文字を持つ1つの図形にする。
  なぜなぜの対策(破線の棒 + 矢印)と、切る矢印(線 + 棒)は、それぞれ1つのまとまり。
- AND: 弧だけのまとまり(図形1つなので、名前だけ)。AND の矢印は箱に接続しており(両端)、グループに入れたときの PowerPoint の動きが
  分からない。接続が保たれれば、グループを動かしても矢印は箱に残り、弧だけが動く(今と同じ)。外れれば、ADR 0027 で得た接続を失う。
  どちらでも、弧が箱について動くようにはならない。PowerPoint 本体で、接続した矢印を含むグループの動きを確かめてから、まとまりを広げるか決める。
- 状態遷移図とフローチャート(`states.ts`): 遷移の名前の白い下地と文字は、グループではなく1つの図形(下地の図形が文字を持つ)にする。
  終了状態は、箱と内側の枠。
- タイムライン(`flow.ts`): 出来事ごとに点、名前、日付。期間の括弧と文字。
- 同心円(`flow.ts`): 引き出しごとに点、線、説明文。
- 凡例(`legend.ts`): 凡例全体と、項目ごとの見本と名前。AND の見本(2本の線と弧)は1項目。

### D5. 帯をまたぐまとまり

親和図のグループやビフォーアフターのパネルは、枠(`group` 帯)と、見出しと中の帯が別の帯になっている(ADR 0050)。レイアウト
(`layout-handlers.ts` の `layoutGroupAt`)は、枠、見出し、中の帯の順に並べる。そこで `LaidOutGroup` に、続く何本の帯が自分の中身かを
記録し(`span`)、`slide.ts` がその帯をまとめて1つのグループにする。矩形の包含からは推測しない。`span` は `layoutGroupAt` の最後で
「今の帯の数 − 枠の位置 − 1」として数える(子の数ではない。入れ子のグループや行の詰め直しで帯が足されても合う)。入れ子のグループも `span` でたどれる。
`slide.ts` は帯を平らに並べるのをやめ、`span` を消費しながら再帰的にたどる。PowerPoint 書き出しは段階表示(reveal)で帯を絞らないので、数はずれない。
接続のための登録(`ctx.glue`)は図形の id で行うので変わらず、コネクタはすべての帯の後に書くので順も変わらない。

今日の線のあるガント(置き場所の規則の難しい例)、(3) 中にグループの入った親和図(D5)、(4) CRT の二重枠(D4)を作る。その後に残りの図を足す。

### D7. 名前

- まとまり(グループ)の名前は `<種類>: <見出し>`。種類は英語の短い語(`class`、`gateway`、`event`、`lane`、`participant`、`message`、`task`、
  `series`、`legend`、`entry`、`axis`、`ball`、`node`、`callout`、`panel`、`AND` など)、見出しはまとまりの代表の文字(40文字まで、今の `nameOf` と同じ)。
  DSL の id があれば後ろに付ける: `class: 注文 [u1]`。id は、スクリプト(python-pptx や VBA の `Shapes("…")`)や AI が図形を探す手がかりになる。
- 帯のグループは、今の `chart-0`(スライドでの帯の番号)から、帯の種類と、同じ種類の中での番号(`chart`、2つ目から `chart 2`)にする。
  `Ctx` に種類ごとの数を持たせる。
- 文字を持つ図形は今と同じ `<種類>: <文字>`。文字のない図形は、役割の語(`frame`、`inner frame`、`arc`、`line`、`marker`、`bar`)に、id があれば
  ` [id]` を付ける。PowerPoint の名前は重複してよい(選択ウィンドウでは親のグループの下に並ぶ)。
- 種類の語は、図の言語(ja / en)によらず英語。今の名前(`box:`、`text:`)と同じ。
- 名前を見るテスト(`test/pptx-edge.test.ts` の `arrow-`、`arrow-t-u`、`bar-t-u`、`core-badge-a`、`name="tree"`、`emotion`、`step-\d+`)は、
  新しい名前に合わせて直す。

### D8. 確かめ方

- `examples/` の SVG が1バイトも変わらない。
- `parts` の有無で、変換の結果(どの文字がどの箱に入り、どの線がどの箱に接続するか)が変わらない(全ギャラリー)。
- D6 の各図を書き出し、まとまりのグループがあること、その名前、中の図形の数をテストで確かめる。D3 の規則でまとまりから外れる図形が出ない
  (許可の一覧を除く)。
- ギャラリーの全図と全オプション変種が pml.xsd に適合し、画像に戻る帯が増えない。プレビューで元の図と一致する。
- PowerPoint 本体(利用者の手元の Microsoft 365 の Windows 版)で、ギャラリーの CRT とクラス図とグラフを開き、グループの選択と、
  箱を動かしたときの接続を確かめる。LibreOffice の判定(`test/helpers/pptx/judge-glue.ts`)では、読み込んだときに接続が残ることだけを確かめられる。

## 結果

- PowerPoint で、クラスや系列や凡例の項目を1回のクリックで選んで動かせる。グループの中の1つの図形は、もう1回クリックすれば選べる。
- 選択ウィンドウで、図形の名前から何の部品かが分かる。id があれば、スクリプトから探せる。
- SVG 出力は変わらない。PowerPoint 用の SVG に属性が増えるだけ。
- まとまりを足すたびに、描く側に属性を足す必要がある。付け忘れても、今と同じ平らな図形になるだけ。
- AND は今回、名前が付くだけ。弧と矢印をまとめるかは、PowerPoint での確認の後に決める。

## 採らなかった案

- 書き出した図形の位置関係から、まとまりを推測する: 図ごとに規則が要り、グラフの目盛り線のように触れているだけの図形を誤ってまとめる。
  描く側は何が1つの部品かを知っている。
- 印のコメント(`<!--sd-part-->`)でまとまりを囲み、PowerPoint のときだけ `<g>` にする: まとまりが描く順で連続していないので囲めない。
  連続させるには描く順を変える必要があり、SVG が変わる。消すときに改行が残る危険もある。
- SVG に常に `<g>` や属性を出す: `examples/` の全 SVG が変わる。
- `group` 帯と中の帯を矩形の包含でまとめる: レイアウトが中身の帯を知っているので、推測は要らない。
- 二重枠を DrawingML の二重線(`a:ln cmpd="dbl"`)の1つの図形にする: 線と線の間隔が線幅の割合で決まり、元の図と合うか未確認。
  今回はグループにし、後で検討する。PERT のクリティカルパスの枠を箱の線にすること、3本に分かれた矢印を1本の折れ線にすることも同じく後で。
