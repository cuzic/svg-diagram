# ADR 0066: デッキの表紙のスライド(`layout: "cover"`)

- 状態: 実装済み(2026-11-16。Opus のレビューを受けて D2・D4〜D6・D8・D10〜D12 を直した)
- 基点: `main`(960d16b8、ADR 0056・0058〜0065 まで)
- 関連: ADR 0055(デッキの JSON と PowerPoint 書き出し)、ADR 0056(`serve`)、ADR 0058(段組み)、ADR 0060(`fit`)

## 背景

デッキの 1 枚目は、たいてい表紙(題・副題・会の名前・日付・発表者)になる。今のデッキには表紙の書き方がなく、`title`・`lead`・`source` だけのスライドは次のように描かれる。

- 見出し(37px)とリード(19px)が、ふつうのスライドと同じく左上に小さく出る。
- 出典(13px)が左下に小さく出る。
- 真ん中は空く。

表紙らしく見えない。nov27 のデッキ(「第2回 AI開発の進め方 勉強会」)では、会の名前・日付・発表者を `source` に詰め込み、表紙の代わりに「今日の流れ」の図を置いていた(利用者の要望、2026-11-16)。

表紙は、`serve`(`lib/present/slide-svg.ts`)と `pptx-deck` / `svg-diagram/pptx/deck/edge`(`lib/pptx/deck.ts`)で同じに見えなければならない。両者は配置を `lib/deck-layout.ts` の `planDeckLayout` で共有している(ADR 0056 D2)。

## 決定

- D1. **入力**: スライドに `layout: "cover"` を書くと表紙になる。表紙で使える欄は次のとおり。

      {"layout": "cover",
       "event": "第2回 AI開発の進め方 勉強会",
       "title": "要件から受け入れテストまで",
       "lead": "AIの困った行動は、最初の渡し方と、機械で判定するテストで防ぐ。",
       "date": "2026年11月27日",
       "presenter": "山田 花子",
       "notes": "…"}

  - `title`(必須): 表紙の題。
  - `lead`: 副題。新しい `subtitle` は作らず、今の `lead`(「見出しの下の 1〜2 文」)をそのまま使う。意味が同じで、ふつうのスライドを表紙に変えるときに書き直しが要らない。
  - `event`(新、80 字まで): 会・シリーズの名前。題の上に出す。
  - `date`(新、60 字まで): 日付。**自由な文字列**(D3)。
  - `presenter`(新、120 字まで): 発表者。所属や複数の名前もこの 1 つの文字列に書く(「株式会社〇〇 山田 花子」「山田 花子、佐藤 一郎」)。
  - `source`: ふつうのスライドと同じく、下に小さく出す(著作権表示や資料の URL など)。
  - `notes`: ふつうのスライドと同じ。
- D2. **表紙で意味のない組み合わせは誤り**(`lib/deck-spec.ts` の `validateDeck`、場所つき)。
  - 表紙に `figure`・`columns`・`columnScale`・`fit`・`callouts` を書いたら、その欄の場所(`slides[i].figure` など)で誤りにする(「表紙には描かない。別のスライドに移す」)。黙って捨てると、書き手が気づかない(ADR 0058 の `figure` と `columns` と同じ考え)。デッキ全体の `fit` は図のあるスライドにだけ効くので、表紙があっても誤りにしない。
  - 表紙に `title` がなければ `slides[i].title` の誤り(表紙では、ふつうのスライドの「`title`・`figure`・`columns` のどれかが要る」の誤りは出さない。同じことを 2 度言わない)。
  - 表紙でないスライドに `event`・`date`・`presenter` を書いたら、その欄の場所で誤り(「表紙にだけ描く。`layout: "cover"` を足すか、消す」)。表紙でないスライドで黙って消えるのを防ぐ。
  - `layout` の値は今は `"cover"` だけ(JSON Schema の `enum`)。書かなければ今のふつうのスライド。
  - CLI で `figure` にパス(`.ts`・`.json`)を書いた表紙も、同じ場所で誤りにする。`lib/deck-load.ts` は表紙の `figure` を読まずに書かれたまま残し、`validateDeck` がその誤りを出す(`.ts` の図は検証の写しから外され、仮の見出し `-` が入るので、読むと表紙の誤りが隠れる。また、壊れたパスの誤りが先に出て、直した後に「表紙には描かない」と言われることもない)。
  - 表紙の組み合わせの決まりは、`validateAgainst` が扱う JSON Schema の範囲では書けない。そこで `layout`・`figure`・`columns`・`callouts`・`fit` の `description` に、表紙で使えるかを書く(MCP の利用者は Schema しか見ない)。
- D3. **`date` は自由な文字列にする**(ISO 8601 の日付にはしない)。
  - 表紙に出したい形は人と会で違う: 「2026年11月27日」「2026年11月27日(金)」「2026-11-27」「2026年 秋」「Nov 27, 2026」。ISO で受けて整形すると、曜日の有無・元号・区切り・英語の月名などの書式の選び方を新しく持つことになる。
  - このツールは日付で何も計算しない(並べ替えも、ファイルのプロパティへの書き込みもしない)。書かれたとおりに描くだけなら、文字列で足りる。
  - ほかの文字の欄(`title`・`source`)と同じく、そのまま描く。検証は長さ(60 字)と制御文字だけ。
- D4. **配置**(`lib/deck-layout.ts`、`planDeckLayout` の中で `layout` を見て分ける。出力 3 つが同じ計算を使う)。
  - 上から `event` → `title` → `lead` → 短い横線 → `date` → `presenter` を、**それぞれ中央揃え**で縦に積み、そのかたまりを、上の余白(32px)から出典の上までの領域の上下の中央に置く。
  - 大きさ・行の送り・色(px、96dpi。pt はその 0.75 倍):

    | 欄 | 大きさ | 行の送り | 太さ | 色 | 次との間 |
    |---|---|---|---|---|---|
    | `event` | 22px(16.5pt) | 29px | 太字 | `1F5FA8`(強調の枠の線と同じ青) | 16px |
    | `title` | 56 / 48 / 40px(D5) | 大きさの 1.2 倍(67 / 58 / 48px) | 太字 | `1F2328`(見出しと同じ) | 20px |
    | `lead` | 26px(19.5pt) | 34px | 細字 | `5B6370`(リードと同じ) | 36px |
    | 横線 | 幅 80px・高さ 3px | | | `1F5FA8` | 28px |
    | `date` | 20px(15pt) | 26px | 細字 | `3A4A5A` | 8px |
    | `presenter` | 24px(18pt) | 31px | 太字 | `1F2328` | |

    - 行の送りは、ふつうのスライドと同じ大きさの 1.3 倍。ただし題だけは 1.2 倍にする(大きい字の 1.3 倍は、日本語の 2 行の題では間が空きすぎる)。
    - 欄がないときは、その欄と「次との間」を詰める。

  - 横線は `date` か `presenter` があるときだけ描く(題のかたまりと、日付・発表者のかたまりを分ける)。
  - 文字の幅は、ふつうのスライドと同じく測った幅で折り返す(`wrapText` の `phrase`)。折り返す幅は、スライドの幅から左右の余白(56px)を引いた 1168px より狭い 1040px にし、ブロックの左端は x = (1280 − 1040) / 2 = 120px(中央揃えの長い行は、左右の端まで届くと読みにくい)。
  - 表紙の文字の大きさは、ふつうのスライドと違う(題は 3 とおり)。`deckTexts` は、表紙では、題を 56・48・40px のすべてで、ほかの欄をそれぞれの大きさと太さで返す。`serve` は `deckTexts` の分だけをまとめて測り、測っていない文字は「文字数 × 大きさ」で数えてしまう(誤りにならない)ので、ここで漏れると `serve` と .pptx の折り返しが黙って食い違う。表紙のどの文字も、`deckTexts` の外で測られないことをテストで確かめる。
  - `figureRooms` は表紙にも呼ばれる(1×1 の仮の図を渡す)。表紙の分岐は図を見ず、`figure: null`・`columns: []`・`room` を持つ完全な `DeckLayout` を返し、仮の図のために `noRoom` にはしない。表紙は `columns` を持てないので、`chooseColumns` には来ない。
  - 出典は、ふつうのスライドと同じく左下に置く。
  - かたまりの高さが領域に入らないか、切れ目のない長い語(URL など)で 1 行が 1040px を超えるときは、そのスライドの誤り(`slides[i]`、「表紙の文字が入らない。題・副題・会の名前・発表者・出典を短くする」)。`wrap="none"` の .pptx では、そうした行がスライドの外に出るため。文は `roomMessage` に表紙の場合を足して 1 か所で持ち、`slideIssues`(.pptx)と `render-deck.ts`(`serve`)の両方がそれを使う。上限いっぱいの欄(題 120 字・副題 300 字・発表者 120 字・会の名前 80 字)では入らないことがある。
- D5. **長い題**: 題の大きさは、56px、48px の順に、「題が 2 行以内で、かたまり全体が領域に入る」最初のものにする。どちらでもなければ 40px にし、行数に上限を置かず折り返す。40px でもかたまりが入らなければ D4 の誤り。
  - 題の 120 字(D1 の今の上限)は、40px・1040px で 5 行(送り 48px で 240px)ほど。
  - 大きさを段階で決めるのは、測った幅だけで決まり、出力によって変わらないため(連続に縮めると、PowerPoint とブラウザで丸めの差が出やすい)。副題が長いときに題を小さくして入れることもある(かたまり全体で見るため)。
- D6. **文字の描き方**:
  - SVG(`serve`): 行ごとに、測った幅でブロックの中の中央に置く(x = 120 + (1040 − 行の幅) / 2)。文字はいつもどおり輪郭にする。
  - PowerPoint: テキストボックスの段落を中央揃え(`algn="ctr"`)にし、`wrap="none"` にする(`lib/pptx/prims.ts` の中央揃えの文字と同じ)。行はこちらで折り返した位置で `a:br` を入れる。`wrap="square"` のままだと、PowerPoint のフォントが測った幅より少し広いとき、中央揃えの行をもう一度折り返して行が増え、下の欄に重なる。`wrap="none"` なら行は増えず、ボックスの中央を軸に左右へはみ出すだけ。
  - `lib/deck-layout.ts` の `TextBlock` に `align?: 'center'` を足す(書かなければ今の左揃え)。
- D7. **明るい・暗い**: 表紙も、ふつうのスライドと同じく白い地に描く(ADR 0056 D2。スライド自体は暗くしない)。図がないので、暗い図の背景の長方形(ADR 0055 D5)も出ない。デッキ全体の配色を選べるようにするときは、表紙もそれに従う(この ADR ではしない)。
- D8. **9pt の警告**: 表紙の文字はすべて決まった大きさで、いちばん小さい出典でも 13px(9.75pt)。縮めないので、9pt 未満の警告(ADR 0055 D4)は表紙には出ない(`planDeckSlide` は表紙で `scale: null` を返す)。
- D9. **JSON Schema と説明**: `deckSchema` に `layout`・`event`・`date`・`presenter` を足し、それぞれの `description` に表紙の欄であることを書く(MCP のプラグインの `render_deck` は `deckSchema` を写すので、そのまま入る)。スライドの `description` に表紙の書き方を足す。README の `serve` の節に表紙の 1 文を足す。
- D10. **`<img alt>` と名前**: `serve` の `slideText` に `event`・`date`・`presenter` を足し、見た目の順(`event`・`title`・`lead`・`date`・`presenter`・`source`)に並べる。PowerPoint のスライド名は今と同じく `title`。デッキの `title` がないとき表紙の題をファイルの題にすることは、この ADR ではしない。
- D11. 表紙を使わないデッキの出力は変えない。`align` を書かない `TextBlock` の `a:bodyPr`・`a:pPr` は今と同じ文字列にする。表紙のないデッキの .pptx と、ふつうのスライドの SVG が、変更の前とバイト単位で同じことを確かめる(nov27 のデッキ・リポジトリのテストのデッキで、変更前に作ったものと比べる)。
- D12. **テスト**: D2 の誤りをそれぞれ正確な場所で。表紙でないスライドの `event`・`date`・`presenter`。表紙とデッキ全体の `fit` は通ること。題の 56 / 48 / 40px の段階(決まった幅を返す仮の測り方で)。入らないときの誤り。中央揃え(.pptx の `algn="ctr"` と `wrap="none"`、SVG の行の x)。`deckTexts` の外で測られる文字がないこと。CLI で `.ts` の図を書いた表紙の誤り。

## 検討したほかの案

- **`subtitle` を新しく足す**: 表紙では副題と呼ぶほうが分かりやすいが、`lead` と意味が重なり、ふつうのスライドを表紙に変えるたびに欄の名前を書き換えることになる。`lead` のまま使い、Schema の説明に「表紙では副題」と書く。
- **`layout` を書かず、図・段・枠がないスライドを自動で表紙にする**: 見出しとリードだけのふつうのスライド(章の扉、まとめの 1 文)も表紙になってしまう。書き手が選ぶ。
- **デッキの最上位に `cover: {...}` を置く**: 表紙は 1 枚目とは限らない(章ごとの扉、2 部構成)。スライドの欄にしておけば、どこにでも置ける。章の扉は、将来 `layout: "section"` として足せる。
- **`date` を ISO 8601 にして整形する**: D3。ガントの図の `DATE`(`spec-kit.ts` の YYYY-MM-DD)は、日付で位置を計算するので ISO にしている。表紙の日付は計算に使わず、書かれたとおりに見せるだけなので、同じにしない。
- **`presenter` を配列にする**: 1 行に並べるか、行を分けるか、所属をどう書くかを決めることになる。初版は 1 つの文字列にし、長ければ折り返す。

## まだやらないこと

- 表紙のロゴ・背景画像・配色の選択。
- 章の扉(`layout: "section"`)。
- `serve` の発表者の画面での表紙の特別な扱い(今のスライドと同じに出る)。

## レビュー(Opus、2026-11-16)で直したこと

- ADR のレビュー: `deckTexts` で題を 3 つの大きさすべてで測る(`serve` は測っていない文字を誤りにせず、文字数 × 大きさで数える)、`deck-load` の仮の見出しが表紙の誤りを隠す、.pptx の中央揃えは `wrap="none"`、題の大きさはかたまり全体が入るかで決める、表紙の誤りの文を `roomMessage` の 1 か所に置く、行の送りと間を数で書く、を D2・D4〜D6・D10〜D12 に入れた。
- 実装のレビュー:
  - 切れ目のない長い語(URL など)の行が 1040px を超えても誤りにならず、スライドの外に出ていた → 誤りにした(D4)。
  - 表紙の `figure` に壊れたパスを書くと、パスの誤りが先に出ていた → 表紙の `figure` は読まない(D2)。
  - `<img alt>` が表紙かどうかを欄の有無で決めていた → `layout` で決める。
  - ふつうのスライドの .pptx の XML が変更前(960d16b8)とバイト単位で同じことを、ハッシュでテストに残した。

## 確かめたこと

- nov27 のデッキ(30 枚)の写しで 1 枚目を表紙にして、`pptx-deck` が 30 枚・警告なしで書ける。`serve` を空いたポートで立ち上げ、1 枚目の SVG を取り出して PNG にして見た(上の表のとおり中央にそろう)。.pptx の 1 枚目も `test/helpers/pptx/preview.ts` で見て、同じ配置だった。
- 表紙のないデッキ(nov27 の元のデッキ 30 枚、nov18 のデッキ 37 枚、段組みを含む)で、.pptx と `serve` の各スライドの SVG が変更前とバイト単位で同じ。
- テストは `test/deck-cover.test.ts`。
- 確かめていないこと: PowerPoint 実機での見た目(この機械にはない)。MCP のプラグインのビューアでの見た目(プラグインのリポジトリ)。
