# ADR 0028: 避けられない交差の見せ方(戻り矢印が他の線を横切る箇所の「飛び越し線」または「ギャップ」。`hop` の任意指定)

- 状態: 提案(未実装)。Opus 3 回目のレビュー(収束)まで反映した版
- 日付: 2026-10-16
- 基点: `main`(925eb17、PR #232 まで)。ADR 0019 D4 のトリガー拡張(`feat/cause-search-trigger`、96b8991)の**上に積む**(積み重ね PR。背景の数は 96b8991 の上のもの)
- 関連: ADR 0016(経路 `layered-route.ts`、点数 (交差, 折れ)、D11〜D13 の AND の並走)、ADR 0019(D4 交差の再探索)、ADR 0015(`cause-crossing` / `cause-parallel`)、ADR 0027(PPTX 書き出し。PR #245、未マージ)
- 範囲外: 曲線どうしの交差、`connect()` の線、`states` / `classes` / `bpmn`(同じ `layoutLayered` を使うが触らない)、外の車線の選び方(別 ADR)、AND の弧そのもの、戻り矢印が AND の弧を貫く不具合(未解決の項目)

## 背景

因果ツリー系(`causeTree` / `pdpc` / `relationDiagram`)の交差を減らす作業を続けてきた。ADR 0019 D4 の再探索とそのトリガーの拡張で、`medius-research` の因果図の交差は 48 から 31 に減った。残りを調べた(スパイクとレビューでの実測):

| 残った交差の型 | 並びの探索で直るか |
|---|---|
| 外の車線の戻り矢印(`returns: 'outer'`、`back: true`)が図を横切る | 直らない(車線の選び方で減るが、0 にはならない)。**大きい FRT 4 本の残り 19 組のうち 12〜15 組**(数え方で差が出る。判定と図の一覧は実装 PR に載せる) |
| 層固定での並びの最適化不足 | 直る(約 5 組) |
| 同じ節に入る矢印の口の並び | 経路の側 |
| グラフ上、避けられない | 直らない |

**減らせない交差は残る。** 交差を無くすのではなく、**交差点で「つながっている」と「すれ違っている」を取り違えないように見せる**。

## 実測(設計の前提。Opus レビューの再現スクリプトによる)

戻りの線(`back` または `outer`)が他の線を横切る箇所を、**画面上の向き**で分けた:

| 図 | dir | 戻りが水平 | 戻りが垂直 |
|---|---|---|---|
| toc/t3-frt | right | 0 | **9** |
| poc/p3-frt | right | 1 | 2 |
| story/f2b-frt | up | 3 | 0 |
| story/f2a-crt, story/f5-crt-medius | up | 各 1 | 各 1 |
| (`back: true` の合計) | | 6 | 13 |

因果ツリーは常に `'right'` の軸でレイアウトを作り、上下の図は転置するだけ(`toc.ts` の `layeredAttempt(..., {dir: 'right'}, {transpose})`)。外の車線の戻りは「尾の層の手前の隙間で曲がり、頭の層の後ろの隙間で曲がる」(`layered-route.ts` の `outerTurns`)ので、経路は

- **層を横切る区間**(層の隙間を、層の向きと直交して走る長い区間。他の線と交わるのはほぼここ)
- **車線の区間**(図の外の車線を、層の向きに沿って走る。他の線とはほぼ交わらない)

でできている。層を横切る区間は、`dir: 'up' | 'down'` の図で画面の**水平**、`'right' | 'left'` の図で画面の**垂直**になる。**画面の向きで規則を書くと、半分の図で効かない**。規則は**レイアウトの軸**で書く。

## 決めること

### D1. 範囲: レイアウト上の戻り矢印(**`LayeredEdgeOut.reversed` の 1 つの基準**。`back: true`、`outer` の車線、宣言の無いインラインの戻りを含む)の、**層を横切る区間**が、他の線を横切る箇所
- 基準が `reversed` 1 つで足りる理由: `back` は必ず `reversed` になり(`graph-layout.ts` の `breakCycles` は、宣言を先に反転し、循環を閉じない `back` は throw する)、`outer` も反転した辺だけに付く。`reversed` を `LaidOutCause.edges` に通す(今の `toc.ts` の `out.edges.push` は捨てている)。
- 宣言の無い戻りは、DFS が恣意的に選んだ辺のことがある(`toc-rules.ts` の「意味上の戻りと違うことがある」)。その辺が上になる(飛び越す側になる)のは許容する。
- 対象外: `kind: 'blocks'`(切る矢印。端がバーで、見せ方の意味が違う)、AND へ入る矢印どうし(`cause-crossing` / `cause-parallel` の領分。並びで直す)。
- 戻りの線が AND のある効果へ入ることはある(f2b の `e5→e1`)。見せ方は `points` を変えないので、`andClashes` の数は変わらない(D5)。
- 戻りどうしの交差は、必ず「層を横切る区間 × 車線の区間」になる(層を横切る区間どうしは平行で、直角に交わらない。車線の区間どうしも同じ)。**層を横切る区間の側が飛び越し、車線の区間の側は素通し**にする。
- **範囲外(数だけ書く)**: 戻りの**車線の区間**が戻りでない線を横切る交差(実測 5: b4-pdpc に 4、p3-frt に 1)。(A) なら図の外側へ膨らむことになり、(B) なら相手を切ることになる。U1 の目視で、必要なら対象に足すかを決める。
- 一般の線どうしの交差への広げ方は、本 ADR では決めない(未解決の項目)。

### D2. 見せ方は 2 通りを U1 で比べて決める。1 つの図の中で混ぜない
**(A) 飛び越し弧**: 戻りの線が、交点で、**層の流れに逆らう側**へ小さく膨らむ(レイアウトの軸で決める。画面では up の図は下、down は上、right は左、left は右)。
- 理由: 尾の側の曲がり(尾の層の手前)では、流れの側に、尾の層へ入る矢印の矢じりが並ぶ(実測 6〜16px)。頭の側の曲がり(頭の層の後ろ)では、逆らう側に同じ隙間の別の矢印のレーンが並ぶ(14px)が、R ≤ 7.5 なら収まる。4 方向の転置・鏡映で数値が一致することは、実測で確かめた(right と left、up と down)。
- 作り方: **Q(2 次ベジェ)の制御点を高さ 2R に置く**(頂点の高さが R になる。半円ではない)。弧の点は **`points` に入れない**(`andClashes`・`runsTogether`・`crossingsOf`・svg-lint の幾何・`--html` が違う線を見る)。`arrowPath` に省略可能な引数を足し、**文字列の上でだけ** `L … Q … L` を挟む。他の呼び出し(`renderCloud` など)は引数を渡さず、byte 同一を保つ。
- R は値ではなく制約で書く: **6〜7.5 の範囲で U1 の目視で決める**。上限は D3 の (h) から導く: 隣の平行な線までの間隔(`LANE = 14`)に、`R + 戻りの線幅/2 + 隣の平行な線の線幅/2 + 余白 ≤ 14`。1280px 幅に映すと R = 5 は 3.3px で見えない可能性が高い。
- 破線・点線の戻り(`back: true` かつ `line: 'dashed'` は書ける)は、弧の上で `stroke-dasharray` が切れて弧が隙間に見えることがある。(A) では、破線・点線の戻りは飛び越さない。

**(B) ギャップ**: 下になる線(戻りでない側)を、交点の前後 G で `M` で切る(背景色の縁取りではなく、**パスを切る**)。
- 向きの規則が要らず、AND の弧と間違えようがなく、背景色やテーマに依存せず、resvg・PPTX の `custGeom`(moveTo)でそのまま表せる。
- **G**: 片側 `戻りの線幅/2 + 3`。`back: true` は幅 3 で 4.5、`back` の無い戻り(`outer` やインライン)は幅 2 で 4。
- 切った線の `points` は変えない(描くときだけ切る)。
- **破線・点線の相手**(`blocks` は既定で破線)との交差は、(B) では無印のまま(ギャップが見えない)。矢じりの近くでは切らない(D3 の (c))。
- 欠点: 戻り以外の線(AND の矢印を含む)を切る。(f) が効かないと、AND の弧と矢じりの間で AND の矢印を切り、弧から矢印が離れて見える。

U1 で、`toc/t3-frt.ts`(right)と `story/f2b-frt.ts`(up)を両方式で並べて目視し、**1 方式に決めて** ADR に書き戻す。事前の見立ては、AND の弧が密な因果ツリーでは (B) が有利。

### D3. 見せ方を付けない場合(従来どおり、線を素通しにする)。距離は 1 つの表で決める
交点から、次のどれかまでの距離が X 未満なら、付けない。**X は方式の大きさで書く**: (A) は `X = R + 2`、(B) は `X = G + 2`(同じ区間の別の交点 (e) は、それぞれ `2R + 2` / `2G + 2`)。**(A)/(B) の列は、どちらの方式に効くか**:

| 行 | 条件 | (A) | (B) |
|---|---|---|---|
| (a) | 自分(戻り)の線の折れ・端 | ○ | ○ |
| (b) | 相手の線の折れ・端 | ○ | ○ |
| (c) | 相手の矢じりの**根元**(先端 − `L`。`L = 12` は `arrowPath` の局所定数なので export する) | ○ | ○ |
| (d) | `blocks` のバーの矩形(半幅 10。点の距離では捉えられない) | ○ | ○ |
| (e) | 同じ区間の別の交点(`2X` 未満) | ○ | ○ |
| (f) | AND の弧の外接矩形(弦の外接矩形から X) | ○ | ○ |
| (g) | 弧の膨らみが、帯の外、または他の箱・ラベルに掛かる | ○ | — |
| (h) | 膨らむ側で、交点 ±(R + 2) の窓の中にある、**平行な他の線・矢じり・AND の弧**までの横の距離が `R + 戻りの線幅/2 + その線の線幅/2 + 2` 未満 | ○ | — |

- (h) は、交わる相手ではなく、膨らむ側に平行に走る第 3 の線を見る(実測: `toc/t3-frt` の x=731 では、逆らう側 14px に隣のレーン `e2→e7` がある)。D2 の R の上限は、この (h) から導く。
- (a) の X = R + 2 では、膨らみの端が曲がり角から数 px になる(t3 の `X(731,147)` は戻り自身の折れから 11px)。U1 の目視の確認項目にし、必要なら (a) だけ `R + 4` にする。

### D4. AND の弧との区別(事実を直す)
AND の弧(`toc.ts` の `AND_END = 21`、`AND_PEAK = 15`)の膨らみは**約 6px**で、(A) の R(6〜7.5)と**ほぼ同じ**。違うのは**弦の長さ**(AND の弧は `PORT = 22` + 両側の `AND_REACH` で約 40px 以上。(A) は 2R で 12〜15px)と、矢じりからの距離。`right` の図では AND の弧も縦に立つ(t3-frt の `d2` の弧は縦)ので、見間違いの余地は向きでは減らない。
- 区別は弦の長さと位置(D3-f で、AND の弧の近くでは飛び越さない)。色や破線では分けない(`dim` のときも成り立たせる)。
- **(B) ギャップなら、曲線を足さないので、この問題が原理的に起きない**。これが (B) 有利の主な理由。

### D5. 検査: 変えない。`cause-hop` の info は作らない。判定はレイアウトで作るデータ
- 事実: `edge-crossings`(`rules.ts:664`)は `connect()` の線だけを数える。因果ツリーの交差の検査は、AND のある効果へ入る矢印どうしの `cause-crossing` / `cause-parallel`(`cause-clash.ts`)だけ。戻り矢印が他を横切っても、今は警告も info も出ない。また図の検査の出力 `VerifyOut`(`verify-handlers.ts`)は `{problems, warnings}` だけで、info の口が無い。
- 飛び越し・ギャップは `points` を変えないので、`cause-crossing` / `cause-parallel` の数は変わらない。
- `cause-hop` の info は**作らない**(図の弧そのものが知らせる)。作る価値があるのは次の 2 つで、U2 で再判断する: (a) `hop` を付けた図で、**D3 のせいで飛び越さなかった戻りの交差**の数(読み手が取り違える箇所。手を打てる)、(b) `hop` を書かない図で、戻りの交差があるとき「`hop: true` で見せ方を付けられる」と知らせる(既定 off の見つけやすさ)。
- **判定は描画前、レイアウトで決めてデータにする**。AND の弧と同じ(`toc.ts` が `out.ands` の幾何を決め、`renderCause` は描くだけ)。`toc.ts` が AND の弧を作った後で、**方式に依らない形**の `LaidOutCause.crossings?: {over: number, under: number, x, y, side}[]`(`ands` と同じく帯に 1 つの列。`over` は戻りの辺、`under` は相手の辺の添字)を作る。`renderCause` は、(A) なら `over` の線に弧を挟み、(B) なら `under` の線を切る。将来の検査・PPTX も同じデータを読む。**D3 で見せ方を付けなかった交差も、理由つきで `crossings` に残す**(`skipped?: 'corner' | 'arrowhead' | 'bar' | 'neighbour' | 'and-arc' | 'band' | 'dashed' | …`)ので、D5 の (a)「付けなかった交差の数」は新しい判定なしで数えられる。D3 の判定が AND の弧の定数と矢じりの長さを要るので、**点だけの層の `polyline-metrics.ts` には置かない**(描画の定数が漏れる)。
- `polyline-metrics.ts` に足すのは `crossingPoints(paths, opts)` だけ。`crossingsOf` をその個数として書き直し、交差の定義(`margin` / `tol`)を 1 つにする(今は `cause-clash.ts` の `cross` が別の定義を持つ)。**`crossingsOf` は `scoreOf` を通して経路の候補選びと ADR 0019 D4 の探索の点数に入る**ので、1 つでも数が変わると配置が変わり golden が動く。U0 で、既存の 3 つの呼び出し(`layered-route` の既定、`rules.ts` の `{margin: 2, tol: 0.5}`、`cause-clash`)の数が**書き直しの前後で同じ**であることをテストで固定し、`pnpm golden` の差分ゼロを確かめる。

### D6. PPTX 書き出し(ADR 0027)
- PoC では因果ツリーは**画像**として入る(`lib/pptx/bands.ts` の `cause: 'image'`)ので、今は影響なし。
- 将来ネイティブに変換するとき: DrawingML の `custGeom` は `arcTo` も `quadBezTo` も `moveTo` も持つ。弧を持つ線も、ギャップで分けた線も、コネクタ(`cxnSp`)ではなく自由形になり、箱との結び付きを失う。これは両方式で同じ。0027 のマージ後に扱いを決める。本 ADR の実装 PR は 0027 に触らない。
- Q を選ぶ理由は PPTX ではなく、「既存の `arrowPath` の M/L 列に挟める」「`svg-geom.ts` と `svg-to-css.ts` が Q を扱える」こと。

### D7. 指定のしかた: `hop: true`(`CauseOpts`)。**既定は off**
- `causeBand` は `causeTree` / `pdpc` / `relationDiagram` が `CauseOpts` を共有する(`lib/dsl/diagrams.ts`)。**3 つとも `hop` を受け付ける**(戻りが出るのは pdpc・relationDiagram の側が多く、D1 が `outer` と `reversed` を含めるため)。
- 書かない図の SVG はバイトで同一(`pnpm golden` の差分ゼロ)。`hop: false` と書かないのは同じ。`hop: false` / 書かないとき、`LaidOutCause` に `crossings` のキーを、`edges` に `reversed` のキーを**付けない**(レイアウトの JSON を比べるテストが落ちないように)。
- `diagram({hop: true})`(図全体の既定)は入れない。

## 作らないもの
- 全図種・一般の線どうしの交差への飛び越し(D1)。
- 飛び越しを探索の点数に入れること(飛び越せるから交差を許す、にはしない)。
- 線の色・太さでの上下の区別、橋の影、背景色の縁取り。

## 未解決の項目
- 戻り以外(一般の直交線)への広げ方。広げるなら「どちらが上か」の規則が要る。
- **戻り矢印が AND の弧を貫く**既存の不具合(t3-frt では、戻りの縦区間 `x=1257` が `d2` の AND の弧の中を通る)。今の検査は捕まえない(「AND の弧が別の矢印を覆う」判定は、同じ効果へ入る矢印だけを見る)。検査(警告)か、経路の側で避けるかを、別 ADR で決める。
- 膨らむ向き「流れに逆らう側」は、4 方向の転置・鏡映で不変であることを実測で確認済み(余白は最小 14px)。残りは U1 の目視だけ。
- 戻りの**車線の区間**が戻りでない線を横切る交差(5)の扱い(D1。範囲外の数のみ)。
- 背景の「12〜15 組」の数え方(戻りの判定、margin)は、実装 PR に図の一覧とあわせて載せる。
