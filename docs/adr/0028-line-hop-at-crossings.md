# ADR 0028: 避けられない交差の「飛び越し線」(因果ツリー系の戻り矢印から。`hop` の任意指定)

- 状態: 提案(未実装)
- 日付: 2026-10-15
- 基点: `main`(925eb17、PR #232 まで)。ADR 0019 D4 のトリガー拡張(`feat/cause-search-trigger`、96b8991)の後を前提にする
- 関連: ADR 0016(経路 `layered-route.ts`、点数 (交差, 折れ)、D11〜D13 の AND の並走)、ADR 0019(D4 交差の再探索)、ADR 0015(`cause-crossing` / `cause-parallel`)、ADR 0027(PPTX 書き出し。PR #245、未マージ)
- 範囲外: 曲線(ベジェ)の線どうしの交差、`connect()` の線、`states` / `classes` / `bpmn`(同じ `layoutLayered` を使うが、本 ADR では触らない)、外の車線の選び方(別 ADR)、AND の弧そのもの

## 背景

因果ツリー系(`causeTree` / `pdpc` / `relationDiagram`)の交差を減らす作業を続けてきた。ADR 0019 D4 の再探索、そのトリガーの拡張で、`medius-research` の実在の 33 本は、交差が 48 から 31 に減った。残りを調べた(スパイク。ADR には結果だけ書く):

| 残った交差の組(大きい FRT 4 本、19 組) | 組 | 並びの探索で直るか |
|---|---|---|
| 外の車線の戻り矢印(`returns: 'outer'`、`back: true`)が図を横切る | 12 | 直らない(車線の選び方で減るが、0 にはならない) |
| 層固定での並びの最適化不足 | 約 5 | 直る |
| 同じ節に入る矢印の口の並び | 1 | 経路の側 |
| グラフ上、避けられない | 1 | 直らない |

**減らせない交差は残る。** そこで、交差を無くすのではなく、**交差している線のどちらが上かを見た目で示す**(飛び越し線。 line hop / bridge)。読み手が、交差点で「つながっている」と「すれ違っている」を取り違えないようにする。

## 決めること

### D1. 範囲: 因果ツリー系の矢印のうち、**戻り矢印(`back: true`、太線)が他の線を横切る箇所**だけ
- 戻り矢印は 1 本だけ太く(`renderCause` の `e.back` は幅 3)、役割がはっきりしている。「戻りの線が他を飛び越える」は、どちらが飛び越えるかの規則が要らない。
- 上の表の 12/19 がこの型。残りの型は、まず並び・経路で減らす。
- **一般の線どうしの交差への広げ方は、本 ADR では決めない**(未解決の項目に置く)。

### D2. 描き方: 戻り矢印の**水平な区間**が、他の線の**垂直な区間**を横切るとき、交点に半径 R の半円の弧を付ける
- 向き: 経路は直交なので(`elbows`、`simplify`)、横切りは「水平 × 垂直」だけ。**戻りの線が水平なら、戻りが弧で飛び越す**(上へ膨らむ)。戻りの線が垂直で、他が水平なら、飛び越さない(D3-1)。他の線の側には、弧を付けない(飛び越すのは戻りの線だけ)。
- 弧は SVG の `A`(円弧)ではなく、`arrowPath` と同じ `M … L …` の列に `Q`(2 次ベジェ)を挟んで作る。理由は D6(PPTX)。
- 半径 R は 5px、飛び越しの両端は交点の左右に R ずつ。交点の左右 R 以内に、別の折れ・飛び越し・矢じりがあるときは、飛び越さない(D3 の理由)。

### D3. 飛び越さない場合(従来どおり、線を素通しにする)
1. 戻りの線が**垂直**で、他が水平のとき。飛び越しを横に膨らませると、隣の線と近づきすぎる。**交差は残り、警告も残る**。
2. 交点が、どちらかの線の折れ・端・矢じりから R + 2 以内にあるとき(弧が曲がり角にかかる)。
3. 同じ区間に 2 つの交点が 2R + 2 より近いとき(弧どうしが重なる)。
4. AND の弧の上、またはその R + 2 以内(**AND の弧と見間違えるため**。D4)。

### D4. AND の弧との区別
AND の弧(`renderCause` の `Q` のパス、幅 2)は、矢じりの手前で、**同じ効果へ入る複数の矢印を渡す弧**で、向きは矢じりの上(膨らみが大きい)。飛び越しの弧は、**線そのものの途中**で、**小さく(R = 5)、線と同じ太さ**。
- 見分けは位置と大きさ。色や破線では分けない(`dim` のときも成り立たせる)。
- 実装時に、実在の図(`toc/t3-frt.ts` と `toc/v1/t3b-nbr.ts`)で目で確かめる。見間違える図があれば、D3-4 の距離を広げる。

### D5. 検査: 因果ツリーには、戻り矢印の交差を数える検査が**今は無い**。飛び越しは検査の数を変えない
- 事実: `edge-crossings`(`rules.ts:664`)は `connect()` の線だけを数える。因果ツリーが出す交差の検査は、AND へ入る矢印どうしの `cause-crossing` / `cause-parallel` だけ(`verify-handlers.ts`、`cause-clash.ts`)。戻り矢印が他の線を横切っても、今は警告も info も出ない。
- よって D5 は、**検査を変えない**。`cause-crossing` / `cause-parallel` は、飛び越しの有無に関わらず同じ数を出す(AND へ入る矢印には飛び越しを付けない。戻りは AND に入らない)。
- 飛び越した箇所の数を知らせるため、**info を 1 つだけ足す**(`cause-hop`、`hop: true` の図だけ。「戻りの線が他を N 箇所飛び越している。避けられない交差が残っている」)。数が 0 なら出さない。
- 飛び越しの判定は、描画前の純関数 `hopPoints(edges)` として `lib/polyline-metrics.ts` に置き、`renderCause` と `cause-hop` が同じ関数を呼ぶ(描画層が検査を読まず、検査が描画層を読まない、という `polyline-metrics.ts` の方針のまま)。

### D6. PPTX 書き出し(ADR 0027)
- 弧は `Q` のパスなので、`svgBlip` フォールバック(図を画像として入れる)ではそのまま出る。**ネイティブの線への変換は、本 ADR では扱わない**(ADR 0027 側で、弧のあるパスの扱いを決める)。
- この ADR の実装 PR は、ADR 0027(未マージ)に触らない。0027 のマージ後に、D2 の `Q` の列が変換でそのまま扱えるか確かめ、扱えなければ 0027 に書き戻す。

### D7. 指定のしかた: `causeTree(..., {hop: true})`。**既定は off**
- 書かない図の SVG は、バイトで同一(`pnpm golden` の差分ゼロ)。
- `hop: true` で、D1〜D3 の飛び越しが入る。`hop: false` と書かないのと同じ。
- `diagram({hop: true})`(図全体の既定)は、本 ADR では入れない。

## 作らないもの
- 全図種の交差への飛び越し(D1)。
- 飛び越しを探索の点数に入れること。探索は交差の数を減らす方向のまま。飛び越せるから交差を許す、にはしない。
- 線の色・太さでの上下の区別、橋の影。

## 未解決の項目
- 戻り矢印以外(一般の直交線)への広げ方。広げるなら「どちらが上か」の規則が要る(経路の長い方、先に描いた方、など)。
- 戻りが**垂直**で他が水平のとき(D3-1)に、飛び越せないことが多すぎないか。実在の図で数える(U1)。
- `cause-hop` の info が要るか(数を知らせる価値が、図に出る弧の数より大きいか)。
- 弧の R = 5 が、14px の本文の図で目に見える大きさか(U1 で目視)。
