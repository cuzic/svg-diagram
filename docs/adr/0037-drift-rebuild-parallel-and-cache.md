# ADR 0037: `check --drift --rebuild` — 並列と成功のキャッシュ、`diff --text`

- 状態: 実装済み
- 日付: 2026-10-20
- 関連: ADR 0031(FCIS。純粋な核は `lib/drift-cache.ts`、読み書きは根の `drift-cache-io.ts` / `drift-pool.ts`)、ADR 0023 D13(`--rebuild` は SVG が作られたときと同じ前提で作り直す)

## 背景

書籍シリーズ(約 1,500 枚)の利用者から、`check --drift` が 100〜190 枚で 55〜74 秒(負荷の高い環境で直列)かかるという報告。もう 1 つ、手書き SVG を DSL に直すとき、旧の文字や数値が落ちていないかを確かめる道具が欲しい、という要望。

## 計測

`--drift` だけ(`--rebuild` なし)は、ソースと import 先のハッシュを SVG の `<metadata>` と比べるだけで、examples 169 枚で約 1 秒。遅いのは `--rebuild`(全部を作り直す)。

`--cpu-prof` で examples 169 枚を直列に回した結果(自己時間の割合、合計約 59 秒のうち):

| どこ | 約 |
|---|---|
| `layered-route.ts` + `polyline-metrics.ts` + `route-search.ts` + `toc.ts`(経路探索) | 28% |
| `graph-layout.ts`(配置) | 9% |
| `node:internal`(読み込み・TS の型除去・fs) | 16% |
| `font-metrics.ts` + wasm(harfbuzz) | 10% |
| `dsl/io.ts`(書き出し・XML 検査) | 4% |
| 残り | 小さい関数の集まり |

1 つの関数が支配していないので、手を入れて速くする場所は無い(WASM 化を見送った判断と同じ)。**同じ入力で同じ仕事を繰り返さない**(キャッシュ)ことと、**8 コアを使う**(並列)ことで減らす。

## 決定

### D1: 並列は子プロセス

`check-diagram.ts` 自身を `--worker` で起動し、標準入力に 1 行 1 ソースを渡して、1 行の JSON で答えを受け取る(`drift-pool.ts`)。空いた子から次を渡す(図ごとに時間が違うので、先に等分しない)。親は答えをソースごとに受け取り、**引数の順に**再生する。出力と終了コードは、直列と同じ。子が途中で死んだら、その 1 枚だけ親が直列でやり直す。数は `--jobs N`(既定: CPU 数、最大 8、`1` で直列)。`process.execArgv` を引き継ぐので `--import` で渡す設定(golden のスクリプトなど)も効く。

### D2: キャッシュは「成功」だけ

保存するのは「再生成がコミット済みの SVG と 1 バイトも違わなかった」という結果だけ。失敗は保存しない(直したら次は必ず確かめる)。誤って「ズレなし」と言わないことを、速さより優先する。

**鍵**(`lib/drift-cache.ts` の `driftKey`、全部が入る): ツール自身のコード(`lib/` 全体と根の CLI ファイル)、`package.json` の版と依存パッケージの版、Node の版、`fc-list` のフォント一覧と `FONTCONFIG*` / `SVG_DIAGRAM_*` 環境変数、解決した設定(`.svg-diagram.json` の中身と `--today`)、ソースの絶対パスと内容、import 先の内容のハッシュ、コミット済みの SVG と reveal ファイルの内容、`<metadata>` の中身。

**ビルドが読んだファイル**: 鍵に入れられないもの(絵、アイコンの定義、フォントの実体)は、ビルド中の `fs.readFileSync` / `fs.existsSync` を記録し(`recordReads`)、内容のハッシュと「あるか」を一緒に保存する。使うときは全部を確かめ、1 つでも違えば使わない(ccache の depfile と同じ考え方)。プロセス内で 1 度しか読まれないもの(フォント)を取りこぼさないよう、記録はプロセス内で足し合わせる。余計に無効になることはあっても、誤って有効になることはない。

**キャッシュしないもの**: 変数で組んだ `import()`(import 先が分からない)、Chromium 計測(ブラウザの版が鍵に入らない)。`--no-cache` で全部やめる。

置き場所は `./.svg-diagram-cache/`(`--cache-dir`)。ソースごとに 1 ファイル(上書き)で、増え続けない。中に `.gitignore`(`*`)を置く。

### D3: 親が先に当たりを調べる

親は子を起こす前に、キャッシュが効くソースを除く。残りが 1 枚以下なら、子を起こさず直列で処理する(子の起動に約 2 秒かかるため)。

### D4: `diff --text`(別の要望)

`svg-diagram diff --text old.svg new.svg [--no-added] [--strict]`。旧の `<text>` 1 つずつについて、新の全文字(空白・句読点・全角半角・大文字小文字・桁区切りを無視。`check --covers` と同じ正規化)に含まれるかを見て、含まれなければ欠けた語・数値を挙げる(`lib/text-coverage.ts`、純粋)。折り返しは、`x` / `y` / `dy` を持つ `<tspan>` を改行として扱い、文字の見た目を変えるだけの `<tspan>` はつなぐ。新旧を入れ替えて「新にだけある文字」も出す(`--no-added` / `--missing-text` で省く)。`--strict` で、旧の文字が欠けたとき終了コード 1。

**限界**: ひらがなだけの語は、助詞と区別できないため語として数えない(`check --covers` と同じ)。1 つのラベルが丸ごとひらがなだけなら、正規化した文字列の完全一致で見る。`<title>` / `<desc>` / 属性の文字は対象外。
