# ADR 0005: 資料づくり(2 巡目)で見つかったツール側の改善要望

- 状態: 実装済み(#8 はツールを変えず、README に注意書き。下の「実装」を参照)
- 日付: 2026-10-11
- 基点: `main`(ADR 0004 の #1〜#8 の実装後。PR #38 まで)
- 関連: ADR 0004

## 背景

ADR 0004 の実装を取り込み、HTML で作っていた図(ハードル差・階段・76%と31%・許可待ち・顧問 3 段階・号令から半年)を svg-diagram に置き換えた。実際に作って画面で確かめたところ、次の 8 件が残った。**すべて講演資料のスクリーンショットで確認した事実**で、推測は含まない。

| # | 要望 | 要約 | 見つけた場所 |
|---|---|---|---|
| 1 | spotlight で薄くした棒が「空の点線枠」になる | 値の大きさを薄い塗りで残せない | 許可待ち(両脇の棒)、夕食の比喩(下 2 本) |
| 2 | bars の棒の色を個別に選べない | `series` は a(青)/b(黒褐色)/c(灰褐色)だけ。「高い=問題」を赤で出せない | ハードル差(左の棒を灰褐色 c で代用) |
| 3 | 絵文字は 18 個だけで、食べ物がない | `icon.emoji()` に無い絵文字は、文字列に直接書けば描けるが検証が無い | 夕食の比喩(🧊🥗📦🥕🌾) |
| 4 | `preview --engine chromium` が 120 秒以上返らない | 絵文字を含む図を確認する手段が事実上無い | 同上(強制終了した) |
| 5 | plane の滑らかな曲線を、途中まで描けない | 区間ごとに `reveal` を分けると折れ線に見える | 号令から半年 |
| 6 | plane の点ラベルが線と重なると、手で逃がすしかない | 4 方向の指定だけ。3 ヶ月目→半年後で、重なりが 3×1px まで出て検査が失敗 | 号令から半年 |
| 7 | 箱のタイトルが 1 文字だけ次の行に落ちる | 「書いて出す」の「す」だけが折り返された | 来週やること(月曜の箱) |
| 8 | banner の見出しが 25 字前後で 4px はみ出す | `padY: 0` でも検査の助言に出る。折り返しもしない | 顧問 3 段階の帯 |

## 要望

1. **spotlight で薄くした棒に、薄い塗りを残す**。今は塗りがなくなり、点線の枠だけになる。`spotlight: {dim: 'fill'}` のように、塗りを muted の薄色にして値の長さを読めるようにしたい。
2. **bars の棒ごとに `tone`**。`BarDatum.tone?: 'accent' | 'danger' | 'muted'` を足す。`series` は残す。
3. **絵文字**。(a) 食べ物・道具・人の表情を数十個足す。(b) あるいは、文字列中の任意の絵文字を許し、フォントに無い場合だけ警告にする。
4. **chromium エンジンのプレビュー**が返らない原因を調べる。タイムアウトと、エラー文を付ける。
5. **plane の path に、途中までの描画**。`revealUpTo` のように、1 本の滑らかな曲線を、通る点の順に伸ばせるようにする。
6. **plane の点ラベル**を、線と重なるときに自動で逃がす。または `labelOffset: [dx, dy]`。
7. **日本語の折り返しで、最終行を 1 文字にしない**(行頭禁則に加え、孤立 1 文字の回避)。
8. **banner** の見出しの幅の計測を、box と同じ内側余白にそろえる。

## 優先度

講演で効くのは #1 と #5(許可待ち層と曲線は、核心の図)。#4 は絵文字を使う図の確認ができないので、早めに欲しい。#7 と #8 は検査・見た目の細部。

## 実装

| # | 内容 |
|---|---|
| 1 | `diagram({spotlight: {ids, dim: 'fill'}})`。薄くした棒は border 色の塗りになり、値ラベル(muted)は塗りの上で検査する。既定(`'outline'`)は従来の点線の枠のまま。`examples/spotlight-dim-fill.ts` |
| 2 | `BarDatum.tone: 'accent' \| 'danger' \| 'muted'`。`series` との併用、tone の綴り違いは throw |
| 3 | `icon.emoji()` に食べ物(🍚🌾🍙🍱🍜🍞🥗🥕🍎🥩🐟🥚🥛🍳🧊📦)、道具・場所・物、表情・人を 36 個足した。フォントの有無と EMOJI_RE は `test/icons.test.ts` が全部見る |
| 4 | 原因は遅さではなく、`preview` / `contact` が Chromium を閉じずに終わり、プロセスが残ったこと(`wrote …` の後に止まる)。`finally` で閉じる。ブラウザ側の `img.decode()` にも 30 秒の上限と、原因を示すエラー文を付けた(実測: 絵文字入りの図で 90 秒超 → 3.4 秒) |
| 5 | `PlanePath.grow: true`。段階ごとに、出ている点までの曲線を同じ形のまま描く(最後の点が出たときだけ矢じりが付く)。`examples/plane-grow.ts` |
| 6 | 点ラベルは `labelAt` を書かなければ、右に置いて衝突するとき左・上・下・斜め 4 方向の空いた所へ自動で移る。`labelAt` で側を書けばそのまま、`labelOffset: [dx, dy]` でずらす(自動では動かさない)。`labelAt: 'auto'` も書ける |
| 7 | 折り返しの最後の行が 1 文字だけのとき、上の行の最後の 1 文字を一緒に下ろす。作者の改行の直後の行、禁則(行頭禁則の文字・行末禁則の括弧)に触れる場合、1 行に収まらない場合は動かさない |
| 8 | 再現できた(deck 側のソースで)。原因は幅ではなく縦: rect は 4px の格子に丸めて描くが、文字の baseline は丸めない。`padY: 0` の 16px の見出しは、字面の上端が baseline の約 18.6px 上まで出るので、rect が下へ丸められた位置(この図は y=362 → 364)では lint の「枠の内側 4px」を割り、4px はみ出す。図の y が 4 の倍数なら出ない。`padY` を 9 以上にすれば通る(deck 側は 6 に直して通った)。**ツールは変えず、README に書いた**。文字も rect と同じ丸めで置く案は、ほぼ全図の SVG が最大 2px 動くため見送り |

## 追記: #8 の「文字も 4px の格子に丸める案」の再検討(実測)

日付: 2026-10-12。本文の「ほぼ全図の SVG が最大 2px 動く」を、`examples/out` の全 28 図(段階ファイルを除く)で測り直した。

**差**(文字の `y` を 4 の倍数に丸めた場合):

| 項目 | 実測 |
|---|---|
| 動く図 | 28 / 28(全部) |
| 動く文字 | 539 / 635(85%) |
| 最大の移動 | 2.0px(186 文字)。1.0px が 214 文字、残りは 0.2〜1.8px |

**padY / 4px の検査を解消するか**: しない。rect の上端は `round4(y)`、文字の baseline は `y + c`(`c` は `padY` と字の高さで決まる定数)。今は上端から baseline までが `c + (y - round4(y))` で、位置によって `c-2`〜`c+2` と 4px 振れる。baseline も丸めると `round4(y+c) - round4(y)` になり、振れは「4 の倍数への切り捨て」に変わるだけで、最悪値は `4*floor(c/4)`。`c` を 16〜28 で 0.5 刻みに全位置(0.25px 刻み)で数えると、最悪値が今より良くなるのが 13 通り、悪くなるのが 9 通り、同じが 3 通り。つまり、`c mod 4` が 2 未満のときだけ得で、それ以外は悪化する。`padY` を足す対処(README)は、どちらでも要る。

**結論**: 全図の SVG が動くのに、検査の問題は解けない。オプションでも入れない(見送りのまま)。直すなら文字ではなく、検査側(「枠の内側 4px」を、丸め後の rect との差で見る)を検討する。
