# ADR 0040: `emblem()` — 図形の中に文字を入れる部品。あわせて badge の中央合わせを直す

- 状態: 実装済み(未マージ。Opus レビュー前)
- 日付: 2026-10-21
- 基点: `main`(PR #315 まで)
- 関連: ADR 0031(FCIS。新しい lib は純粋な層に置く)、ADR 0012(`scope`)
- 範囲外: 星形・吹き出し・パスで渡す自由な図形、`box({shape})`(既存の `box` に形を足す案)、ワイヤーフレームの `mid()`(0.36 の基線)

## 背景

「丸・三角・四角の中に文字があるフリー素材のような部品を増やせないか」という要望。調べると:

- `badge`(`lib/badge.ts`)は円・四角・三角の中に短い文字を入れるが、**ワイヤーフレームの中だけ**で、番号や記号向けの小さな印。
- `bpmn` の円・ひし形、`stateDiagram` の円、`venn` / `concentric` の円は、それぞれの図の中でしか使えない。
- `box` は角丸の四角だけ。
- つまり、図の自由な位置に置ける、文字入りの独立した図形がない。

他の作図ツールでは、これは「図形(Shape。PowerPoint・Visio・draw.io)」または「node(Graphviz・Mermaid)」で、文字は図形に直接入力する機能として扱われる。

## 決定

### D1: 名前は `emblem`
`shape` は一般的すぎる(別の意味にも読める)という指定で避けた。`node` はこの tool が既に「図の中のノード」の意味で使っている。`medal`(円のイメージが強い)・`seal`(用途が狭い)・`token`(既存の意味と衝突)・`mark` / `figure`(既存の語と衝突)も避け、既存と衝突せず「形と文字の組み合わせ」を表す `emblem` にした。

### D2: flow-shapes の 6 つ目の種類にする
新しい帯の種類は、型の和・`CHILD_BANDS` / `LAYOUT_HANDLERS` / `MEASURE_HANDLERS` / `EMIT_HANDLERS` / `FIT_HANDLERS` / `REVEAL` / `VERIFY_HANDLERS` / PPTX の分類など、10 か所以上に配線が要る。`chevron` / `funnel` / `cycle` / `venn` / `concentric` と同じ `FlowShapeBand` に入れると、**配置・検査(ラベルが図の外に出ない・重ならない)・anchor(`id` が `connect` / spotlight の対象)・`scope`・`reveal`・`width: 'fit'`** がそのまま効き、足りない配線はコンパイラが列挙した(tsc の型の穴埋めで済んだ)。

### D3: 書き方は 2 通り
```ts
emblem('重要', {kind: 'triangle', sub: '期限厳守', tone: 'danger', id: 'warn'})   // 1 個。id は図形の anchor
emblem([{label: '課題', kind: 'hexagon'}, {label: '原因', sub: '3 件'}], {kind: 'circle', size: 112})   // 複数。kind は既定
```
他の flow-shape は配列で書くので配列形を基本にし、1 個の場合だけ文字列形の overload を足した。文字列形の `id` は図形の id(帯の id ではない)。

### D4: 形は 5 種類、文字が入る長方形を形ごとに決める
`circle` / `square` / `triangle` / `diamond` / `hexagon`。形の幅 D に対する割合で「文字が入る長方形」を持つ(円 .76×.56、四角 .84×.84、ひし形 .56×.34、六角形 .68×.5、三角形 .54×.32 で下寄り)。長方形の四隅が輪郭の内側に入るように決めた値で、文字は長方形の幅で折り返し、長方形の中央に置く。

### D5: 形が文字に合わせて広がる。同じ帯の中は同じ大きさ
D を `size`(最小。既定 96)から 8px ずつ広げ、全項目のラベル(と `sub`)が各自の長方形に入った最初の D を使う。320px で入らなければ、ラベルと直し方(短くする・`sub` に移す・`kind: 'square'`)を書いて throw する。サイズを揃えるのは、並べたときの見た目と、行の折り返しの単純さのため。幅が足りなければ次の行へ折り返す(`gap`)。

### D6: 描き方
円は `circle` の primitive に `fill`(箱の tone)を足して、箱と同じ塗り・輪郭・線種で描く(色だけに頼らない)。それ以外は `polygon`。頂点と図形の位置は 4px の格子に吸着する。

## 同時に直したこと: badge の中央合わせ(2 コミット、`badge.ts`)

`badge` の文字が図形の中央からズレる、という指摘。Chromium で実測すると、修正前は横 最大 ±2px・縦 最大 -2.5px ズレていた。原因は 3 つ:
1. 図形は 4px 格子に吸着し、文字は `Math.round`(1px)で別々に丸めていた(最大 2px)。→ 中心を 1 回だけ決め、文字も同じ値を使う。
2. 縦位置の定数 `0.36` は経験値だった。→ 実測(数字・英大文字・かな・漢字の字面の中心は基線の約 0.38em 上、Yu Gothic)の `INK_MID = 0.38` に。
3. 三角形の `+4` は場当たりの補正だった。→ 内接円の中心(文字が最も大きく入る点)から計算。

Chromium は SVG の文字の基線を整数ピクセルに丸めるので、整数の中心と整数の基線では **縦 0.5px が下限**(これ以上は詰められない)。例の SVG は 5 件(`steps` / `steps-loop-back` / `emphasis-tiers` / `inventory-*`)が 1〜2px 動き、再生成した。

`lint-svg.ts` の `coordinate-grid` は、座標の正規表現が `\b` で始まるため `stroke-width="2"` まで「図形の座標」として数えていた。円が多い図(`emblem` が典型)は、`cx` / `cy` が格子に乗っていても 69% になって strict の lint で落ちる。`(?<![\w-])` に直した(192 件の既存 SVG に新しい指摘は出ない)。

## 見送ったこと・残り
- 星形・吹き出し・パスで渡す自由な図形(「フリー素材」のように)。`kind` を増やすか、`path` を受けるかは、最初の 5 種類の使われ方を見てから。
- `box({shape: 'circle'})`(既存の `box` に形を足す案)。`row` や `connect` との相性はよいが、変更が `box` 全体に広がる。
- ワイヤーフレームの `mid()`(チップなどの基線)にも同じ `0.36` が残っている。
- `emblem` は文字が入る長方形に折り返すだけで、輪郭に沿った文字の流し込みはしない(三角形は文字の量に比べて大きくなりがち)。
- 計測した環境のフォントは Yu Gothic。Noto Sans JP の字面の中心は 0.36〜0.37em と見込むが実測していない(差は 14px で 0.3px 以下)。
- 同時に直した badge の縦の中央合わせと lint の修正は、`emblem` とは別の変更。PR を分けるかどうかは未決。
