## 背景

決める人の言葉: 「今まで重ならないように考えてたけど、吹き出しは重なって z-order も含めて適切に配置することが求められる」。

今の設計は、どれも「重ならない」を前提にしている。

| 設計 | 前提 | 困ること |
|---|---|---|
| ADR 0077 `balloon()` | 箱として**流れ(row / grid)の中に置く**。本体は場所を取り、図の上に浮かべられない。しっぽが他の箱を横切る `balloon-tail-box` は問題。z-order の規則は無い | 目標のそばの空き地に浮かべたいとき、行の `gap` で場所を空けるしかない(0077 D5「空きは確保しない」) |
| ADR 0074 `comic()` | ふきだしは 6px の隙間をあけて積み、重ならない。別の話し手のふきだしの後ろを通るしっぽは `comic-tail-crosses-bubble`(問題) | 本物のマンガのような、ふきだしの小さな重なりが作れない |
| ADR 0076 | コマの中の層の順(紙 → 小道具 → 胴 → 顔 → マンプ → ふきだし)。ふきだし同士の順は決めていない | ふきだしが重なったときの上下が未定義 |

図では、注記の吹き出しは図の上に浮かび、空き地・箱の背景・線の上に載ってよい。**載ってはいけないのは、文字(と、関係を読ませる矢じり・しっぽの先、データの印)を隠すこと**。この ADR は、その「重なってよい」を、規則・幾何・検査・配置・順序で決める。

## スパイクの結果(`spikes/balloon-overlay/`。`lib/` は触っていない)

**スパイクの限界(数字を読む前に)**
- 文字の矩形は SVG の `<text>` からの**推定**(全角 = 1em、その他 = 0.55em)。`lib/` では U0 の目録から取る。
- 障害物は、枠つきの `<rect>` の箱、閉じた輪郭(ひし形)・円(**意味のある図形として、覆うと内容と同じに数える。`lib/` の分類よりも厳しい見方**)、矢じり(塗りだけの閉じた小さな経路)、`fill="none"` の経路(コネクタ)。**アイコン・画像・番号の札・グラフの印・ガントの棒は障害物に入っていない**(U0 の目録が無いため)。吹き出しの本体は矩形。
- 吹き出しの足跡(footprint)= 本体 + しっぽ + halo(3px。D2)。数えるのは全部この足跡(しっぽの halo は頂点を重心から押し出す近似)。
- 初版のレビューで、SVG を絵にして目で確かめた(スパイクの初版の置き方は、斜めの向きとしっぽの平たい三角が多く、ひし形・矢じりを避けていなかった)。第 2 版は下の規則を足し、数字を取り直した。

### マンガの 2 個のふきだしの重なり(`comic.ts`。コマ 420×352。しっぽは `tailOf`、輪郭は `balloonPath`)

全組み合わせ 324 通り(1 個目・2 個目の話し手 3×3、行数 1〜3 の 2×2、幅 188 / 204 の 2×2)のうち、`layout.ts:86` の積みの規則で**積まれるのは 297 通り**(同じ話し手 108、別の話し手 189)。2 個目を `1 個目の下端 − 深さ` に置いて数えた。

| 重なりの深さ(px) | 同じ話し手 108: 1 個目が上で 2 個目の文字が覆われる | 同: 2 個目が上で 1 個目の文字が覆われる | 別の話し手 189: 1 個目が上で 2 個目の文字が覆われる | 同: 2 個目が上で 1 個目の文字が覆われる |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0 |
| 4 | 0 | 0 | 0 | 0 |
| **8** | **0** | **0** | **0** | **0** |
| 12 | 108 | 108 | 144 | 144 |
| 16 | 108 | 108 | 144 | 144 |

- **深さ 12 から、文字が覆われる。深さ 8 までは覆われない。** 本体の重なりだけの数(別の話し手の 1 個目のしっぽは含めない。しっぽは別に数える)。文字は上端から 10〜11px 内側から始まる(`PAD_Y = 10`)。
- 別の話し手 189 通りのうち、1 個目のしっぽが 2 個目の本体を通る(= 今の `comic-tail-crosses-bubble`)のは **72 通り**。2 個目を上にすると、その 72 通りのうち 38 通りで、しっぽの 20% 以上が隠れ、72 通りすべてで、しっぽの先が 2 個目の外に出る(しっぽが 2 個目の後ろを通って、**2 個目のしっぽのように見える**)。1 個目を上にすると、しっぽは 2 個目の上に描かれ、文字の矩形(内側全体。保守的)を覆う(72 通り)。**どちらの上下でも、しっぽが交差する 72 通りは問題のまま**(D5)。
- しっぽが交差せず、本体が重なる別の話し手の組は 72 通り(`左 / 中央` の幅が狭い組など。x の範囲が重なり、上のしっぽは下のふきだしに触れない)。同じ話し手の組(108 通り)は、上のしっぽを描かないので、本体が重なる(全部)。
- **この数字は「重ねで帯に入る」ことを示すものではない**(帯の行数の予算は変えない。D5-2)。

## 決定

### D1. `balloon()` の置き方 — `place: 'overlay'`(浮かべる)と `place: 'flow'`(流れに置く)

**選択肢**: A. `flow` だけ(0077 のまま)。B. `overlay` だけ。C. 両方を持ち、`place` で選ぶ。

**推奨: C。`balloon()` の既定は `overlay`**(Q1。決める人)。

- `overlay`: 吹き出しは**目標を基準に置かれ、レイアウトに場所を取らず**、層の順の最後(D2)に描く。大きさは 0077 D3 のとおり文字から決まる(置き場所には依らない)。
- `flow`: 0077 のまま(箱として row / grid / areas / `board` の子に置かれる。検査も 0077 D8 のまま)。
- 理由(`overlay` を既定にする): 0077 が「重ならない」を保つために抱えた費用 — D5 の「空きを確保しない」、`balloon-tail-box`、PPTX で行・格子の中に絵と見えない図形を置く `rectPicture` — は、「吹き出しが流れの中にある」ことから来る。浮かべれば、(1) 吹き出しのために行の `gap` を空けなくてよい、(2) 吹き出しを足し引きしても**ほかの帯の座標が動かない**、(3) PPTX では図形のあとに絵を足すだけになる(D6)。注記の吹き出しの多くは「ここを見て」と添えるもので、流れに加わる内容ではない。
- `flow` を残す理由: 吹き出しが内容そのもので、行に並べたい場合(会話を縦に並べる)。0077 の設計はこの場合に正しい。

**`overlay` は箱の欄にしない — 図の最上位にだけ置ける(明記)**

- `place: 'flow'` は 0077 D2 のとおり(`BoxBand` の内部の欄 `balloon`)。
- `place: 'overlay'` の `balloon()` は `BoxBand` を返さず、**図の最上位の重ねの項目 `OverlayBalloon`**(`Band` ではない)を返す。`diagram().add()` は受けるが、`row()` / `col()` / `grid()` / `areas()` / `board()` の子の型は受けない(**コンパイルで落ちる**。型の信頼できない経路(JSON の spec、`any`)では実行時のエラー: `balloon(): place: 'overlay' goes at the top level of the figure, not inside a row/grid/areas cell (use place: 'flow' to put the balloon in the flow)`)。
- 理由(0077 の「箱 + `balloon` の欄」を `overlay` には使わない): 箱の置き方(`flex` / `col` / `span`、行の `gap`、格子の升、areas の領域)・`anchors`・箱の検査(`rects` の外接矩形、`nowrap`、コントラスト)・PPTX の箱(`renderBoxRect`、図形)・`walkBands` / `childrenOf` / `withNodeIds` の歩き方は、すべて「箱は流れに場所を持つ」ことを前提にしている。0x0 の箱にして全部を例外にするより、**帯でないものとして分ける**ほうが、箱を知らない読み手に壊れた絵を出させない(0077 が箱の欄を選んだ理由は `flow` にだけ当てはまる)。重ねの項目は `diagram` の別の一覧(`overlays`)に入り、帯を歩く処理には**見えない**。
- 枠(`group` / frame)の中に直接書く形は、**v1 は入れない**(座標の箱の定義が要る。Q11)。要望が出たら別の ADR。
- `id` のスコープ(ADR 0012): 重ねの項目の `id` は図のスコープに宣言される。型は `OverlayBalloon & OverlayDeclares<Id> & Refers<T>`(`Declares<Id>` ではない)。**`connect` / `callout` の端(`Declares` を要求)にできない**ことが、型で分かる(Q8)。`to` が**先に宣言した**重ねの吹き出しを指すのは許す(D4 の宣言順に解ける)。
- `reveal` / `until`: 重ねの項目は**自分の `reveal` / `until`** を持つ(目標の `reveal` には従わない。目標が現れる前の段にも見えるのは問題になりうるので、目標より先に現れる指定は `balloon-reveal-order`(助言。0077 D5)で知らせる)。**覆いの検査と配置は、その吹き出しが見える段のうち、どれかで見える内容**を障害物にする(段ごとに数えず、和集合で見る。保守的)。
- `gap` は 0 以上(既定 4)。**しっぽの先は目標の縁の手前で止まる**(`gap: 0` は縁に触れる)。縁の中へ入るしっぽ(負の `gap`)は**入れない**(`balloon-tail-through-target` が 0077 のまま使える)。`@at` つきの `to`(`step2.top@0.3`)は、その**点が先の基準**(0077 D3: 点 + 外向きの法線 × `gap`)で、D4 の「最寄りの縁の点」より優先する。
- `to` / `tip` / `shape` / `base` / `radius` などは 0077 のまま。追加の欄は `place`、`z`(D2)、`at` / `dist`(D4)。`flow` に `z` / `at` / `dist` を書くとエラー。
- JSON の spec(0077 D9): `place` と上の欄を足す。spec では、`place: 'overlay'` の部品は図の最上位だけに書ける(`row` の子に書くと spec のエラー)。

### D2. 図全体の z-order

**決定: 描く順で決める(SVG の DOM の順。`z-index` は使わない。0076 と同じ)。**

```
L0 基本の中身   帯(宣言順。今のまま)
L1 コネクタ     connectSvg(今のまま。ラベルを含む)
L2 重ね         overlay の吹き出し(z の昇順、同じ z は宣言順。あとが上)
```

- **L2 は 1 つの `<g class="overlays">`**(`lib/emit.ts` の `connectSvg` のあとに足す)。吹き出しごとに `<g data-node=… data-balloon-to=…>`(0077 D4)。中は **(halo の `<path>`、本体としっぽの 1 本の `<path>`、文字)の順**。1 つの吹き出しの文字は、自分の輪郭の直後に描く。
- **z の指定**: `balloon({z: 1})`。整数、既定 0。**宣言順が既定**(あとに書いたものが上)。`z` が同じなら宣言順。
- **しっぽは本体と同じ層**(1 本の経路。0077 D6)。しっぽの先は目標の縁の手前(`gap`)で止まり、縁に触れる(`gap: 0`)ときも、目標の**上**に描かれる。
- **halo(紙色の縁取り)**: `overlay` の吹き出しには、**輪郭の外側に紙色の太さ 3px の縁取り**を付ける(輪郭と同じ形の `<path>` を `fill="none"` `stroke=紙の色` `stroke-width=` 輪郭の線の太さ + 3px × 2、`stroke-linejoin="round"` で先に描く)。**必要**: 暗い塗りの箱(`tone: 'solid'`)の上に halo 無しの吹き出しを重ねると、輪郭の 2px のインクが塗りに溶け、しっぽが読めない(初版のレビューで、絵にして確かめた)。**`flow` には付けない**(紙の上に置く前提で、0077 の golden に影響しない)。
- **halo は足跡の一部**: 覆いの検査(D3)と配置(D4)は、**本体 + しっぽ + halo を足跡**として数える(halo が文字・矢じりの縁を消すため)。「塗りと枠を覆ってよい」の判定だけ、halo を除いた輪郭で見る(halo は紙色で、塗りと枠の上に載ってよい)。
- **PPTX の順**: D6。
- 別の部品(付箋など)を L2 に載せるときは、`z` を共通の数直線にする(この ADR では決めない)。

### D3. 覆ってよいものの分類 — 「重ならない」の代わりの規則

**まず目録(U0)**: 覆いの検査も配置も、「下に何があるか」を知らなければ決められない。今の `lib/` にその一覧は無い(上の表)。**U0 で、レイアウトが「内容の目録」を作る**。1 つの図につき 1 つの一覧で、要素は次のとおり。

| 要素 | 持つもの | 出どころ(帯ごと) |
|---|---|---|
| 箱・カード・帯の文字 | 文字の行ごとの矩形(`wrappedRuns` の位置と測定した幅)。箱の形の多角形(矩形・ひし形・円・角丸の矩形)と、枠線の太さ | 箱、見出し、キャプション、凡例、表のセル |
| アイコン・画像・番号の札・タグ・スタンプ | 矩形 | 箱、`image`、ステップの札 |
| コネクタ | 折れ線(経路)、端の矢じり(端から 12px の矩形)、ラベルの矩形 | `connect` |
| **意味のある図形(データの印)** | 外形の多角形 | グラフの棒・点・線、ガントの棒、タイムラインの印、プレーンの印、ベンの円 |
| その他の吹き出し(`flow`・`overlay`) | 本体と文字、しっぽの多角形(先から 8px の矩形も) | `balloon` |

- **目録の出どころ**: 描くとき(`emit`)に出す矩形を記録する(文字は描く位置と、配置に使った同じ測定の幅)。帯の種類ごとに v1 の範囲を決め、**目録をまだ作らない帯は、帯の矩形全体を内容として数える**(その帯の上には吹き出しが置かれない。保守的)。v1 の範囲は、U0 の最初の PR で表にする(箱・列・格子・areas・コネクタ・キャプション・凡例から)。
- **スパイクは SVG から読んだ文字の推定と箱・ひし形・円・矢じり・コネクタだけ**で数えた(上の「限界」)。

**分類**: 吹き出しの足跡(本体 + しっぽ + halo)が、下にあるものを覆う。

| 下にあるもの | 覆うと | 検査 |
|---|---|---|
| **内容**: 文字(他の箱・コネクタのラベル・凡例・表のセル・**目標の自分の文字**)、他の吹き出しの文字、アイコン・画像・番号の札 | **問題** | `overlay-covers-text`(新) |
| **データの印**(グラフの棒・点・線、ガントの棒、タイムラインの印)。印の面積の 10% を超えて覆う、または印のラベルに触れる | **問題** | `overlay-covers-mark`(新) |
| **関係の端**: コネクタの矢じり(端から 12px。両端が矢じりのものは両方、折れ線は最後の脚)、他の吹き出しのしっぽの先(先から 8px)。コネクタの長さの 50% 以上(下) | **問題** | `overlay-hides-link`(新) |
| **塗りと枠**: 箱・枠・帯の背景と縁線、箱の形(ひし形・円など)の塗り、他の吹き出しの本体の塗りと縁 | **許す**(報告しない) | — |
| **コネクタの線**(端と上の割合を除く) | **助言** | `overlay-covers-connector`(新) |
| 空き | 自由 | — |

- **理由**: 吹き出しの目的は「ここを見て」と添えること。箱の背景を少し覆うのは普通の見た目で、報告すると配置が窮屈になる。文字・データの印を隠すと、図が読めなくなる(問題)。コネクタの線を横切るのは、読めるが図が汚れるので助言(Q3)。矢じりと先は、**どこからどこへ**を決める部分なので、隠すと関係が読めなくなる(問題)。ひし形の箱の隅を覆うのは(文字を覆わなければ)許す(スパイクは、ひし形全体を内容として数えたので、`lib/` より厳しい)。
- **コネクタの 50%**: 折れ線の長さに対する割合ではなく、**脚(線分)ごと**に「その脚の長さの 50% 以上、または覆う長さが 40px 以上」を問題にする(長い線の途中を少し覆うのは助言、短い線がほぼ隠れるのは問題)。
- **幾何**(0077 D8 の SAT を広げる):
  - 文字・アイコンの矩形は U0 の目録の矩形。測定のゆれ 0.0156px は、0.5px² の等値の幅に吸収される(スパイク)。
  - 吹き出しの足跡は、本体(角丸の矩形の凸多角形)、しっぽ(三角形)、halo(本体を 3px、しっぽを 3px 膨らませた多角形)。覆う面積は、凸多角形どうしの切り取り(Sutherland-Hodgman)の面積で、**0.5px² を超えたら**覆うとする(0077 D8 と同じ)。**雲**は凸でないので、凸包で近似する(覆いを多めに見る方向の誤り)。しっぽの円(雲)は円の外接正方形。凸でない目録の要素は凸多角形に分ける(U0)。
  - コネクタの長さは、折れ線の各線分を足跡の多角形で**厳密に**切り取った長さ(スパイクの初版は 0.5px 刻みの数え方で、12px²/px の重みと合わせて 6px² の粒になった)。
  - 1 つの (吹き出し, 下のもの) の組につき、**報告は 1 つ**。優先は 内容 > データの印 > 関係の端 > コネクタの線。
- **変わる既存の検査**(二重報告を避けるため):

| 既存の検査 | `flow` | `overlay` |
|---|---|---|
| `balloon-tail-box`(しっぽが他の箱を横切る。問題) | そのまま | **使わない**。箱の中身は `overlay-covers-text`、塗りと枠は許す |
| `balloon-tail-through-target` | そのまま | そのまま(負の `gap` が無いので、目標を通り抜けるしっぽだけが対象)。同じ目標の文字が `overlay-covers-text` で報告されるときは出さない(1 つの誤りに 1 つ) |
| `balloon-tail-edge`(しっぽがコネクタと交わる。助言) | そのまま | **使わない**(`overlay-covers-connector` / `overlay-hides-link` が足跡全体を見る) |
| `balloon-out-of-bounds` / `balloon-target-inside` | そのまま | そのまま |
| 重なりの検査(箱どうし)/ 文字どうし | そのまま | 重ねの項目は帯ではないので、`rects` に**入らない**(D1)。吹き出しの文字は、**一般の文字の重なりの検査に出さず**、`overlay-covers-text` が見る(二重にならない)。吹き出しの文字が自分の本体に収まるかは `box` と同じ検査 |

### D4. `overlay` の自動配置(決定的)

**候補**: 目標の矩形のまわりの **8 方向(東・南東・南・南西・西・北西・北・北東)× 距離 12 / 28 / 48px**(目標の縁と本体の最寄りの縁の間)の 24 個。本体の位置は 4px の格子に丸める。

- **しっぽの先**: `@at` つきの `to` ならその点 + 外向きの法線 × `gap`(0077 D3。**著者の指定が優先**)。そうでなければ、**本体が向く側の縁**(目標の中心から本体の中心へのずれの大きい軸の側)の上で、本体の中心に最も近い点を、**角から 8px 以上離して**選び、法線の外へ `gap`(既定 4)出した点。先は縁に直角に近い向きから出る。
- しっぽが作れない候補(0077 D3 の縮退)は候補にしない。**しっぽが縁と 30° 未満で出る候補は、ほかに候補が残るかぎり落とす**(平たい三角形は「旗」に見え、どの箱を指すか曖昧になる)。
- 辺つきの `to`(`step2.top`)は、その辺に向く方向だけ(上なら 北・北東・北西)。

**点数(辞書式。上の項目が等しいときだけ、次を見る。面積と長さは `eps` 以内を等しいとする)**:

1. 覆う**内容**(文字・図形・データの印)の面積。足跡(halo を含む)で数える。`eps = 0.5px²`
2. 隠す**関係の端**の数(矢じり・他のしっぽの先)
3. 覆う**そのほか**: 箱の塗りの面積 + 12 × (覆うコネクタの長さ px)。**`eps` の 4 倍(2px²)以内を等しいとする**(測定のゆれで順が変わらないように。スパイクで、この幅が無いと 1.4% が変わった)
4. **斜めの向きは、直角の向きのあと**(東・南・西・北を先に)
5. 距離(12 → 28 → 48。近いほどよい)
6. しっぽと交わるコネクタの本数
7. 候補の順番(固定。距離が近いほう → 方向は 東・南東・南・南西・西・北西・北・北東)。**必ず 1 つに決まる**

- スパイクは 1〜7 を実装した(2 は、例の図にコネクタの矢じりを隠す候補がほとんど無く、取り合う場合を測っていない)。点数の重み(12)と `eps` は暫定で、U2 の例の図で決める。
- **手動の上書き**: `at: 'ne'`(方向を 1 つに絞る。距離は探す)、`dist: 28`(距離を絞る)、`at: [dx, dy]`(本体の中心を、目標の中心からの相対で固定。探索しない)、`tip: [dx, dy]`(0077 D3)。**手動の吹き出しは先に置き**、自動のものがそれを避ける。手動の置き方が文字を覆うときは、そのまま描いて D3 の検査が報告する。
- **図の範囲(0077 Q14 のまま)**: キャンバスは広げない。本体・しっぽ・halo がキャンバスの外に出る候補は**候補にしない**。どれも収まらないとき、範囲を無視して最良を選び、`balloon-out-of-bounds`(問題)で報告する。
- **複数の吹き出し**: **宣言順**に置く。**先に置いたもの**(本体は「そのほか」、文字は「内容」)が、あとのものの障害物になる。あとから置くものは、前のものを動かさない(貪欲)。`z` は描く順だけで、配置の順には影響しない。
- **決定的であること**: 同じ図は同じ置き場所になる(目録が同じなら)。**ゆれの吸収は `eps` と候補の差の余裕による**。スパイクでは、全部の入力(文字・箱・図形・矢じり・コネクタ)を ±0.0156px ずらしても、`eps ≥ 0.5` なら**選ばれる候補は 2760 回中 0 回しか変わらず**、`eps = 0` では 1.4% 変わった。±1px で 1.6%、±4px で 14.6%(`eps = 0.5`)。**候補どうしが 1px² 以内で拮抗する図**は多くなく(2 位が点数 1〜4 番で並ぶのは 28%)、固定の順(7)で決まる。
- **性能**: 1 つの吹き出しが約 0.3〜0.6ms(24 候補)。コネクタが多い図ではその切り取りが大半(U1 で、線分ごとの外接矩形で絞る)。
- **配置の段**: 重ねの吹き出しは、**コネクタの経路が決まったあと**に置く(障害物にコネクタの経路を使うため)。コネクタの経路は吹き出しを避けない(CRT の層の順や辺の経路探索には見えない)。

### D5. マンガのふきだし(`comic()`)

**この節は、重ねを「帯に入れるための道具」にはしない**(レビューで確かめた: `lineBudget` が行数の予算を決めるので、重ねても入る行数は増えない)。**見た目の選択肢**として、小さな重なりを足す。

1. **重なりの深さは見た目の選択肢**: `comic()` の項目 `overlap: 0 | 4 | 8`(任意。**既定 0**)。0 は今のまま(隙間 6px。**既存の golden は変わらない**)。4 / 8 のときは、積むときの隙間 6px のかわりに、2 個目を**1 個目の下端より深さのぶん上**に置く。**上限は 8px**(`PAD_Y − 2`)。根拠: スパイクで、深さ 8 までは本体の重なりがどちらの文字も覆わず、12 では覆う(別の話し手 189 通りのうち 144、同じ話し手 108 通りの全部)。文字は上端から 10〜11px 内側から始まるので、8 は**余裕を持った規則**で、閾値ではない(U4 で文字の大きさを変えて確かめる)。方向は縦(積むとき)だけ。横に並ぶものは今の規則のまま。
2. **行数の予算と帯は変えない**: `lineBudget`(`layout.ts:30`)と `comic-text-budget` / `comic-bubble-zone` は、隙間 6px で数える今のまま(0074 の予算の文面を変えない)。重ねは、積んだ高さを**縮める**だけで、入らなくなった図が入るようにはしない(7:5 で 3+2 行が入るという初版の主張は取り下げる)。
3. **積みの上下(`z`)**: ふきだしの `z` の既定は、**あとに読むほうが上**(`dialogue` の後のものが手前)。ふきだしの項目 `z` で上書きできる(Q2。決める人)。
   - **理由は、描く順と読む順の一致**: SVG の描画の順は DOM の順で、DOM の順がスクリーンリーダーの読む順。**今の出力はすでにふきだしを `dialogue` の順に描いており**(`lib/comic/emit.ts:31,35`)、あとのものが手前になる。「先に読むほうを手前に」にすると、DOM を逆にするか、`z` を足して見た目だけを逆にする必要があり、見た目の順と読み上げの順がずれる。重なりが目的のとき、どちらが上かは見た目の細かい違いで、読む順を保つほうを選ぶ。
   - 「先に読むふきだしを手前にする」という作法をよく聞くが、**この ADR を書く間の検索では、一次資料で確かめられなかった**。見つかった範囲の資料は、読む順(左上から右下へ)、しっぽを交差させないこと、重なりが重要度や発言の続きを示すこと、を述べている: [BnF の資料](https://bdnf.bnf.fr/uploads/fiches/8.%20Speech%20Bubbles.pdf)、[Clip Studio のヒント](https://tips.clip-studio.com/en-us/articles/4811)、[Shanower のブログ](https://www.goodreads.com/author_blog_posts/26043709-shanower-s-secrets-of-professional-cartooning---no-2-a-panel-layout-to?tab=book)。作法が決める人の知るものなら、`z` で上書きできる(Q2)。
4. **しっぽの規則は変えない**:
   - `comic-tail-crosses-bubble`(別の話し手のふきだしの後ろを通るしっぽ。問題)は**そのまま**。スパイクの上のとおり、別の話し手の組でしっぽが交差する 72 通りは、上下どちらでも問題のまま(2 個目が上だと、しっぽが 2 個目の後ろを通り、2 個目のしっぽに見える)。**重ねてよいのは、しっぽが交差しない組(別の話し手の 72 通り + 同じ話し手の全部)だけ**になる。
   - 同じ話し手の上のしっぽを描かない規則(0074 U1。`layout.ts:149`)も**そのまま**。
   - 0076 D5 の `comic-tail-cross`(助言。しっぽが別のしっぽ・別のふきだしの箱を通る)も**そのまま**(変更なし。二重に報告しない: `comic-tail-crosses-bubble` が問題のとき、助言は出さない。今の 0076 の規則のまま)。
5. **文字は覆わない**: 新しい検査 `comic-bubble-covers-text`(問題): ふきだしの輪郭(しっぽを含む)が、別のふきだしの文字の矩形(穴の矩形を含む。**穴は、予約した最大の幅で数える**(`reserveDialogue`)ので、値に依らない)を 0.5px² 超覆う。`overlap` が 8 以下なら出ない(手動の `z` / `anchor` の上書きで起きる)。顔・マンプ・小道具と重ならない規則(0074 `comic-bubble-face`、0076)は**変えない**(重なりを許すのは**ふきだし同士だけ**)。
6. **描く順**: 今の `emit.ts` は、ふきだしごとに(輪郭 → 文字と穴)の対で、`dialogue` の順に描く。**変えない**。`z` を指定したときだけ、z の昇順に並べ替える。0076 D1 の「ふきだしの輪郭 → ふきだしの文字と穴」は、**ふきだしごとの対**と読むと明記する(文言の明確化。出力は変わらない)。
7. **幾何の地図**: `bubbles` の項目に `z`(整数。既定は `dialogue` の順)を足す。値(穴の中身)は地図に入らない。
8. **0074 D4 / D5 の不変条件**: 深さ・z は、**行数(最大の幅で数えた)・`overlap`・ふきだしの順だけ**で決まる。穴に値を入れても動かない。

### D6. PPTX への書き出し(順序と材料。実装は 0077 の範囲外のまま)

- **`overlay` の吹き出しは、z の昇順に、図形・ネイティブのコネクタのあとに足す**(`spTree` の末尾。PPTX は XML の順がそのまま重なりの順)。図形(L0)→ コネクタ(L1)→ 吹き出し(L2)で、SVG と同じ順。
- 吹き出しは絵(SVG + PNG。0077 D2。halo を含む)で、**1 つの図形(`p:pic`)**。`descr` に文字と目標の id を入れる。**のり付け(glue)は付けない**(重ねの項目はコネクタの端にならない。のり付けが要るのは `flow` だけ)。
- 絵の矩形は、本体 ∪ しっぽ ∪ halo の外接矩形で、キャンバスの内側に切る(`bandPicture` と同じ。キャンバスの外に出るしっぽは `balloon-out-of-bounds` が問題として報告する)。
- マンガの帯は 1 枚の絵(0074 D5 の書き出し)なので、ふきだしの順は SVG の順がそのまま絵になる。
- 吹き出しの文字は PowerPoint で編集できない(0077 D2 と同じ)。

## 代替案(全体)

1. **重ならないままにして、空きを自動で作る(0077 のまま)**: 目標のそばに空きを作るには、配置が目標に引かれて循環しうる(0077 D5)。**却下**。
2. **`overlay` のみ(`flow` を捨てる)**: 吹き出しが内容そのもので並ぶ図(会話の列)に使えない。**却下**。
3. **`overlay` を `BoxBand` の欄のまま、流れの中にも書けるようにする**(初版): 箱を知る読み手が全部例外になる(D1)。**却下**。
4. **すべての重なりを許す(検査なし)**: 文字が隠れても通る。**却下**(内容は問題にする)。
5. **箱の背景を助言にする**: 注記の吹き出しはほぼ必ず箱の背景に触れるので助言だらけになる。**却下**(許す)。
6. **`z-index` を使う**: SVG に `z-index` は無く、DOM の順で決めるほうが PPTX の順と一致する。**却下**。
7. **自動配置を点数の重みの合計にする**: 重みの調整が全図に影響し、結果が説明しにくい。辞書式は「文字を覆うものを絶対に選ばない」を保証できる。**却下**。
8. **自動配置を最適化(焼きなまし・力学)にする**: 候補が 24 個で足りる。複数の吹き出しの全体最適は後の ADR。
9. **マンガで、重ねで帯に入れる・しっぽが後ろに潜るのを許す**(初版): `lineBudget` が行数を決めるので入る行数は増えず、しっぽが後ろに潜ると別のふきだしのしっぽに見える(72 通り)。**却下**。重ねは見た目の選択肢にとどめる。
10. **マンガで深さの上限を設けない**: 12px 以上で文字が覆われる。**却下**。

## 影響

- 既存の図: `balloon()` は 0077 U1 しか進んでいない(U2 以降は未実装)ので、**既存の golden に影響しない**。`comic()` は `overlap` の既定が 0 で、**既存の `comic` の golden は変わらない**。
- 0077 の U2 / U3 は、この ADR の採用後に進める。0077 の U1(輪郭の生成)は影響されない。
- 検査: 新しい id は `overlay-covers-text`、`overlay-covers-mark`、`overlay-hides-link`、`overlay-covers-connector`、`comic-bubble-covers-text`。`RULE_DOCS` の行は各単位が足す(0076 A21 と同じ)。
- 読み上げ: `overlay` の吹き出しは DOM の最後に出る。`data-balloon-to` が目標を指す(0077 D4)。
- 例の文の規則(公開リポジトリ): 例・golden・テストの文は中立な作り話だけ。

### U0: 内容の目録

- 範囲: 図ごとの内容の一覧(D3 の表)。v1 は箱・見出し・キャプション・凡例・コネクタ(ラベルと矢じり)・`flow` の吹き出し・グラフの印(棒・点)・ガントの棒。それ以外の帯は帯の矩形全体を内容として数える。
- 完了の基準: (1) 例の図(`examples/`)の全部で、目録の文字の矩形が、描かれた `<text>` の位置・幅と 0.5px 以内で一致する(測定器を同じにして)。(2) 目録を作っても、既存の SVG と golden が変わらない(記録するだけ)。(3) 目録に無い帯は、帯の矩形全体が出る。
- テスト: 例の図ごとの一致、帯の種類ごとの範囲の表、凸でない形の分割。

### U1: 覆いの幾何と候補の点数

- 範囲: 凸多角形どうしの重なりの面積(`clipArea`)、線分の多角形内の長さ(厳密)、角丸・雲の凸多角形(雲は凸包。0077 U1 に追加する多角形を返す関数を使う)、膨らませ(halo)、候補の生成と点数、`best()`(辞書式、`eps`)、`placeAll()`(宣言順、手動が先)。
- 完了の基準: (1) 同じ入力は同じ結果(1000 通りの乱数で 2 回)。(2) **全部の入力(文字・箱・図形・矢じり・コネクタ)を ±0.0156px ずらしても選ぶ候補が変わらない**(例の図 6 枚 + 文字が詰まった図 2 枚の全箱で 0 件。`eps = 0.5`)。(3) 候補どうしが `eps` 以内で拮抗するときは固定の順で決まる(単体テスト)。(4) 凸多角形の切り取り面積と線分の長さが、既知の値と 1e-6 以内で一致。(5) 縮退(しっぽが作れない、図の外、障害物が空)で `NaN` が出ない。(6) しっぽの先が目標の角から 8px 以上離れ、辺と 30° 以上の角で出る(ほかに候補が残るとき)。`@at` つきの `to` のとき、先がその点 + 法線 × `gap`。
- テスト: 上の性質テスト、候補が全部図の外のときの `balloon-out-of-bounds`、手動の `at` / `dist`、宣言順の障害物。

### U2: 部品とレイアウト

- 完了の基準: (1) `place: 'overlay'` の吹き出しを足しても、**ほかの帯の座標と既存の golden が変わらない**。(2) `flow` は 0077 のとおり。(3) `overlay` を `row` / `grid` / `areas` / `board` の子に書くと、型のエラー(spec と `any` では実行時のエラー。文言は「`flow` を使う」と言う)。(4) `overlay` を `connect` / `callout` の端にすると型のエラー。(5) 層の順が「帯 → コネクタ → 重ね(z の昇順、同じ z は宣言順)」で、DOM の順をテストで固定する。(6) halo は `overlay` だけ。(7) PPTX で `overlay` が図形・コネクタのあとの図形で、`flow` は 0077 のとおり。(8) `reveal` / `until` が重ねの項目にある。
- テスト: 配置の golden(暗い配色を 1 枚)、エラー文言、`z` の順、`reveal`、`scope` の中の参照、`gap: 0`、`@at`。

### U3: 検査

- 完了の基準: わざと悪くした図(文字を覆う、目標の文字を覆う、他の吹き出しの文字を覆う、データの印を覆う、矢じりを隠す、他のしっぽの先を隠す、コネクタを横切る、箱の背景だけを覆う、halo だけが文字に触れる)で、それぞれ期待の id だけが 1 回ずつ報告される(`overlay-covers-text` / `overlay-covers-mark` / `overlay-hides-link` / `overlay-covers-connector` / 報告なし)。`flow` の検査は変わらない。同じ誤りが `balloon-tail-box`・`overlay-covers-text`・一般の文字の重なりの検査と二重にならない(`overlay` + `flow` の吹き出し + 一般の文字の重なりを 1 枚の図に入れたテスト)。例の図では 0 件。
- テスト: 悪い図ごとの結果、閾値の境(0.5px²、矢じり 12px、脚の 50% / 40px、印の 10%)、雲が凸包で多めに報告する向き、外接矩形では「重なり」で厳密な切り取りでは「重ならない」配置が報告されない。

### U4: マンガ

- 完了の基準: (1) 既存の `comic` の golden が変わらない(`overlap` 0)。(2) `overlap` は 0 / 4 / 8 だけ(Schema の列挙。12 以上はエラー)。(3) 同じ入力の穴の値だけを変えても、ふきだしの位置・深さ・z が変わらない。(4) `overlap: 8` の全組み合わせ(上の 297 通り)で、ふきだしどうしの文字が覆われない。文字の大きさ(`FONT` 18 / 14)と行数を変えても同じ。(5) `comic-tail-crosses-bubble`、同じ話し手の上のしっぽを描かない規則、`comic-tail-cross` は変わらない(同じ入力で同じ結果)。(6) 手動の `z` / `anchor` で文字が覆われると `comic-bubble-covers-text`。(7) 描く順が、ふきだしごとの対(今の DOM の順)で、`z` を指定したときだけ並べ替わる。
- テスト: スパイクの 324 通りの組を単体テストの表にして、深さごとの数(上の表)を再現する。

### U5: spec・Schema・例

- spec の部品に `place` / `z` / `at` / `dist` と、`comic()` の `overlap` / ふきだしの `z` を足す。`pnpm schema`。例 `examples/balloon-overlay.ts`(3 個を宣言順、手動の `at`、暗い配色、コネクタの上、箱の背景の上)。例の文は中立な文だけ。

## テスト方針

- 純粋な核(U1)は単体テストと性質テスト(全入力のゆれ)。検査(U3)は悪い図ごと。`comic` は 324 / 297 通りの表と値の不変条件のテスト。golden は `scripts/golden-docker.sh`(既存の golden は変えない)。
- この ADR の PR は文書とスパイクだけで、`lib/` を変えない。`pnpm typecheck` が通る。

## スパイクの再現

```
node spikes/balloon-overlay/run.ts      # 例の図 6 枚の配置、安定性、時間。out/*-3balloons.svg と measurements-place.txt
node spikes/balloon-overlay/comic.ts    # out/comic-*.svg と measurements-comic.txt(コマ 420x352)
```

数字は、文字の矩形が推定なので環境に依らない(時間だけ環境で変わる)。乱数は固定の種だが、取る順を変えると ±数件変わる(安定性の数字)。
