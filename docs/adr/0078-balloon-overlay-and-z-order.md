## 背景

決める人の言葉: 「今まで重ならないように考えてたけど、吹き出しは重なって z-order も含めて適切に配置することが求められる」。

今の設計は、どれも「重ならない」を前提にしている。

| 設計 | 前提 | 困ること |
|---|---|---|
| ADR 0077 `balloon()` | 箱として**流れ(row / grid)の中に置く**。本体は場所を取り、図の上に浮かべられない。しっぽが他の箱を横切る `balloon-tail-box` は問題。z-order の規則は無い | 目標のそばの空き地に浮かべたいとき、行の `gap` で場所を空けるしかない(0077 D5「空きは確保しない」) |
| ADR 0074 `comic()` | ふきだしは 6px の隙間をあけて積み、重ならない。別の話し手のふきだしの後ろを通るしっぽは `comic-tail-crosses-bubble`(問題)。同じ話し手の 2 個の上のしっぽは描かない | 行数の多い 2 個が帯に入らない(7:5 で 3+2 行)。しっぽを避けるために並びを変えるしかない |
| ADR 0076 | コマの中の層の順(紙 → 小道具 → 胴 → 顔 → マンプ → ふきだしの輪郭(しっぽを含む) → ふきだしの文字)。ふきだし同士の順は決めていない | ふきだしが重なったときの上下が未定義 |

実際のマンガでは、ふきだしは少し重なり、手前のふきだしが別のしっぽを隠す。図でも、注記の吹き出しは図の上に浮かび、空き地・箱の背景・線の上に載ってよい。**載ってはいけないのは、文字(と、関係を読ませる矢じり・しっぽの先)を隠すこと**。この ADR は、その「重なってよい」を、規則・幾何・検査・配置・順序で決める。

### 吹き出しの自動配置(8 方向 × 距離 12 / 28 / 48px = 24 候補)

### マンガの 2 個のふきだしの重なり(`comic.ts`。コマ 420×352 と 420×300。しっぽは `tailOf`、輪郭は `balloonPath` の本体 + しっぽ)

全組み合わせ 324 通り(1 個目・2 個目の話し手 3×3、行数 1〜3 の 2×2、幅 188 / 204 の 2×2)を、2 個目を `1 個目の下端 − 深さ` に置いて数えた。

**6:5(帯 220px。今の 6px の隙間のときも 324 通りすべて入る)**

| 重なりの深さ | 1 個目が上: 2 個目の文字が覆われる | 2 個目が上: 1 個目の文字が覆われる | 1 個目のしっぽが 2 個目の本体を通る | そのうち 2 個目が上で、しっぽの 90% 以上が隠れる |
|---|---|---|---|---|
| -6(今: 隙間 6px) | 108 | 0 | 177 | 0 |
| 0 | 108 | 0 | 180 | 24 |
| 4 | 108 | 0 | 180 | 12 |
| 8 | 108 | 0 | 180 | 12 |
| **12** | **252** | **252** | 180 | 12 |
| 16 | 252 | 252 | 180 | 12 |

- **深さ 12 から、文字が覆われる**(252 / 324)。深さ 8 までは、**本体の重なりが文字を覆うことは無い**(文字は上端から 10px(1 行は 11px)内側から始まる = `PAD_Y`)。「1 個目が上」の 108 は、深さに依らない = **しっぽ**が 2 個目の文字を覆うもの(下)。
- 1 個目のしっぽが 2 個目の本体を通る組み合わせは **180 / 324**(深さに依らない。今の `comic-tail-crosses-bubble` の対象)。**1 個目が上なら、その 180 通りすべてでしっぽが 2 個目の上に描かれ**、文字の矩形(内側の全体。保守的)を覆う。**2 個目が上なら、しっぽは 2 個目の後ろに入り、先は下に出る**。90% 以上が隠れて先まで見えなくなるのは 12〜24 通り(深さ 0 で 24、4 以上で 12。7%)だけで、残りは先が見える。

**7:5(帯 168px)**

| 重なりの深さ | 帯に入る組み合わせ(324 中) | 1 個目が上: 2 個目の文字が覆われる | 2 個目が上: 1 個目の文字が覆われる |
|---|---|---|---|
| -6(今) | 216 | 72 | 0 |
| 0 | 216 | 72 | 0 |
| 4 | **288** | 96 | 0 |
| 8 | 288 | 96 | 0 |
| 12 | 288 | 224 | 224 |

7:5 では、**深さ 4 で入る組み合わせが 216 → 288 に増える**(3+2 行は 178px で 168px に入らないが、重なり 8px なら 164px で入る)。6:5 では、今でも全部入るので、重なりは「入れる」ためではなく**しっぽを隠すため**に要る。

## 決定

### D1. `balloon()` の置き方 — `place: 'overlay'`(浮かべる)と `place: 'flow'`(流れに置く)

**選択肢**: A. `flow` だけ(0077 のまま)。B. `overlay` だけ(0077 の流れは捨てる)。C. 両方を持ち、`place` で選ぶ。

**推奨: C。`balloon()` の既定は `overlay`**(Q1。決める人)。

- `overlay`: 吹き出しの本体は**目標を基準に置かれ、レイアウトに場所を取らず**、層の順の最後(D2)に描く。大きさは 0077 D3 のとおり文字から決まる(置き場所には依らない)。
- `flow`: 0077 のまま(箱として row / grid / areas / `board` の子に置かれる。しっぽの検査も 0077 D8 のまま)。
- 理由(`overlay` を既定にする): 0077 が「重ならない」を保つために抱えた費用 — D5 の「空きを確保しない」、`balloon-tail-box`、PPTX で行・格子の中に絵と見えない図形を置く `rectPicture` — は、すべて「吹き出しが流れの中にある」ことから来る。浮かべれば、(1) 吹き出しのために行の `gap` を空けなくてよい、(2) 吹き出しを足し引きしても、**ほかの帯の座標が動かない**(既存の golden に影響しない)、(3) PPTX では図形のあとに絵を足すだけになる(D6)。注記の吹き出しの多くは「ここを見て」と添えるもので、流れに加わる内容ではない。
- `flow` を残す理由: 吹き出しが内容そのもので、行に並べたい場合(会話を縦に並べる、手順の吹き出しの列)。0077 の設計はこの場合に正しい。
- **0077 の表現への影響**(D2 の「箱 + `balloon` の欄」は**維持**する。`overlay` も箱の一種):
  - `balloon` の欄に `place: 'overlay' | 'flow'`(既定 `overlay`)を足す。
  - `overlay` のとき、箱は**流れに入らない**: `row` / `col` / `grid` の中に書かれても、置き場所(`flex` / `width` / `col` / `span`)の欄は無視せず**エラー**にする(`balloon(): 'flex' is not supported with place: 'overlay'`)。`width` だけは文字の折り返しの幅として受ける。`row` の中の位置は、`id` のスコープ(ADR 0012)と `reveal` / `until` の親だけを決める。**書く場所は図の最上位を推奨**する(流れの中に書いても動かないので、読み手が混乱する)。
  - レイアウトは、`overlay` の箱の**大きさだけ**を測り(0077 D3)、配置では 0 × 0 の帯として扱う(`gap` も数えない)。位置は、コネクタの経路が決まったあと(D4)に決める。
  - 本体は `anchors` に**入れない**(配置のあとでしか位置が決まらず、そこから出るコネクタとは循環する)。`overlay` の吹き出しを `connect` / `callout` の端にすると、`balloon(): an overlay balloon cannot be the end of a connector (use place: 'flow')` のエラー。`to` が**先に宣言した**`overlay` の吹き出しを指すのは許す(D4 の宣言順に解けるため)。
  - `to` / `tip` / `gap` は 0077 D3 のまま。**`gap` は負でもよい**(下限は `-8`)。`gap < 0` は、しっぽの先が目標の縁の**内側**に入る(しっぽが目標の縁に触れる・入り込む絵。D2)。先が目標の中に入っても、`balloon-target-inside`(先が**本体**の中)ではない。
  - PPTX(0077 D7): `overlay` は D6 のとおり。0077 D2 の `rectPicture` を行・格子の子に置く部分は、`flow` の吹き出しだけの仕事になる。
  - JSON の spec(0077 D9): `place`、`z`(D2)、`at` / `dist`(D4)を足す。

### D2. 図全体の z-order

**決定: 描く順で決める(SVG の DOM の順。`z-index` は使わない。0076 と同じ)。**

```
L0 基本の中身   帯(宣言順。今のまま)
L1 コネクタ     connectSvg(今のまま。ラベルを含む)
L2 重ね         overlay の吹き出し(z の昇順、同じ z は宣言順。あとが上)
```

- **L2 は 1 つの `<g class="overlays">`**(`lib/emit.ts` の `${body}` と `connectSvg` のあとに足す)。吹き出しごとに `<g data-node=… data-balloon-to=…>`(0077 D4)。中は **(必要なら halo の `<path>`、本体としっぽの 1 本の `<path>`、文字)の順**。1 つの吹き出しの文字は、自分の輪郭の直後に描く(あとの吹き出しの輪郭が自分の文字の上に来ないように、0076 の「輪郭を全部 → 文字を全部」ではなく**吹き出しごとの対**にする。D5)。
- **z の指定**: `balloon({z: 1})`。整数で、既定 0。**宣言順が既定**(あとに書いたものが上)。`z` が同じなら宣言順。決定的で、書き手が上書きできる。
- **しっぽは本体と同じ層**(1 本の経路。0077 D6)。しっぽの先が目標の縁に触れる、または `gap < 0` で縁の中に入るとき、しっぽは L0 / L1 の目標の**上**に描かれる(目標の縁線がしっぽで隠れて、「ここを指している」と自然に読める)。本体としっぽの間に別の吹き出しは挟まらない。
- **halo(紙色の縁取り)**: `overlay` の吹き出しには、**輪郭の外側に紙色の太さ 3px の縁取り**を付ける(輪郭の `<path>` と同じ形を `fill="none"` `stroke=紙の色` `stroke-width=7`(輪郭の 2px + 外 3px × 2。内側 2.5px は本体の塗りが隠す)`stroke-linejoin="round"` で先に描く)。理由: 暗い塗りの箱(`tone: 'solid'`)や線の上では、2px のインクの縁だけでは吹き出しの縁が見えない。紙色はテーマの `PALETTE.bg`(暗い配色では再配色される)。**`flow` には付けない**(紙の上に置く前提で、0077 の golden に影響しない)。必要性は 1 枚の図の判断で、数字では測っていない(U3 で例の図で見て、不要なら外す。暫定)。
- **PPTX の順**: D6。
- 別の部品(付箋など)を L2 に載せるときは、`z` を共通の数直線にする(この ADR では決めない)。

### D3. 覆ってよいものの分類 — 「重ならない」の代わりの規則

吹き出しの**輪郭**(本体 + しっぽの 1 本の経路。halo は数えない)が、下にあるものを覆う。下にあるものを 4 つに分ける。

| 下にあるもの | 覆うと | 検査 |
|---|---|---|
| **内容**: 文字(他の箱・コネクタのラベル・凡例・表のセル・**目標の自分の文字**)、他の吹き出しの文字、アイコン・画像・番号の札など意味のある部品 | **問題** | `overlay-covers-text`(新) |
| **関係の端**: コネクタの矢じり(端から 12px)、他の吹き出しのしっぽの先(先から 8px)。コネクタの線の 50% 以上 | **問題** | `overlay-hides-link`(新) |
| **塗りと枠**: 箱・枠・帯の背景と縁線、他の吹き出しの本体の塗りと縁 | **許す**(報告しない) | — |
| **コネクタの線**(端と 50% 以上を除く) | **助言** | `overlay-covers-connector`(新) |
| 空き | 自由 | — |

- **理由**: 吹き出しの目的は「ここを見て」と添えること。箱の背景を少し覆うのは普通の見た目(Office の吹き出しも箱の上に載る)で、報告すると配置が窮屈になる。文字を隠すのは、図が読めなくなるので問題。コネクタの線を横切るのは、読めるが図が汚れるので助言(Q3。決める人。推奨は助言)。矢じりと先は、**どこからどこへ**を決める部分なので、隠すと関係が読めなくなる(問題)。
- **幾何**(0077 D8 の SAT を広げる):
  - 文字・アイコンの矩形は、**配置の文字の矩形**(各箱の `textRect`、コネクタのラベルの `labelBox`)。目標の文字も同じ。測定のゆれ 0.0156px は、0.5px² の等値の幅に吸収される(スパイクで、選ばれる候補は ±1px まで変わらなかった)。
  - 吹き出しの輪郭は、本体(角丸の矩形は弧を折れ線で近似した凸多角形)とそのしっぽ(三角形)の**2 つの凸多角形**。覆う面積は、凸多角形どうしの切り取り(Sutherland-Hodgman)の面積で、**0.5px² を超えたら**覆うとする(0077 D8 と同じ閾値)。**雲**は凸でないので、凸包で近似する(覆いを多めに見る。文字を隠さない方向の誤り)。しっぽの円(雲)は円の外接正方形。
  - コネクタは折れ線(経路)で、吹き出しの内側に入る長さを 0.5px 刻みで数える。
  - 1 つの (吹き出し, 下のもの) の組につき、**報告は 1 つ**。優先は 内容 > 関係の端 > コネクタの線。
- **変わる既存の検査**(二重報告を避けるため):

| 既存の検査 | `flow` | `overlay` |
|---|---|---|
| `balloon-tail-box`(しっぽが他の箱を横切る。問題) | そのまま | **使わない**。箱の中身は `overlay-covers-text`、塗りと枠は許す |
| `balloon-tail-through-target` | そのまま | そのまま。ただし同じ目標の文字が `overlay-covers-text` で報告されるときは出さない(1 つの誤りに 1 つ) |

### D4. `overlay` の自動配置(決定的)

**候補**: 目標の矩形のまわりの **8 方向(東・南東・南・南西・西・北西・北・北東)× 距離 12 / 28 / 48px**(目標の縁と本体の最寄りの縁の間)の 24 個。本体の位置は 4px の格子に丸める。しっぽの先は、本体の中心に最も近い目標の縁の点から、本体のほうへ `gap`(既定 4)出した点。しっぽが作れない候補(0077 D3 の縮退)は候補にしない。

- 辺つきの `to`(`step2.top`)のときは、その辺に向く方向だけ(上なら 北・北東・北西)。

**点数(辞書式。上の項目が等しいときだけ、次を見る)**:

1. 覆う**内容**の面積(D3)。**0.5px² 以内は等しい**(`eps = 0.5`)
2. 隠す**関係の端**の数(矢じり・他のしっぽの先)
3. 覆う**そのほか**: 箱の塗りの面積 + 12 × (覆うコネクタの長さ px)(12 は暫定の重み: 太さ 2px の線 + 余白 10px)
4. 距離(12 → 28 → 48。近いほどよい)
5. しっぽと交わるコネクタの本数
6. 候補の順番(距離が近いほう → 方向は 東・南東・南・南西・西・北西・北・北東)。**固定の順で、必ず 1 つに決まる**

- スパイクは 1・3・4・5・6 を実装した(2 は未実装。例の図にはコネクタの矢じりを隠す候補がほとんど無い)。点数の重み(12)と `eps` は暫定で、U2 の例の図で決める。
- **手動の上書き**: `at: 'ne'`(方向を 1 つに絞る。距離は探す)、`dist: 28`(距離を絞る)、`at: [dx, dy]`(本体の中心を、目標の中心からの相対で固定。探索しない)、`tip: [dx, dy]`(0077 D3。しっぽの先だけ指定。本体の位置は探す)。**手動の吹き出しは先に置き**、自動のものがそれを避ける。手動の置き方が文字を覆うときは、そのまま描いて D3 の検査が報告する(勝手に動かさない)。
- **図の範囲(0077 Q14 のまま)**: キャンバスは広げない。本体としっぽの点がキャンバスの外に出る候補は**候補にしない**。どれも収まらないとき、範囲を無視して最良を選び、`balloon-out-of-bounds`(問題)で報告する。
- **複数の吹き出し**: **宣言順**に置く。**先に置いたもの**(本体は「そのほか」、文字の矩形は「内容」)が、あとのものの障害物になる。あとから置くものは、前のものを動かさない(貪欲)。`z` は描く順だけで、配置の順には影響しない。1 つが変わると後ろが変わりうる(貪欲の性質)ので、安定性は 1 つずつ測る。
- **決定的であること**: 同じ図は同じ置き場所になる(文字の矩形が同じなら)。文字の矩形の測定のゆれは、`eps` と候補の差の余裕で吸収する。スパイクでは、**全部の文字の矩形を ±0.0156px ずらしても、選ばれる候補は 2760 回中 0 回しか変わらず**、±1px でも変わらなかった(920 回。±4px で 4%)。ただし、**候補どうしが 1px² 以内で拮抗する図**は測っていない。そのときは固定の順(6)が決める。
- **性能**: 1 つの吹き出しが約 0.5〜0.9ms(24 候補。文字の矩形 9〜46)。コネクタが多い図ではその走査が大半(U2 で、線分ごとの外接矩形で絞る)。
- **配置の段**: `resolveBalloons`(0077 D2)は、**コネクタの経路が決まったあと**に `overlay` の吹き出しを置く(障害物にコネクタの経路を使うため)。コネクタの経路は吹き出しを避けない(CRT の層の順や辺の経路探索には見えない。0077 D5 と同じ)。

### D5. マンガのふきだし(`comic()`)

**決定**:

1. **重なりの深さの上限は 8px**(`OVERLAP_MAX = 8`。`PAD_Y − 2`)。根拠: スパイクで、深さ 8 までは本体の重なりがもう一方の文字を覆わず、**12 では 324 通り中 252 通りで覆う**(上の表)。方向は**縦だけ**(積むときの上下の重なり)。横に並ぶものは今の規則のまま(横の範囲が重なれば積む)。
2. **いつ重ねるか(推奨)**: 今の隙間 6px で帯に**入るときは今のまま**(既存の golden が変わらない)。**入らないとき**だけ、隙間を 0 に詰め、それでも入らなければ深さを 4、8 と増やす(1 個ずつ 4px の格子)。`comic()` の項目 `overlap: 0 | 4 | 8`(任意)を足すと、書き手が最初から重ねを指定できる(重ねを使うと、しっぽを隠す絵になる。D5-3)。**配置は行数だけで決まる**(穴の値に依らない。0074 D4 / D5 の不変条件)。
3. **積みの上下(`z`)**: ふきだしの `z` の既定は、**あとに読むほうが上**(`dialogue` の後のものが手前)。ふきだしの項目 `z` で上書きできる(Q2。決める人)。
   - 慣習の確認: 「先に読むふきだしを手前にする」という作法をよく聞くが、**この ADR を書く間の検索(1 回)では、一次資料で確かめられなかった**(見つかった範囲では、読む順は左上から右下へ、しっぽは交差させない、重なりは重要度や発言の続きを示す、とあった(BnF の資料、クリスタのヒント、Shanower のブログ))。したがって「慣習だから」ではなく、**この配置の幾何**で決める: 上の(先に読む)ふきだしのしっぽは下の話し手へ**下向き**に伸び、下の(あとに読む)ふきだしの上を通りやすい(324 通り中 180)。**先のふきだしが手前だと、その 180 通りすべてでしっぽが後のふきだしの本体と文字の上に描かれる**(今と同じ問題が残る)。**あとのふきだしが手前なら、しっぽは後ろに入り、先は下に出る**(先まで見えなくなるのは 12〜24 通り)。
   - 比べた案: (A) 先が手前(慣習とされる。しっぽの問題が残る)、(B) **あとが手前(推奨。しっぽが下に潜る。単純)**、(C) 組ごとに決める(しっぽが通る側のふきだしを手前にし、通らない組は先が手前。しっぽが互いに通る循環は宣言順に戻す。見た目はもっとも自然だが、規則の説明が重くなる)。
4. **しっぽ**: しっぽは自分の本体と同じ z(1 本の経路)。
   - `comic-tail-crosses-bubble`(0074。しっぽが別の話し手のふきだしの後ろを通る。問題)は、意味を変える: **しっぽが、自分より手前(z が上)にないふきだしの上を通る**ときだけ問題(しっぽが他のふきだしの上に描かれる)。手前のふきだしの後ろに潜るしっぽは**許す**。
   - 新しい検査 `comic-tail-hidden`(問題): しっぽの先、またはしっぽの 90% 以上が、手前のふきだしの本体に隠れる(誰が話しているか分からなくなる)。
   - **同じ話し手の 2 個のうち、上のふきだしのしっぽを描かない規則(0074 U1)は変えない**: 同じ話し手の 2 個は 1 つに読ませたいので、しっぽは下のふきだしだけが持つ。この規則が働く条件は「上のしっぽが下のふきだしの後ろを通る」のままで、z に依らない(`tailCrosses` は幾何だけで判定する)。
5. **文字は覆わない**: 新しい検査 `comic-bubble-covers-text`(問題): ふきだしの輪郭(しっぽを含む)が、別のふきだしの文字の矩形(穴の矩形を含む。穴は最大の幅で数える)を 0.5px² 超覆う。深さの上限 8px(1)と、手前のふきだしのしっぽが文字を覆わない(`comic-tail-crosses-bubble`)で、通常は出ない(手動の `overlap` / `z` / `anchor` の上書きで起きる)。顔・マンプ・小道具と重ならない規則(0074 `comic-bubble-face`、0076)は**変えない**(重なりを許すのは**ふきだし同士だけ**)。
6. **描く順**: 0076 D1 の層の順の「ふきだしの輪郭 → ふきだしの文字と穴」を、**ふきだしごとの対**(輪郭 → その文字と穴)にして、z の昇順に並べる。マンプ・小道具・顔・胴より上、は変えない。
7. **幾何の地図**: `bubbles` の項目に `z`(整数)を足す。`tails` はしっぽが手前に隠れる割合(`hidden: 0..1`)を足す(0076 A10 の追加)。値(穴の中身)は地図に入らない。
8. **0074 D4 / D5 の不変条件**: 深さ・z・隠れる割合は、**行数(最大の幅で数えた)とふきだしの順だけ**で決まる。穴に値を入れても動かない。

### D6. PPTX への書き出し(順序と材料。実装は 0077 の範囲外のまま)

- **`overlay` の吹き出しは、z の昇順に、図形・ネイティブのコネクタのあとに足す**(`spTree` の末尾。PPTX は XML の順がそのまま重なりの順)。図形(L0)→ コネクタ(L1)→ 吹き出し(L2)で、SVG と同じ順になる。
- 吹き出しは絵(SVG + PNG。0077 D2 の判断。halo を含む)で、**1 つの図形(`p:pic`)**。`descr`(代替の文字)に文字と目標の id を入れる。**見えない図形でののり付け(glue)は付けない**(`overlay` はコネクタの端にならない(D1)。のり付けが要るのは `flow` だけ)。
- 絵の矩形は、本体 ∪ しっぽ ∪ halo の外接矩形(0077 D2 と同じ)。
- マンガの帯は 1 枚の絵(0074 D5 の書き出し)なので、ふきだしの順は SVG の順がそのまま絵になる。帯を図形にするとき(未定)は、ふきだしを z の昇順の図形にする。
- 吹き出しの文字は PowerPoint で編集できない(0077 D2 と同じ)。

### D7. 0074 / 0076 / 0077 の変更

下の表のとおり。0077 は PR #435 で承認済みなので、マージのあと、この ADR の採用と同時に 0077 の状態の行へ「ADR 0078 が一部変更」を足す(ドキュメントの PR)。

## 代替案(全体)

1. **重ならないままにして、空きを自動で作る(0077 のまま)**: 流れの中で目標のそばに空きを作るには、配置が目標に引かれて循環しうる(0077 D5 が断った)。吹き出しの数だけ他の帯が動く。**却下**。
2. **`overlay` のみ(`flow` を捨てる)**: 吹き出しが内容そのもので並ぶ図(会話の列)で、行の高さに加わらない。**却下**(`flow` は 0077 の設計をそのまま活かせる。費用は小さい)。
3. **すべての重なりを許す(検査なし)**: 文字が隠れても通る。**却下**(D3 の「内容」だけは問題にする)。
4. **重なりを許し、箱の背景は助言にする**: 注記の吹き出しはほぼ必ず箱の背景に触れるので、助言だらけになる。**却下**(許す)。
5. **`z-index` を使う**: SVG に `z-index` は無く(CSS の `z-index` は SVG 2 の要素に効かない環境がある)、DOM の順で決めるほうが PPTX の順と一致する。**却下**。
6. **自動配置を点数の重みの合計にする**: 面積と距離を 1 つの数にまとめると、重みの調整が全図に影響し、結果が説明しにくい。辞書式は「文字を覆うものを絶対に選ばない」を保証できる。**却下**。
7. **自動配置を最適化(焼きなまし・力学)にする**: 決定的にできるが、候補が 24 個で足りるので不要(スパイク 0.5〜0.9ms)。複数の吹き出しの全体最適は**後の ADR**(貪欲で足りなくなったとき)。
8. **マンガで深さの上限を設けない**: 12px 以上で文字が覆われる(252 / 324)。**却下**。

## テスト方針

- 純粋な核(U1)は単体テストと性質テスト。検査(U3)は悪い図ごと。`comic` は 324 通りの表と値の不変条件のテスト。golden は `scripts/golden-docker.sh`(既存の golden は変えない)。
- この ADR の PR は文書とスパイクだけで、`lib/` を変えない。`pnpm typecheck` が通る。

## 質問と決定(決める人。推奨を付ける)

| Q | 質問 | 推奨 | 理由 |
|---|---|---|---|
| Q1 | `balloon()` の既定の置き方 | **`overlay`**。`flow` は `place: 'flow'` | D1。流れの中に置くための費用(空きの確保、`balloon-tail-box`、PPTX の絵の置き方)が要らず、足し引きで既存の図が動かない。0077 は未実装なので、既定を変える費用は 0 |
| Q2 | マンガのふきだしの重なりの上下の既定 | **あとに読むほうが手前**(`z` で上書き可) | D5-3。先が手前だと、しっぽが後のふきだしの上を通る 180 / 324 通りのすべてで本体と文字の上に描かれる。あとが手前だと、しっぽが後ろへ潜る。「先が手前」という作法は、この ADR を書く間の検索では確かめられなかった(重なりは重要度を示すという資料はあった)。決める人が作法を知っていれば、(A)先が手前 を選んでもよい(その場合、しっぽの問題は 180 通り残る) |
| Q3 | コネクタの線を覆うことを許すか | **許す(助言)**。矢じりと線の 50% 以上は問題 | D3。「ここを見て」の吹き出しは線の上を通ることが多い。矢じりは「どこへ」を決める |
| Q4 | マンガの重なりの深さの上限 | **8px**(`PAD_Y − 2`) | スパイク: 12px から文字が覆われる(252 / 324) |
| Q5 | マンガの重ねを、隙間 6px で入るときも使うか | **使わない**(入らないときだけ。`overlap` で書き手が指定) | 既存の `comic` の golden を変えない |
| Q6 | 箱の背景(塗りと枠)を覆うことを許すか | **許す**(報告しない) | D3 |
| Q7 | halo(紙色の縁取り) | **`overlay` だけに付ける。U3 で例の図を見て、不要なら外す**(暫定) | 暗い塗りの箱の上で縁が見えるため。目で確かめていない |
| Q8 | `overlay` の吹き出しをコネクタの端にしてよいか | **しない**(エラー。端にしたいときは `flow`) | 位置が配置のあとに決まり、循環する(D1) |
| Q9 | 自動配置の点数の重み(`eps = 0.5`、コネクタ 12px²/px) | **暫定**。U2 の例の図で決める | スパイクの図は空きが多く、拮抗する場合を測っていない |
| Q10 | 同じ話し手の 2 個のふきだしの、上のしっぽを描かない規則 | **変えない** | D5-4。z で隠れても、同じ話し手の 2 つのしっぽは口が 2 つに見える |
