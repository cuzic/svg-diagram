## 用語(この ADR の全体で 1 回だけ定義する)

- **最初の並び / `base`**: 書いた順の並びを、迂回(`noDetour`)なし・同じ幅の当てはめ(`sameFit`)で置いた図(`toc.ts` の `base`。探索の基準)。**`first`** は同じ並びを迂回つきで置いた図(最終の選びの出発点。`base` と高さがほぼ同じ)。**`best`** は探索がこれまでに採った最良の図(`bestScore`)。**`pick`** は最終の選びの、これまでの最良(`pickScore`。最初は `first`)。
- **高さ `h`**: `LaidOutCause.h`。**交差 `crossings`**: `scoreOf(辺の点列).crossings`(AND の矢印どうしの交差も含む、全辺の交差の数)。**AND の交差**: `andClashes(..., 'crosses')` の数。**AND の並走**: `andClashes` の `crosses` 以外の数。
- **組 `pairs(P, sep)`**: 経路の点列 `P` の、異なる 2 本の経路の run の組を数えた和。1 本ごとに `runsOfRoute` で run にし、2 本ずつ `runPairWays(a, b, sep)` の `level + plumb` を足す(`polyline-metrics.ts`。測定の `pairsAt`)。つまり (a) 同じ向きの run が `sep` 未満で並び、重なりが 4px を超える組(`parallelRuns` の組)と、(b) 同じ線の上にあり、端が `sep` 未満しか離れていない組(`parallelRuns` が数えない)の合計。**`sep` は 1 つの式 `laneStepOf(space × scale) = round(14 × space × scale)`**(`space` は `density`、`scale` は canvas の線の倍率 `lineScale`。倍率なしで描く図は 1)。実装では `layoutCauseBandAt` が 1 回だけ求め、探索の採点と `layeredAttempt` の `better()` の両方へ同じ値を渡す(測定の `toc.ts` の `curSep` と `layered-route.ts` の `laneStepOf(unit)` は同じ式)。`edge-parallel`(`rules.ts`)の `sep` も同じ式だが、倍率を外した帯(`lineScaleDropped`)は、検査が倍率つきの間隔で測る(ADR 0070 D7)のに対し、組は実際に描く線の間隔(14px)で数える。
- **層の順位**: 層に沿う座標の値を、0.5px 以内を同じとして昇順に並べた順位(下の D1 (e))。
- **組だけの改善(pairs-only)**: 候補が、その段の候補の一覧の中で「窓」(D2 の折れの上限)に入り、**組の少なさだけで**選ばれること。**AND の交差を消す動きは、組だけの改善ではない**: `better()` でも探索の採点でも、AND の交差(`better()` では `andCrossings`。`layered-route.ts` の `apartOf` が使うもの。AND の組が無い図では無い)は、交差と並べて先に比べる(AND を先に比べる順)ので、交差の総数が同じで AND の交差が減る経路は、窓の外から勝ち、**折れの上限は掛からない**。
- **採点 `score(t)`**: `[AND の交差, AND の並走, 交差, 組, 折れ]`(辞書式で小さい方が良い。D2 で組を入れる)。`lexLess` は 2 つの採点を辞書式で比べる。

## 論点(2026-11-21 に決定済み)

- **Q1(高さ)**: 交差が減るなら、高さを何 % まで払うか。**決定: 高さの高い候補は、交差が減るときだけ採る。上限は最初の並びの高さの 1.25 倍まで。層の比べ方は層の順位**(D1)。
- **Q2(組)**: 並走の組を減らす代わりに、折れが増えてよいか。**決定: よい。順位は (交差, 組, 折れ, 高さ)(高さは同点の最後の key。D1-2)。`better()` と探索の採点の両方で使う**(D2)。折れの増えは、組だけの改善では +4 まで(D1-4)。
- **Q3(層の並び)**: 層の並びそのものを探す探索(焼きなましなど)を入れるか。**決定: 後で**。この ADR の実装(U1〜U4)の後に測り直し(U5)、その結果でスパイクと別の ADR を決める。この ADR では入れない。
- **Q4(利用者に確かめる)**: 点 4 がどの線か。**回答(利用者、2026-11-21): 点 4 は取り下げられた**。指していたのは、箱(fixture の e2)の上の辺から並んで出る 3 本(e2 → e4・e2 → u2・e2 → e3)で、U4 の時点の約 20px 間隔が入る矢印に見えた。U5 の後は 28px で読める。真ん中の線が横切る 1 本は 5 つの交差の 1 つ(e2 → u2 × e3 → u3)で、点 1 に属する(ADR 0070 Q6)。この ADR の作業は増えない。

### D1: 順序探索の採点とふるい

選択肢:

| 案 | 内容 | 測定 |
|---|---|---|

| B | 高さのふるいを外す | 交差 344 → 320(7 枚)・183 → 172(5 枚)。高さ +490px(13 枚、最大 +87px = +19%) |
| **C(決定)** | **高さと交差の交換**: 基準より高い候補は、**交差が厳密に減る**ときだけ、最初の並びの高さの 1.25 倍まで採る。ふるいを通る候補・最終の選びの両方に同じ規則 | B と同じ利得(344 → 320、183 → 172、`cause-crossing` 35 → 29・19 → 16)。高さが増える図は 11 + 8 枚(+0.55%)。D1 単独の最大は #106 +24%・#75 +19%、全部入りの最大は幅 1800 で +15%・canvas で +10%。費用は「影響」の費用 |

#### 規則(規範)

候補 `t`(最初の並びと違う並びを、`sameFit` で置いた図)について、次を**この順に**判定する(`toc.ts` の探索ループと最終の選び)。

- (a) **土台の条件**(今のまま): `NoFit` でない、`loose` の数が `base` 以下、`fitApplied` の数が `base` と同じ、層の順位が `base` と同じ(e)。1 つでも外れる候補は採らない。
- (b) **高さが `base.h + 0.5` 以下**(ふるいを通る): 今までどおり。`lexLess(score(t), score(best))` のときだけ採る。
- (c) **高さが `base.h + 0.5` を超える**(高い候補): 次の 3 つが**すべて**成り立つときだけ採る。
  1. `t.h ≤ 1.25 × base.h`(上限は **`base`、つまり最初の並び**の高さが基準。`best` の高さではない。採った高い候補が次の高い候補の基準になることは無い。`best` がどれだけ高くても、上限は `1.25 × base.h` のまま)。
  2. `crossings(t) < crossings(best)`(**これまでの最良 `best`** の交差より厳密に少ない。最初の並びとの比べではない)。**これは交差の総数**(AND の交差でも組でもない)。
  3. `lexLess(score(t), score(best))`(下の「AND を先に比べる key との関係」)。
- (d) **最終の選び**(`pick`): `found`(最良の並びに迂回を付けた図)と `best` の各々に、(a)・(b)・(c) を同じに適用する。`best` の代わりに `pick`・`score(best)` の代わりに `pickScore` を使う(最初は `first`)。高い候補は `crossings(t) < crossings(pick)` が要る。
- (e) **層の順位**: `base` の各節の層に沿う座標を並べた順位と、`t` のそれが**全節で同じ**ときだけ同じ層とみなす。順位は、座標の値を昇順に並べ、隣り合う値の差が 0.5px を超えるところで順位を 1 つ上げて付ける(0.5px 以内は同じ順位)。**測定の `probe.patch` は `Math.round(2v)/2` の格子で丸めた値を比べていた**(0.02px 離れた 2 つの値が別の格子に入りうる)。この ADR は差の 0.5px で連結する形にする(本物の違いは、座標が格子の倍数でない隙間で起きる)。差で連結する版(`rankEps`)を測り直した結果、**乱数の 218 枚すべてで、格子の版と点列が同じ**(境界をまたぐ値は、この標本には無い)。
- (f) **打ち切り**(`PATIENCE` 30・`PATIENCE_QUIET` 14・`MAX_ORDERS` 60 と `lastBetter`)は変えない。数えるのは今までどおり、**配置を試みた並びすべて**(予想 `proxy` で飛ばした並び、(a)・(b)・(c) で捨てた並び、`NoFit` の並びを含む)。**採られた高い候補は、`lastBetter` を更新する**(ほかの採る候補と同じ道。測定の probe もそう)。高さ・交差の条件で捨てた候補は `lastBetter` を更新しない。`bestProxy` も採った候補で更新する(今まで同じ)。
- (g) **canvas の再配置との関係(PR #402 の `fitLineScale`)**: 高い並びは、帯の `heightBudget` を通っても、まわりの帯と合わせた図が canvas の高さを超え、図全体の再配置で**倍率の線を外させる**ことがある。その順序を決める: 図全体の再配置は、(1) 高さの交換**あり**で倍率つき、(2) **交換なし**(`(c)` を使わず、(b) だけ)で倍率つき、(3) 帯を 1 つずつ倍率なしにする(今の `fitLineScale`。ここも交換なし)の順に試し、収まった最初を採る。**したがって高さの交換が `lineScaleDropped`(`cause-line-scale-dropped`)の原因になることは無い**(交換なしの (2) で収まる図は、main と同じ規則で描かれる)。旗は `layoutBands` に渡す `lines` の object(`{seen, drop}`。`fitLineScale` が作る)に `exchange: boolean` を足して持つ(最初の配置は `true`、(2) と (3) の再配置は `false`)。帯ごとの `layoutCauseBand` は `layoutCauseBandHere` を通して同じ object を読む。**費用**: (2) は `fitLineScale` の今の条件(`contentHeight > canvas.height`)で動くので、**交換と関係の無いはみ出しでも、1 回余分に全体を配置する**。(2) でも収まらなければ (3) の再配置が続く。つまり、はみ出す図の全体の配置は **1 + 1 + `seen`(帯の数)回まで**(今は 1 + `seen` 回)。測定の乱数の canvas(帯 1 つ、2400×1800)では、どの版でも `lineScaleDropped` が増える図は 0 で、この道は走らない。**複数の帯の図は測っていない。U1 で、下のテスト 9 の入力で 1 回測る**(旗を実装した版で、(2) の費用と結果を PR に書く)。

#### AND を先に比べる key との関係

探索の採点 `score` は今までどおり **AND の交差を先に**比べる(ADR 0019 D4。AND の弧が交差する矢印の上で読み誤るのを避けるため)。Q1(「高い候補は交差が減るときだけ」)との関係は次のとおり。

- 高い候補を採る条件は、`lexLess`(AND 先)**に加えて**、交差の総数が厳密に減ること(c-2)。`lexLess` だけでは、AND の交差が減る代わりに交差が増える高い候補が通る。それを (c-2) が止める。**高い候補で、交差が増える・同じものは、どの経路でも採られない**。
- 高さが `base.h + 0.5` 以下の候補(b)は、今までの規則のまま。AND の交差が減る代わりに交差が増える候補を採りうる(ADR 0019 D4 の既存の規則。この ADR は変えない)。乱数の 218 枚では、交差が main より増える図は 0(D2 を単独で入れたときの #137 を除く。下の D2)。**決定(2026-11-21、オーナー): AND を先に比べる今の順を保つ**。AND の交差を 1 つ消すために、交差の総数が増える候補を (b) で採ることは**意図した動き**で、変えない。したがってピン P1 は「交差が main より増えない」でなく、「交差が増える図は、AND の交差が減っている図だけ(ピンに記録する。乱数の 218 枚では 0 枚)」とする。高い候補 (c) には、この交換は無い(c-2 が止める)。
- 測定の `probe.patch` の `height: 'xdrop'` は、(c-2) の代わりに「採点の先頭 3 つ(AND の交差・AND の並走・交差)の辞書式で小さい」だった(AND の交差だけが減る高い候補も通る形)。**規則どおりの版(`height: 'xcross'`)を測り直した結果、218 枚すべてで xdrop と点列が同じ**。つまりこの ADR の規則は、測定した数値と一致する。

#### 規則から出る帰結(測定した)

- 比べる相手が `best`(走っている最良)であり、最初の並びでも main の最終の図でもない。そのため、**採った高い候補が、main が最後に探し当てる交差の同じ低い並びより高いまま**になる図がある(高さの key の前の測定)。幅 1800 で #37・#42・#84・#99・#114(+2px)・#136(D3 の道の変化)の 6 枚、canvas で #13・#37・#42 の 3 枚(いずれも、最終の交差は main と同じで、高さだけが +18〜+84px 上がる)。理由(高さの key の前): 高い候補を先に採ると、後から見つかる「交差が同じで低い」並びは `lexLess` で厳密に良くならず(その版では高さが採点に無い)、採られない。次の決定で高さが最後の key になり、この理由は消える。
- **決定(2026-11-21、オーナー): 高さを採点の最後の key にする**(同じ採点なら低い並びが勝つ。測定の `tieH`)。探索の採点は `[AND の交差, AND の並走, 交差, 組, 折れ, 高さ]`、`better()` の key は (交差, 組, 折れ, 高さ)。高さは `Math.round(h)` の整数で比べる。測定(探索の採点に入れた版): 採った高い候補が main より高いまま残る図が、幅 1800 で **6 枚 → 3 枚**(#37・#84・#99 が直る。#99 は +84px → −8px)、canvas は 3 枚のまま(変わる図は 29 → 31 枚)。残る #42・#114・#136(幅 1800)と #13・#37・#42(canvas)は、探索の道の変化によるもので、同点の高さの比べでは直らない。**`better()` の key に入れた版は測っていない**(U1 で測る)。高さの key は、高い候補の交換(D1 の (c))と別の働きで、(c) の上限・交差の条件はそのまま。高さが最後なので、採られた高さだけの改善も `lastBetter` を更新する(待ちが延びる。費用は U1 で測る)。

#### その他の D1 の決定

- **打ち切り**は (f) のとおり変えない。外すと 60 節で 2.2s → 8.5s(×3.9)、交差の利得は −3%(344 → 335)。飛ばした並びを数えない版も、費用(60 節 3.2s・120 節 10.8s)に見合わない。
- **予想(`proxy`)のふるい**は今のまま(外しても 1 枚しか変わらず、費用だけが増える)。
- 高さを**唯一の**交換の手段にする案(`height: 'key'` だけ、交換なし)は、交換(C)より利得が小さい(試した: 交差 −7% は同じだが折れ・組が増える図が増える)ので採らない。決定した最後の key(`tieH`)は、C に足す形。
- **純関数**: `mayBeTaller(t: {h, crossings}, base: {h}, best: {crossings}): boolean`(`t.h ≤ base.h + 0.5` なら true、そうでなければ (c-1) かつ (c-2))と、`layerRank(values: number[]): number[]`(e)を `toc.ts` から export して単体で試す。探索ループと最終の選びは、この 2 つだけを呼ぶ。

- 決定は (c): **ranking key は (交差, 組, 折れ, 高さ)**(高さは D1-2 の最後の key)。`better()`(`pick0`・`worse`・`apartOf`)と、探索の `scoreOfCause` の**両方**に入れる。探索の採点は `[AND の交差, AND の並走, 交差, 組, 折れ, 高さ]`(AND を先に比べる key に、組を交差と折れの間へ足し、高さを最後に足す)。`better()` が見る高さは `Attempt.size.h`(層の配置後・canvas の当てはめの前の、図の高さ)。同じ並びで経路の選び方だけが違う案どうしでは高さが同じ(層の座標が同じ)ので、`better()` では高さは効かず、並びの違う案を比べる探索の採点で効く(U1 で、同じ並びの案の `size.h` が同じことを確かめる。違うなら `better()` の key から高さを外す)。組の数え方と `sep` は用語のとおり 1 つの式。
- (b) は安全だがほとんど効かない。採るなら代替の弱い版(「探索の採点だけ」)。
- **D2 だけでは、交差が増える図がある**: 乱数の幅 1800 で #137 の交差が 1 → 5 になる(測定: 折れ +6、組 1 → 0。探索の道が変わるため。D1・D3 と一緒にすると 0 に戻る)。最終の選びは辞書式で交差が先なので、**選びの規則から起きるのではなく、探索が別の並びを見つけた結果**。そのため規則のガードは足さず、**ピン P1(図ごとの交差が main より増えない)で守る**(U2 は U1 の後なので、実際には #137 は起きない見込み。後の変更で再び起きれば、P1 が落ちる)。

#### 折れが増える図と、受け入れる図(測定: D1 + D2 + D3 の全部入り、main との図ごとの差)

| 幅 1800 #130 | 38 → 42(+4) | 交差 6 → 4(組は 1 → 3 に増える) |

合計は 3770 → 3762(−0.2%)・2190 → 2166(−1.1%)で、全部入りでは減る(D3 が −58・−40 を出すため)。D2 だけでは +54(+1.4%)・+20(+0.9%)。**合計の基準は、D3 が減らした分で隠れるので、単独では意味が無い**(レビューの指摘のとおり)。

- **図ごとの基準(提案。P4)**: **各ピンの図について、最終の図の折れ ≤ 「組の key を切った同じ版(`pairs`・`sPairs` を外す。ほかは全部入りのまま)の図の折れ」+ 4**。原因を問わず、組の key が足せる折れを +4 までにする(オーナーの上限そのもの)。**例外は規則で決める**: 最終の図の AND の交差が、組を切った図の AND の交差より少ないときは、折れの増えを許す(AND を先に比べる順の結果で、P1 の AND の例外と同じ条件。図の名前では決めない)。**組を切った版との差の測定**(上限の前、全部入り − 組を切った版): 幅 1800 で #48 +20(AND の交差が −2 なので例外)・#143 +14・#103 +4・#114 +4、canvas で #75 +20・#61 +14・#67 +4・#34 +2。**+4 を超えて例外でもない図は、幅 1800 の #143、canvas の #75・#61 の 3 枚**で、下の折れの上限で外れる見込み(外れなければ P4 が落ちるので、見つかる)。#101(+12)は、組を切った版も +12 なので、組の key のせいではなく、P4 の外。#13 は組を切った版と同じ折れ。
- **受け入れる図(上限の測定前の一覧)**: 例外は規則(AND の交差が組を切った図より少ない)で決まり、名前を持たない。上の 3 枚(#143・#75・#61)は、組の key が +14〜+20 の折れを足している図で、折れの上限で外れる見込み。#13・#67 は P4 の内。
- **折れの上限(決定 2026-11-21、オーナー: +4)**: 上限は、**各段で、その段が作った候補の一覧の全体に対する選択**として定める。2 案ずつの比べ(`better(a, b)`)を畳み込む形にはしない(窓つきの 2 案の比べは推移的でなく、3 案で循環する。例: 組 0・折れ 9 の a、組 1・折れ 5 の b、組 2・折れ 1 の c は、a が b に、b が c に、c が a に勝つ)。選択は次のとおり(同じ一覧なら、並べる順に依らず同じ案を選ぶ):
  1. 一覧の各案の **C** を比べ、最小を取る。**並びの探索では C = (AND の交差, AND の並走, 交差)**(探索の採点の先頭 3 つ。用語の `score` と同じ)、**`better()` では C = (交差) だけ**(AND の交差は key に持たない。`aside`・`apartOf` が `andCrossings` の増えを別に止める。AND の交差を減らすための窓の突破は、並びの探索の段にだけある)。
  2. C を持つ案のうち、折れの最小を b* とする。
  3. 窓は、C を持ち、折れが b* + 4 以下の案。
  4. 窓の中から、(組, 折れ, 高さ)の最小の案を選ぶ。同じなら一覧の先の案。
  - **一覧を見る場所**: `pick0`・`sharing`(`layeredAttempt` が複数の案を作る段)は、案の一覧に上の選択を 1 回掛ける(関数 `selectAttempt(list)`)。2 案だけの段(`worse(a, b)`・`apartOf` の「前と後」)は、2 案の一覧への選択と同じ(窓は b* の案が必ず入り、窓の外の案は無いので、2 案では組の少ない方を折れの差が +4 以内のときだけ採る、と同じ)。U2 で、`better()` を 3 案以上に畳み込んでいる呼び出しの一覧を作り、すべて `selectAttempt` に直す。
  - **並びの探索(`toc.ts`)**: 試した並びのうち採りうる案((a)〜(e)と、高さの (b)・(c) を通ったもの)の**採点を、全部保つ**(最大 `MAX_ORDERS` 60 個。重いのは配置した図で、窓に入る案のものだけ保てば足りる: 窓は、C が下がれば前の案がすべて外れ、C が同じで b* が下がれば縮むだけなので、窓の外へ出た案は二度と戻らない)。案が来るたびに、保った一覧に上の選択を掛け直し、**選択された案を、その時点の `best`(`bestScore`・`bestOrder`・`bestProxy`・`lastBetter`)とする**。選択が別の案に変わったとき(窓の中で組・折れ・高さが良い案が来た、または窓が縮んで前の案が外れた)に `lastBetter` を更新する。**探索の終わりでの置き換えは無い**(いつも選択された案が `best`)。高い候補の条件 (c-2) の `best` も、そのときの選択。最終の選び (d) は、`first`・`found`・探索の `best` の一覧に、同じ選択を 1 回掛ける。
  - 段ごとの上限は、窓から来る(1 段が足せる折れは、旧い key の最良に対して +4 まで)。**段を重ねた図ごとの増えは、この規則だけでは守れない**ので、最終の図の上限は P4(組を切った同じ版との比べ)で守る。
  - **U2 で測る(未測定)**: 影響を受けるのは #143・#75・#61 の見込み(上の P4)。この 3 枚の組だけの交換は採られなくなり、組が増える(または同じ)側に動く。U2 の PR で、組の合計・図ごとの組を測り直し、ピンを更新する。
- **組の増える図**(同じ全部入り。**上限と高さの key の前の測定**): 幅 1800 で #42・#99・#102 が +1、#130 が +2、canvas で #42・#71 が +1。基準は「**ピンの図以外で組が増えない。組の合計は main(幅 1800 で 43・canvas で 30)以下**」。ピンの図の数と上限の値、合計の余裕は、U2 で測り直して決める(前の版の 42・26 以下は、上限で #143・#61 の組が戻り(各 +1)、余裕が変わるので外した)。
- **D3 が組を増やす件(M2 の指摘)**: D3 の採る条件の `gainsRunPairs`(後述)は局所の検査(`routeOnce` の `gains`。**図の倍率つきの間隔 `laneStepOf(space × scale)` で測る**。`routeOnce` の中の `LANE` はこの値)で、**最終の図の組を保証しない**。D3 だけを入れると canvas の #11・#51 が 0 → 1 になる。D2 と一緒にすると 0 に戻る(測定。理由は未確認)ので、**U3 は U2 の後に入れ、組の合計・図ごとを U3 の PR で測り直す**。

### D3: AND の矢印の段差(点 2)

選択肢: (a) 今のまま(段差 28px)。(b) `align` に AND の矢印も通す(両方の口を 1 つの高さに寄せる)。**(c)(決定)頭の口は動かさず、尾の口だけを頭の高さへ寄せる**(`align(i, tailOnly)`)。

| 案 | fixture | 乱数(折れ / 図の数) | 弧・口 |
|---|---|---|---|
| (a) | 折れ 56、段差 2 本 | — | — |
| (b) | 折れ 50、段差 0 | −68(29 枚)/ −42(18 枚) | 頭の口の間隔が一部変わる(最大 103 → 116) |
| (c) | 折れ 52、段差 0 | −58(26 枚)/ −40(18 枚) | 弧の隙間 10.2px・切れ目 30px・口の間隔 28px が**変わらない** |

(c) は、D3(ADR 0070)の口の間隔と D8 の弧を変えず、段差だけを消す。

#### 規則(規範。`probe.patch` の `align(i, tailOnly)` と、その呼び出しの条件)

`routeOnce` の直線化(`direct` の `align`)の後に、AND の矢印だけを 1 本ずつ、次で試す。**どの規則も、1 つでも外れればその矢印は動かさない**。

1. **対象**: AND の組に入る矢印(`groupOf(i) !== undefined`)で、**直接の矢印**(層をまたがない 2 点の辺。`points.length === 2`)であり、**自己ループ・外周の戻り(`outer`)・丸い端(`round(from)`・`round(to)`)の節の矢印ではない**。`straighten: false` の図では動かさない。
2. **目標**: **頭の口の高さ(層に沿う座標)を目標**にする。頭の口は動かさない。すでに尾と頭の差が 0.5px 未満なら対象外。
3. **尾の箱の範囲**: 目標は、尾の箱の縁から **6px 内側**まで(`[A.y + 6, A.y + A.h − 6]`)に入っていること。外なら動かさない(目標を範囲に切り詰めない。測定の `tailOnly` は、範囲外のとき `undefined` を返す)。
4. **口の順と間隔**: 尾の箱の同じ辺で、動かす口の前後の口との間隔を、**今の間隔の規則のとおり保つ**(前の口の高さ + `slot.before`、次の口の高さ − `slot.after`。間隔は 1 口分、別の AND の組との間は 2 口分)。範囲から外れれば動かさない(順が入れ替わる動きは採らない)。例: fixture の e3 → u2 は、口の順を壊すので段差のまま。
5. **同じ高さの別の口**: 同じ 2 つの層の間の別の矢印の口(どちらの端でも)が、目標の高さの 3px 以内にあれば動かさない(run が 1 本に見える)。
6. **採る条件**(動かした図を作って比べる): (i) (交差, 折れ)が厳密に良くなる(交差が減る、または同じで折れが減る)。(ii) 新しい直線が、ほかの矢印の水平の run に沿わない(`alongOther`: 3px 以内で 1px を超えて重ならない)。(iii) 組の局所の検査 `gainsRunPairs`: **`tracks` のとき、交差が減らなかった場合に限り、`runPairGain(…, laneStepOf(space × scale)) > 0` なら動かさない**(図の倍率つきの間隔。canvas の倍率 1.29 で 18px、それ以外は 14px。交差が減るなら組の増えは見逃す)。(iv) **AND の矢印どうしの交差が増えない**(`groupCrossings`)。
7. **段差の大きさに依らない**: 対象になる段差は、尾と頭の差が 0 でなければ**どの大きさでも**直す(測定: fixture の 28px・22px、`toc-core` の `rush>cost` 39px、`toc-tt` の `u3.need>u3` 11px、asap の `e8>u4` 2px。`examples/toc-*` の AND の段差は 22・39・11px で、1 口分(22・28px)だけではない)。AND の矢印でない段差(`toc-crt-loop` の `switch>late` 21px など)は対象外で、そのまま残る。

#### 適用しない場合

- 規則 1 の外: 自己ループ、`outer`、丸い端、AND に入らない矢印、層をまたぐ矢印(中継点がある)、`straighten: false`。
- 規則 3〜5 のどれかに当たる矢印(範囲外、口の順を壊す、同じ高さの別の口がある)。
- 規則 6 のどれかが外れる矢印(交差・折れが良くならない、ほかの run に沿う、組が増える、AND の中の交差が増える)。
- **asap・compact では除外しない**: fixture の asap(`e8>u4` の 2px 段差が消え、折れ 116 → 112)、compact(折れ 56 → 52)でも動く。弧の隙間・切れ目・口の間隔は両者で変わらない(測定)。

#### 影響と測定

- 乱数での損は無い: 交差・`cause-crossing`・`loose` が図ごとに増えない。組は canvas で ↑2 ↓1(D3 単独。D2 と一緒にすると増えない。D2 の記述のとおり)。高さは 1 枚が増える(#136 +35px、探索の道が変わる)。

### D4: トラックで隙間の大きさを数える(`trackLoad`)

**採らない**(ADR 0070 U4c の保留の結論)。順序探索を直した上で測った:

得が無く、図ごとの単調性も満たせないので入れない。**層の順位の検査(D1 の (e))だけ入れる**(将来、隙間の大きさが並びで変わる実装を入れても探索が壊れないように)。

### D5: D12〜D14(`shiftOf`・`turnAt`・`moveApart`)

- **D14 は外す**(最終の図に効かない。幅 1800 の 138 枚・canvas 80 枚で、止めても経路が同じ(配置を固定すると canvas で 1 枚が数 px 動くだけ)。費用も変わらない)。`route-apart.ts`・`apartOf`・`AttemptOpts.apart` と、そのテストを消す。

### D6: `edge-parallel` を他の図へ広げない

relationDiagram 68 / 100 枚・pdpc 19 / 100 枚で指摘が出る(`causeTree` は 3 / 100)。この 2 つは D3・D4(トラック)が効かない図で、近い run はポートの間隔から来る設計どおりの形なので、**利用者が直せない指摘になる**。whyWhyTree は 0 / 98 枚で、広げても何も出ない。広げるなら、ADR 0070 の未決(D3・D4 を pdpc・relation に入れる)を先に決める。`origin` の検査は今のままにする。

### #397 との関係

Issue #397 は、`toc-hop-all` が 502 → 621px に高くなった(#385 以降)件で、論点は「順序探索の比べ方に高さを入れるか」。

- **この ADR が解くこと**: 高さのふるいが、交差の少ない並びを捨てる側(D1 の (c))。高さを採点の key にはせず、**交差が減るときの上限つきの交換**にした(Q1)。
- **高さの最後の key(決定 2026-11-21)**: 「同じ採点なら低い並びを選ぶ」を入れる。#397 の論点「比べ方に高さを入れるか」への答えは、**(1) 交差が減るときの上限つきの交換、(2) 同点の高さの比べ**の 2 つ。測定: 採った高い候補が main より高いまま残る図は 幅 1800 で 6 → 3 枚(canvas は 3 枚のまま)。
- **残ること**: 高さを交差や組と重みづけて交換する(例: 高さ 10% と交差 1 つ)ことはしない(交差が減る高い候補だけ、1.25 倍まで)。高いまま残る 3 + 3 枚は、探索の道の変化によるもの。
- **症状**: 現在の main では `toc-hop-all` は 505px で、U4b の後に症状は消えている(502 に近い)。U1 の後も 505px のままであることをテストで固定する(全部入りの測定で 505)。
- **#397 を閉じる条件**: **U1 の PR のマージ後に閉じてよい**。閉じるときに、上の「残ること」(重みづけの交換をしない、高いまま残る図)をコメントに書く。U1 のテスト 10(`toc-hop-all` 505px)と、高さの最後の key のテスト(同点なら低い並びが採られる)が通っていること。

## 決定済み(2026-11-21)

- **Q1**: 高い候補は、交差が減るときだけ採る。上限は最初の並びの高さの 1.25 倍。層の比べ方は層の順位。
- **Q2**: (交差, 組, 折れ, 高さ)の順(高さは D1-2 で足した最後の key)。`better()` と探索の採点の両方に組を入れる。折れ +1〜2% は受け入れる。組だけの改善での折れの増えは +4 まで(D1-4)。
- **Q3**: 層の並びを直接探す探索は後で。U1〜U4 の実装後に U5 で測り直し、その結果で、スパイクと別の ADR を決める。
- **Q4**: 利用者が点 4 を取り下げた(U5 の後は 28px で読める)。交差 1 つ(e2 → u2 × e3 → u3)は点 1 に属し、Q3 の測り直しで扱う。
- **D1-1(調整役の決定。オーナーの Q1 の範囲内。確認済み)**: 比べる相手は走っている最良(`best`・`pick`)。上限は**最初の並び(`base`)の高さの 1.25 倍**。測定の probe のとおり。
- **D1-2(オーナー: する)**: 高さを採点の最後の key にする。key は (交差, 組, 折れ, 高さ)で、同点なら低い並びが勝つ。#397 は U1 のマージ後に閉じてよい(残ることはコメントに書く。「#397 との関係」)。
- **D1-3(オーナー: 保つ)**: AND を先に比べる今の順を保つ。AND の交差を消すために交差の総数が増える候補を、(b) で採ることは意図したもの。ピン P1 はこれを反映する。
- **D1-4(オーナー: +4)**: 組だけが良くなる交換は、折れの増えが 1 図あたり +4 まで。D2 に入れた。U2 で測り(#143・#61 が影響を受ける見込み)、受け入れる図の一覧は縮む。
- **D1-6(調整役の決定。オーナーの AND を先に比べる決定(D1-3)の範囲内)**: P4 の例外(AND の交差が、組を切った図より少ない図は、折れの増えを許す)を、そのまま受け入れる。測定の例は幅 1800 の **#48**: AND の交差 2 → 0・`cause-crossing` 1 → 0 は、組の key を入れたときだけ起き(組を切った版の #48 は main と同じ)、折れが +20(44 → 64)になる。つまり折れの増えは組の key が起こすが、AND を先に比べる順では AND の交差を消すことが折れの上限に勝つので、例外にする。次に同じ図が出ても、P4 は例外として通す(PR で理由を書く)。**U2 の実装で分かったこと: `better()` の C は交差だけなので、#48 の AND の交差の消えるのは並びの探索の段でだけ起こりうる。U2 の実装(上限 +4)では #48 は変わらない(AND の交差は残る)。決定の例は `better()` の段では成り立たない**(上限なしの版では、`better()` の段で折れ +22 と引き換えに消える)。
- **D1-5(調整役の決定。オーナーの Q1 の範囲内: 書いたとおり)**: canvas の再配置の順は D1 の (g) のとおり((1) 交換あり、(2) 交換なし・倍率つき、(3) 倍率を外す)。
