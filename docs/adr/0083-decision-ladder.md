# ADR 0083: 判断のはしご（`decisionLadder()`）— はい/いいえの質問を縦に並べ、「はい」は右の答えへ、「いいえ」は下の次の質問へ

- 日付: 2026-11-26
- 基点: `main`（8379af91。ADR 0081 U4 まで）
- 関連: ADR 0041（`flowchart()`。`StatesBand` の上の薄い入口、ひし形の寸法）、ADR 0016（層に分ける配置と経路 `layered-route.ts`）、ADR 0080（帯の定義 `BandDef`、D2b の `.type ===` ラチェット、tree shaking）、ADR 0069（`partCatalog`）、ADR 0071（JSON Schema）、ADR 0027 / 0054（PPTX）

## 背景

利用者が必要としている形は次のとおり。

- 質問 Q1〜Q5 を縦に積む。
- 各質問の「はい」は、右にあるその質問の答えの箱へ進む。
- 「いいえ」は、真下の次の質問へ進む。最後の質問の「いいえ」は、最後の箱で終わる。

`flowchart()` では、この形をきれいに描けない。

- `dir: 'right'`: 斜めの階段になる。既定の幅（900px）に収まらず止まる（必要な幅は 1592px）。
- `dir: 'down'`: これも斜めの階段になり、背が高い（940×1040）。16:9 のスライドでは 69% に縮み、いちばん小さい文字は 7.3pt になる。

層に分ける配置（ADR 0016）は、「はい」の答えと次の質問を同じ層に置き、層ごとに右（下）へずらすため、どちらの向きでも階段になる。今の利用者は、`areas` と `box` と `connect` で手で組んでいる。

### 測ったこと（試し。`spikes/decision-ladder/out/measurements.txt`）

質問 5 つと最後の箱 1 つ。文字はすべて 14px（本文・注・矢印のラベル）。「1280×720 に収めたとき」は、SVG 全体を `min(1280 / W, 720 / H)` 倍にしたときの、いちばん小さい文字の大きさ（1280px 幅の 16:9 スライドは 960pt なので、1px = 0.75pt）。

| 図 | 大きさ | 倍率 | いちばん小さい文字 | 見た目 |
|---|---|---|---|---|
| `flowchart`, `dir: 'down'` | 940×1040 | 0.692 | 9.7px（**7.3pt**） | 斜めの階段 |
| `flowchart`, `dir: 'right'`（`width: 1640`。900 には収まらない） | 1640×372 | 0.780 | 10.9px（8.2pt） | 斜めの階段 |
| はしご、質問はひし形 | 940×820 | 0.878 | 12.3px（9.2pt） | 行の高さがひし形で 100〜128px |
| **はしご、質問は角の丸い箱** | 940×436 | 1.362 | 19.1px（**14.3pt**） | 幅で決まる（中身は 900px の帯のうち約 470px） |
| はしご、角の丸い箱、`diagram({width: 640})` | 640×436 | 1.651 | 23.1px（**17.3pt**） | |
| はしご、角の丸い箱、長い質問（2 行に折り返す）と注のある最後の箱 | 940×476 | 1.362 | 19.1px（14.3pt） | 最後の行が 2 字だけになる（D2 の折り返しで直す） |

- はしごの図は `check-diagram --strict` を通る。重なりの検査（`statesProblems`）の問題は 0。
- `lint --strict` の助言「`はい` / `いいえ` が 4px はみ出す」は、矢印のラベルを持つ図すべて（今の `flowchart` も）に出る既存のもので、はしごに固有ではない。
- PPTX（`svg-diagram pptx`）: 今の SVG → 図形の変換で、質問と答えの文字が `<a:t>` として編集できる図形で入ることを確かめた。PPTX のコードは変えない。

## 検討

| 案 | 内容 | 判断 |
|---|---|---|
| A: `flowchart({layout: 'ladder'})` | 節と辺は今の `flowchart` のまま、配置だけを差し替える | **v1 では取らない**。節と辺は任意のグラフを書けるので、「はしごの形をしているか」（判断の鎖、判断ごとに答えが 1 つと次が 1 つ、最後が 1 つ）を検査して、外れたときに直し方を言うエラーが要る。作者（多くは AI）が辺を 10 本正しく書く手間も残る。配置の実装は C と同じものを使えるので、後から足すのは安い（Q1） |
| B: 新しい帯の種類 `ladder` | 配置・描画・検査・PPTX を新しく作る | 取らない。描画（箱・ひし形・矢印・ラベルの白い chip）、検査、anchor、`focus`、PPTX の変換はすべて `states` の帯がもう持っている。ADR 0080 の帯の定義を 1 つ足し、型で引く表も増える |
| C: 新しい部品 `decisionLadder()` を、`StatesBand` の上の薄い入口として作る | 入力は「質問と、はいの答え」の並びと、最後の箱。部品が節と辺を作り、帯に `arrange: 'ladder'` を付ける。`states` の配置は、これを見て固定の 2 列の配置に切り替える | **採る**。入力の形そのものがはしごなので、形の検査が要らない。描画・検査・anchor・PPTX は `statesDefinition` のまま（ADR 0041 が `flowchart()` を `stateDiagram()` の上に作ったのと同じ構造） |
| D: `areas` + `box` + `connect` を組み立てる関数（compose） | 今の手組みを関数にする | 取らない。箱の幅をそろえる・行の高さをそろえる・ラベルを置く、を外から計算することになり、帯の中で測る C より壊れやすい。spec でも使いにくい |

## 決定

### D1: API

```ts
decisionLadder(
  [
    {q: '利用者カードを持っている？', yes: 'カードで受け付ける'},
    {q: '本人確認の書類がある？', yes: 'その場でカードを作る'},
    {q: '家族がカードを持っている？', yes: '家族の同意書で受け付ける'},
    {q: '館内で読むだけ？', yes: '閲覧席へ案内する'},
    {q: '予約だけしたい？', yes: '仮予約の票を渡す', sub: '7 日間有効'},
  ],
  '後日の来館をお願いする',                 // 最後の「いいえ」の行き先。{label, sub?, tone?} も可
  {yes: 'はい', no: 'いいえ'},              // 省略時の既定もこの 2 つ
)
```

- 段（step）: `{q, yes, sub?, tone?, yesLabel?, noLabel?}`。`q` は質問、`yes` はその答えの箱の文字、`sub` と `tone` は答えの箱に付く。`yesLabel` / `noLabel` はその段だけ矢印の言葉を変える（「ある」「ない」など）。
- 最後の箱（`otherwise`）は必須（最後の「いいえ」の行き先が無いはしごは作らない。Q6）。
- 選択肢: `yes` / `no`（矢印の言葉。既定 `'はい'` / `'いいえ'`。空文字ならラベルを付けない）、`question: 'box' | 'diamond'`（既定 `'box'`。D3）、`maxNodeW`、`id`、`scope`、`reveal` / `until`（`flowchart` と同じ）。
- anchor の id: 質問 `q1`〜`qN`、答え `a1`〜`aN`、最後の箱 `otherwise`（`connect()` や `focus` から指せる）。
- 段が 1 つも無ければ throw。段の数に上限は付けない（多すぎる図は `aspect-tall` の info に任せる）。

### D2: 配置（`arrange: 'ladder'`。`lib/ladder.ts`）

- 2 列。左の列に質問を上から積み、その下に最後の箱。右の列に、各質問と同じ行に、その答え。
- 列の幅はそろえる: 質問の列は、いちばん広い質問（と最後の箱）の幅、答えの列は、いちばん広い答えの幅。行の高さは、その行の質問と答えの高い方。質問と答えは行の中で上下の中央にそろう。
- 「はい」は行の中央の水平な矢印（質問の右辺 → 答えの左辺）。ラベルは矢印の**上**に置く。
- 「いいえ」は質問の列の中央の垂直な矢印（質問の下辺 → 次の質問の上辺）。ラベルは矢印の**右**に置く。
- 間隔: 列の間 = `max(48, はいのラベルの幅 + 2·10 + 矢じり 14)`、行の間 = `max(32, ラベルの高さ + 10)`。経路の計算（`layeredAttempt`）は使わない。矢印はすべて 2 点の直線。
- 2 列は帯の幅（`w`）の中央に置く。
- 折り返し: 試しでは「質問の列は残りの幅の 55%」で折り返したため、長い質問の最後の行が 2 字だけになった。実装では、質問の列の幅を、`(w − 列の間)` の範囲で 8px 刻みに試し、**行数が最小のうち、最後の行が短すぎない（4 字以上）幅**を取る。答えの列は残りの幅で折り返す。
- 収まらないとき（2 列が `w` を超える）: 向きは変えない。`fit-width` の `NoFit` で止め、直し方（`maxNodeW` を狭める / 図を広げる / 文を短くする）を言う。

### D3: 質問の形

- 既定は**角の丸い箱**（`flowchart` の process と同じ見た目、太字）。行の高さが 1 行の文字で決まるので、5 段でも 16:9 に 14pt 以上で収まる（測った値）。
- `question: 'diamond'` でひし形（ADR 0041 D3 の寸法）。行がひし形の高さになるので、5 段で 9.2pt まで縮む。「判断はひし形」を守りたい場面のための選択肢として残す。
- 平らな六角形（判断の別の記号）は v1 では足さない（新しい形は描画・検査・PPTX の変換に手が要る。Q3）。

### D4: 帯と ADR 0080 の約束

- 新しい帯の種類は作らない。`StatesBand` に内部の欄 `arrange?: 'ladder'` を足し、`flavor: 'flowchart'` を付ける（エラーと検査の言葉は `flowchart` の表から引く。名前は `decisionLadder()` に変える行を 1 つ足す）。
- `layoutStatesBandAt` の先頭（id の検査の後）で `arrange === 'ladder'` なら `layoutLadder` へ分ける。帯の種類の文字列で分岐しないので、`test/band-type-literals.test.ts` のラチェットは増えない（試しで確かめた）。
- 帯の定義は `statesDefinition` をそのまま使う。`lib/ladder.ts` は `states.ts` だけが import する（states を使わない図のバンドルには入らない）。
- `density`・`fitLayout` の向きの切り替え・`returns` は、はしごには効かない（向きは固定）。`density: 'compact'` は行の間と列の間だけを縮める。

### D5: spec（JSON）

- 新しい部品 `decisionLadder`（`lib/spec-parts/decision-ladder.ts`）: `steps`（`{q, yes, sub?, tone?, yesLabel?, noLabel?}` の list、1〜12）、`otherwise`（文字列か `{label, sub?, tone?}`）、`yes`、`no`、`question`。`anchors` は `q1`… の固定の id。`pnpm schema` で作り直す。
- 説明文（`list_diagram_parts` に出る）:「はい/いいえの質問を縦に並べ、はいは右の答え、いいえは次の質問へ。判断が 1 本の鎖のときは flowchart より小さく、16:9 に収まる」。`flowchart` の説明にも「判断が 1 本の鎖なら decisionLadder」を 1 文足す。

### D6: 検査

- 重なり・はみ出しは `states` の検査（`statesProblems`、`anchorRects`）がそのまま効く。試しで問題 0。
- `flowchart-decision-edges` は、はしごでは必ず 2 本でラベルが付くので出ない（`yes` / `no` を空にしたときだけ info が出る。それで正しい）。
- テストで押さえること: (i) 矢印がすべて 2 点の水平/垂直の直線、(ii) 「はい」のラベルが質問・答えの箱に重ならず、矢印の上にある、(iii) 「いいえ」のラベルが次の質問に重ならない、(iv) 列の幅がそろう、(v) 長い質問で最後の行が 4 字以上、(vi) 収まらないときのエラーの文言に `stateDiagram` / `flowchart` が出ない。

### D7: PPTX

- コードは変えない。今の SVG → 図形の変換で、箱と文字が編集できる図形として入る（試しで確かめた）。

## 決める人への質問（決定済み: すべて推奨どおり）

| # | 質問 | 推奨 |
|---|---|---|
| Q1 | 新しい部品（C）にするか、`flowchart({layout: 'ladder'})`（A）にするか | **C**。入力がそのままはしごの形で、形の検査が要らない。A は、要望が出たら同じ配置を使って後から足す |
| Q2 | 名前 | **`decisionLadder`**（spec の `type` も同じ）。`ladder` だけでは何のはしごかわからない |
| Q3 | 質問の既定の形 | **角の丸い箱**（14pt 以上で収まる）。ひし形は `question: 'diamond'` で選べる。六角形は足さない |
| Q4 | 矢印の言葉 | 既定 **はい / いいえ**。図全体の `yes` / `no` と、段ごとの `yesLabel` / `noLabel` で変えられる |
| Q5 | 質問と答えの見分け | **何も足さない**（質問は「？」で終わり、左の列にある）。要望が出たら `numbered: true`（Q1、Q2 …の前置き）を足す |
| Q6 | 最後の箱を省けるか | **省けない**（必須）。最後の「いいえ」が行き先の無い矢印になるのを避ける |
| Q7 | はしごは既定の図の幅（900px）より狭い（約 470px）。幅で倍率が決まるので、スライドでの文字は 14pt にとどまる（`width: 640` なら 17pt） | **README と例で `diagram({width: 640})` を案内する**だけにする。図の幅を中身に自動で縮める仕組みは、この ADR では作らない |
