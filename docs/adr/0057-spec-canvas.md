# ADR 0057: JSON spec の図をスライドの大きさで描く（`canvas`）

- 状態: 実装済み
- 日付: 2026-11-15
- 基点: `main`(837df96)
- 関連: ADR 0017(`canvas` と `fontFloor`)、ADR 0052(`canvas.fit: 'content'`)、ADR 0055(デッキ)

## 背景

JSON spec(`svg-diagram/spec`、MCP の `render_diagram` の入力)は、図を必ず幅 940px で描く。文書の本文の列(約 930px)に等倍で貼ると、14px の文字が 14px で読めるようにするためで、幅を超えると `doc-width` が「縮められて文字が小さくなる」と知らせる。

スライドに置く図ではこの前提が合わない。LT のスライド(Slidev、16:9)に、21 ノードの現状ツリー(CRT)を左から右へ描こうとしたところ、横向きには 1681px 要り、940px には収まらなかった。`maxNodeW` の下限 120 も、14px で 1 行 8 文字ほどを保つための値で、これ以上は詰められない。作り手は spec の外で `specToDiagram()` の結果の `width` を書き換え、1760px で描いて回避した(spec の外なので MCP からは描けない)。

DSL にはスライド 1 枚を等倍で描く `diagram({canvas: {width, height, minText, fit}})` が既にある(ADR 0017、0052)。spec がそれを出していないだけだった。

## 決定

- D1. spec の最上位に `canvas` を足す。中身は DSL と同じ `width`(整数、1280〜3840)、`height`(整数、360〜2160)、`minText`(数、14〜24)、`fit`(`'content'` のみ)。どれも省略でき、既定は DSL と同じ 1280×720・24px・高さ固定。値はそのまま `diagram({canvas})` に渡す(変換しない)ので、同じ図は DSL と同じ SVG になる。
- D2. 範囲は、`partCatalog()` の 64 部品の例がすべて問題なく描ける範囲に限る(テストで全例を README の 1920×1080・`minText` 20、既定の `{}`、範囲の四隅で描いて確かめる)。
  - 幅は既定のスライド(1280)から 4K(3840)まで。文書の図(940)より狭いキャンバスでは、幅の要る部品(mindmap・bowtie など)が収まらない。
  - `minText` の下限は既定の文字の下限(`fontFloor` 14)。DSL は 10 まで下げられるが、`renderSpec` は案件の設定を持たず `fontFloor` 14 のままなので、14 未満は Node の経路で例外になる(spec からは下げられない)。
  - `minText` の上限は DSL の既定と同じ 24。これより大きいと、文字に合わせて大きさを変えない配置(steps の差し戻しの線の通り道、因果ループ図の遅れの印、ツリーマップの見出しなど)に文字が収まらず、例のいくつかが重なりで落ちる(幅 1280〜3840 で、28 では 1 部品、32 では 2〜3、48 では 17〜18)。4K の画面に大きい文字で描くには、それらの配置を文字に合わせてから上限を上げる(今後の課題)。
  - 範囲は `CANVAS_LIMITS`(spec-kit)に置き、スキーマと説明文が同じ値を使う。範囲外は `canvas.minText` などの場所つきで返る。
- D3. 自由な `width` だけを出す案は採らない。幅だけ広げると文字は 14px のままで、表示する側が縮めれば文字が小さくなる(`doc-width` が警告する状態そのもの)。`canvas` は「この大きさで等倍に見せる」と宣言し、文字の下限(`minText`)も一緒に決めるので、スライドで読める大きさが保証される。
- D4. デッキ(ADR 0055)の図には `canvas` を書けない。デッキはスライドの空きに合わせて図を縮めるので、図が自分の大きさを決める `canvas` とは両立しない。デッキのスキーマの `figure` から `canvas` を外し、`validateDeck()` は `slides[i].figure.canvas` で断る。図の残りは `canvas` を除いて検査するので、ほかの誤りもいっしょに返る。
- D5. キャンバスでは、グラフの部品の固定の寸法も文字と同じ倍率(`canvasFontScale(minText)`)で大きくする。キャンバスは文字・余白・間隔だけを拡大していたので、DSL の `diagram({canvas})` でも、目盛りの文字が目盛りの線に重なる(plane の折れ線・散布図・管理図など)、ガントの日付と「今日」が重なる、PERT の箱に ES/LS の行が収まらない、といった誤りがあった(spec の経路だけの問題ではない)。
  - plane・bars は、`labelRole` を書かないと余白と文字のずれを 14px のまま置く(fill の図の配置を変えないため)。キャンバスでは `labelRole: 'note'` と同じに置く(文字の大きさは同じで、ずれだけが文字に合う)。
  - plane の高さとラベルの `offset`、縦棒の高さと下の文字との間、ガントの行・棒・見出しの高さと余白、PERT の箱の大きさを、その倍率で大きくする。
  - キャンバスでない図(文書の図・fill の図)は倍率 1 で、配置は変わらない(examples の SVG はすべて同じ)。

## 結果

- 横向きの CRT のように 940px に収まらない図を、`canvas: {width: 1920, height: 1080, minText: 20, fit: 'content'}` で spec のまま描ける(MCP からも描ける)。
- `partCatalog()` の 64 部品の例は、README の 1920×1080・`minText` 20、既定の `{}`、範囲の四隅のどれでも問題なく描ける(テストで確かめる)。
- 範囲外の値・知らない項目・`'slide'` のような文字列は、`canvas.width` などの場所つきで返る。
- MCP のプラグインは `specSchema` をそのまま入力のスキーマにしているので、vendor の core を差し替えれば `render_diagram` から使える。プラグインのビューアーの PNG を 4K まで等倍で出す変更は、プラグインのリポジトリでの作業で、この PR には含まない。

## レビュー(Opus)で直したこと

- `minText` 10〜13 は `renderSpec`(Node)で `fontFloor` の例外になり、結果ではなく throw で返っていた → spec の下限を 14 にした(D2)。
- デッキの図に範囲外の `canvas` を書くと、`canvas.width` と `canvas` の 2 つが返った → `canvas` を断るときは中身の誤りを返さない。
- `renderSpec`(Node)・単体の PPTX(`renderPptxEdge`)で `canvas` を描くテストを足した。

## レビュー(2 回目)で直したこと

- README の勧める 1920×1080・`minText` 20 で、64 部品の例のうち 8 つ(gantt・lines・strategyCanvas・pert・burndown・burnup・scatter・controlChart)が重なりで落ち、`{}` では 11、3840×2160・48 では 23 が落ちた。DSL の `diagram({canvas})` でも同じだった(core の誤り)→ D5 で配置を文字に合わせ、D2 で範囲を全例が描けるところに絞った。全例を代表のキャンバスで描くテストを足した。
- デッキの図の `canvas` が範囲外だと、スキーマの段で止まり、図のほかの誤りが返らなかった → `canvas` を除いて検査する(D4)。
- 結果から、確かめていない CRT の寸法を外し、プラグインのビューアーの話はこの PR に含まないと書いた。
