# ADR 0068: 一部の図を Excel(.xlsx)に書き出す(`svg-diagram xlsx`)。描いた絵ではなく、図の元のデータを表にする

- 状態: 提案(2026-11-20。Opus のレビューを 4 回反映。同日、利用者の決定(ガントの形、休日、140 日、BPMN の 2 枚のシート)を反映し、さらに Opus のレビューを 2 回反映。最後の回で Blocker・Major なし。同日、予実のガント(D4b)を足し、Opus のレビューを反映)
- 基点: `main`(7a95096e、ADR 0067 まで)
- 関連: ADR 0027(PowerPoint への書き出し)、ADR 0054(PowerPoint のグループと表)、ADR 0007(結果が入力だけで決まること)

## 背景

PowerPoint に加えて、Excel でも保存したいという要望が届いた(利用者、2026-11-20)。例として挙がったのは BPMN とガントで、「すべての図を Excel にできる必要はなく、表形式やグラフなどを含めて一部の図だけでよい」とのこと。

Excel で図を受け取った人がしたいことは、PowerPoint の場合とは違う。PowerPoint では見た目を少し直してスライドに貼る。Excel では、並べ替える、日付を書き換える、行を足す、集計する、別の表に写すといった、**データとしての使い方**をする。そのため Excel に図の絵(図形の配置)を写しても、使い道は少ない。ただし BPMN については、日本の現場で多い「Excel 方眼紙に描いたフロー図」の需要もある。

初稿を見た利用者が、次のことを決めた(2026-11-20)。

- ガントは「表現と内部データを分離した上で、Excel 方眼紙で、セルの背景色や IF を使って」Excel にする(D4)。
- 「土日、祝日とかも内部データとして持たせた上で、休日と分かるように出力」する(D4a)。
- 1 日 1 列と 1 週 1 列の境は 140 日でよい(D4)。
- BPMN は「両方の書き方のシートを含む Excel を出力して、使う側が選択できるように」する。業務の一覧の表と、方眼紙に描いたフロー図の 2 枚(D7)。
- 予定と実績の 2 段のガントを、新しいバンドではなく既存の `gantt` の入力で指定できるようにし、この ADR に入れる(D4b)。

コードで確かめたこと(`main` 7a95096e):

- 図の各バンドは、描く前の入力を持っている。
  - `gantt`(`GanttBand`、lib/types/timeline.ts): `rows` は、タスク `{label, id?, start, end? | days?, milestone?, progress?, after?, tone?}` か、セクション `{section}` の並び。ほかに `from` / `to` / `today` / `todayLabel` を持つ。
  - `bpmn`(`BpmnBand`、lib/types/diagrams.ts): `lanes {id, label, tone?}`、`nodes {id, lane, label?, sub?, kind?, tone?}`(kind は `task` / `start` / `end` / `xor` / `and` / `or`)、`flows {from, to, label?, line?}`(`line: 'dashed'` はレーンをまたぐメッセージフロー)。
  - `table`(`TableBand`): `columns {label?, flex?, align?, …}` と `rows`。セルは `string | number | {text?, mark?, icon?, tone?, …}`。利用者が直接書いた数値は数値のまま残る。**しかし意味の表の組み立て側は、数値を文字にしている**: FMEA の RPN は `{text: String(n)}`(lib/semantic-table.ts:104)、QFD の得点は `String(n)`、相対 % は `n.toFixed(1)`(同 :138-139)。列の見出しにも `'故障\nモード'` のような手で入れた改行がある。
  - `chart`: `kind`(`ChartKind`、lib/charts-base.ts:13 の 20 種)と、kind ごとの `spec` を持つ。compare のセルは `{mark, note}`、harvey は評価のほかに `notes`・`levels`・`highlight`、heatmap は `min`・`max`・`levels`・`unit`・`decimals` を持つ。
  - **折れ線・棒・散布図は `chart` バンドではない**。`lines()` は `plane` バンドに展開され(lib/charts-lines.ts の `linesOpts`)、系列の構造はバンドに残らない。`bars`・`stackedBars`・`pareto`・`histogram` は `BarsBand`(lib/types/bars.ts)。
- 入れ物のバンド(`group`・`row`・`grid`・`grouprow`、`image` の `children`、tree の band ノード、swimlane の steps)は子のバンドを持つ。たどる処理は `CHILD_BANDS` / `childrenOf` / `nestedBandsOf`(lib/band-children.ts)にある。
- ガントの日付の計算のうち、`spanOf`(`days` から終了日を出す)は export された純粋な関数(lib/gantt.ts:32)。`axisOf`(軸の範囲)も独立した関数だが export されていない(同 :50)。**入力の検査は `layoutGantt` の中に直接書かれている**: `after` の未知の id と循環、`progress` の範囲、id の重複、タスクや `today` が軸の外にあること、タスクが無いこと。BPMN の検査は既に `checkBpmnInput`(lib/bpmn.ts:36)として切り出されている。
- `today: 'auto'` は、DSL の `detachData` の中の `fillAutoToday` で日付に置き換わる(lib/dsl/diagram.ts:104)。JSON の spec は `auto` を受け付けない(lib/spec.ts)。
- 入力の種類ごとの表の前例は `LAYOUT_HANDLERS`(lib/layout-handlers.ts)と `CHILD_BANDS` で、どちらも `{[T in Band['type']]: …}` の形。`EMIT_HANDLERS` と PowerPoint の `BAND_HANDLERS` は、レイアウト結果の種類(`LaidOutType`)で引いている。
- PowerPoint の書き出しには、Node 用の入口(`pptx-diagram.ts`、`lib/pptx/emit.ts`)と、ファイルシステムの無い場所用の入口(`lib/pptx-edge.ts`、`svg-diagram/pptx/edge`)がある。MCP のダウンロードは後者を使う。zip は `lib/pptx/zip.ts`、edge の圧縮(`deflateRaw`、非同期)と `zipPackage` は `lib/pptx-edge.ts`、Node の圧縮は `lib/pptx/zip-node.ts` にある。同じ入力から同じバイト列を出す(ADR 0027)。
- XSD の検査(test/helpers/pptx/xsd.ts)は、取得済みの ECMA-376 の過渡的スキーマを使い、今は `pml.xsd` を決め打ちしている。同じ場所に `sml.xsd` もある。

## 決定

### D1: 元はレイアウトの結果ではなく、バンドの入力のデータ。検査と計算は共有する

Excel のシートは、`Diagram` の `bands`(入力)から作る。`LaidOut*` は使わない。

- 理由: Excel に写したいのは位置ではなく意味(タスク、日付、担当、値)である。入力にはそれが残っている。レイアウトの結果は、ピクセルに直したあとの値である。
- 結果として、データのシートを作るのに**レイアウトをしない**。文字の幅の計測もフォントも要らない。
- 例外は BPMN のフロー図のシート(D7)で、図形の位置にレイアウトの結果(`LaidOutBpmn`)を使う。このシートだけは文字の計測が要る(D9)。
- レイアウトの中にある**入力の検査と計算は、純粋な関数として切り出し**、SVG・PowerPoint・Excel が同じものを呼ぶ。入力の検査(`checkGanttInput` / `checkBpmnInput` が出すもの)で誤りになる入力は、Excel でも同じメッセージで誤りにする。Excel 用に書き直さない。レイアウトでしか分からない誤り(ガントのタスク名が長すぎる、描画の領域が狭すぎる、BPMN が幅に収まらない)は、計測しない Excel では出さない。
  - ガント: 内部データ(モデル)を作る `ganttModel` を切り出す(D4a)。検査(`checkGanttInput`)、軸(`axisOf`)、期間(`spanOf`)、休日はこの中で計算する。`layoutGantt`(SVG と PowerPoint)と Excel の書き出しは、どちらもこのモデルを読む。
  - BPMN: 既存の `checkBpmnInput` を使う。
- `today: 'auto'` は CLI でも埋める(D9)。

### D2: 入力のバンドの種類ごとに「シートにする / 子をたどる / しない」の表を持つ

`XLSX_HANDLERS` を `satisfies {[T in Band['type']]: XlsxHandler | 'children' | 'none'}` で書く(前例は `LAYOUT_HANDLERS` と `CHILD_BANDS`)。全バンド種に宣言がないとコンパイルが通らない。`chart` は `{[K in ChartKind]: …}` で kind ごとに宣言する。

- 入れ物のバンド(`group`・`row`・`grid`・`grouprow`、子を持つ `image`、band ノードを持つ `tree`)は `'children'` とし、それ自身はシートにせず、`childrenOf` で子だけをたどる。それ自身(絵やツリー)は「飛ばした」に数える(D3)。`swimlane` は第 2 段までは `'none'` とし(steps は箱なので、たどっても飛ばすだけ)、第 3 段で handler に替える。grid の中の表やガントも落とさない。シートの順は、深さ優先の出現順。

第 1 段で対応するもの:

| バンド | シート |
|---|---|
| `table`(RACI、マトリクス、FMEA、QFD などの意味の表を含む) | 表(D5) |
| `chart` の `compare`・`harvey`・`heatmap` | 表(D5) |
| `gantt` | データのシート(タスク、休日)と、方眼紙の表示のシート(D4、D4a)。予実の 2 段のガントも(D4b) |

第 2 段: `bpmn` の業務一覧とフロー図の 2 枚のシート(D7)。第 3 段: 数値のグラフ(D6)と swimlane(BPMN と同じ形)。

対応しないもの(`'none'`): 構成図、箱と矢印、マインドマップ、ワイヤーフレーム、数式など、データの表にすると意味を失う図。

### D3: 1 つの図は 1 つのブック。対応するバンドごとにシート(ガントと BPMN は複数枚)

- シートの名前は、バンドの `id` があればそれ、なければ種類と番号(`表 2` など)。ガントと BPMN のように 1 つのバンドが複数枚になるときは、名前の後ろにシートの役目を付ける(`ガント`・`ガント タスク`・`ガント 休日`、`業務一覧`・`フロー図`)。Excel の決まりに合わせて直す。31 文字を超えるときは、役目の部分(` タスク` など)を残して、id の側を切る。
  - 31 文字まで(UTF-16 の単位で数える)。
  - `[ ] : * ? / \` を使わない。空にしない。先頭と末尾に `'` を置かない。
  - `History` は予約されているので使わない。
  - 重複は大文字と小文字を区別せずに判定し、重なれば番号を付ける。
- 対応しないバンドは飛ばす。飛ばしたバンドは、種類ごとに 1 つにまとめて(「箱 12 個を飛ばした」)、CLI では警告として出し、edge では結果の `issues` に入れる。
- 対応するバンドが 1 つも無い図は、ブックを作らずに誤りにする。メッセージには、Excel にできる部品の一覧を入れる。
- **シートの行の配置**(全シート共通):
  - 1 行目: 図の題(`title`)。出典(`sourceLine`)、アイコンを省いた注記(D5)、harvey の段階の名前(D5)があれば、同じ行の右に続けて書く。
  - 2 行目: 空ける。題と見出しのあいだに空の行が無いと、Excel の並べ替えとフィルターが見出しを見誤る。
  - 3 行目: 見出し。4 行目から本体。
  - 出典や注記を表の下に置かないのは、行を足したときにぶつかるため。
  - 並べ替えとフィルターの範囲は `<autoFilter ref="A3:…"/>` で見出しの行から明示する(ガントのタスクのシートは、色の列を含む全列。並べ替えで色がタスクから離れないように)。自動の範囲検出に任せない。
  - ガントの表示のシートと BPMN のフロー図のシートは表ではないので、この配置に従わない(D4、D7)。
- 表のバンド自身の `title`(ER のエンティティ名など)は、図の題とは別に、1 行目の題の後ろに「 — 」で続けて書く。
- 図の絵(SVG や PNG)は、第 1 段ではブックに入れない(未決の 3)。

### D4: ガントはデータのシートと、Excel 方眼紙の表示のシートに分ける

ガントの 1 つのバンドは、次の 3 枚のシートになる。利用者が直すのはデータのシートで、表示のシートは数式で追いかける。

| シート | 役目 |
|---|---|
| `ガント タスク` | データ。1 行 1 タスク(セクションも 1 行)。利用者が直す |
| `ガント 休日` | データ。軸の期間の祝日と指定の休日(D4a)。利用者が足せる |
| `ガント` | 表示。方眼紙の上にバーを描く。セルは数式だけで、手では書かない |

ブックを開いたときに見えるのは、最初のガントの表示のシートとする(作業中のシートに指定する)。

#### タスクのシート(データ)

D3 の行の配置に従う(見出しは 3 行目、本体は 4 行目から)。

| 列 | 中身 |
|---|---|
| A | 種類: `タスク`・`マイルストーン`・`セクション` |
| B | 名前(タスク名、またはセクション名) |
| C | 開始日(日付の値) |
| D | 終了日。`end` のタスクは値、`days` のタスクは数式 `=C4+E4-1`、マイルストーンは `=C4` |
| E | 日数。`end` のタスクは数式 `=D4-C4+1`、`days` のタスクは値、マイルストーンは `1`(両端を含む暦日。SVG と同じ) |
| F | 稼働日数: `NETWORKDAYS.INTL(C4,D4,週末,休日)`。週末は D4a の曜日、休日は休日のシートの日付の列 |
| G | 進捗(`progress` を `0%` の表示形式で。無ければ空) |
| H | 先行タスク(`after` の id を、そのタスクの名前で書く) |
| I | 色: `danger` / `muted`。`accent` と、利用者が足した行は空 |
| J | id(`after` が参照する名前。無ければ空) |

- D 列と E 列を入力の形に合わせるのは、`days` で書いたタスクの期間を、数式を書き換えずに E 列の値で直せるようにするため。
- セクションの行は C〜J を空にし、灰色と太字を条件付き書式(A 列が `セクション`)で付ける。並べ替えても書式が行についていく。
- `NETWORKDAYS.INTL` は Excel 2010 で入った関数なので、ファイルには `_xlfn.` を付けて書く必要がある見込み(実機で確かめる)。週末を 7 曜日すべてにする入力(`"1111111"`)は Excel でエラーになるので、`ganttModel` の検査で弾く。

#### 休日のシート(データ)と名前の定義

- 列: A 日付、B 名前(`元日`・`振替休日` など)、C 種類(`祝日`・`振替休日`・`国民の休日`・`指定`)。行は日付の順。
- 本体の最後の行より 50 行先までを、`休日` という名前にする(範囲は `'ガント 休日'!$A$4:$A$N`)。名前はシートに限った定義名(`localSheetId` 付き)とし、同じ名前をタスクのシートと表示のシートに 1 つずつ定義する(シートに限った名前は、そのシートからしか引けないため)。ガントが 2 つあるブックでも衝突させない。タスクのシートの F 列と、表示のシートの補助の行(後述)は、この名前を参照する。利用者が下に休日を足せば、どちらにも効く。
- 週末の曜日は、モデルの値(D4a)を数式の中に定数として書く(`NETWORKDAYS.INTL` の週末の文字列 `"0000011"` など)。シートでは変えられない(未決)。

#### 表示のシート(方眼紙)

列の並び:

| 列 | 中身 |
|---|---|
| A | 名前 `=IF(INDEX('ガント タスク'!$B:$B,ROW())="","",INDEX('ガント タスク'!$B:$B,ROW()))` の形 |
| B | 開始日(写し。`=N(INDEX('ガント タスク'!$C:$C,ROW()))`) |
| C | 終了日(写し。同じく `N(INDEX(…))`) |
| D | 進捗(写し。同じく `N(INDEX(…))`) |
| E | 種類(写し。文字なので A と同じ形。隠す) |
| F | 色(写し。A と同じ形。隠す) |
| G 以降 | 日付の方眼 |

- 行はタスクのシートの行と 1 対 1 で、**同じ行の番号の行を `INDEX(列, ROW())` で引く**。決まったセル(`'ガント タスク'!B4`)を参照すると、タスクのシートの途中に行を挿入したときに参照がずれて足した行が表示されず、行を削除したときに `#REF!` になるため。`INDEX` は揮発性の関数ではない。
- この形で、タスクのシートの並べ替え・途中への挿入・削除・末尾への追加のどれにも、表示が追随する。行の数は、タスクの数より 50 行多く用意する。予備の 50 行を超えて足した行は、表示されない。
- 数値の写し(B〜D)は `N(…)` で包み、空のセルを 0 にする。空の文字列 `""` のままだと、進捗の無いタスクや開始日だけの行で、方眼の数式が `#VALUE!` になるため。
- タスクのシートでフィルターをかけて行を隠しても、表示のシートの行は隠れない(仕様)。
- 条件付き書式は、同じシートの写しの列(B〜F)と補助の行だけを参照する。別のシート(定義名を通すものも含む)を条件付き書式から参照しない(古い Excel と LibreOffice で効かないことがあるため)。別のシートを参照するのは、セルの数式だけにする。
- 1〜3 行目: 1 行目に題、2 行目に月(`m月`)、3 行目に日(日付の値を `d` で見せる)。4 行目から本体。見出しの行と A〜D 列を固定する。
- 補助の行(隠す。本体の最後の予備の行の下に置く): 日付の列ごとに休日かどうかを `=IF(OR(COUNTIF(休日,G$3)>0,週末の判定),1,0)` の形で出す。週末の判定は、D4a の曜日を `WEEKDAY(G$3)` と比べる式にする。**土日も祝日と同じく休日として塗る**。1 週 1 列のときは、補助の行も休日の規則も置かない(週の最初の月曜が祝日のとき、週全体が塗られてしまうため)。
- 方眼: 日付の列は正方形に近い幅(1 日 1 列は約 3 文字、1 週 1 列は約 4 文字)にし、行の高さをそろえる。
- 軸が 140 日以下なら 1 日 1 列、それより長ければ 1 週 1 列(月曜始まり)。境は、SVG が目盛りを週から月に切り替える日数(lib/gantt.ts の `SHORT_AXIS` = 140)と同じ(利用者が決定)。

方眼のセルは **IF の数式で状態を出し、背景色は条件付き書式で塗る**。Excel では数式からセルの色を変えられないので、役目を分ける。

- セルの数式(1 日 1 列): 次の値を返す。
  - マイルストーンの日は `"◆"`。
  - 済んだ部分は `2`、残りの期間は `1`、期間の外は `""`。
  - 済んだ部分の判定は、開始日から `ROUND(日数×進捗,0)` 日ぶん。
  - 例: `=IF($E4="マイルストーン",IF(G$3=$B4,"◆",""),IF(AND($B4>0,G$3>=$B4,G$3<=$C4),IF(G$3<$B4+ROUND(($C4-$B4+1)*$D4,0),2,1),""))`。`$B4>0` は、開始日の無い行(写しが 0)を期間の外にするため。
- 1 週 1 列のときは、比較を「週の範囲との重なり」に替える。週の最初の日を `G$3` として、`AND(G$3<=$C4,G$3+6>=$B4)` の形にする。マイルストーンの判定も `G$3=$B4` を `AND(G$3<=$B4,G$3+6>=$B4)` に替える(月曜でないマイルストーンも、その週の列に出るように)。
- 表示形式は `;;;@` にする。数字(1・2)は見せず、文字(◆)だけを見せる。
- 条件付き書式(評価の順。`stopIfTrue`):
  1. 済んだ部分: 値が `2` のセルを濃い色にする。
  2. バーの色: 値が `1` のセルを、F 列(色)に応じて塗る。まず `danger`・`muted` の規則を置き、最後に F 列の条件なしで accent の規則を置く。**F 列が空の行(利用者が足した行を含む)は accent で塗られる**。
  3. セクションの行: E 列が `セクション` の行を灰色にし、A 列を太字にする(`dxf` の `font`)。静的な書式にしないのは、並べ替えで書式が行から離れるため。
  4. 休日: 補助の行が `1` の列を薄い灰色にする(バーより後に評価するので、バーは休日の上でも途切れない)。規則は同じシートの補助の行だけを参照する。
- `today` は、その日(週)の列の見出しを赤にする。静的な塗りで、`TODAY()` は使わない。ビルドは時計を読まない(ADR 0007)。
- 依存の矢印は描かない(タスクのシートの H 列の文字だけ)。

日付は 1900 年方式のシリアル値で書く。

- 値は 1899-12-30 からの日数(UTC の日の通し番号 + 25569)。
- Excel は 1900 年 2 月 29 日を実在の日として数えるので、1900-03-01 より前の日付はこの式で 1 日ずれる。そうした日付は誤りにする。
- 計算は UTC の日で行い、実行環境のタイムゾーンに依存させない。

### D4a: 土日と祝日は、ガントの内部データとして持つ

- `ganttModel(band)`(D1)が返すモデルに、休日を持たせる。
  - `weekend: number[]`: 週末の曜日(0 = 日曜)。既定は `[0, 6]`(土日)。
  - `holidays: {day: number, name: string, kind: '祝日' | '振替休日' | '国民の休日' | '指定'}[]`: 軸の期間の休日。
- 入力に次を足す(`GanttOpts`)。
  - `calendar?: 'jp' | 'none'`: 祝日の暦。既定は `'jp'`(日本の国民の祝日)。
  - `holidays?: (string | {date: string; name?: string})[]`: 会社の休業日など、指定の休日。
  - `weekend?: number[]`: 週末の曜日。
- 日本の祝日は、外から取ってこずに、祝日法の規則を書いた純粋な関数(`jpHolidays(year)`)で計算する。ビルドがネットワークに触れず、結果が入力だけで決まるようにするため(ADR 0007)。
  - 扱うもの: 日付の決まった祝日、ハッピーマンデー、春分の日と秋分の日、振替休日、国民の休日。
  - 2000 年以降の規則の切り替え:
    - 成人の日と体育の日のハッピーマンデー(2000 年から)
    - 海の日と敬老の日のハッピーマンデー(2003 年から)
    - 昭和の日の新設、みどりの日の 5 月 4 日への移動、振替休日の規則の変更(2007 年から)
    - 山の日(2016 年から)
    - 天皇誕生日の 12 月 23 日から 2 月 23 日への移動(2019 年は該当日なし、2020 年から 2 月 23 日)
    - 体育の日からスポーツの日への改称(2020 年から)
  - 一回きりの例外: 2019 年の即位の日(5 月 1 日)と即位礼正殿の儀の日(10 月 22 日)、それに伴う国民の休日、2020・2021 年のオリンピックとパラリンピックによる海の日・スポーツの日・山の日の移動(2021 年 8 月 9 日の振替休日を含む)。
  - 春分の日と秋分の日は、天文の計算による近似の式で出す。正式には前年の 2 月に官報で決まるので、発表のない年の値は予測である。
  - 扱う範囲は 2000〜2099 年(春分と秋分の近似の式は 1980〜2099 年で有効とされる)。軸がその外にかかるときは誤りにせず、範囲の外の祝日を空にし、Excel の書き出しだけで警告を出す。SVG と PowerPoint はこの ADR では休日を描かないので、今描ける SVG のガント(1990 年の計画など)が描けなくなることはない。
  - 法の改正があれば、この関数を直して新しい版を出す。
- 休日は、Excel では休日のシート(D4)と方眼の塗りに使う。1 週 1 列のときは、週の中に休日と平日が混ざるので方眼は塗らず、稼働日数(F 列)にだけ効く。
- SVG と PowerPoint のガントは、この ADR では休日を描かない(未決)。モデルは持つので、あとから描ける。
- JSON の spec の gantt の部品(lib/spec.ts)の schema・説明・例に、`calendar`・`holidays`・`weekend` を足す。

### D4b: 予定と実績の 2 段のガントは、既存の `gantt` の入力で指定する

利用者の要望(2026-11-20): 予定と実績を 2 行で並べるガントを作りたい。新しいバンドは作らず、`gantt` に入力を足す(利用者が決定)。軸・セクション・今日の線・依存の矢印・PowerPoint の表の枠・Excel のモデルはすべて今のガントと共通で、変わるのはタスクの行の中身だけだからである。バンドを分けると、`LAYOUT_HANDLERS`・`EMIT_HANDLERS`・PowerPoint の `BAND_HANDLERS`・`XLSX_HANDLERS`(D2)・部品の一覧に同じ登録が 2 つずつ要り、予定だけのガントに実績を書き足すときに `type` を変えることになる。

この節は Excel だけでなく、SVG と PowerPoint の描き方も変える。

#### 入力

- `GanttOpts` に `actual?: boolean` を足す。`true` のとき、どのタスクの行も予定と実績の 2 段で描く。
  - 2 段にするかどうかをタスクのデータから自動で決めないのは、全部のタスクが未着手(実績が無い)のときにも 2 段の形を保つため。行の高さも全部のタスクで揃う。
  - バンドの `actual` は真偽、タスクの `actual` は日付の組で、同じ名前で意味が違う。JSON の schema の説明にそれぞれを書く。
- `GanttTask` に `actual?: {start: string; end?: string; days?: number}` を足す。
  - 日付は予定と同じく `spanOf` で解釈する(書式、`end` と `days` のどちらか一方、`days >= 1`、`end` は最終日を含む)。誤りのメッセージは欄の名前を言う(`"設計" actual.start` など)。
  - マイルストーンの実績は `{start}` だけを書く(`end`・`days` は誤り)。実績のマイルストーンは、その 1 日で済んだものとする(進行中にはならない)。
  - マイルストーンでないタスクで、`end` も `days` も無いものを**進行中**とし、実績のバーを `today` の日まで伸ばす。
- 検査(`checkGanttInput`、D1)に足すもの:
  - バンドの `actual` が `true` でないのに、タスクに `actual` がある: 誤り(「`actual: true` を付ける」と言う)。黙って捨てない。
  - バンドの `actual` が `true` のときの `progress`: 誤り。実績のバーで進み具合は見えるので、同じことを 2 通りに描かない。
  - 進行中のタスクがあるのに `today` が無い: 誤り。
  - `today` があるとき、実績の始まり、または実績の最終日(`end`、`days` から出した日、マイルストーンの日)が `today` より後: 誤り(まだ来ていない日の実績)。終わりの見込みを書きたいときは、終わりを書かずに進行中にする。`today` が無いときはこの検査をしない。
  - JSON の spec の検査(lib/spec.ts の gantt の部品の検査)は、予定の日付について独自に検査している(終わりが始まりより前、`end` と `days`、期間が 3 年を超える)。実績の日付にも同じ検査を足し、期間の長さには実績の日付も含める。
- 軸(`axisOf`)は、`from` / `to` で決めていない側について、実績の期間も含むように広げる。`from` / `to` で決めた軸の外に実績がかかるときは、予定のバーと同じく誤りにする。
- モデル(`ganttModel`)は、タスクごとに実績の期間(`[開始, 終了)` の日の番号。進行中は `today` の翌日まで)と、進行中かどうかを持つ。
- JSON の spec の gantt の部品(lib/spec.ts)の schema・説明・例に `actual` を足し、`examples/` に予実のガントの例を 1 つ足す(Excel のタスクのシートの K 列まで出る例にする)。

#### SVG と PowerPoint

- タスクの行の高さを、2 段のときは 1 段のときより高くする(14px の基準で 32px → 44px)。行の上の段に予定のバー、下の段に実績のバーを置く(それぞれ高さ 14px 程度)。タスク名は行の上下の真ん中に 1 つだけ書く。セクションの行の高さは変えない。
  - マイルストーンの菱形の大きさはバーの高さから決まる(`BAR_H/2+2`)ので、2 段のときは小さくなる。各段に収めるため、これでよいとする。
- 行の高さが行ごとに違うので、`layoutGantt` は行の位置を `top + i*ROW_H` ではなく、上からの積み上げで出す。セクションの帯、図の高さ、依存の矢印の経路(行と行の境の線)もこの位置を使う。
- `ganttTexts`(計測する文字の一覧)は、今は予定の日付だけから軸を出している。実績の日付で広がった軸の目盛りの文字も計測するよう、軸は `ganttModel` から取る。
- `LaidOutGantt` に `rows: {y: number; h: number}[]`(`band.rows` と 1 対 1)を足す。1 段のガントでも持たせる。PowerPoint の表の枠(下記)はこれを読む。
- 予定のバーは、タスクの色(`tone`)の薄い塗りと、同じ色の細い枠にする。実績のバーは、タスクの色で塗りつぶす。今の進捗のあるバー(薄い塗りと枠の上に、済んだ部分を塗る)と同じ描き方の部品で描ける。
- 進行中の実績のバーは、`today` の線(その日の真ん中に引かれる)で止める。右の端は角を丸めず(ほかのバーは角が丸い)、最後の一日分を薄くぼかして、まだ続くことを示す(ぎざぎざの端にする案もあり、実装で見比べる)。
  - モデルと Excel は `today` の日を丸ごと含める(Excel では今日のセルまで塗る)。SVG で今日の真ん中で止めるのは、今日の線とバーの端を揃えるためで、この違いは意図したものとする。
- マイルストーンは、予定を枠だけの ◇、実績を塗った ◆ にする。
- 凡例(`actual: true` のときだけ。1 段のガントの高さは変わらない): 図の下(最後の行の下)に、高さ 24px 程度の凡例の帯を足し、その左の端に「予定」の薄いバーと「実績」の塗ったバーを並べる。
  - 見出しの行に置かないのは、目盛りの日付(上の段)と `today` の文字(下の段)が見出しの行の上下をほぼ使い切り、どちらも自分の x を中心に置かれてタスク名の列の上にもはみ出すため。図の下なら何ともぶつからず、タスク名の列の幅も変わらない。
  - 図の高さは凡例の帯の分だけ増える。`plot.y2`(バーの領域の下の端)は変えない。
  - `LaidOutGantt` に `legend?: {swatches: (Rect & {kind: 'plan' | 'actual'})[]; texts: GanttText[]}` を足す。`texts` に混ぜないのは、PowerPoint の表の枠が、タスク名の列にある文字を行の名前とみなして表のセルに移す(`isRowLabel`)ため。PowerPoint では凡例を表のセルにせず、表の最後の余白の行の上に図形として重ねる(余白の行の高さは `plot.y2` から図の下の端までなので、凡例の帯を含む)。
  - `ganttTexts` に「予定」「実績」を足す。
  - 凡例は ADR 0054 の部品として、目盛り(`GANTT_AXIS`)と並ぶ `legend` の部品にする。
- 依存の矢印(`after`)は、予定のバーどうしを結ぶ。矢印の経路は、予定と実績の両方のバーをよける。`connect()` の端点になる `id` も予定のバーとする。
- レイアウトの結果(`LaidOutGantt`)では、実績のバーを `bars` に混ぜず、別の配列 `actuals: (Rect & {task: number; tone: 'accent' | 'danger' | 'muted'; milestone?: true; open?: true; part?: string})[]` に置く。`task` は `bars` の番号。実績の無いタスクには要素が無いので、`actuals` はタスクと 1 対 1 ではない。`bars` はタスクと 1 対 1 のまま(依存の矢印の計算がタスクの番号で `bars` を引いているため)。グループ(ADR 0054)の部品の名前は、予定のバーと同じタスクの名前にする。
- PowerPoint の表の枠(`ganttTable`。ブランチ `feat/pptx-native-rating-tables` で作業中で、この ADR の基点の `main` にはまだ無い)は、今は全部の行を同じ高さとして割っている。これを `rows` の位置から行の高さを取るように直す。タスクの 1 行は表の 1 行のままとし、予定と実績の段は同じ表の行の中に図形として重ねる(段の境に罫線は引かない)。

#### Excel

- タスクのシート(D4)の列は、2 段のときに次のように変える。
  - C・D の見出しを「予定開始」「予定終了」にする。E 日数と F 稼働日数は予定について数える。実績の日数の列は置かない(実績開始と実績終了から分かり、列を増やさないため)。
  - G 進捗の代わりに、G 実績開始、H 実績終了を置く(進捗は 2 段のときに使わないため)。値は日付。進行中のタスクは H を空にする。マイルストーンの H は、D と同じく `=G4` とする。
  - 先行タスク・色・id は I・J・K にずれる。セクションの行で空にするのは C〜K。列の文字は書き出しの中で列の名前から引き、数式に直接書かない。
- 表示のシートは、**1 タスクを 2 行**(上が予定、下が実績)にする。
  - 写しの式は、`INDEX(列, ROW())` の代わりに `INDEX(列, 4+INT((ROW()-4)/2))` でタスクのシートの行を引く。決まったセルを参照しないので、D4 と同じく並べ替え・挿入・削除・追加に追随する。予備の行は 50 タスク分(100 行)にする。
  - 上の行か下の行かは、書き出すときに行ごとに決め、それぞれの行に別の式を書く(`ISODD(ROW())` のような数式では決めない)。
  - 列: A 名前(上の行だけに出す)、B 区分(`予定` / `実績` の定数)、C 開始・D 終了(上の行は予定、下の行は実績の写し。どちらも `N(…)`)、E 種類・F 色(隠す。D4 と同じ位置)、G 以降は方眼。進捗の列は無い。
  - 下の行の D(実績の終了の写し)は、実績の終了が空で開始があるとき(進行中)に、書き出したときの `today` の値(数式の中の定数。D4 と同じく `TODAY()` は使わない)にする。`today` の無いガントで利用者が終了を消した場合は、開始の日だけを塗る。マイルストーンはタスクのシートの H が `=G4` なので、進行中にならない。
  - 方眼の数式(1 日 1 列)。上の行の例:
    `=IF($E4="マイルストーン",IF(G$3=$C4,"◇",""),IF(AND($C4>0,G$3>=$C4,G$3<=$D4),1,""))`
    下の行は `1` を `2` に、`"◇"` を `"◆"` に替えた式にする。`$C4>0` で、実績の無いタスクの下の行は空になる。
  - 1 週 1 列のときは、比較を `AND($C4>0,G$3<=$D4,G$3+6>=$C4)` にする。マイルストーンの判定も、`G$3=$C4` を `AND(G$3<=$C4,G$3+6>=$C4)`(その週に入るか)に替える。
  - 固定する列は D4 と同じく A〜D。
  - 条件付き書式(評価の順。どれも `stopIfTrue`):
    1. 値が `2`(実績)で F 列が `danger` → 濃い danger。同じく `muted` → 濃い muted。値が `2` → 濃い accent(F 列の条件なし)。
    2. 値が `1`(予定)で、同じ順に薄い danger・薄い muted・薄い accent。
    3. セクションの行(E 列が `セクション`)を灰色にし、A 列を太字にする。セクションの 2 行はどちらも灰色にし、名前は上の行にだけ出す。セクションの行の方眼は空なので、バーの規則が先に止めることはない。
    4. 休日(D4a)。D4 と同じく最後。
- 遅れ(実績の終わりが予定の終わりより後)を自動で色にすることは、この ADR ではしない(未決)。

### D5: 表はセルに、意味の値はセルの値に

- **数値は数値で書く**。利用者が直接書いた数値はそのまま書く。意味の表の組み立て側が文字にしている値(RPN、QFD の得点と相対 %)は、`TableCellSpec` に `value?: number` を足し、組み立て側で元の数値を残す。
  - `value` は内部用とする(`iconGlyph` と同じく組み立て側だけが入れる)。spec の schema には出さず、Excel の書き出しだけが読む。
  - `value` があれば、Excel には `text` ではなく `value` を書く。`text` は SVG の表示にだけ使う。
  - 表示形式は組み立て側が `value` と一緒に決める(`valueFormat?: string`)。QFD の相対 % は 12.3 のまま `0.0` で書く(SVG の表示と同じ数字にする)。
  - 文字列を正規表現で数値に戻すことはしない(郵便番号や品番を数値にしてしまうため)。
- `mark`(○△×◎)は、`cellOf`(lib/seq-table.ts)と同じ規則で、記号と、`text` があれば空白を挟んで続けて書く。`icon` は書き出さない(Excel のセルは SVG のアイコンを持てない)。代わりに 1 行目の題の行に注記を書く(D3)。
- 見出しの行、`rowHeader` の列、行の `tone` の塗り、太字、揃え、罫線は、SVG と同じ色で写す。色は常にライトの配色にする(Excel にはダークモードの考え方が無い)。
- 見出しの中の `\n` はセルの中の改行にし、折り返しを有効にする。
- 列の幅は、列の中の最長の文字列から決める(全角は半角 2 文字分として数える。改行のある文字列は最長の行で数える)。レイアウトの結果は使わない(D1)。
- **compare**: セルは table の `mark` と同じく「記号 + 空白 + note」。
- **harvey**: 評価は 0〜4 の数値の列と、玉の文字(◔◑◕● など)の列の 2 列にする。`notes` はその右の列に書き、`levels`(段階の名前)は 1 行目の題の行に凡例として書く(D3)。`highlight` の列は見出しを太字にする。玉の字形が Excel の標準のフォント(游ゴシック、MS ゴシック)にあるかは未確認で、実装の前に確かめる。無ければ玉の列は書かない。
- **heatmap**: 値は数値のまま書く。濃淡は、`spec` の `min`・`max`・`levels` から段階ごとの `cellIs`(値の範囲)の条件付き書式を作って写す。値を直すと色も変わる。`unit` と `decimals` は表示形式に写す(例: `0.0"件"`)。

### D6(第 3 段): 数値のグラフは、データの表と Excel のグラフ

- 1 枚のシートの上にデータの表を書き、その表を参照する Excel のグラフ(`xl/charts/chartN.xml`、`c:chartSpace`)を、シートの描画(`xl/drawings/drawingN.xml`)に置く。データを直すとグラフも変わる。
- **前提として、元の系列をバンドに残す型の変更が要る**。`lines()` は `plane` に展開されて系列の構造を失い、棒は `BarsBand` という別のバンドである。組み立て関数が `source?: {kind: 'lines', series: …}` のように元のデータを残すようにする。この変更は、PowerPoint のネイティブのグラフ(ADR 0027 D3 で後回しにしたもの)の前提でもある。
- 写す先: `bars`・`stackedBars`・chart の `stacked` は `c:barChart`、`lines` は `c:lineChart`、`radar` は `c:radarChart`、散布図と `bubble` は `c:scatterChart` / `c:bubbleChart`。
- Excel の従来のグラフに無いもの(waterfall、treemap は chartex の `cx:chart`。sankey は該当なし)は、データの表だけを書く。
- グラフの XML の部品は、PowerPoint と共有できる形で作る。

### D7(第 2 段): BPMN は、業務一覧とフロー図の 2 枚のシートを 1 つのブックに入れる

利用者の決定に従い、使う側が選べるように両方を出す。

#### 業務一覧のシート(データ)

- D3 の行の配置に従う。1 行 1 ノードの表にする。列は次のとおり。
  - 番号
  - レーン
  - 種類: タスク、開始、終了、排他分岐(xor)、並行分岐(and)、包含分岐(or)
  - 名前、補足(`sub`)
  - 次の手順: 番号と、条件があれば条件。複数あれば改行で区切る
  - 前の手順: 番号
  - 受け渡し: 次の手順へのフローが `line: 'dashed'`(レーンをまたぐメッセージ)なら、その旨
- 並び順のキーは(層、レーンの順、入力の順)。層は、`layoutLayered` のうちノードの大きさに依らない層の割り当て(循環を `breakCycles` で切ったあとの最長路の層)だけを、D1 に従って切り出して使う。差し戻しのフローは、切られた辺として「次の手順」に書く。

#### フロー図のシート(方眼紙の上の図形)

- シートの全部の列の幅と行の高さを、同じ大きさの正方形(20px 程度)にそろえる。いわゆる Excel 方眼紙にする。
- レーンの枠はセルで描く。
  - レーンのセルの範囲に罫線と塗りを付ける。
  - レーン名は、名前の列(縦向きの図では名前の行)の結合したセルに書く。
- ノードと矢印は、シートの描画(`xl/drawings/drawingN.xml`)の図形にする。
  - タスクは角丸の四角、イベントは円、ゲートウェイはひし形。
  - 矢印は、PowerPoint の既存のコネクタの書き出し(lib/pptx/connectors.ts)を使う。経路が既定の折れ線(`bentConnector`)の形に合う矢印は、両端をノードの接続点に結ぶ(`a:stCxn` / `a:endCxn`)。合わない矢印は、接続しない折れ線(`freeform`)にする。**ノードを動かしたときについてくるのは、接続できた矢印だけ**である。
  - ノードの形(角丸の四角・円・ひし形)ごとに、接続点の番号(`idx`)と、レイアウトが選んだ辺(上下左右)との対応を決める。
  - 条件のラベルは、テキストボックスにする。
- 位置は `LaidOutBpmn`(レイアウトの結果)から取り、px を方眼のセルとセルの中のずれ(`xdr:twoCellAnchor`)に直す(D1 の例外)。利用者が列の幅を変えたときに図形が伸び縮みしないよう、`editAs="oneCell"` を検討する。
- 図形の XML は PowerPoint と同じ DrawingML なので、PowerPoint と共有する。コネクタは既存の connectors.ts を使い、新しく作るのはノードの図形(角丸の四角・円・ひし形と、その中の印や文字)を書く関数だけである。
  - 今の PowerPoint の BPMN は、SVG から変換した図形で、矢印がノードに接続されていない。
  - ノードの図形の関数ができれば、PowerPoint の BPMN の矢印もノードに接続できるようになる。PowerPoint 側をそれに替えるかは、別に決める。

### D8: パッケージは自前で書き、zip と圧縮は PowerPoint と共有する

- 書くパーツは次のとおり。第 2 段で `xl/drawings/`(BPMN のフロー図)、第 3 段で `xl/charts/` が加わる。
  - `[Content_Types].xml`、`_rels/.rels`
  - `xl/workbook.xml`、`xl/_rels/workbook.xml.rels`、`xl/styles.xml`、`xl/worksheets/sheetN.xml`、`xl/sharedStrings.xml`
  - `docProps/app.xml`、`docProps/core.xml`
- `styles.xml` に入れるもの:
  - 日付の表示形式(`d`、`m月`)と `0%`、`0.0` などを、id 164 以降の `numFmts` に足す。
  - 条件付き書式の塗りは `dxfs` に置く。`dxf` の `patternFill` では `fgColor` ではなく `bgColor` で色を指定する。
- 文字列は共有文字列(`sharedStrings.xml`)に置き、前後の空白と改行を保つために `<t xml:space="preserve">` で書く。
- ブックの定義名(`<definedNames>`)に、ガントの `休日`(D4)を書く。
- `autoFilter` を置くシートには、Excel が自分で保存するときと同じく、隠れた定義名 `_xlnm._FilterDatabase`(`localSheetId` 付き、`hidden="1"`)を `workbook.xml` に書く。
- `docProps/core.xml` に作成日時を書かない。同じ入力から同じバイト列を出す(ADR 0027 と同じ保証)。
- zip と圧縮は PowerPoint と共有するため、`lib/ooxml/` にまとめて移す。
  - 移すもの: `lib/pptx/zip.ts`、`lib/pptx/zip-node.ts`、`lib/pptx-edge.ts` の `deflateRaw` と `zipPackage`。
  - PowerPoint 側の import を直す。`zipPackage` は `svg-diagram/pptx/edge` から公開され、lib/pptx-deck-edge.ts も使っているので、pptx-edge から再 export して公開の名前を保つ。
- 依存のライブラリ(exceljs、SheetJS など)は入れない。理由は ADR 0027 D4 と同じで、出力の決定性と、edge(Cloudflare Worker)で動くかどうかを自分で管理するため。ライブラリごとの詳しい比較はしていない。

### D9: 入口は PowerPoint と同じ 2 つ

- CLI: `svg-diagram xlsx <source.ts>... [--out FILE | --out-dir DIR] [--today YYYY-MM-DD]`(`xlsx-diagram.ts`)。
  - `.ts` の入力は `detachData` を通し、`today: 'auto'` を `--today`、`SVG_DIAGRAM_TODAY`、`.svg-diagram.json` の `today` の順で埋める(`build` と同じ)。
- edge: `svg-diagram/xlsx/edge` の `renderXlsxEdge(spec): Promise<{xlsx: Uint8Array | null, issues}>`。
  - JSON の spec を受け取る。edge の圧縮が非同期なので Promise を返す。
  - データのシートにはレイアウトが要らない(D1)。text engine は省略できる引数とし、rasterize は受け取らない。
  - BPMN のフロー図のシートには text engine が要る。渡されなければ業務一覧のシートだけを書き、フロー図を省いたことを `issues` に入れる。MCP のダウンロードは、PowerPoint と同じく text engine を渡す。
  - package.json の `exports` に `./xlsx/edge` を足し、test/package.test.ts も直す。
- core は `xlsxSupported(spec): boolean` を公開する。入れ物の中までたどって判定する(D2)。
- MCP のダウンロード(svg-diagram-mcp-plugin)に「Excel で保存」を足すのは、別の変更とする。ボタンは `xlsxSupported` が真の図にだけ出す。
- デッキ(`deck.json`)の Excel 化は範囲外にする。

### D10: 確かめ方

- 単体のテスト:
  - バンドごとに、セルの値・数式・書式・条件付き書式を確かめる。
  - 日付のシリアル値は、うるう年・月末・年またぎ・1900-03-01 の前後で確かめる。
  - 入れ物の中のバンドがシートになることを確かめる。
  - ガント: 行を足したとき(色の列が空)に accent のバーで塗られることを、条件付き書式の規則の形で確かめる。方眼のセルの数式が、期間・進捗・マイルストーン・週の重なりで正しい値を返すことを、式を評価する小さな関数で確かめる。
  - 祝日: `jpHolidays` の結果を、内閣府が公開している祝日の一覧(CSV)を固定したデータと突き合わせる(2000 年から、一覧にある最後の年まで)。CSV は Shift_JIS で、振替休日と国民の休日はどちらも「休日」という名前で載るので、突き合わせは日付で行い、名前は祝日に限って比べる。
  - 入力の検査で誤りになる入力が、Excel でも同じ誤りになることを確かめる。
  - 予実のガント(D4b): 入力の検査の各誤り、軸が実績まで広がること、進行中のバーが `today` まで伸びること、`bars` がタスクと 1 対 1 のままで依存の矢印が実績のバーをよけること、PowerPoint の表の行の高さがレイアウトの行と合うこと、Excel の表示のシートの 2 行の写しと方眼の値を確かめる。SVG と PowerPoint の見た目は、プレビューの PNG を見比べる。
- XML の検査: `test/helpers/pptx/xsd.ts` を一般化し、各シート・`workbook.xml`・`styles.xml` を `sml.xsd` で検査する。
- ゴールデン: 例(`examples/gantt.ts`、表の例、`chart-compare.ts` など)の .xlsx のバイト列を固定する。
- 実機:
  - Excel(Microsoft 365)と LibreOffice Calc で開く。ガントのタスクのシートで日付・進捗・色を直すと表示のシートのバーが変わること、タスクのシートの並べ替えで表示も並び替わること、休日のシートに日付を足すと方眼と稼働日数に効くこと、タスクのシートの途中への行の挿入と行の削除に表示が追随すること、行を足しても塗られること、フィルターから並べ替えたあともバーの色とマイルストーンがタスクに付いていること、範囲の下に足した行も並べ替えに入ること、条件付き書式の優先度が効くことを確かめる。BPMN のフロー図で、ノードを動かすと接続できた矢印がついてくることを確かめる。
  - Google スプレッドシートは、開けることと、条件付き書式が読まれるかだけを確かめる(互換は未確認)。xlsx の図形は読み込まないはずなので、BPMN のフロー図のシートは見えない見込み(未確認)。

## 検討した別案

- **図の絵を Excel に描く**(PowerPoint の図形の書き出しを、シートの描画に向ける): 作るのは比較的易しい。ただし、並べ替え・集計・日付の修正といった、Excel で受け取った人がしたいことには役立たない。BPMN だけは、データの一覧と並べて出す(D7)。
- **予実のガントを新しいバンド(`ganttActual` など)にする**: 2 段の描き方を今のガントのコードから切り離せる。しかし軸・セクション・依存・表の枠・Excel のモデルを共有するので、各所の登録が二重になり、予定だけのガントに実績を足すときに種類を替えることになる。入力の `actual` を選ぶ(D4b)。
- **ガントを 1 枚のシートにする**(タスクの列と方眼を同じシートに置く。初稿の形): シートが少なく済む。しかし利用者は表現と内部データを分けることを選んだ。データのシートは並べ替えやフィルターを自由に使え、表示のシートは方眼の見た目に専念できる。
- **祝日を外のデータ(内閣府の CSV、API)から取る**: 規則を書かずに済む。しかし、ビルドがネットワークに依存し、結果が実行した日で変わる。規則の関数とし、内閣府の一覧はテストの突き合わせにだけ使う。
- **ガントのバーをセルの直接の塗りにする**: 実装は単純になる。しかし日付を直してもバーが動かず、Excel のガントとしての価値が下がる。条件付き書式を選ぶ。
- **tone ごとに行単位の条件付き書式を作る**: 並べ替えや行の追加で、規則と行がずれる。隠した色の列を参照する、範囲全体の規則を選ぶ。
- **文字列のセルを正規表現で数値に戻す**: 型の変更が要らない。しかし品番や郵便番号まで数値にしてしまう。`value` を足す。
- **レイアウトの結果から作る**: PowerPoint と揃う。ただし、レイアウトはピクセルに直したあとの値で、Excel に要る意味(日付、数値)が落ちている。また文字の計測が要り、edge が重くなる。
