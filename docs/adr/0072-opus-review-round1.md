The spike files are in `/tmp/claude-1002/-home-cuzic/0926059a-61aa-4814-bcfe-b2e2d373d9e0/scratchpad/review-0072/`. "Read" below means I checked by reading the code. "Ran" means a spike showed it.

## Blocker

### B1. Every band loses its symbol before layout: `detachData` → `cloneData` copies only `Object.entries`
- **Location:** ADR 0072 l.23 (U0 premise), l.31 (D2 "spread keeps it"), l.68 (WeakMap rejected). Code: `lib/dsl/diagram.ts:101-130` (`cloneData` uses `for (const [k, x] of Object.entries(v))`, l.129). Its own doc comment, l.112-113, says *"Not copied: … symbol keys (NUMBERING, GIVEN, RICH)"*. It is called by `detach()` at `lib/dsl/render.ts:17-21`, which both `renderDiagram` (l.28) and `checkDiagram` (l.94) use. So every `build`, `check`, `show`, deck and PPTX path goes through it.
- **What happens:** U0 checked that `{...band}` and `cloneBand` keep enumerable symbols, which is true (`lib/dsl/shared.ts:58-60`). It did not check the deep copy that runs first on every render. Ran (`spike1.ts`, every export wrapped): before `checkDiagram`, every `d.bands` entry has the symbol (`caption:true box:true row:true group:true cycle:true … table:true banner:true connect:true`). After it, **every** laid-out band has lost it (`caption:false box:false row:false group:false cycle:false … table:false banner:false`). The diagram-level symbol survives, because `detachData` spreads `d` itself. As written, D2–D6 would produce no location for any part, in any CLI.
- **Second trap for the fix:** the natural holder, the object passed to `Error.captureStackTrace`, keeps its `stack` as a **non-enumerable** own property. Ran: `Object.getOwnPropertyDescriptor(h,'stack').enumerable === false`, `Object.keys(h) = []`. If someone "fixes" `cloneData` by recursing into symbol values, the holder is turned into `{}` and the stack is lost silently.
- **Fix:** In `cloneData`, copy the `SOURCE` key **by reference** (`for (const k of Object.getOwnPropertySymbols(v)) if (propertyIsEnumerable) out[k] = v[k]`), or limit it to `SOURCE` and leave NUMBERING/GIVEN/RICH as they are on purpose. Make the stored value a small class instance (`class SourceRef {constructor(readonly holder)}`), so any deep copy that shares class instances also shares it. Rewrite the U0 bullet (l.23) to name `detachData` as the path that matters, and add a U2 test that goes through `checkDiagram()`/`renderDiagram()`, not only `rewrite`/`styled`/`mapBands`. With the one-line `cloneData` patch applied, boxes, captions, banners and connects keep the symbol (ran). Containers still don't (see M1).

## Major

### M1. Many layout handlers build the laid-out band from scratch, so "spread keeps it" is false for containers and most figures
- **Location:** ADR l.23, l.31. Code: `lib/layout-handlers.ts:190` (group: `{type: 'group', x, y, …, id: band.id, reveal: band.reveal}`, explicit field picks), l.320 (swimlane), l.361 (legend), l.408 / l.474 / l.513 (row), l.557 / l.576 (grid), l.618 (pyramid); `lib/seq-table.ts:215` (table); `layoutFlowShape` behind `lib/layout-handlers.ts:118-125` (cycle/chevron/funnel/venn/…). About 20 such constructions in layout-handlers.ts alone, and more in `lib/charts-dsl.ts` and `lib/layout-util.ts` (grep for `{type: '…',` without `...band`).
- **What happens:** Ran (`spike1.ts`, with B1 patched): `laidOut: caption:true box:true row:false group:false box:true cycle:false row:false box:true table:false banner:true`. Patching handler by handler would mean touching dozens of sites, and new parts would forget it: the same objection the ADR raises against per-constructor capture (l.70).
- **Fix:** Propagate centrally at the one dispatch point, `ctx.stack` (`lib/layout.ts:339-345`). Record `n0 = ctx.laidOut.length`, run the handler, then set `SOURCE` on every new `ctx.laidOut[i]` (i ≥ n0) that lacks it. Ran (`spike-propagation.diff`, 3 lines): with that patch and the B1 patch, every top-level laid-out band in the spike carries the symbol (`caption, box, row, group, cycle, table, banner` all true). Nested `ctx.stack` calls (group contents, row children) keep their own, more precise location, because the patch only fills missing keys. Do the same for `deferred` connects at `lib/layout.ts:349`. Also rewrite the WeakMap rejection (l.68): once propagation is central, a WeakMap keyed by input band works just as well. The real reason to keep the symbol is the many *pre-layout* copies (`cloneBand`, `rewrite`, `mapBands`), not the layout.

### M2. Bands that don't come out of a wrapped export get no location, `.connect()` among them, which D1 explicitly promises
- **Location:** ADR l.27 (D1 lists `connect(...)` / `.connect(...)`), l.33. Code: `lib/dsl/diagram.ts:91` (`Diagram.connect` calls the internal `connectBand`, not the exported `connect`); `lib/dsl/defaults.ts:9-24` (`applyConnectDefaults` rebuilds every connect with `connectBand(b.from, b.to, merged)`, called from `add()` at `lib/dsl/diagram.ts:85` whenever `diagram({connectDefaults})` is set); composite constructors that build inner bands with the unwrapped module functions (e.g. `steps()` → row of boxes, `swimlane` steps); `expandLoopBacks` (`lib/pipeline.ts:32`) and the auto legend (`lib/pipeline.ts:40`).
- **What happens:** Ran: `d.connect('b1','b2')` produces `connect:false` even before detach. With `diagram({connectDefaults: {...}})`, the exported `connect('a','b1')` also turns `false` inside `add()`. The inner boxes of `steps([...])` are `box:false` after layout, even with B1 and M1 patched. Any rule or overlap finding on these parts falls back to "no location".
- **Fix:** (a) Wrap `Diagram.add`/`Diagram.connect` too: `connect` captures like an export, and `add` gives every band without `SOURCE` the `add()` call site. (b) In `applyConnectDefaults`, copy `SOURCE` from `b` to the rebuilt band. (c) In `located()`, after the call, walk `nestedBandsOf(result)` (`lib/rules.ts:184-190` already has the walker) and give every untagged descendant the outer call's holder. That covers `steps`/`swimlane`/`versus` internals for free. (d) Give loop-back connects the `SOURCE` of the band that declared `loopBack`. Add these cases to the U2 test.

### M3. D3 "innermost frame in the checked source" puts all calls of a same-file helper on one line
- **Location:** ADR l.35-37. Real case: `examples/areas-trace.ts:6` defines `const head = (text) => caption(text, …)`, and l.13 calls `head()` four times.
- **What happens:** Ran (`spike-d3.ts`): with `const head = t => box({title: t})` and two calls `head('A')`, `head('B')`, the in-source frames are `[head @2:29, define @5:5, <module> @10]` and `[head @2:29, define @6:5, <module> @10]`. The innermost frame is l.2 for **both**. The "same label in two places" benefit (結果 l.75) fails for exactly this pattern. So does the extension's planned "search the label inside the call range" (D1 l.27), because the label at l.2 is the variable `t`, not a literal. The ADR's `_parts.ts` example only works because the helper is in *another* file.
- **Fix:** Keep the whole chain of in-source frames (innermost first; it is already in the captured stack) as `loc` plus `via: SourceLoc[]`. Text/github/SARIF use `loc`. The extension tries the innermost call range first, and when the label literal is not found there (or several parts share the same `loc`), moves outward along `via`. The other option is to make `loc` the outermost in-source frame below the frame that called `define`, but that is wrong for `.map(t => box(...))` written on several lines. Either way, the ADR should state the rule and include this case in the U1/U2 tests.

### M4. D4 doesn't cover errors thrown during layout, the most common `build-error` (unknown anchor id)
- **Location:** ADR l.41 (D4 build-error: "from the thrown error's `stack`"), l.44. Code: `lib/layout.ts:349` → `lib/layout-connect.ts:228` (`connect(): unknown anchor id`); the layout-time throws in `lib/layout-handlers.ts:220, 250, 275, 278`.
- **What happens:** Ran (`check --format json` on `src/bad.ts` with `connect('a', 'nope')`): the stack is `resolveConnect ← layoutBands ← lay ← layoutWith ← layoutDiagram ← layoutFitted ← runChecked`, with no user frame. D3 finds nothing, so the error lands on line 1 as it does today. By contrast, define-time throws do carry the user frame (ran: `bad2.ts` box tone → `at define (src/bad2.ts:5:5)`), so U1's claim (l.59) holds only for those.
- **Fix:** In `ctx.stack` (and around the deferred `resolveConnect` loop), catch, set `err[SOURCE] ??= band[SOURCE]`, and rethrow. In D4, `build-error` reads `err[SOURCE]` first and the `err.stack` frames second. This depends on U2, so list it explicitly under U2 or U3 and drop "U1 alone fixes it" for layout-time errors.

### M5. `problemFindings` as a parallel array next to ~99 string push sites, plus ~96 rule push sites, is fragile and larger than U3 implies
- **Location:** ADR l.42-43, l.61. Code: `lib/verify.ts:146-161` (`problems` concatenated from `checkOverlaps` l.39-51, `checkConnects` l.56-81, `checkBounds` l.123-131, `figure.problems`, `contrastProblems`, …). `grep 'problems.push'` gives 99 sites in `lib/*.ts`, and there are about 96 `{rule: '…', severity` push sites across 6 or more files (`rules.ts`, `connect-rules.ts`, `fta-rules.ts`, `axis-rules.ts`, …; `lintAll` at `lib/rules.ts:875-900` calls more than 20 rule families). For `appearance: 'auto'`, `verifyDiagram` merges both sides by string (`lib/verify.ts:141`, `mergeSides` at `lib/appearance-auto.ts:70-74`).
- **What happens:** Read. A `problems: string[]` and a `problemFindings[]` built side by side will drift out of sync (order, dedupe in `mergeSides`, `check-diagram.ts:411` iterating only `problems`). And "rules that look at a part take its `SOURCE`" really means editing each of about 96 sites by hand, with nothing that measures coverage.
- **Fix:** Make the internal channel structured once (`{message, loc?, related?}` everywhere in verify), and derive `problems = structured.map(p => p.message)` at the edge for compatibility. For rule findings, add a helper `at(band)` that returns `{loc}`, plus a test over `examples/*.ts` that reports the share of findings with a `loc` per rule. That makes U3 something you can finish and keep from regressing. Do the overlap, bounds and connect checks (via `collectRects`, `lib/verify-handlers.ts:378-383`, one central place) first.

## Minor

### m1. 背景 misstates the extension's current placement
- **Location:** ADR l.14. Code: `~/svg-diagram-vscode/src/check.ts:76-88`.
- **What happens (read):** The extension places on the label only when it appears **exactly once** (`hits.length === 1`). Otherwise it uses line 1 with `approximate: true`. It never "puts it at the first hit", so it is not "wrong" with two hits. It is on line 1.
- **Fix:** Reword: "a label that appears twice, or is built at run time, falls back to line 1."

### m2. Frame paths: percent-encoding, realpath and Windows aren't handled by "remove `file://`"
- **Location:** ADR l.27 (D1 `file` relative to cwd), l.36.
- **What happens (ran):** A source at `…/日本 語/図.ts` shows in the stack as `file:///…/%E6%97%A5%E6%9C%AC%20%E8%AA%9E/%E5%9B%B3.ts:3:26`. Run through a symlinked dir (`linkdir/図.ts`), the frame shows the **real** path. The extension already works around the latter for crash stacks (`check.ts:124-127`). Naive stripping gives a path that never equals the checked source, so D3's source-first match fails silently for Japanese file names (likely in this project). On Windows it gives `/C:/…`.
- **Fix:** Specify `fileURLToPath()` after removing the query, `fs.realpathSync` on both the frame path and the checked source before comparing, and `path.relative(cwd, logicalPath)` (the CLI argument's logical path, not the realpath) for output. Add a test with a non-ASCII, space-containing path.

### m3. "Package root" as the skip boundary skips the repo's own sources
- **Location:** ADR l.36.
- **What happens (read):** When the CLI runs from a clone, the package root is the repo, so `examples/*.ts`, `test/fixtures/*` and the golden run (`package.json` `golden` script: `check-diagram.ts --drift --rebuild examples/*.ts`) are all "inside the package". Source-first saves the checked file itself, but the fallback ("user file") drops `examples/_parts`-style helpers. pnpm is fine, because ESM resolves symlinks, so `import.meta.url` and stack paths are both real paths.
- **Fix:** Define "package frames" as frames under the directory of the module that defines `located` (realpath of `new URL('.', import.meta.url)`, i.e. `lib/` or `dist/lib/`) plus the CLI entry files, not the package root.

### m4. Wrapper semantics are underspecified: `export *`, non-band returns, re-tagging
- **Location:** ADR l.30, l.60, l.70. Code: `lib/dsl-pure.ts:5-18` (`export *` from 13 modules); `lib/dsl/styled.ts:18-29` (returns a function); `lib/dsl/rewrite.ts:77` (returns the *same* objects for unchanged bands); `wf`/`em`/`icon` are objects, not functions.
- **What happens:** Ran: at runtime `dsl-pure` exports 127 functions and 3 objects (`em`, `icon`, `wf`), not "60+" (l.70). `export *` can't be wrapped, so every name has to become `export const x = located(ns.x)` plus `export type * from …`. I prototyped this for `diagram`/`box`/`row`: `tsc -p .` passes, and a probe `connect('a','nope')` still gets the `unknown anchor id "nope"` type error, so the type tricks (`IdsOf`, overloads, `Declares`) survive an identity-typed `located<F>(fn: F): F`. Unspecified: tagging a returned `rewrite(...)` array would overwrite each unchanged band's precise location with the `rewrite()` call site. Tagging must skip functions (`styled`) and non-band objects (`analyzeCriticalPath` results). `wf.*` nodes (wireframe children) get no location.
- **Fix:** State the rules in D2: tag only objects with a string `type` (and the elements of a returned array), **never overwrite** an existing `SOURCE`, skip functions, and treat `wf.*` as out of scope (or give it its own wrapper). Note the maintenance cost of the explicit export list, and let the U2 "unwrapped export" test enumerate `Object.entries(dslPure)` against a table of sample arguments.

### m5. U2's `partCatalog()` test doesn't cover most parts and never resolves a location
- **Location:** ADR l.60. Code: `lib/spec.ts:648`.
- **What happens (ran):** `partCatalog()` has 65 types, all JSON-spec parts. It lacks `box`, `row`, `group`, `caption`, `connect`, `grid`, `banner`, `stat`, `wireframe`, `screens`, the seaborn-style charts and others. Its examples are built through `lib/spec-parts/*.ts`, which import `lib/dsl.ts`, so every frame is inside the package and D3 resolves nothing. The test could only check that the symbol is present, not that it resolves to the right line.
- **Fix:** Use an explicit table that maps each band-returning export to minimal arguments (it is also needed for m4), built from a `.ts` fixture so that resolution is checked as well.

### m6. Enumerable symbols do show up in `assert.deepStrictEqual`, the same objection raised against a plain field
- **Location:** ADR l.67.
- **What happens (ran):** `assert.deepStrictEqual({a:1,[Symbol('x')]:1},{a:1})` throws, while the loose `deepEqual` passes. There are 217 test files using `deepStrictEqual`/`deepEqual`. Capture is off by default, so existing tests are fine, but any test that turns capture on (U2, CLI-level tests in process) and compares bands will fail.
- **Fix:** Say so in the ADR, and have tests that enable capture compare after stripping, or keep capture-on tests to the CLI's process boundary.

### m7. Which entry points turn capture on doesn't match who consumes it; D7 should not depend on it
- **Location:** ADR l.32, l.54.
- **What happens (read):** `show`, `serve` and `notes` are listed but produce no located output under D5/D6. `md`, `pptx`, `deck`, `site` and `pptx-deck` aren't listed (all install the resolve hook and load sources: `markdown-diagram.ts`, `pptx-diagram.ts:5`, `pptx-deck-diagram.ts:8`, `site-diagram.ts:10`). `build-error` (U1) needs no capture at all. The drift `--worker` children are spawned from the same `check-diagram` file (`drift-pool.ts:24`), so they inherit whatever `check` does, which is fine.
- **Fix:** Turn it on only in `check`, and in `build` when `--locations` is given. Say that U1 works without capture. Make D7's JSON Pointer always-on, since it needs no stack. That includes the library path the MCP server uses, which has capture off. Also define the prefix for a diagram inside a deck file (`/slides/4/diagram/parts/3`).

### m8. Dedupe by text drops the second location for identical labels
- **Location:** ADR l.75 (結果). Code: `lib/rules.ts:747-748` (`headlineLength` keeps a `seen` set keyed by line text); `lib/rules.ts:725`, `lib/verify.ts:141` (`mergeSides` keyed by `rule\0message`, `lib/appearance-auto.ts:70-74`).
- **What happens (read):** Two parts with the same over-long headline give one finding, so one location. With `appearance: 'auto'`, a dark-side finding whose message equals a light-side one from a *different* part is dropped.
- **Fix:** Include the location (or band identity) in those dedupe keys once `loc` exists.

### m9. D6's map is underspecified for connectors and nesting
- **Location:** ADR l.52. Code: `lib/emit.ts:109` (`viewBox="0 0 ${width} ${canvasHeight}"`); `lib/dsl/render.ts:67-69` (fill/canvas scale is applied *in layout* through roles, pad and gap); `lib/types/verdicts.ts:29`.
- **What happens (read):** The coordinates claim holds: the laid-out coordinates are the viewBox user units, including after fill/canvas scaling and `layoutFitted`. The extension inlines the SVG and zooms with CSS (`preview-html.ts:61-62, 95`), so the client has to map through `getScreenCTM()`. Unspecified: connects have `pathSegments`/`labelBox`, not a rect. Groups contain boxes, so a click hits several rects. Parts hidden at the final reveal stage are still in the map.
- **Fix:** Emit connectors as the bbox of the path plus the label (or the segments). Define hit order as smallest area first, then the latest band. Say that the client converts client coordinates with `getScreenCTM().inverse()`.

### m10. `Error.stackTraceLimit` is raised only inside the wrapper; U1's thrown errors keep the default of 10
- **Location:** ADR l.38, l.59.
- **What happens (read/ran):** An error thrown from a DSL check already spends 2 or more frames in the package (ran: `assertOneOf ← box ← define`). Deep user helper chains, plus `.map` and internal frames, can push the source frame past 10. This matters most for exactly the helper-heavy projects D3 targets.
- **Fix:** Have the CLI set `Error.stackTraceLimit = 50` once at startup (check and build), instead of only inside `located`.

## Nit

- **n1 (ADR l.22, l.78):** The cost figures are optimistic. Ran (`bench.mjs`, stack about 25 deep): capture costs 2.3 µs at limit 10 and 4.8 µs at limit 30. Formatting costs 9–25 µs. Retained heap is about 0.9–2 KB per unformatted capture. That is still negligible for hundreds of parts, but quote measured numbers.
- **n2 (D1 l.27):** V8's column points at the callee: `connect` in `d.connect(…)`, `box` in `box(…)`, the property in `W.box(…)`. It is not the start of the expression. Say so, so the extension's "call range" parser starts at the callee.
- **n3 (D5 l.48):** Adding `region` to SARIF changes GitHub code-scanning alert identity once: old alerts close and new ones open. Consider `partialFingerprints` that reuse the baseline fingerprint (`check-diagram.ts:175`).
- **n4 (D5 l.47-48):** For a `location` in another file, say what `github`/`sarif` annotate: the other file (useful in a PR), or the checked source with no line.
- **n5 (D3):** Read frames through the structured CallSite API (`Error.prepareStackTrace = (_, cs) => cs` around the lazy `.stack` read) instead of regex-parsing strings. It handles paths with parentheses, `async`/`new` frames and the ESM "at file://…" form with no function name, uniformly.
- **n6 (D5 l.49):** The `text` format change (one path per finding) alters output that `test/cli.test.ts` and users' scripts may parse. Mention it as a compatibility note.
- **n7 (実装の順):** Reorder U2 as U2a: propagation infrastructure (B1 `cloneData`, M1 `ctx.stack`, M2 `add`/`connect`/defaults, M4 error tagging), tested on the laid-out tree; then U2b: the export wrapper. U2a is where the risk is, and the wrapper is mechanical.
