# ADR 0075: causeTree の層の並びの探索(図につき 1 回の焼きなましを、順序探索の後ろの候補として足す)

- 状態: 提案(Proposed。2026-11-22。決める人は「スパイクが通ったので ADR を書く。範囲は e1 に絞る」と決定済み。下の「決める人への質問」が未決)
- 日付: 2026-11-22
- 基点: `main`(eec05f8c)。測定は cb55027d の上(その後の `lib/` の差は `movedAside` の削除だけで、出力は変わらない。patch は当たる)。測定の道具と試作は PR #432(`docs/spikes/layer-order-search.md`、`scripts/crt-u6-measure/q3-layer-order.patch`、`lo-run.sh`・`lo-compare.mjs`・`lo-bench.sh`)
- 関連: ADR 0073(順序探索の採点・U5 の Q3。この ADR はその「層の並びを直接探す探索」)、ADR 0070(CRT の辺の読みやすさ。完了の基準)、ADR 0053(探索の費用)、ADR 0019 D4(並びの再探索)
- 範囲外: 報告の図の交差 5 を減らすこと(**この ADR では減らない**。下の「棄却」)。`pdpc`・`relationDiagram`・`whyWhyTree`(`causeTree` の自分の帯だけ。`band.base`・`band.layerFrom` のある帯は変えない)。`layer: 'asap'`(どの版でも変わらなかった)。AND でない矢印の段差(ADR 0073 U6)

利用者の実際の図のラベル・言い回しは、この ADR にも測定にも持たない。図は fixture の ID と乱数の CRT の図番号で指し、実ファイルは `REPORT_CRT` で数だけ測った。

## 背景

ADR 0073 の U5 で、層の並び(ダミー節を含む)を焼きなましで動かして層の間の交差の下限を出し、その並びを**すべての配置に強制**すると、fixture と報告の図が 5 → 2、乱数の CRT の交差が約 46% 減ることが分かった。しかし `cause-crossing` が +2〜+12、折れが +2〜+6%、CPU が ×7(配置のたびに焼きなますため)で、60 節のベンチマークでは利得が出なかった。決める人は 2026-11-22 に「先にスパイク。ゲートを通ったときだけ ADR」と決めた(ゲートは、`cause-crossing` が合計でも図ごとでも増えない、折れ ≤ +3%、費用 ≤ +30%)。スパイクの結果(PR #432)は、**探索を図につき 1 回にして既存の探索の後ろの候補として足す**形(e1)がゲートを通る、というもの。この ADR はその形を決める。

## 決定

### D1: 層の並びの探索は図につき 1 回、最初の配置の中で走らせる

- `layoutCauseBandAt` の最初の `base` の配置(`once(undefined, false, true, undefined, true)`)の中の `layoutLayered` で、層の並び(ダミー節を含む行)が掃引で決まった直後に探索を 1 回だけ走らせ、見つけた行の並びを結果として取っておく(`base` の配置自体の並びは変えない)。配置のたびには走らせない(U5 の版の ×7 の原因)。
- 探索は**隣り合う 2 節の入れ替え**だけで、同じ連結成分の中に限る。1 手の差は、その 2 節の隣の層との辺の組だけで出る(U5 の版は毎回全体を O(E²) で数え直していた)。目的は層の間の交差の数で、**同じ AND の結果に入る 2 本の辺の交差は重み 6**(AND の交差が採点の最初の key だから)。
- 手順(固定): 掃引の並びを種に、乱数で各行を崩した再出発を**5 回**、それぞれ**3000 手**の焼きなまし(温度 2 から 0.05 まで幾何に冷やし、受理は `exp(-差 / 温度)`)。最良の並びを返し、仕上げに挿入のしぼり込み(各節を行の中の最良の位置へ動かす。同点は元の位置に近い方)を最大 8 回かける。
- **決定的**: 乱数は線形合同法(`s = (s × 1664525 + 1013904223) mod 2^32`)で、**種は定数 7**(図に依らない。同じ図は同じ並びを得る)。既存の順序探索の種(`20260417 + 節の数`)とは別の列を使う。種を変える(例: 節の数を足す)ときは測り直す。
- 費用の上限は手の数で決まる(5 × 3000 手)ので、節が増えても探索そのものは線形に近い。

### D2: 結果は、既存の順序探索のループの**後ろ**で候補として足す

- 既存の順序探索(最初の順序・回転・乱数の並び・隣の入れ替え)は、**main とまったく同じに最後まで走らせる**(同じ点列・同じ選び)。その後で、D1 の並びを強制した配置を**1 つの候補**として `windowPool` に足す。
- **ループの前に足してはならない**。最初の版(ループの前)は、図ごとの測定で `cause-crossing` が増えた(乱数の #33。main では順序探索が AND の交差 0・交差 7 の並びを見つけるのに、交差 4・AND の交差 1 の並びが先にプールの最良になり、その後の探索の道筋が変わって AND の交差 0 の並びに届かなかった。canvas の #149 も)。ループの後なら、main の選びは必ず候補に残る。
- `post`: 順序探索が選んだ最良の並び(`bestOrder`)がある図では、その並びで 1 回配置し直し、その掃引の並びを種に D1 をもう一度走らせて、その結果も候補として足す(1 配置の追加)。最良の並びが `base` のままなら省く。

### D3: 選びは既存の採点と 1.25 倍の規則のまま。main の選びを最終の選びに残す

- 候補は、既存と同じふるい(`inFrame`: 同じ層の順位・AND の置き去り・サイズ制限の数)と同じ高さのふるい(`passesHeight`。1.25 倍は**最初の順序の図**に対して)を通り、同じ採点(AND の交差 → 窓(交差・組・折れ)→ 高さ。ADR 0073 D1・D2)で選ばれる。新しい key も重みも足さない。
- 最終の選び(`pickFinal`)の候補は、`first`・`found`(選ばれた並びの詳細な経路つき)・`best` に加えて、**main が選んだ並びの詳細な経路つきの図**(層の並びの候補が勝ったときだけ、1 配置を足して作る)と、main が選んだプールの図を残す。層の探索の候補が、main が選んだ図より AND の交差の多い図を選ばせない(詳細な経路で AND の交差が増える図があるため)。

### D4: 4px 未満の重なり(`ov`)を増やさない保護を、規則にする

- 候補の図の `parallelRuns(経路, 4)` の数が、プールのその時点の最良の図より多いときは、候補に入れない。これは採点の key ではなく、ふるいである(ADR 0073 の完了の基準「4px 未満の重なりが増える図 0」を、探索が破らないため)。
- 測定の根拠: 保護が無い版(d1)は、重なりが plain 14 → 20(5 枚)・canvas 5 → 9(3 枚)に増えた。保護(e1)で 14 → 12・5 → 3、増える図 0。

### D5: 費用の上限と母数

- 探索とその候補の配置は、`layoutCauseBand` の最初の図が交差を持つ(既存の順序探索に入る)図でだけ走る。交差 0 の図(乱数の CRT の約 2/3)は、いまと同じに最初の図で返る。
- パラメータ(5 × 3000 手、`k`=1、`post`)は**固定**する(設定項目にしない)。`k`(違う並びを複数個候補にする)は棄却(下)。

## 棄却: `k`=3(違う並びを 3 つ候補にする)

`k`=3(10 回の再出発・各 4000 手、`ov` つき = e2)は、fixture と報告の図の交差を **5 → 2**(折れ 52 → 40、報告の図は 42、最大 4 → 2 / 4)にする(U5 の下限に届く)。しかしゲートを通らない。

| 項目 | e2 |
|---|---|
| 乱数の CRT の交差 | −18.2% / −20.6% |
| `cause-crossing` | −19.6% / −21.2% |
| 折れ | +1.2% / +2.6% |
| 費用 | サンプル +15% / +16%、60 節 +8%、**120 節 plain +41%** |
| fixture(既定・canvas なし・minText 14・報告の図) | 倍率の線の間隔の組 **0 → 1**(ADR 0070 の基準「組 0」を満たさない) |

(`k`=3 + `post` は 120 節 plain +98%・60 節 AND +40%、5 × 3000 手・`k`=3・`post` は 120 節 plain +51%。60 節 AND では k3 は交差 26 → 44・折れ 168 → 202 を選ぶ。AND の交差 1 → 0 との交換。)よって**いまは棄却**し、報告の図の点 1(交差 5)は残す。再検討の条件: 費用の刻み(質問 2)が入り、かつ ADR 0070 の組の基準を決める人が見直したとき。

## 60 節のベンチマークの所見: 層の間の交差の下限は 0 ではない

U5 は「60 節では強制しても利得が出ない」の原因を追っていなかった。測ると、**下限そのものが 0 ではない**。

| 図 | 層の間の交差(焼きなまし) | main の経路の交差 |
|---|---|---|
| 60 節 plain | 19(30 回 × 30000 手で 13) | 17 |
| 60 節 AND | 19〜30 | 26 |
| 120 節 plain | 約 60 | 59〜62 |

乱数の CRT の小さな図(8〜19 節)では 0 だったが、リンクが多い大きな図には 0 の並びが無い。さらに、経路の交差は層の間の交差より 6〜10 多く(ポート・AND の弧・トラック)、main は既にその下限に届いている。強制した並びの経路の交差は、60 節 plain で 19(main は 17)。**探索の不足ではなく、構造上の限界**である。大きな図での利得は、AND の交差を採点が先に見る交換(60 節 AND の 26 → 22)に限られる。

## 影響

- 乱数の CRT の `cause-crossing` が約 22〜24% 減り、交差が約 19% 減る。fixture・`examples/toc-*`・報告の図は**変わらない**(交差 5、折れ 52、組 0。点列の hash が main と同じ)。ADR 0070 の基準は main と同じに満たす。
- 交差のある図の最初の配置に、探索 1 回と、候補の配置 1〜2 回(層の探索の候補、`post` の再配置、勝ったときの main の図)が足される。
- `lib/` に足すのは、層の探索の関数(新しいファイル)・`layoutLayered` の差し込み 1 か所(掃引の後。種の行を取る / 強制した行を入れる)・`toc.ts` の候補の足しと最終の選びの 2 か所。`causeTree` 以外の図(pdpc・relationDiagram・whyWhyTree・states・classes・semnet・bpmn)は golden の差分 0。

### U1

- 試作 `q3-layer-order.patch` を元に実装する。**デバッグ用の環境変数 `LO`・`searchStats` の `why*` などの計測の項目は持ち込まない**(`laid` の隣に、層の探索の配置数だけを足す)。グローバルの `layerSpike` は、`layoutLayered` の引数(種の行を返す関数・強制する行)に直す(`prep` を通す)。
- テスト: (1) 層の探索の関数: 行の入れ替えが交差を数え直した値と一致する(差の計算の検証)。同じ入力で同じ並び(決定的)。同じ連結成分の外へ動かさない。重み 6 の辺の交差は、重み 1 より減らされる。(2) `toc` の候補の位置: ループの前では #33 の `cause-crossing` が増える図を、後ろでは main と同じになる(乱数の #33 または小さな再現の図)。main の選びが、層の探索の候補が負けた図で変わらない。(3) `ov` の保護: 重なりが増える候補が採られない。(4) `post` が、最良の並びが `base` のとき走らない。(5) `band.base`・`band.layerFrom` のある帯は変わらない。
- ピン(`test/fixtures/crt-random-pins.json`): 点列の hash は更新しない(図ごとの値で持つ)。P1 に例外 3 枚(plain #147・#162、canvas #147)を足す。P3 に組が増える図を足す(質問 1 の結果による)。P4 の折れは、折れの外れ値の図の記録を足す。ピンの値は、e1 の測定の値(上の表)を上限にする。
- golden: `examples/toc-*` と fixture は変わらない(差分 0 を示す)。乱数の CRT の golden を持つ図があれば、点列が変わる図(68 + 43 枚)に当たるものだけ更新する。CI の golden は Noto フォントで作る(`scripts/golden-docker.sh --write`)。

### U2

U1 の上で、上の測定を測り直す(plain・canvas の合計、図ごとの悪化、60/120 節の費用、fixture・報告の図)。費用が +30% を超える図があれば、質問 2 の刻みを入れる。結果を ADR 0073・0070 の注記に書く。

## 完了の基準

- `cause-crossing` が、合計でも図ごとでも main より増えない。折れの合計が +3% 以下(plain・canvas とも)。
- 交差が main より増える図は、AND の交差が減る図だけ(上の 3 枚)。4px 未満の重なりが増える図 0。
- 費用が +30% 以下(plain・canvas のサンプルと、60/120 節の plain・AND・canvas)。
- fixture・`examples/toc-*`・報告の図が変わらない。他の図の golden の差分 0。

## 決める人への質問(それぞれ推奨つき)

1. **組が増える図(plain 9 枚、canvas 6 枚)を受け入れるか**。推奨: **受け入れる**。採点は交差・AND の交差が組より先で(ADR 0073 D2 の決定)、合計は減る(−5%/−11%)。受け入れる場合は、ピン P3 の記録の図に足す。受け入れない場合は、候補の採用に「組が増えない」を足すと(`ov` と同じ型のふるい)、利得が減る(測っていない。U1 の前に測る)。倍率の線の間隔の組 0 は fixture と報告の図の基準で、これらは満たされたまま。
2. **120 節 plain の費用(+27.5%、境界)の刻み**。推奨: **U1 では入れず、U2 で測って +30% を超えたら入れる**。入れるなら、節の数(ダミー節を含む行の合計)が 150 を超える図では再出発を 5 回から 3 回にする(120 節 plain で、およそ +27% が +20% 前後になると見込む。測っていない)。`k`=3 の再検討(報告の図の 5 → 2)は、この刻みが入ってから。
3. **折れの外れ値(1 枚で +6〜+10)の扱い**。推奨: **ピンに記録して受け入れる**。いずれも交差か AND の交差が減る図で、合計は +0.2%/+0.7%。折れの上限(図ごとに +4)を新しく規則にすると、#99・#140 の利得(交差 −3・−4)を捨てる。
4. **`k`=3 の棄却を ADR 0070 の組の基準とあわせて見直すか**。推奨: **いまは見直さない**。報告の図の交差 5 → 2 は利用者に見える改善だが、組 0 → 1 と費用 +41% が付く。質問 2 の刻みの後に、組を `k`=3 の候補の採用条件にした版(組が増える候補は入れない)を U2 で測れる。
5. **種を定数 7 にしてよいか**(図に依らない固定の列)。推奨: **よい**。決定的で、再出発の乱数は図の形から作る意味が薄い。変えるなら測り直す。
