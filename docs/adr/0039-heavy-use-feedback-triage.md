# ADR 0039: 大量利用の報告にもとづく改修依頼 14 項目の仕分けと順序

- 状態: 提案(方針のみ。各項目は別 PR で、必要なら個別の ADR を足す)。Opus の読み取りレビュー 2 巡目までを反映した版
- 日付: 2026-10-21
- 基点: `main`(PR #312 まで)
- 関連: ADR 0037(別の大量利用の報告にもとづく診断改善)、ADR 0038(`check --drift --rebuild` の並列とキャッシュ)、ADR 0019(`maxNodeW`・`dir: 'auto'`)、ADR 0015(TOC の `tocCheck`)、ADR 0036(`diagram({density})`)
- 由来: 書籍原稿の制作で、画像生成 AI が作った PNG 約 250 枚の SVG への置き換えと、章ごとの TOC 図約 100 枚を、並列エージェント約 26 本で作った利用者の報告(別セッションから受領)

## 背景

依頼は 14 項目。性質が違うので、まとめて実装せず、**運用で足りる / 小さい修正 / 新機能**に分ける。レビューで利用者の実ファイルを使って測った結果、**新しい部品を足す前に、既存の機能で足りる項目が複数ある**ことが分かった(D3)。

確認した事実:

- 項目 1: 再現した。原因は型定義の解決ではなく、報告者のプロジェクトに typescript が無く **`tsc` が見つからない**こと。
- 項目 2: 型検査を走らせれば `banner({text})` は `TS2353` になる。しかし実行時は `build` も `check --strict` も通り、中身の無い banner が黙って出る。さらに、**未知の「値」も実行時に素通り**している(`steps()` の項目の不正な `tone`、`caption` の不正な `align`、`row` の不正な `arrows`。`assertBoxTone` は `box()` やレーンにはあるが `steps()` の項目には効いていない)。
- 項目 3: `check --covers 語.csv` が、表(md / csv)の語の一覧を既に受け付ける(`lib/covers.ts` の `checkCovers`)。#312 は `diff --text`(SVG どうしの語の網羅照合)を新しく足したもの。入力が画像のものは無い。
- 項目 5: SVG の `<title>` は、`title` が無ければ最初の caption / banner の見出しから取られる。報告者の図の約半数は、`diagram({title})` と同じ文字列の caption を**二重に**書いていた。
- 項目 6: `keepWords` は `cycle` に効かない(README)。さらに効いているのは別の所: `lib/flow-shapes.ts` の `layoutCycle` が円の半径を `Math.min(54, …)`、図の高さを `Math.min(520, …)` で頭打ちにしていて、ラベルの幅が約 81px(全角 5 字)になる。幅が 940px あっても円は大きくならない。
- 項目 7: 横の列の戻りは `loopBack` / `loop-under` で既に描ける。描けないのは**縦の列の、同じ側どうしのアンカー**(`s7:left` → `s1:left`)で、`elbow` は両端の x が同じだと向きの符号が 0 になって箱の縁をまっすぐ通り、`loop-under` は下へ回るだけ。しかもエラーの「直し方」の文(`route: 'loop-under'`)が縦の列では誤り。
- 項目 10: `toc-ude-count` と `toc-no-desired-result` は**既定で info**(`diagram({tocCheck: 'strict'})` の図だけ warn)。報告者の全図の `accept` を外しても `check --strict` は通った。`cause-crossing` は warn だが、部分図かどうかとは関係ない(部分図でない図でも AND の交差は起きる)。
- 項目 11: `.svg-diagram.json` の `{"accept": {…}}` が案件全体に効く(図ごとの `accept` が優先)。
- 項目 12: 縦横比の最大は 1.84 で、2 を超える図は無かった(334 枚で実測)。`fold` は `causeTree` にしか無く、縦長の図の大半は `group` / `row` を手で積んだもの。
- 項目 13: `--jobs` と成功キャッシュは `check --drift --rebuild` にだけある(ADR 0038)。`.svg-diagram.json` は**カレントディレクトリから上へ**探す(ソースの場所からではない)。

## 決定

### D1: 先に出す修正(1 PR ずつ)

| 項目 | 内容 |
|---|---|
| 1 | `typecheck` は、プロジェクトに typescript が無いとき、svg-diagram 自身の typescript を使う(**実装済み**)。順は「プロジェクト → 自身 → PATH の `tsc`」(古い `tsc` は `init` が書く `erasableSyntaxOnly` を知らず `TS5023` で止まるため、確かめてある自身の版を PATH より先にする)。**自身の typescript があるのは clone で入れたときだけ**(`devDependencies`。パッケージで入れた環境には無い)ので、見つからないときのエラー文に「clone 版ならその clone で `pnpm install`」と書く。`init` の最後の案内(`pnpm add -D typescript @types/node`)は、パッケージで入れた利用者には正しいので変えない。PATH の `tsc` の分岐をテストで通せるよう、環境変数 `SVG_DIAGRAM_NO_OWN_TS=1` で自身の版を外せるようにする。異常終了で残った一時ファイルは、次の実行が(生きていない PID のものを)消す。同時に、一時 tsconfig の名前に PID を入れる(固定名だと、同じディレクトリで並列に走らせたとき、片方が終わって消したファイルをもう片方が読みに行って落ちる) |
| 2 | **キーの一覧より先に、次の 2 つ。** (a) 必須の欄が空なら throw する(`banner` に `headline` が無い。`box` は、中身になる欄 — `title` / `body` / `lines` / `note` / `icon` / `statValue` など — が**全部**無いとき。`box({icon})` だけの箱は正しい使い方なので throw にしない。実装の前に `examples/` と `test/` を回して、throw にしても通ることを確かめる)。綴りの間違いの症状の大半はこれで捕まる。(b) 既にある列挙の値の検査を、全部の入口で通す(`steps()` の項目の `tone` など)。未知キーの検出そのものは、使用頻度の高い部品に限る。受け付けるキーの一覧は `as const satisfies Record<keyof Opts, true>` で型と結びつけ、キーの足し忘れも余分も `tsc` が落とす(生成もテストも要らない)。全部品の一括導入はしない |
| 7 | 同じ側どうしのアンカーを、その側へ外に回す**新しい route**を足す(`loop-side` など。名前は実装時に決める)。**既存の `loop-under` の向きは変えない**: 側が下でないアンカーに `loop-under` を書いた既存の使い方(右と右、上と上)があり、変えると既存の SVG が変わって「書かなければ 1 バイトも変わらない」に反する。エラーの直し方の文をアンカーの向きで出し分ける。回る余地が図の余白(`pad`)しか無い場合に、viewBox からはみ出さないことを検査に含める。「外周レーンを `steps` / `row` に持ち込む」大工事は、これで足りなかったときだけ |
| 5 | `diagram({title, showTitle: true})`: 題名を図の先頭の見出しとして描く。既定 off(書かなければ SVG は 1 バイトも変わらない)。`title` と先頭の caption が同じ文字列なら `showTitle` を勧める info を同時に足す(二重に書いた図の移行の道筋)。題名を描くと `cjk-line-long` の対象になること、移行すると既存の見た目(太字の caption と `role: 'title'`)が変わり、golden の差分が大量に出ることを README に書く |
| 6 | `layoutCycle` の頭打ち(半径 54・高さ 520)を見直す。楕円の環(横の余白を使う)も比べる。`keepWords` を `cycle` に効かせるのは、その後で足りなければ。語が割れるとき・環が帯に収まらないときの扱い(throw か、警告つきで出すか)を決めてから実装する |

### D2: 設計してから(各項目で個別に ADR 化するかを決める)

- **項目 4(`math()` の日本語)**: 今は `lib/math-tex.ts` が、`<text>` が出ると throw する(字の幅が当てにならないため)。案 A: `\text{}` の CJK だけを通常の文字描画にする(MathJax の `<text>` は、送りは 1 字 1em だが、**1 字ずつ別の `<text>`、`font-family="serif"`、0.884em** で出る(実測)ので、そのままでは書体・大きさが図と合わず、字間が空く。1 本につなぎ、図の書体・大きさに置き換えて `lib/font-metrics.ts` で幅を測り直す後処理が要る)。resvg の PNG・PPTX の書き出し・暗色テーマも別々に確かめる。案 B: HarfBuzz で字を輪郭にする(`lib/emoji-color.ts` で既に使っている。数式は「全部輪郭」の約束が保たれるが、フォントのファイルが見つかることが前提)。**どちらでも、数式の中の語は `diff --text` / `check --covers` / `doc-fidelity`(`<text>` を読む)から見えなくなるか、ばらばらになる**ので、`math()` の `alt` を照合に含めるかを、項目 3 と一緒に決める。上付きの小さな字(約 70%)で CJK が読めるか、最小の字の大きさ(`fontFloor`)の検査に当たるかも確かめる。再現の基準は、語の算式を `caption('＝')` + `box` + `caption('÷')` で組んだ既存の図。
- **項目 8(矢印ラベルの重なり)**: 報告された再現例は、回避のためにラベルが消されていて、今は再現できない(元の版も版管理の外)。**依頼元に失敗した版を出してもらってから**設計する。
- **項目 9(`flowchart`)**: `bpmn` には `xor` / `and` / `or` のゲートウェイ、開始・終了イベント、差し戻しの迂回がある。足りないのは (a) レーンを描かない 1 本の流れ(`BpmnLane` は `label` 必須)と (b) 縦向き(自動では切り替わらない)。**まず「`bpmn` のレーン無し・縦向き」で何が足りないかを測り**、足りないと分かったときだけ新しい部品にする。
- **項目 12(縦長)**: 縦横比の閾値は、実測(最大 1.84)では 2 だと何も出ない。版面(本文の領域は約 1.5〜1.6)を基準に決める。勧める内容は部品ごとに分ける(`causeTree` は `fold`、`row` は `cols` で 2 列、それ以外は図を分ける)。自動で `fold` にはしない(図の見え方が黙って変わるため)。

### D3: 運用の返事で足りるもの(コードの変更なし。README / skill にレシピを書く)

- **項目 10(`partial`)**: **見送り**。`toc-ude-count` などは既定で info なので、`accept` はもともと要らない。要るなら、図のディレクトリに `.svg-diagram.json` を 1 つ置く。`cause-crossing` を `partial` に入れるのは分類の誤り。`partial` は、部分図だと分かることで**検査の中身**(UDE の数え方・孤立節の扱い)が変わると示せるまで足さない。
- **項目 11(`kind: 'form'`)**: **見送り**。案件の `.svg-diagram.json` の `accept` に `gray-tone-collision` / `density` を 1 行書けば、図ごとの許容は不要になる。閾値の違いが実際に要る例が出てから、名前(ADR 0036 の `density` との衝突)と範囲を決める。
- **項目 3(PNG との文言照合)**: まず、画像から語を書き起こした一覧(1 行 1 語の CSV)を `check --covers` に渡すレシピを書く。書き起こしは画像を読めるエージェント自身でよい。足りないのは、逆向き(SVG にだけある語)と「要目視」の別枠くらい。**OCR(外部コマンド)は、そのレシピで書き起こしが当てにならないと分かってから**。
- **項目 13**: 並列利用の注意を README に書く。`build` は引数のソースだけを触る(glob の展開は呼び出し側)/ 書いたファイルを 1 行ずつ出す / `typecheck` と `.svg-diagram.json` の探し方(**カレントディレクトリから**。別のディレクトリから走らせると設定が読まれず、結果が揺れる)/ キャッシュの書き込みは rename で原子的(`drift-cache-io.ts`)。`check --strict` への `--jobs` と成功キャッシュは、ADR 0038 の仕組みを流用できるか調べてから決める。**版管理の外にある図での `--drift` の振る舞い**(キャッシュのキー、来歴)も、その調査に含める。
- **項目 14(`--fix-refs`)**: `check --docs` の検出条件を広げる。「参照先の PNG が無く、同名の SVG がある」だけでなく、**移行の途中で一番多い「PNG は残っていて、同じ名前の SVG もある」**も対象にする(今の `check-diagram.ts` は、PNG が無いときは `doc-image-missing` を出して先へ進み、PNG があるときは SVG を探さない)。まず差し替え案を出すところまで。書き換え(`--fix-refs`)は `--dry-run` と差分表示を付けた次の PR。

### D4: 順序

1. 項目 1(実装済み + PID の一時ファイル + エラー文)
2. D3 の返事(10・11・3・13)。コードの変更が無く、報告者の次の改訂にすぐ効く
3. 項目 2 (a)(b)。項目 1 の直後に報告者が直す内容と重なる
4. 項目 7 → 5 → 6
5. 項目 4(案の比較を ADR にし、項目 3 との影響を同じ ADR で決める)
6. 項目 8(失敗した版が届いてから)→ 12 → 14 → 9(測ってから)

## 結果として

- `typecheck` が走るようになると、既存図の型エラーが見える。型検査を走らせ忘れると素通りするので、**`check --strict` の終わりに「typecheck を走らせていない」と 1 行出す**か `check --typecheck` を足すかを、項目 2 の PR で決める(全体の `tsc` は 248 本で約 3.4 秒)。
- 項目 5 の移行は既存の SVG を変える。報告者に勧めるときは、差分が見えるよう図を版管理に入れることも添える。

## 未決

- 項目 3 の OCR を、外部コマンドにするか WASM 版を同梱するか(後回し。レシピの結果しだい)。
- 項目 10 の `partial` を、検査の中身が変わる使い方が見つかったときに足すか。
- 項目 9 を部品として足すか、`bpmn` のレーン無し・縦向きとして足すか(測ってから)。
