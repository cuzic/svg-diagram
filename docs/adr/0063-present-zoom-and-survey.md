# ADR 0063: スライドの拡大縮小と、主なプレゼンテーションのツールの機能の調査

- 状態: 拡大縮小は実装済み(2026-11-15、利用者の要望)。調査は下の節
- 基点: `feat/deck-serve`(ADR 0062 まで、未コミット)
- 関連: ADR 0056(`serve`)、ADR 0062(聴き手と発表者の画面の操作)

## 背景

利用者から「拡大縮小もできるようにしてほしい。主なプレゼンテーションのツールが持っている機能を網羅的に調べて」と要望があった(2026-11-15)。スライドは文字まで輪郭にした SVG なので、拡大しても文字がぼやけない。細かい図を会場や手元の端末で読むのに向く。

## 決定: 拡大縮小

- D1. **どの画面でも**(聴き手・発表者)拡大縮小できる。1 倍(スライド全体)から 6 倍(`MAX_ZOOM`)まで。
- D2. **操作**:
  - キー: `+`(`=`・`;`)で拡大、`-` で縮小、`0` か Esc で元の大きさ。拡大している間は、矢印キーで見る所をずらす(PowerPoint Live と同じ)。そのため、拡大中は矢印キーでスライドが変わらない。PageUp・PageDown と操作バーのボタンでは変わる。
  - マウス: Ctrl + ホイールで、指している所を中心に拡大縮小する(トラックパッドのピンチも、ブラウザはこの形で送る)。ダブルクリックで、その所を 2.5 倍に、もう一度で元に戻す。
  - タッチ: 2 本指のピンチ。ダブルタップで 2.5 倍と元を切り替える。
  - パン(見る所をずらす): 拡大している間だけ。マウスのドラッグ、1 本指のドラッグ、ホイール(拡大していないときのホイールとスワイプは、今までどおりスライドを送る)。
  - ボタン: 聴き手の操作バーと発表者の画面に「－」「100%」「＋」。「100%」は今の倍率を表示し、押すと元に戻る。
- D3. **スライドが変わったら元の大きさに戻る**(どのツールも、拡大はそのスライドの間だけ)。
- D4. **発表者の拡大は聴き手にも見える**(PowerPoint の発表者ビューの拡大と同じ考え方)。
  - 発表者の画面で拡大すると、`{type: 'zoom', index, z, x, y}` を送る(1 秒 30 回まで、保存しない)。
  - 連動している間、または発表者に付いている聴き手のうち、同じスライドを見ている人の画面が同じ所を拡大する。
  - 聴き手が自分で拡大縮小したら(元に戻す操作も含む)、そのスライドの間は自分の拡大を優先し、発表者の拡大で動かない。「発表者に合わせる」(`b`)で、発表者の拡大に戻る。
- D5. **作り**: 画像を `transform: translate() scale()` で動かし、枠(`.zbox`)の外を切る。レーザーポインターの位置は、拡大した画像の上で計算する(拡大していても、指した所に出る)。

確かめたこと(nov18 の写し、Chromium、自動の操作で 20 項目。ADR 0062 の 23 項目もそのまま通る):

- `+` 2 回で 156%、`0` で元に戻る。拡大中の → でパンし(スライドは変わらない)、Esc で元に戻る。
- Ctrl + ホイールで、指している所(スライドの 70%, 42% の点)が拡大の前後で動かない。
- 拡大中は、ドラッグでパンでき、ホイールはパンになってスライドが変わらない。
- ダブルクリックで元に戻り、別の所でダブルクリックすると 250%。次のスライドに移ると 100%。
- 発表者が 195% にすると、付いている聴き手も 195% になる。聴き手が自分で元に戻した後は、発表者がさらに拡大しても動かない。「発表者に合わせる」で、発表者の 244% になる。
- 携帯の幅:
  - 2 本指のピンチで拡大し、ダブルタップで元と 250% が切り替わる。
  - 拡大中のスワイプは、パンになってスライドが変わらない。
- 自動テスト:
  - 拡大のやりとりの形と範囲(`test/present-sync.test.ts`)。
  - 手元とWorker で、発表者の拡大が聴き手に届き、聴き手からは送れないこと(`test/serve-cli.test.ts`、`worker/test/worker.test.ts`)。

## 調査: 主なプレゼンテーションのツールの機能(2026-11-15)

発表と閲覧の機能(作る側の機能は除く)を、各ツールの公式の文書で調べた。対象は PowerPoint、Keynote、Google スライド、Canva、Pitch、Prezi、reveal.js、Slidev、Marp、impress.js、Beamer / pdfpc、Teams・Zoom・Meet の発表の機能、Mentimeter / Slido。全文(英語、出典の URL つき)は `docs/research/presentation-tools-2026-11.md`。

### 前提が変わったこと

- PowerPoint の「Present Live」(聴き手が QR で自分の携帯から見る、字幕つき)は 2025-05-30 に終わり、「Teams の PowerPoint Live」に移った。
- Keynote Live は、Apple のガイドで「提供を終了する」とされている。
- 2026 年に聴き手が自分の端末で付いてくる形を持つのは、Teams の PowerPoint Live、Slidev、reveal.js(multiplex)、Canva、Pitch。いちばん詳しい手本は Teams の PowerPoint Live。
  - 聴き手は自分で見て回り、「発表者に合わせる」で戻る。
  - 発表者は自分で見て回ることを止められる。
  - 聴き手は自分で一覧・拡大・ハイコントラスト・翻訳・スクリーンリーダーを使える。
  - ADR 0062 と D4 の形は、これとほぼ同じ。

### 次に作る候補(未着手。利用者に確かめてから)

調査の推奨(「今作る」)のうち、まだないもの:

1. 黒・白の画面(`B` / `.`、`W` / `,`)。発表者が押すと聴き手の画面も暗くなる。クリッカーの「画面を消す」ボタンもこれを送る。
2. 直前に見ていたスライドへ戻る(Keynote の `Z` にならう)。
3. `?` で操作の一覧を重ねて出す。
4. ノートの文字の大きさ(発表者の画面で +/−。拡大のキーとぶつかるので、ノートの上にボタンを置く)。
5. 残り時間の表示と、進み具合の色(今は「n 分早い・遅い」の文。reveal.js と pdfpc にならい、帯の色でも示す)。
6. 範囲を囲んで拡大、スポットライト(pdfpc)。

作らないもの:
- 字幕・翻訳(音声を外に送ることになる)。
- Q&A・投票・反応(別のサービスの領分)。
- 録画・カメラ・Presenter Coach。
- 画面の選び方(ブラウザの窓で足りる)。
- 段階表示・凝った切り替え効果(デッキに段階がない)。
