# ADR 0085: デッキの図の文字が、スライドの本文に比べて小さいときの警告と、部品ごとの文字サイズの引き上げ

- 状態: 提案(Proposed。2026-11-27。決める人への質問 Q1〜Q6 が未決。実装はまだしない)
- 日付: 2026-11-27
- 基点: `main`(f1c8205f。PR #500 まで)
- 関連: ADR 0060(図の配置: `fit: "fill"`、倍率の上限 1.5。**この ADR の前提**)、ADR 0024(`stat()` の値を収まる大きさへ縮める。候補の大きさを測定に登録する前例)、ADR 0055 D4・ADR 0056 D2(9pt を下回ると警告。経路をそろえる)、ADR 0017(文字サイズの下限の層)、ADR 0014 D3(byte 同一の扱い)、ADR 0059(段の図)
- 依頼(B3、デッキの利用者から): 16:9 のスライドで、concentric(`labels: inside` の輪の名前)、venn(集合の名前とラベル)、cycle(4〜6 段階の円の中の文字)、sankey(節の名前)、versus(本文つきの項目)の文字が、短い言葉でも本文の半分に満たないほど小さい。同じ内容を mindmap・chevron・table にすると読める。「文字をスライドに合わせて大きくする」か、せめて「小さすぎる」警告がほしい。今は警告が出ない。
- 試しの測定: `renderDeck` で 1 部品 1 枚のデッキを描いて測った(下の「測ったこと」)。例の言葉はすべてこの ADR のための作り話で、利用者の図の言葉は使っていない。
- 範囲外: 文書の図(`renderSpec`・`build`)、`canvas` の図、`.ts` の図が持つ `fill: true`(ADR 0060 以前からある別の仕組み)、mindmap・chevron・table の変更

## 背景

### 測ったこと

方法: 1 つの部品を `figure` に置いた 1 枚のデッキを `loadDeck` と `renderDeck` で描く(`measure: 'font'`、日本語フォント)。スライドは 1280×720 で、同じスライドの文字は見出し 37px、リード 19px、強調の枠 16px(`lib/deck-layout.ts` の `STYLE`)。図の文字の実効の大きさは、図の中の大きさ × k(入れ子の `<svg>` の width ÷ viewBox の幅)。スライドの SVG は文字が輪郭に変わっているため、大きさは glyph の `scale(s -s)` × 1000 から読んだ。

条件 A は見出しとリードだけ(図の空き 約 1168×553)。B は見出し・リード・強調の枠 1 つ(約 1168×500)で、中身を増やした。C は見出しだけ(約 578 の高さ)。言葉は作り話(「チーム」「顧客と取引先」「計画」「実行」「紙で申請する」など)。

読み取れること。

- 再現した: concentric・venn・cycle と、項目が多い versus は、12〜16px。対照(mindmap・chevron・table)は 19〜21px。
- 再現しなかった: sankey と、項目が少ない versus は 21px で読める。sankey は 1 つの層に節が多いときだけ縮む(行 C)。
- 依頼の「本文の半分未満」は、既定のリード(19px)に対しては再現しなかった。最悪でも 0.64 倍。利用者の本文がもっと大きいか、図がもっと詰まっているかの可能性が高い(Q の前に、利用者の数字を聞くのがよい)。
- どの部品も、図の中の文字は 14px(versus の題だけ 15px)。違いは k だけ。
- 2 段組みでは、段が狭いため幅の探索が狭い配置を選び、radial な部品も k=1.5 に届く(例: cycle 563×364)。問題は、広くて低い空きに 1 つの図を置くスライド。

### 原因

共通の原因: デッキは図を `k = min(空きの幅 ÷ 図の幅, 空きの高さ ÷ 図の高さ, 1.5)` 倍に縮尺する(ADR 0060 の `fillSearch`)。図の中の文字は役割の固定の大きさ(`ROLES`、14px。`lib/tokens.ts`)で、k 以外では変わらない。横長で低い部品(mindmap・chevron・table、節が少ない sankey)は上限の 1.5 に届き、文字が 21px になる。高さが部品自身の寸法で決まる部品は、k が空きの高さ ÷ 図の高さ(約 1.0)で止まる。幅を狭める探索(ADR 0060 D1)は、円は幅を狭めても低くならず、行を積む部品は高くなるだけなので、効かない。

部品ごとの原因(`origin/main` を読んだ)。

| 部品 | 場所 | 原因 |
|---|---|---|
| concentric | `lib/flow-concentric.ts:83-95` | 半径 `R = min(220, w × .42)` は、幅 940 では常に 220(直径 440、図の高さ 496)。文字は `roles.note`(14)。輪の厚みは R÷n(輪 3 で 73px、5 で 44px)で、文字はもっと大きくできるが、寸法から大きさを選ぶ処理がない。固定の寸法(絶対の上限)と固定の文字。 |
| venn | `lib/flow-venn.ts:25-30` | 半径 `r = min(w × .21, 170)`(3 集合)、`min(w × .23, 190)`(2 集合)。高さは 1.28r + 1.52r + 余白 = 576(全体の枠あり)。直径 340px の円の中に 14px。`fits` は収まらないときに `misfits` を報告するだけ。固定の寸法と固定の文字。 |
| cycle | `lib/flow-cycle.ts:51-64`、`:106` | `h0 = min(520, max(300, w × .62))`、円の半径 `nr` は最大 54。ラベルは `roles.note`(14)。円の中に余白が多い。固定の寸法と固定の文字。 |

### 既存の検査

- `smallTextWarning`(`lib/deck-layout.ts`、`MIN_TEXT_PT = 9`): 「縮めた後のいちばん小さい文字が 9pt(12px)未満」。**絶対の値**で、スライドの本文との比ではない。`renderDeck`・`serve`・`pptx-deck` が同じ警告を出す(ADR 0055 D4、ADR 0056 D2)。測った図はどれも 12.2px 以上なので、警告は 1 つも出ない(venn B は 12.2px = 9.15pt で、線のすぐ上)。依頼の「今は警告が出ない」はこれ。
- `analyzeFit`(`lib/fit.ts`): `slide` の図に「on-slide text is ~Npx (< 12px)」。既定 `minEffectiveFont` 12。`canvas` と文書の図は対象外。同じ絶対の 12px。
- `slide-min-text`・`slide-canvas-overflow`(`canvas` だけ)、`font-size-too-small`(lint-svg、倍率 1 で 14px)、`font-floor-lowered`(info)。ADR 0017 の層。どれも本文との比ではなく、部品ごとでもない。
- `text-too-small` という名前の規則は無い。同じスライドの本文と図の文字を比べる処理は無い。

### 既存の仕組みと、使えないところ

- `diagram({slide, fill: true})` の `.ts` の図は、`findFillScale`(`lib/slide-fill.ts`)で役割を最大 1.8 倍にして空きの高さを埋める。デッキの spec の図の経路(`renderDeckSpec`)は `fontScale: 1` で、この仕組みを使わない。
- 役割を全体で拡大すると、箱も一緒に大きくなる。行を積む部品(versus・sankey)は図も高くなり、k が下がるので、実効の大きさはほとんど変わらない。**固定の寸法を持つ部品(円)だけ**、文字だけが大きくなって得をする。だから、役割の全体拡大ではなく、部品ごとの対応にする。

## 決定の案

どの項目も「決める人への質問」(下)の答えで確定する。ここに書くのは推奨の案。

### D1. 警告: スライドの本文に対する相対の下限(U1)

`smallTextWarning` に、絶対の 9pt に加えて、**図のいちばん小さい文字の実効の大きさが、そのスライドのリード(なければ強調の枠)の大きさの X 倍を下回る**ときの警告を足す。X は Q1(推奨 0.8)。リードも強調の枠も無いスライドは、絶対の 9pt だけ。

- 場所: `smallTextWarning`(`lib/deck-layout.ts`)に、スライドの本文の大きさ(`STYLE.lead.size`、なければ `STYLE.callout.size`)を渡す。`present/render-deck.ts` と `pptx-deck-edge-core` の両方がすでにこの関数を呼ぶので、`serve`・`site`・`pptx-deck` に同じ警告が出る(ADR 0056 D2)。
- 文言: 「図の文字が約 Xpx で、スライドの本文(Ypx)の N% しかない。図の中の部品(venn, cycle, …)の項目を減らすか、スライドを分ける」。部品の名前を入れる。
- 描画の結果は変わらない。警告の追加だけ。

### D2. 部品の文字を、寸法に合わせて大きくする(U2。concentric・venn・cycle)

デッキの図に限り、concentric・venn・cycle は、文字の大きさを **{14, 16, 18, 20, 22} から、ラベルが輪の帯・円・節に収まる最大のもの**にする(上限は Q3)。

- 収まるかの検査は既存のものを使う(concentric の `chord(k.h)`、venn の `fits`、cycle の `fits`)。輪の帯 44〜73px、円 340px、節 約 108px で、余地がある。
- 大きさは部品に 1 つ(ラベルごとにしない)。ラベルの大きさがそろう。
- 候補の大きさは、ADR 0024 D3 の前例にならって、`*Texts()` の測定の登録に入れる(登録にない大きさの幅は引けない)。
- 文書の図・`examples/out` は **byte 同一**(ADR 0014 D3)。デッキだけの内部の指定(ADR 0060 D7 の `wideWidths` と同じ種類)で渡し、spec の項目は増やさない。
- 目安の効果: 輪 3 の concentric は 14 → 約 20px で、実効 15.6 → 約 22px。

### D3. sankey の節の高さ(U3)

節 1 つに割り当てる高さを、文字から決める。`H = max(300, (lh + gap + 余白) × 層の最大の節数 + 120)` へ(Q4 で係数を決める)。1 層 8 つで H が 488 から約 400 に下がり、k は 1.1 から約 1.4 になる。部品の既定の見た目が変わる(文書の図の golden が動く)ので、**デッキだけ**にするか、文書の図も変えるかを Q4 で決める。

### D4. versus(U4)

Q5 で決める。推奨は、まず D1 の警告だけ(新しい配置を作らない)。

### D5. 作業の順(Q6)

U1(D1)→ U2(D2)→ U3(D3)→ U4(D4。必要なら)。U1 は描画を変えず、単独で入れられる。

## 決める人への質問

Q1. **相対の下限(D1 の X)**

| 案 | 内容 | 効果(測った図) |
|---|---|---|
| a | 本文(リード 19px)の **0.8 倍**(15.2px) | venn・cycle・versus B・sankey C・concentric B を警告。concentric A(0.82)は警告しない |
| b | 0.75 倍(14.25px) | venn・cycle・versus B・concentric B(0.74)を警告。sankey C(0.81)・concentric A は警告しない |
| c | 絶対の **14px**(役割の下限。ADR 0017) | 警告する図は a に近い。リードの大きさが変わっても動かない |

推奨: **a**。リードに連動するので、利用者が大きい本文を使うほど厳しくなり、依頼の「本文に比べて」に合う。c は単純だが、本文が小さいスライドでは過剰になる。

Q2. **警告か誤りか**

| 案 | 内容 |
|---|---|
| a | 警告(`warnings`)。スライドは描く |
| b | 誤り(`errors`)。スライドを描かない(「図の問題は誤り」の ADR 0056 D2 と同じ扱い) |

推奨: **a**。既存のデッキが急に止まらない。9pt の警告と同じ扱いで、そろう。b は、誤りにしたいという要望が出てから。

Q3. **concentric・venn・cycle の文字をデッキだけ大きくするか、その上限**

| 案 | 内容 |
|---|---|
| a | デッキの図だけ、{14, 16, 18, 20, 22} の最大。**上限 22px**(22px × k(約 1.0〜1.2)で約 22〜26px) |
| b | 上限 20px |
| c | 大きくしない(D1 の警告だけ) |

推奨: **a**。ADR 0060 D2 の「縮尺は 1.5 まで、見出し 37px よりずっと小さく」と同じ考えで、大きくした文字が本文(19px)を超え過ぎないようにする。22px で k=1.0 のとき本文の 1.16 倍。c は、依頼の「文字をスライドに合わせて大きく」に応えない。

Q4. **sankey の節の高さ**

| 案 | 内容 |
|---|---|
| a | 節 1 つの高さを文字から決める。**デッキの図だけ** |
| b | 同じ変更を文書の図にも入れる(golden が動く) |
| c | 変えない(D1 の警告だけ) |

推奨: **a**。測った限り、問題が出るのは 1 層に節が多いときだけ(行 C)で、他は 1.5 に届く。文書の図は変えない(byte 同一)。係数(`46` → `lh + gap + 余白`)は U3 のときに、行 C が k=1.4 前後になる値を試して決める。

Q5. **versus**

| 案 | 内容 |
|---|---|
| a | 警告だけ(D1)。項目を減らすか、スライドを分ける |
| b | デッキの図で、片側が 3 項目を超え、高さで縮むときは、各側の項目を枠の中で 2 列に並べる |

推奨: **a**。新しい配置を作らない。2 列(b)は、利用者が密な versus を求めたときに別の ADR の段階にする。

Q6. **作業の順**

| 案 | 内容 |
|---|---|
| a | U1(警告)→ U2(concentric・venn・cycle)→ U3(sankey)→ U4(versus。Q5 が b のときだけ) |
| b | U2 を先に |
| c | 1 つの PR にまとめる |

推奨: **a**。U1 は描画が変わらず、単独で入れられて、以後の U2・U3 の効果(警告が消えること)を測る基準になる。

## 作業の順(Q の答えが出てから)

- U1: `smallTextWarning` の相対の下限(D1)。`renderDeck` の再現テスト(venn B・cycle B・versus B が警告を出し、対照の mindmap・chevron・table は出さない)、`pptx-deck` でも同じ警告。描画は変わらない。
- U2: concentric・venn・cycle の文字(D2)。デッキの図だけ。実効の文字がリードの 0.8 倍以上になるテスト。文書の図が byte 同一であるテスト。
- U3: sankey の節の高さ(D3)。
- U4: versus(Q5 が b のときだけ)。
