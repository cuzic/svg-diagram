# ADR 0042: `bpmn(..., {dir: 'v'})` — レーンを列にして、流れを上から下へ

- 状態: 実装済み(PR は本 ADR と同じ)
- 日付: 2026-10-21
- 基点: `main`(PR #316 = 戻る矢印が向かい合う辺につながる)
- 関連: ADR 0016(層状の図の経路)、ADR 0035(経路探索の罠)、ADR 0036(`density`。`env.space` を行の間隔に掛ける)、ADR 0031(FCIS。新しいファイルは純粋な層)
- 範囲外: `swimlane()` の縦向き、`fit: 'shrink'` の縦向き版、PPTX の図形書き出し(`bpmn` は今まで通り画像として入る)

## 背景

業務フローを「上から下」に流したい場面がある(縦長のページ、担当が多く流れが短い図)。ブラウザ版の「業務フロー図メーカー」(Artifact)は、ライブラリにない縦向きをその画面の中で自前に描いていた。その経路は、箱や文字や他の線を確かめずに決めており、次の図が出た:

- ゲートウェイの 2 本の分岐が、同じ下の頂点から出て、ラベルが同じ位置に重なる
- 「失注」(受注するか→完了)と「入金なし」(入金確認→督促)の横線が 4px しか離れず、縦線も一直線に続いて、別の矢印に見える
- 戻る矢印が、自分のゲートウェイの名前の文字を貫通する

ライブラリへ入れれば、`check`(重なりの検査)・`density`・`connect()`・`reveal`・ノードの id が、そのまま使える。

## 決定

### D1: `BpmnOpts.dir?: 'h' | 'v'`。既定は `'h'`(今のまま)
`'v'` だけが新しい配置(`lib/bpmn-vertical.ts`、`layoutBpmnVertical`)を通る。入力の検査(レーン・ノード・フロー)とノードの大きさの測定は `lib/bpmn.ts` の `checkBpmnInput` / `measureBpmnNodes` を両方向で共有する。`dir` が `'h'` / `'v'` 以外、または `dir: 'v'` と `fit` の併用は throw(縦向きの幅は列から決まり、詰める段がない)。

### D2: 配置
- 列 = レーン(幅 `min(240, floor(w / レーン数 / 4) * 4)`。4 の倍数にして、レーンの縁を 4px の格子に乗せる)。タスクの最大幅は `列 − 28`(80 未満なら throw)。
- 行 = 流れに沿った層(`layoutLayered`、横向きと同じ)。同じ(レーン, 層)に 2 つ以上あれば縦に積む。行の間隔は `44 × density`。
- 開始・終了イベントとゲートウェイの名前は、図形の右に置く(列が持つ余白の幅で折り返す)。ゲートウェイの名前は、頂点を通る横線の上に出す(横の頂点から出る線が、名前の下を通れる)。

### D3: 経路 = 候補を作って選ぶ
進む矢印は、出口(下 / 左右の頂点)× 入口(上 / 左右の頂点)× 横線の高さ × 袖の長さ、戻る矢印は、左右の頂点同士・上下辺から出て列の外を回る形、の候補をすべて作る。各候補を点数で比べる: 長さ + 曲がり × 12 + 側面の罰(行き先に面さない頂点から出る 80、面する側 25、側面から入る 60 / 120)+ 他の線との交差 × 80 + 衝突 × 1000。衝突は、他のノード・名前・条件ラベル(箱は 4px、文字は 2px の余白)に当たる線、他の線と同じ向きで 5px 未満に並ぶ線(端が 8px 未満しか離れず一直線に続くものを含む)。進む矢印は短い順に、戻る矢印は最後に決める(外側を回る線は、中を通る線に場所を譲らせない)。条件ラベルの白い札は、その矢印を決めた直後に置き、後から決める矢印がそれを避ける。

### D4: 検査と描画
`LaidOutBpmn` に `dir?: 'v'` を足し、レーンの `labelH`(名前の見出しの高さ。縦向きでは `labelW` は 0)を足した。描画はレーンの見出しを上に、検査(`checkBpmn`)は文字の範囲の上端に `labelH` を使う。矢印・ノード・札・PPTX(画像として)の扱いは変わらない。

## 見送った案
- **横向きの配置を回転して流用**: 横向きの経路は「前へ進む」前提(列の隙間の使い方、名前が下に垂れる)で、回すと名前や札の置き場が合わない。
- **ブラウザ版の経路をそのまま移す**: 型がなく、札と線の重なりを後から検査していた(置ける場所が残らない)。D3 のように札を先に置く方へ直した。

## 残り
- 実在の図での計測(レーンが 5 つ以上、ノードが 20 以上)と、`density: 'compact'` の効き。
- ブラウザ版の業務フロー図メーカー(Artifact)を、この描画に差し替える(今は画面側の描画を直した版で公開している)。
- 同じ 2 つのノードを結ぶ往復(入金なし ⇄ 督促)が、右の頂点側を回る形になる。専用の「往復」の形は作っていない。
