- 状態: 実装済み(第1段。D1〜D4・D6〜D9 と U0〜U8・U11。D5 の第2段 `straight` / `order`(U10)、D10 の文面(U12)、D11 の AND の並走(U13)は未着手。下の「実装での補足」を参照)
- 日付: 2026-10-13
- 基点: `main`(4e58744、PR #124 まで)
- 関連: ADR 0008(同じ依頼元の第 3 巡)。依頼の原文は「Medius への AI・DX 提案資料」の図づくりで挙がった要望の A 節(A1〜A5)。追補(2026-10-14): 同じ依頼元の G 節のうち G1・G2・G6(下の D9〜D11。TOC の他の要望は ADR 0015、G5・G10 は ADR 0010)

## 背景

資料づくり側(Medius の提案資料、図 約 25 枚)から、「自動配置の図で矢印が何度も直角に折れ、交差も多い」という要望が最優先で届いた。5 件ある。

| ID | 要望 | 優先度 |
|---|---|---|
| A1 | 折れ線の数を最小にするレイアウト(連関図 `b3-relation` が縦に 1362px、PDPC の戻る点線が何度も折れる)。`routing: 'min-bends'` か `straighten: true` の案 | 高 |
| A2 | 端点の整列(因果ツリーで親子の中心がずれ、矢印がわずかに折れる)。Brandes-Köpf 法のような整列の案 | 高 |
| A3 | 手動の整列ヒント(`align` / `rank` / `order` / `straight`) | 中 |
| A4 | `check` に `edge-bends` ルール(1 辺あたり・図全体の折れ数の閾値。`accept` で許容) | 中 |
| A5 | 戻り辺(PDPC の「対策 → 元の工程」)を、図の外周の専用レーンにまとめる | 中 |

要望には「既存の機能で解決できるものがあれば教えてほしい」とある。先にコードを読み、既に満たされているもの・いないものを確かめた。

### 現状(事実)

自動配置の図は、行き先で配置の仕組みが 3 つに分かれる。

| 仕組み | 使う図 | 折れ・整列の扱い |
|---|---|---|
| 木 `layoutTree` / `layoutBalanced`(`lib/graph-layout.ts:36`, `:91`) | `tree`(`lib/tree.ts:86`)、`mindmap`(`lib/map-layouts.ts:68`) | 親は子の幅の中央に置く(`:57-60`)。辺は肘(中点で折れる)か曲線か直線(`types.ts:1030` の `edges`)で、既に選べる |
| 層状 `layoutLayered`(`:160`)+ 経路 `routeLayered`(`lib/layered-route.ts:47`) | `stateDiagram`(`lib/states.ts:64`, `:100`)、`causeTree` / `relationDiagram` / `pdpc`(`lib/toc.ts:93`, `:122`。`relationDiagram` と `pdpc` は `lib/dsl.ts:1640`, `:1661` で `causeTree` に渡る)、`classDiagram`(`lib/classes.ts:59`, `:94`)、`semnet`(`lib/semnet.ts:86`, `:92`) | 下で詳しく |
| 層だけ借りる | `bpmn`(`lib/bpmn.ts:84`) | 列は `layoutLayered` の層。行はレーン(`:103-116`)、同じ列・レーンの重なりは入力順(`:105`, `:132-143`)。座標は `layoutLayered` の結果を使わない |

要望の図(連関図・PDPC・因果ツリー・状態遷移・BPMN)のうち、`bpmn` 以外は全部 `layoutLayered` + `routeLayered` を通る。ここが直す場所である。

`layoutLayered` の手順(`lib/graph-layout.ts`):

1. 閉路は DFS で見つけた戻り辺を逆向きにして切る(`:168-182`)。
2. 層は最長経路(`:184-197`)。入ってくる辺のない節は層 0 に寄る。出る辺しか持たない節を、行き先の手前まで寄せ直す処理は無い。長い辺が増える。
3. 層を飛ばす辺は、層ごとに大きさ 1x1 の「ダミー」を挟む(`:199-223`)。
4. 交差の削減は重心法の上下の掃き出しを 4 回(`:230-245`)。入れ替え(transpose)も、交差数を数えて良い方を残す処理も無い。
5. 座標は「各層を最も広い層に合わせて中央寄せ → 隣の重心へ寄せて押し広げる」を 3 回(`:247-275`)。ダミーも隣の重心に寄るだけで、ダミーの鎖を一直線に揃える処理(Brandes-Köpf の内側セグメント優先)は無い。

`routeLayered` は、座標が決まったあとに、層ごとに水平-垂直-水平の肘(`elbows`、`lib/layered-route.ts:28-39`)を作る。2 点の y が違えば必ず折れる(`:31`)。1 辺に付く端点は、箱の辺に沿って等間隔に開く(`:74-92`。端点が 1 つなら中央で、`:88` の注釈どおり「まっすぐな矢印はまっすぐのまま」)。

実測(`examples/out/*.svg` の矢印の経路。矢じり除く)。

| 図 | 辺 | 折れの合計 | 1 辺の最大 | 備考 |
|---|---|---|---|---|
| `qc-relation` | 13 | 60 | 10 | 3 辺が 10 折れ |
| `qc-pdpc` | 10 | 20 | 4 | 6 辺が 2 折れ、2 辺が 4 折れ |
| `toc-crt` | 7 | 8 | 2 | 3 辺が直線 |
| `state-diagram` | 7 | 8 | 2 | |
| `bpmn` | 7 | 9 | 2 | |
| `semnet-causal` / `semnet-pert` | 16 / 24 | 4 / 6 | 1 | ほぼ直線 |

`qc-relation.svg:22` の経路は `M444,76 L444,136 L464,136 L464,440 L368,440 L368,592 L388,592 L388,764 L448,764 L448,780`。層を飛ばす辺のダミーが層ごとに 464 → 368 → 388 → 448 と別の位置に置かれ、層ごとに折れている。依頼の「連関図で矢印が何度も折れる」の正体はこれで、ダミーの鎖を揃えれば消える折れが大半である。層を飛ばす辺そのものを減らす(手順 2)ことも効く。

### 要望が既存の機能で満たされているか

| 要望 | 判定 | 根拠 |
|---|---|---|

| A1 `tree` / `mindmap` | **対象外**(既に満たす) | 親は子の中央。肘は約束の形(`edges: 'straight'` で直線にもできる)。子が 1 つなら肘は直線に潰れる |

| A3 `order`(同じ層の並び) | **一部** | 入力順は掃き出しの同点の決め手(`graph-layout.ts:226-239`)で、`causeTree` は AND の原因を隣り合わせに並べ直す(`lib/toc.ts:79-82`)。指定の手段は無い |
| A3 `rank` | **既にある(別の形)** | `start`(層 0 に固定、`graph-layout.ts:180`, `:189`)。それ以外の層の指定は要らない(下の決定) |
| A3 `align` / `straight` | **未対応** | |

## 論点

1. 折れ数と交差数を、どの段階で、どう目的関数にするか。座標を決めるときの折れ(層の中心を結んだ点列)と、描く折れ(`routeLayered` の端点の開き・レーンのあと)は違う。
2. 既存の図は、再生成すると SVG が動く。どこまでの差分を許すか(ADR 0005 の 4px の格子の見送りと同じ問題)。
3. 「折れ数を減らす」と「戻り辺を外周に回す(A5)」は逆向きに働く(外周は折れが増える)。どちらを優先するか。
4. A3 のヒントは、要望の 4 つ全部が要るか。
5. A4 の閾値を、既存の図で警告が出ない値にするか、悪い図だけに出る値にするか。
6. 折れの合計を、`bpmn`(座標はレーン)にも課すか。

## 決定

### D1. 点数は「従来の候補から離れてよいのは、(交差数, 折れ数)が厳密に良いときだけ」。座標の候補を複数作って選ぶ(A1)

- 折れ・交差は、`routeLayered` を通した経路で数える(論点 1)。層の中心を結んだ点では、端点の開きやレーンが入らず、実際の折れと合わない。
- 候補は、**従来の候補**(今の座標の寄せ直し。D4 の変更は入れない)と、**新しい候補**(Brandes-Köpf の座標。D4 の層の寄せ直し・入れ替えは、この新しい候補の中だけで使う)。
- 選び方:
  1. 新しい候補は、次の**足切り**をすべて満たすものだけが残る: ① 描けない AND の弧(`loose`、`lib/toc.ts:138`)が従来より増えない、② verify が通る(矢印が無関係の箱を貫かない、`lib/verify.ts:244-258` ほか。従来が通るなら新しい候補も通る)、③ 幅が `w` に収まる(従来が収まっていれば)。逆に、**従来が幅に収まらず新しい候補が収まるなら、新しい候補を採る**(点数に関係なく。ADR 0010 が不要に向きを変えないため)。足切りに落ちた候補は点数を見ない。`loose` が増えると `build` が止まり(README の AND の記述)、貫通は検証で止まるため。
  2. 残った新しい候補のうち、`(交差数, 折れ数, 全長)` の辞書式でいちばん良いものを 1 つ選ぶ(全長は新しい候補どうしの比較にだけ使う)。
  3. その候補が、従来の候補より **`(交差数, 折れ数)` の辞書式で厳密に良い**ときだけ採る。そうでなければ従来の候補を返す(全長が短いだけでは動かさない)。
- 公開の切り替えは `straighten?: boolean`(既定 `true`。`false` で従来の座標。`CauseOpts` / `StatesOpts`、`classDiagram` / `semnet` の opts)だけ足す。`routing: 'min-bends'` のような別の種類の経路は足さない。`false` は、過去の SVG を動かしたくない人の逃げ道。ただし D7 の外周の戻り辺(`returns`)は `straighten` と独立で、`straighten: false` でも変わる(`returns: 'inline'` を指定すれば戻る)。
- **改善しない図は 1 バイトも変わらない**。`(交差数, 折れ数)` が厳密に良くならない図、つまり従来の候補がすでに最小の図や、新しい候補が足切りに落ちる図は、従来の候補のまま出る(論点 2)。折れが 0〜1 の図でも、新しい候補が厳密に良ければ動く(動くのは正しい)。

### D2. 座標は Brandes-Köpf で揃える。ダミーの鎖を直線にする(A1・A2)

- `graph-layout.ts:247-275`(手順 5)の代わりに、Brandes-Köpf の 4 方向の整列(左上・右上・左下・右下)を作り、4 つの平均(中央値の 2 つの平均)を座標にする。ダミーを含めた内側のセグメント(ダミー同士の辺)を優先して揃えるので、層を飛ばす辺が直線になる。連関図の 60 折れの大半はこれで消える見込み。
- 親は、子が奇数なら中央の子に揃う(A2 の「中央の子と揃える」)。偶数なら中央の 2 つの間に置く。
- `layoutLayered` の引数に `coord?: 'relax' | 'bk'`(既定 `'relax'`)を足し、既存の呼び出しの結果を変えない。選ぶのは D1 の呼び出し側。
- 手順 5 は、成分ごとに座標を決める(D8)。端点の開きとの衝突は、座標では解かず D3 で経路の側で解く。

### D3. 端点は、両端の箱が重なるなら 1 本の直線にする(A2 の端点)

- `routeLayered` で、辺の両端の端点が箱の辺に **1 つだけ** なら、今も中央で、直線になる(`:88`)。複数あるとき、次の**すべて**を満たすときだけ、2 つの端点の高さを同じにして直線にする: ① 2 つの箱が across 軸で重なっていて、重なりの中に両方の端点の許容範囲(箱の端から 6px 内側、`:89`)が入る、② その高さが同じ辺の他の端点と間隔(`portStep`)を保てる、③ AND の弧の前提(同じ側・同じ向き・先端が揃う、`lib/toc.ts:136`)を壊さない、④ **左側の端点を半段下げる処理(`layered-route.ts:86-91`)が避けている状態**(ある箱の尾の端点と次の箱の頭の端点が同じ高さで、2 本が 1 本の線に見える)を作らない。つまり揃えた結果が、同じ層の対の別の辺と同じ高さに並ぶなら揃えない。
- 満たせないときは今までどおり開く。

### D4. 層の決め方を直す(新しい候補の中だけ。A1)

- 最長経路のあとに、「出る辺しか持たない節を、行き先の層 - 1 まで寄せる」処理(`tighten`)と、隣り合う節の入れ替え(transpose)+掃き出しの途中でいちばん交差が少なかった並びを残す処理を足す。連関図の `est` のような、原因だけの節が層 0 に張りついて長い辺を作るのを減らす。`start` の節は動かさない。
- **従来の候補は変えない**。この 2 つは新しい候補を作るときだけ使い、`layoutLayered` の既定の結果(`tighten: false`、transpose 無し)は今と同じにする。D1 の選び方で、悪くなる図は選ばれない。
- `tighten` は、因果ツリーの「根本原因は最下段」(原因の節が最初の層)の読み方を崩す。`causeTree` / `relationDiagram` / `pdpc` は、`tighten` を既定で**外す**(入れ替えだけ使う)。`stateDiagram` / `classDiagram` / `semnet` は使う。`bpmn` は列が層で決まり列が動くと図全体が変わるので、`tighten: false` を渡して当面動かさない(論点 6)。
- 層の寄せ直しで 1 層ぶん縦が縮む図は、高さも減る。

### D5. A3 は 2 段階。第 1 段は入れない。第 2 段で `straight` と `order` だけ入れる(A3)

> **決定(2026-10-15、ユーザー): 手動の整列ヒント(`straight` / `order`)は実装しない。** 以下の第 2 段の計画(U10)は取り下げる。`order` を前提にしていた D11 の「順序の指定」と、ADR 0019(H3)の `order` の口も、この決定に従い、自動の並べ替え(交差の再探索)で直す。

- 第 1 段(この ADR の実装範囲)は、D1〜D4・D7・D8 だけ。自動配置が良くなってから、残った不満に対してヒントを設計する。
- 第 2 段で入れるもの:
  - `straight: [['from', 'to'], ...]`。その辺を直線にする。Brandes-Köpf の整列で最優先の辺として扱う。直線にできないときは、直し方を書いて止まる。
  - `order: [['a', 'b', 'c'], ...]`。同じ層の並びを左から右(上から下)に固定する。掃き出しがこの組の中の並びを変えない。
  - **入れない**: `align`(層が同じなら並びで、層をまたぐ同じ列は `straight` で言える)。`rank` は、`stateDiagram` / `bpmn` には `start`(層 0 に固定、`graph-layout.ts:180`)があるが、**`causeTree` 系は `start` を渡していない**(`lib/toc.ts:93`)ので、`start` で足りるとは言えない。ただし層は辺の向きで決まるもので、手で動かすと辺が逆向きになるため、`rank` は入れない。層を変えたいときは辺を足す・向きを直す。
- `diagram` ではなく、各 band の opts に置く(`causeTree(nodes, links, {straight, order})`)。

### D6. A4: `edge-bends` を `check` の規則に足す。第 1 段は情報(info)、自動配置の帯の辺だけ、閾値は原則から固定する(A4)

- `lib/rules.ts` に `edge-bends` を足す(`RULE_DOCS` に登録するので `accept` が使える)。数える辺は、**自動配置の帯の辺だけ**(`cause` / `states` / `bpmn` / `classes` / `semnet`)。利用者が手で引いた `connect()` の線は数えない。自己ループ(`states` の `LOOP`)と曲線は数えない。
- 重大度は**既定 info**。`diagram({layoutCheck: 'strict'})` のように**明示した図だけ warn** にする(warn は `check --strict` で終了コード 1、`check-diagram.ts:253`。既定を warn にすると利用者の CI を勝手に落とすため、opt-in にする)。この opt-in の仕組みは ADR 0014 の `layout-*` 規則と共通で、オプション名は **0014 側が決める**(ここでは「0014 の `layoutCheck`」と呼ぶ。名前が変わりうるので、実装時は 0014 の決定に合わせる)。info は、`check` が `--verbose` のときだけ出る(`check-diagram.ts:239`)ので、既定の `check` や `build` では目に触れない。そのため、**`build` に警告の行を足すことも、`check` の既定の出力に出すこともしない**。見せ方は `--verbose`、README の `check` の規則の一覧(U9)、`layoutCheck` の指定に書くだけにする。
- 折れ = 経路の内側の点で、前後の 2 辺が同じ軸でないもの(`simplify`、`layered-route.ts:14` と同じ数え方)。
- 閾値は、examples に合わせず**原則から固定**する: ① 1 辺の折れが 5 以上(層を 1 つ飛ぶごとに 0 折れが目標、外周の戻り辺(D7)は 4 まで)、② 図全体で「折れの合計 ÷ 辺の数」が 3 を超える。examples の実測は、この値の確認に使うだけで、値を動かす根拠にはしない(`qc-relation` は現状 ① ② に当たり、改善後に当たらなくなることが、効果の確認になる)。
- 型: `semnet` の `LaidOutNetwork` は辺ごとの折れ線を持たず(セグメントだけ、`lib/semnet.ts`)、辺ごとの折れ数が出せない。辺ごとに `points` を持つ型(`LaidOutNetwork['edges']`)を足す(U6)。ほかの帯は既に辺ごとの `points` を持つ。
- 折れの数え方(`bendsOf` / `crossingsOf`)は、純粋な関数として `lib/polyline-metrics.ts` に置き、`layered-route.ts` と `rules.ts`(`edgeStats` を作り直す)が共有する。`rules.ts` を `layered-route.ts` から読むと、描画の層が検査に依存してしまう(ADR 0007)ため。

### D7. A5: 戻り辺は、層を 2 つ以上飛ぶものだけ外周の専用レーンに回す。`returns` の選択で、`pdpc` だけ既定を `'outer'` にする(A5)

- 隣り合う層の戻り辺は、すでに別の帯を通っている(`layered-route.ts:99-101`)。変えない。
- 層を 2 つ以上飛ぶ戻り辺(`reversed` かつ層の差が 2 以上)は、ダミーを作らず(図の中を横切らず、層の詰まりも減る)、図の across 軸の端の外側に専用の帯を取って通す。帯は戻り辺ごとに `LANE`(14px)ずつ外へ。折れは 3〜4 になる。これは D1(折れ最小)と逆向きだが、戻り辺は「戻る」という意味を位置で示すので、**意味を優先する**。
- **幅が増える**。帯のぶんだけ across 軸の幅が増え、今は `w` に収まっている `pdpc` がはみ出しうる。はみ出したら、その図だけ `returns: 'inline'` に**自動で戻す**(既定の `'outer'` のときだけ。明示した `'outer'` ははみ出したら試した案つきで止まる)。これで「今収まっている図が、`pdpc` の既定の変更で止まる」ことはない。ADR 0010 の向きの自動選び(`dir: 'auto'`)は、この戻した後の結果を試行として扱う(共通の `layeredAttempt` の中で完結する)。
- `returns?: 'inline' | 'outer'`(`CauseOpts` / `StatesOpts`)。`causeTree` / `stateDiagram` の既定は `'inline'`(README の既存の記述と SVG を動かさない)。`pdpc` の既定だけ `'outer'`(`lib/dsl.ts:1645` が `dir` の既定を足しているのと同じ場所)。`relationDiagram` は既定 `'inline'`。
- `pdpc` の SVG は、既定が変わるので、戻り辺のある図は動く(`straighten: false` でも動く。上の D1)。`examples/qc-pdpc.ts` は更新して説明を付ける。

### D8. 非連結の成分は、層番号を全体で 1 つのまま、成分ごとに座標を決めて詰める(ADR 0010 の B3 を引き取る)(A1)

- ADR 0010 の初版は「層番号は成分ごとに 0 から・`levelGap` も成分ごと」とした。これは `routeLayered` と両立しない。`routeLayered` は層番号で `layerRight` / `layerLeft` を引き、成分をまたいで最大・最小を取る(`layered-route.ts:53-59`, `:123`)ので、折れる位置が別の成分の隙間に出て、箱を貫く。**層番号は全体で 1 つのままにする**。
- 手順 4(並び)で、同じ成分の節を**連続して並べる**(**`coord: 'bk'` のときだけ**。従来の候補には適用しない。下の「実装での補足」)(成分の順は入力順。掃き出しは成分の中だけで動かす)。手順 5(座標)は、成分ごとに across の座標を決め、成分の across の範囲を詰めて並べる(成分の間は `gap`)。層の位置(`at`)・厚み(`thick`)は全体で共有する。成分が 1 つなら今と同じ結果。
- **先に空白の原因を再現する**(U0-b)。依頼の例は「`dir: 'right'` にすると、2 つの独立した因果の塊が離れて置かれ、中央に大きな空白ができた」。今の手順 5 は層ごとに「最も広い層に合わせて中央寄せ」(`:252-257`)にするので、別の成分の幅の広い層に引かれて空白ができる、というのが仮説。依頼者のソースか同じ形の図で、空白の大きさと成分の across 範囲を測って、仮説が合うかを確かめてから U2 に入る。

#### U0-b の測定結果(2026-10-14。`layoutLayered` に固定サイズの箱を直接渡した。フォントに依存しない)

依頼者のソースは手元に無いので、同じ形(独立した 2 つの塊)の入力で再現した。箱は 120x40、`dir: 'right'`、`gap: 24`、`levelGap: 60`。成分 A は「根 1 → 中間 5 → 結果 1」の 3 層(across の範囲 296)、成分 B は 4 層の鎖(across 40)。

| 入力(節の並び順) | 図 | 成分の across 範囲 | 成分の間の空白 |
|---|---|---|---|
| A のあとに B | 660x360 | A [0,296]、B [320,360] | 24(`gap` どおり) |
| A のあとに A2(同じ形) | 480x616 | 296 と 296 | 24 |
| A、B、A2 | 660x680 | 296、40、296 | 24、24 |
| B の鎖 2 本 | 660x104 | 40 と 40 | 24 |
| **B のあとに A** | **660x1000** | **B [0,147]、A [704,1000]** | **557** |

- **再現できた**。節の並びが「狭い成分 → 幅の広い成分」のとき(B のあとに A)だけ、空白が `gap` の 24px でなく 557px になり、図の高さは詰めたときの 360 の約 2.8 倍になる。B の鎖も across 方向に 107px ずれて(b3・b4 が b1・b2 から外れる)、まっすぐでなくなる。逆の並びでは 24px で詰まる。つまり**空白は入力の並びに依存する**。
- **仮説は半分だけ合っていた**。「層ごとに最も広い層へ中央寄せ」(`:252-257`)の初期配置は、空白の原因ではない(初期配置では B の鎖は中央に 1 本、A の根が隣で、空白は出ない)。実際の原因は、その後の `settle`(`:258-272`)の**行ごとの平均のずらし**(`shift`、`:264`)である。1 つの層の行に別々の成分の節が混ざると、行全体を平均で動かすので、一方の成分の押し広げ(幅の広い A の中間層)が、無関係な成分(B の鎖)を同じだけ反対側へ動かす。上り・下りの掃き出しのたびに約 107px ずつ離れ、3 回の反復で 557px になる(トレースで確認: 中間層の A が押し広げられるたびに B の節が -85 → -192 → -299 と動く)。A のあとに B の並びで空白が 24px で済むのは、押し広げが一方向(`:263`, `:266`)で、B が押される側に並ぶため。偶然である。
- **U2 への含意**: D8 の方針(同じ成分を連続して並べ、成分ごとに座標を決めて詰める)で原因が消える。ただし「初期の中央寄せをやめる」だけでは直らず、**`settle` の行ごとの平均のずらしを成分の中に閉じる**ことが必須(行の中の別の成分を平均に入れない)。D8 のテスト(d)には、成分の並び順を入れ替えても空白が `gap` になる(上の B のあとに A の入力を使う)を加えるとよい。
- 依頼者のソース・本物のフォントでの再現は未実施(配置は箱の大きさだけで決まり、フォントは箱の幅を通してしか効かないため、上の結論は変わらない見込み)。

### D9. 戻り辺を宣言する: `back: true` は層の決定から外す。宣言した戻り辺は外周のレーンを既定にする(G1)

依頼 G1: CRT に悪循環の戻り矢印を足すと、UDE が最下段に落ち、線が何度も折れる(FRT の好循環も同じ)。要確認の「`back: true` の記法は既にあるか」は、**無い**(`CauseLink` は `{from, to, line}` だけ、`lib/types/diagrams.ts:109-114`)。

**再現と原因(測定、フォントに依存しない)**: `examples/toc-crt.ts` の 7 節に `late -> kpi`(UDE → 根本原因の悪循環)を足すと、`late`(UDE)が `kpi` より**下**の最下段に落ち、折れは 10 → 14。`kpi` を最初の節に並べ替えると層は正しいが、折れは 16。原因は `layoutLayered` の手順 1(`graph-layout.ts:168-182`)で、**戻り辺を DFS が選ぶ**こと。DFS は節の並びの先頭からたどり、`late → kpi → … → switch → late` と回って、**順方向の辺 `switch -> late` を戻り辺として逆向きにする**。意味上の戻り辺(`late -> kpi`)ではない。つまり、同じグラフが節の並びで違う図になる。

- `CauseLink` に `back?: true`(既定なし)を足す。`from` は 1 つの節(配列と併用すると throw。戻り辺は 1 本ごとの宣言)。`relationDiagram` / `pdpc` のリンクにも通す。
- **層の決定から外す**: `layoutLayered` に `back?: readonly number[]`(宣言された辺の、入力の辺の添字)を足す。手順 1 は、宣言された辺を最初から「戻り辺」(`reversed: true`)にし、**DFS はそれ以外の辺だけに掛ける**(宣言された辺をたどらない)。**添字の対応**: `back` は `layoutLayered` に渡す辺の添字で決まる。`toc.ts` が渡す辺は、AND を原因ごとに分けたもの(`arrows`)なので、`causeTree` はリンクの添字から `arrows` の添字へ変換する(`back` と配列の `from` は併用不可なので、`back` のリンクは 1 対 1 に対応する)。**検証**: `back` の辺 `a -> b` は、`b` から順方向(`back` 以外)の辺をたどって `a` に戻れなければならない(循環を閉じない辺に付けると層が黙って逆向きになるため)。戻れなければ throw(どの辺か、戻れる道が無いことを書く)。**1 つの循環に `back` が 2 本以上ある**(宣言の重複)場合も throw し、エラー文に、その 2 本の辺と、「1 つの循環は戻り辺 1 本で切れる。意味上の戻りの 1 本だけに `back` を残す」という直し方を書く。宣言のあとにまだ循環が残るときだけ、残りを今までの DFS で切る(宣言が不足している図でも止まらない。D2 の検査 `toc-cycle-undeclared`(ADR 0015)が知らせる)。手順 1 の DFS の結果(どの辺を戻りにしたか)は、純粋な関数 `breakCycles(nodes, edges, declared)` に切り出して `layoutLayered` と検査が共有する。
  - 宣言した図では、層が**節の並びに依存しなくなる**(宣言を除いたグラフは非循環で、最長経路の層は並びに依らない)。
- **既存の図は 1 バイトも変わらない**: `back` を書いた図だけが対象で、書かない図は手順 1 が今と同じ DFS を同じ入力で走らせる(`declared` が空なら分岐しない)。`relationDiagram` の「戻る矢印も可」(README)・`stateDiagram` の戻る遷移は、宣言が無いので今のまま。
- **D7(外周の戻り辺)との関係**: D7 は「層を 2 つ以上飛ぶ戻り辺(`reversed` で層の差が 2 以上)だけ、ダミーを作らず外周の専用レーンに回す」。D9 は「**どの辺が戻り辺か**」を宣言で決める話で、D7 は「戻り辺をどう通すか」の話。つながり方は次のとおり。
  1. 戻り辺の集合の決め方が変わる(DFS → 宣言)。D7 の条件(`reversed` と層の差)は同じ式で使える。
  2. **宣言した戻り辺は、`returns` の既定に関係なく外周を既定にする**(層を 2 つ以上飛ぶ場合)。`returns` の既定('inline')は、**DFS が見つけた**戻り辺(宣言の無い循環)の話で、SVG を動かさないために残す。宣言した図は新しい書き方なので、既存の SVG に影響しない。`returns: 'inline'` を明示すれば、宣言した戻り辺も図の中を通る。層を 1 つだけ戻る辺は、今のとおり隣り合う層の別の帯(D7 の最初の項目)。
  3. 外周のレーンを足して幅がはみ出す図は、D7 の自動で `'inline'` に戻る処理に従う(宣言した戻り辺も同じ)。
  4. 実装の順序: 宣言(U11)が先で、そのときの戻り辺は今の戻り辺の経路(隣り合う層の別の帯、層を飛ぶものはダミーを通る)で描かれる。外周のレーン(U7)が入った時点で、宣言した戻り辺が外周へ回る(U7 は `reversed` を読むだけで、宣言の有無は区別しない。宣言したものは `returns` の既定を無視する、の 1 点だけを U7 に足す)。
- **D1(候補の選択)との関係**: 宣言は入力の意味(どの辺が戻りか)で、最適化の候補ではない。従来の候補・新しい候補の**どちらも宣言を尊重する**(足切りの比べ方は変えない)。`straighten: false` でも宣言は効く。
- 見た目: 宣言した戻り辺は、通常の辺より太く描く(`arrowPath` の `width` を 3 に。`lib/emit-common.ts:123` が `width` 引数を持つので描画の変更は小さい)。`LaidOutCause.edges[]` に `back` を持たせる。注釈(ラベル)は ADR 0015 の未決。
- 凡例: 宣言した戻り辺は、`legend: 'auto'` の項目(`edge:back`、ADR 0015 D6)になる。

### D10. 循環の途中の AND(G2): 戻り辺の宣言で大半が解け、残りは理由つきで止める(G2)

**再現(測定)**: FRT 風の `inj → tool`、`[tool, trust] → use`、`use → result`、`result → trust`(成果が信頼を生む循環)で、`loose: ['use']` になり verify が止まる。原因は D9 と同じ。`inj` から DFS すると `result → trust → use` と回り、**AND の一員 `trust -> use` が戻り辺にされ**、`trust` が `use` より上の層に置かれて、`use` への 2 本が反対側から着く。意味上の戻り辺は `result -> trust` で、そこに `back: true` を付ければ AND の 2 本は同じ側から着き、弧が描ける(依頼の「AND を 2 本の独立した矢印に分けて回避した」は不要になる)。

- **戻り辺が AND の一員ではない場合**(上の例。依頼の例の大半): D9 だけで解ける。実装は足さない。
- **戻り辺そのものが AND の一員の場合**(`[tool, result] -> use` で `use -> result` が戻る、のように、AND の原因が結果より下流にある): 原因の矢印が結果に**反対側から着く**ことは、層の構造から避けられない(測定では並びを変えても止まる)。第 1 段階は、**止め方を直す**: verify の文面(`lib/verify-handlers.ts:181`)が、どの AND か(結果と原因の一覧)と、どの原因が反対側から着くか(最後の run の向きが他と逆の矢印)を名指しし、直し方を 1 つ指す(「`result -> use` を AND から外して別のリンクにする(OR)」「`back: true` を付ける(その辺は戻りで、AND の一員にしない)」のうち、該当するもの)。
- 第 2 段階(別の PR、必要なら): 戻り辺である AND の一員を、外周のレーンから AND の他の矢印と同じ側(原因側の辺)へ回して着ける。`routeLayered` の端の割り当てと D7 の外周の帯に依存し、折れが 4 以上になる。第 1 段階で止まる図が実際に多いかを測ってから決める。
- 既存の図は変わらない(止まる図が止まる文面が変わるだけ)。

### D11. AND の矢印の並走(G6): 隙間のレーンを、直接の矢印と長い矢印で共有する。順序の指定は D5 の `order`(G6)

**再現(測定)**: 6〜8 節の AND を含む乱数のグラフ(種固定)18 個のうち 3 個で `[cause-parallel]` が出た。1 つを取ると、節の並びを 5 通り試して 4 通りで警告が残り、**「節の順序を替える」は確実な直し方ではない**(原因が並びではないため)。

**原因(経路の座標で確かめた)**: 並走している 2 本は、AND の頭 `n5` に入る「直接の矢印」(`n2 -> n5`、隣り合う層)と「長い矢印」(`n3 -> n5`、層を飛ぶ)。直接の矢印は、頭の端へ入る最後の縦の run(座標 470)を、隙間の尾の側の曲がり(`STUB + レーン`、`lib/layered-route.ts:124`)から頭まで伸ばす。長い矢印は、ダミーの列(座標 474)を通り、頭の手前の最後の曲がり(`lastTurn`、`:132`)で自分の端(492)へ移る。**`lastTurn` が直接の矢印の曲がりより頭に近い**ので、2 本の縦の run が、その間(再現では y 方向 22px)を **4px 隔てて並ぶ**。AND の頭の端の間隔(`PORT`)は十分で、並走は経路の中ほどに起きる。2 つの曲がりは別々に決まり(`:129` の注釈は「重ならない」前提)、同じ隙間の中で互いを見ない。

- **直し方**: 同じ隙間の曲がりを 1 つのレーンの表から取り、**長い矢印の `lastTurn` を、同じ頭に入る直接の矢印の曲がりより尾に近い側に置く**(長い矢印が先に自分の端の列へ移り、直接の矢印の最後の run と並ばない)。隙間は、そのぶんのレーンを持つ幅にする(`corridorLoad` は直接の矢印だけを数える、`:140` 付近)。ただし隙間が広がると、いまは並走していない図の SVG も動く。**動かさないために、候補の選択(D1)に乗せる**: 並走の数(`runsTogether`。verify の `together`(`lib/verify-handlers.ts:164`)と同じ定義)を、`toc` のときだけ**採る条件に足す**(点数の順序は変えず、悪化の定義も `(交差, 折れ)` のまま)。従来の候補が並走 0 なら従来のまま。並走があるときだけ、レーンを共有する新しい候補を作り、**並走が厳密に減り、かつ `(交差, 折れ)` が従来より悪くならない**ときだけ採る(足切りは D1 と同じ)。並走が減っても交差が増える候補は採らない(その図は並走の警告が残り、`order`(U10)で直す)。`runsTogether` は U1 の `lib/polyline-metrics.ts` に置き、`verify-handlers.ts` と共有する(定義がずれない)。レーンの表の実装は、再現の入力(下のテスト)で並走が 0 になることを確かめながら詰める(上は、経路の座標から立てた設計で、実装で確かめる)。
- 順序の指定: 「AND の矢印の入り口を少しずらす」は、頭の端(`PORT`)で既にずれている。並走は経路の中ほどの話なので、ずらしで直る問題ではない。**手動の `order`(D5 第 2 段)を、G6 の要望として優先度を上げる**(U10 の中身は変えない。`causeTree` の `order: [['a', 'b'], ...]` が、同じ層の並びを固定する)。verify の警告の文面は、「節の順序を替える」から「`order` で並びを指定する(U10 の後)、`dir` を変える」に直す(U10 の前は、並びを変えても直らないことがあるので、`dir` / `maxNodeW` を先に挙げる)。

## 代替案

- **`routing: 'min-bends'` の切り替えを足す**(要望の案)。却下。折れが少ない方が悪い図は無い。切り替えが要るのは「従来の SVG を保つ」ときだけで、それは `straighten: false` で足りる。
- **座標の寄せ直し(今の手順 5)を改良するだけにする**(Brandes-Köpf は入れない)。却下。寄せ直しは、隣の平均に寄るだけで、ダミーの鎖を揃える保証が無い。3 回で打ち切っている(`:269`)ため、回数を増やすと図ごとに不安定になる。Brandes-Köpf は決定的で、保証(内側のセグメントは直線)がある。
- **ELK / dagre など外部のレイアウトエンジンを使う**。却下。ADR 0007 の純粋な核(測った大きさだけを渡し、決定的に動く)と、依存を増やさない方針に合わない。同じ入力で同じ出力になる保証も、辺ごとの端点・レーンの規則(`routeLayered`)との組み合わせも、自前の方が制御できる。
- **折れ数を座標の段階の目的関数に直接入れる(焼きなましなど)**。却下。決定性と実行時間の見積もりが難しい。候補を数個作って選ぶ(D1)で、改善の大半が取れる見込み。
- **A3 の 4 つのヒントを全部入れる**。却下(D5)。`align` と `rank` は、`straight` / `start` と重なるか、辺の向きの意味を壊す。
- **A5 の戻り辺を全部外周に回す**。却下。隣り合う層の戻りまで外周に出すと、折れが増えるだけで読みやすくならない。`stateDiagram` の既定が変わり、SVG が大きく動く。
- **戻り辺を、DFS の起点を変えるだけで直す**(`causeTree` が `start` に根本原因を渡す)。却下(D9)。どの節が根本原因かは役割で分かるが、悪循環は UDE から根本原因へ戻るので、起点を根本原因にしても、FRT の好循環(成果 → 信頼 → 利用)では起点が決まらない。起点で決まる戻り辺は、並びが変わると変わる。宣言した辺を層から外す方が、入力の意味を直接に写す。
- **`back` を宣言なしで自動推定する**(フィードバック辺集合の最小化)。却下。最小の辺集合は 1 つに決まらず、どれが「戻り」かは意味の問題(悪循環の戻りか、順方向か)。推定が外れると層が崩れる原因が見えなくなる。宣言を書かない循環は今のまま(DFS)にして、ADR 0015 の検査で気づけるようにする。
- **AND の長い矢印を、必ず専用レーンに回す**(G6)。却下。隙間が広がり、並走していない図の SVG も動く。候補の選択(D1)で、並走があるときだけ採る。
- **`edge-bends` を `edge-crossings` に統合する**。却下。`edge-crossings` は `connect()` の線の規則で、`accept` の理由も別になる。折れは、数える対象(帯の辺)も、直し方(座標・ヒント)も違う。

## 影響

- **SVG の差分**: D1 は「従来より `(交差数, 折れ数)` が厳密に良いときだけ動く」ので、改善する図だけが動く。それでも `examples/out/` の自動配置の図(`toc-*`、`qc-relation`、`qc-pdpc`、`state-diagram`、`class-diagram`、`semnet-*`)と、文書側で再生成する人の SVG は変わる。`check --drift` が「ソースが変わっていないのに SVG が古い」と言うことはない(生成元の SHA はソースとその import だけ。`check-diagram.ts:184-185`)が、`--rebuild`(同:`:179-195`)は差分を「再生成」として報告するので、`pnpm golden` を通すには再生成が必要。ADR 0008 の #11(4px の格子)は全図が動くから見送ったが、今回は動くのが「折れが減る図」だけで、動いた図は良くなる。この違いが、差分を許す根拠である。
- **幅**: 外周の戻り(D7)と、座標の候補の選択で、図の幅が増える図がある。幅の超過の検査(`toc.ts:95` など)に入る。候補の選択(D1)は、幅が `w` を超える候補を足切りで除く。`pdpc` の外周の戻り辺(D7)ではみ出す図は、自動で `'inline'` に戻る。

### テスト方針

- **単体**: `test/polyline-metrics.test.ts`(U1)。`test/layered-attempt.test.ts`(U0)は、候補が 1 つのときに従来と同じ結果になることを、`examples/` の自動配置の図全部で固定する。`test/graph-layout.test.ts` に、(a) 鎖・ダイヤモンド・層を飛ぶ辺を含む固定の入力で、`coord: 'bk'` のダミーの鎖が直線になる、(b) 重ならない・層の順・決定性が `'relax'` / `'bk'` の両方で保たれる、(c) 改善しない入力(すでに最小の鎖・ダイヤモンド)では、結果が従来と同一、(d) 非連結の入力(成分 2〜3 個)で、成分ごとに across の範囲が詰まっていて、成分が 1 つのときは `'relax'` と同じ座標、を足す。
- **性質**(小さな有向グラフ、種を固定した 200 個程度。「従来より悪くならない」は従来の候補を含むので自明なため、これは使わない): ① 従来の候補が verify を通るなら、選ばれた候補も通る、② 従来の候補の幅が `w` に収まるなら、選ばれた候補も収まる、③ `loose` が従来より増えない、④ 選ばれた候補が従来と違うなら、`(交差数, 折れ数)` が従来より辞書式で厳密に良い、⑤ `tighten` が辺の向きと `start` を保つ、⑥ 決定性。
- **「悪化」の定義**: 図の回帰での悪化は、`(交差数, 折れ数)` の辞書式で従来より悪いこと。幅・高さは別に表で報告し、増えたら理由を説明する。
- **図の回帰**: `examples/*.ts` のうち自動配置の図について、折れの合計・1 辺の最大・交差数・幅・高さを、PR 直前の `main` と変更後で比べる表を PR に載せる。**悪化した図があれば、理由が説明できるまで通さない**。折れの合計の上限を固定するテスト(`test/bends-budget.test.ts`。上限は変更後の実測)を足す。
- **SVG の差分の扱い**: 動いた図は `pnpm golden`(`--drift --rebuild`)が差分として報告するので、再生成して `examples/out/` を更新する。再生成した図は、`diff-svg.ts`(`lib/svg-diff.ts`)で説明を付け、`contact-sheet.ts` で並べて目で確かめる。**動いてはいけない図**を固定するのは、(a) `tree` / `mindmap` / `bpmn`(座標を変えない)と、(b) `straighten: false` の図(`returns` の影響を除く)だけ。これが 1 バイトでも変われば、足切りか比べ方か、`false` の分岐が壊れている。`toc-crt`(折れ 8)・`semnet-*`(4 / 6)・戻り辺のない `returns: 'inline'` の図は、Brandes-Köpf で厳密に改善するなら**正しく動く**ので、固定しない。動いたかどうかの判定は、性質 ④(動いたなら `(交差数, 折れ数)` が従来より辞書式で厳密に良い)と、PR の比較表(悪化 0)で行う。`qc-pdpc` は D7 でも動く(`straighten: false` でも)。
- **`straighten: false`** の図が、`returns` の影響を除いて、PR 直前の `main` と byte 同一であることを、`examples/` のうち 3 図で固定する。
- **幅**: `pdpc` の既定 `'outer'` で、今は収まっている図がはみ出さない(自動で `'inline'` に戻る)ことを、幅いっぱいの `pdpc` で確かめる。
- **戻り辺の宣言(U11)**: (a) 宣言した辺の集合 `F`(`F` を除くと非循環)を持つ小さなグラフ 200 個程度(種固定)で、**節の並びを入れ替えても層が同じ**(宣言した辺は全部 `reversed`、それ以外の辺は層が増える向き)。DFS 任せ(宣言なし)では同じ性質が成り立たないことも、1 つの固定の入力で示す(再現: `toc-crt` の 7 節 + `late -> kpi`。UDE `late` が `kpi` より上、を**層の順**で見る)。(b) 宣言なしの図は、`examples/` の自動配置の図の全部で、変更前と byte 同一。(c) `back` と配列の `from` の併用は throw。(d) 宣言のあとに循環が残る入力でも止まらない。(e) 宣言した戻り辺が層を 2 つ以上飛ぶとき、U7 のあと外周を通る(U7 のテスト)。層の絶対座標は使わない。
- **循環の途中の AND(U12)**: (a) `[tool, trust] -> use`、`result -> trust`(`back: true`)で `loose` が空になり弧が描かれる(D9 の効果)。(b) `[tool, result] -> use`、`use -> result` で verify が止まり、文面に結果の id と、反対側から着く原因の id が含まれる(文面全体は固定しない)。
- **AND の並走(U13)**: 乱数のグラフ(種固定、6〜8 節、AND あり)200 個程度で、(a) 変更前に `cause-parallel` が出たものが、変更後は減る(厳密に増えない・性質 ④ と同じ)、(b) 変更前に出なかった図は byte 同一、(c) 選ばれた候補が従来と違うなら、並走が厳密に減り、かつ `(交差, 折れ)` が従来より悪くない(並走が減って交差が増える候補を採っていないこと)、(d) verify が通る、(e) 決定性。再現の 1 例(7 節、`[n0, n2, n3] -> n5`)を、並走の数が 0 になる固定の入力としてテストに入れる。座標の値は固定せず、`runsTogether` の数で見る。
- **検査**: `test/rules.test.ts` に、折れが多い図で `edge-bends` が出る(info)・`accept` で外せる・`connect()` の線・自己ループ・曲線は数えない、を足す。
- すべて `pnpm test` と `pnpm typecheck` を通す。

### 完了の基準

- `qc-relation`(再生成後)が、D6 の閾値 ①②(1 辺の折れ 5 以上、平均 3 超)に当たらない。これは、固定した閾値で効果を確かめるもので、閾値を図に合わせて動かさない。折れの合計は、実装後の実測を PR に書く(目標は「半分以下」だが、基準には使わない)。
- `qc-pdpc` の戻り辺が外周を通る(折れは 4 まで)。折れの合計の数値目標は置かず、**悪化した図が 0**(`(交差数, 折れ数)` の辞書式)であること、動かない図が動いていないことを基準にする。
- `edge-bends` は info なので、完了後の `examples/` に対して `check --strict` が通る。
- (G 節)循環を含む CRT(`late -> kpi` の悪循環つき)に `back: true` を付けると、UDE が根本原因より上に置かれ、**節の並びを変えても層が同じ**。FRT の循環の途中の AND(`[tool, trust] -> use` と `result -> trust`)が、`back: true` で止まらずに描かれる。依頼の並走の例(`cause-parallel`)が減る。`back` を書かない既存の図は byte 同一。

## 実装での補足(U0〜U8・U11 = PR #157・#169・#170・#172・#175・#176・#177・#180・#183)

- **D1 の候補の選択を U2 に含めた**: ADR の表では候補の選択は U4 だが、動かす条件(D1)を満たすため、`layeredAttempt` の選択部(足切り → 厳密に良いときだけ新しい候補)を U2 の PR(#177)に入れた。U4 に残ったのは、公開の `straighten` の型(U8)と `bends-budget`(PR #183)。`straighten?: boolean`(既定 true)は `CauseOpts` / `StatesOpts` / `ClassesOpts` / `SemnetOpts` にあり、`true` 以外は throw。`returns` とは独立。
- **D8 は `coord: 'bk'` のときだけ**: 成分ごとの並びの連続化・掃き出しの成分内への閉じ込め・成分ごとの座標と `gap` での詰めは、新しい候補(`coord: 'bk'`)にだけ適用した。従来の候補(`'relax'`)に適用すると、成分を持つ図(`toc-core` など)が `straighten: false` でも動き、byte 同一の条件と食い違う。U0-b の原因(`settle` の行ごとの平均のずらしが別の成分の節を動かす)は、`'bk'` では成分の内側だけで計算するので起きない。
- **D6 の `bends-budget` は固定サイズの箱**: 折れの数は文字幅(フォント)に依存するので、`examples/` の SVG の折れ数は固定しない。`test/bends-budget.test.ts` は、固定サイズの箱(120x40)で `qc-relation` / `qc-pdpc` / CRT + `back: true` / 状態遷移 / クラス図の構造を `layeredAttempt` に渡して測る。原則(1 辺 5 以上にならない、外周の戻り辺は 4、平均 3 以下)と、図ごとの上限(今の実測)を固定する。同じ理由で、「`straighten: false` の図が examples のうち 3 図で PR 直前の `main` と byte 同一」は、`layeredAttempt` の `straighten: false` が従来の配置と同一であること(U2 のテスト)と、既定との相対比較で代えた。
- **D6 の `edge-bends`(U6)**: 型は、ADR の `LaidOutNetwork['edges']` ではなく、`LaidOutChartPart.edges?: {from, to, points}[]`(semnet は `LaidOutChart`)。`pert` / `dependencyNetwork` / `causalLoop`(輪でないもの)が記録する。外周の戻り辺は 4 までと区別することは、閾値 ① を一律 5 以上のままにして、していない(`LaidOutCause.edges[].outer` は持たせてある)。重大度は `layoutSeverity(d)`(`diagram({layoutCheck: 'strict'})` の図だけ warn)で、`build` に警告の行は足さない。
- **D3 の `round`(U5)**: 円(`shape: 'circle'`)・六角形(`obstacle` / `risk`)の端は、直線にするために動かさない(円の bbox の辺の端に直線を当てると、円との間に隙間ができる。`qc-arrow` が壊れる)。`AttemptOpts.round` / `routeLayered` の `round` で、`toc.ts` と `states.ts` が 1 行ずつ渡す。条件 ④ は、同じ層の対の別の箱は across 軸で重ならないのでほぼ自明に満たされるため、端点どうしの距離に加えて、できた直線が他の矢印の水平な線に沿っていないかを実際の経路で確かめる形にした。「厳密に良いときだけ」の判定は、図ごとではなく矢印 1 本ずつの貪欲な採用(悪化しないことは保たれる)。
- **D7(U7)**: 外周の戻り辺の形は「尾の箱の左 → 尾の層の手前の隙間 → レーン → 頭の層の後ろの隙間 → 頭の箱の右」で、折れ 4(ADR の 3〜4 のうち 4)。隙間の曲がりの位置(尾は右側、頭は左側から数える)と、隙間の幅(外周の曲がりの数を足して広げる)は、ADR に無い設計判断。幅だけでなく高さも増える(`qc-pdpc` で 84px)。`pdpc` の既定は `CauseBand.returnsDefault: 'outer'`(`returns` を書かなかったことを見分けるため)。書かなかったときだけ、幅がはみ出す、または外周のほうが描けない AND の弧(`loose`)が増えるなら、図の中に戻す。明示した `'outer'` がはみ出したら `returns: 'inline'` を案に書いて止まる。`stateDiagram` の外周の戻り辺は、自己ループの置き場(`reserve`)と同じ側に出るので重なりうる(既定は `'inline'`)。
- **D9(U11)**: `back: true` の辺は、層番号を決める前に戻り辺として外す(`breakCycles(nodes, edges, declared, start)` を `graph-layout.ts` から export)。宣言した辺が循環を閉じない・1 つの循環に 2 本以上・添字が範囲外・配列の `from` との併用は throw。宣言した戻り辺は(層差 2 以上なら)`returns` を書かなくても外周が既定。
