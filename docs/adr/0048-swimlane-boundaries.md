# ADR 0048: `swimlane()` の `boundaries` — サービスブループリントの線

- 状態: 実装済み(レビュー前)
- 日付: 2026-10-30
- 基点: `main`(PR #345 まで)
- 関連: ADR 0047(Wardley Map を plane の拡張で描いた前例)、`swimlane()`、`journeyMap()`(ステージ×レーン、感情曲線つき)
- 範囲外: 専用の `serviceBlueprint()` 帯、レーンの固定 5 本の preset、レーンの間に引く線の種類ごとの見た目の違い、時間の軸(列)に引く線、`journeyMap()` との統合

## 背景
サービスブループリントは、顧客の行動を上に、表の業務(接点)、裏の業務、支援システムを下に並べ、レーンの境目に 3 本の線(相互作用線・可視線・内部相互作用線)を引く図。「顧客体験を裏側でどう実現しているか」を見せる。試作(`swimlane()` を変えずに描く)では、5 レーン(物的証拠・顧客の行動・表の業務・裏の業務・支援システム)と、縦にまたぐ矢印は描けた。足りなかったのは、境目の線とその名前だけだった。レーン名に「(可視線の上)」と書く手は、線が見えないので図として弱い。

## 決定
### D1: `swimlane(lanes, steps, {boundaries: [...]})`
各要素は `{after: レーンの id, label?}` か `{between: [レーンの id, レーンの id], label?}`。そのレーンの境目に、太い破線(3px、`10,6`)を全幅に引き、`label` があれば、境目をまたぐ丸いチップ(ラベル列の幅 − 16px、1 行)にその名前を書く。線は既存のレーンの区切り(2px の実線)の上に重ねる。色だけでなく太さと破線で区別でき、白黒でも読める。
- **`between` を勧める**: 隣り合っていない 2 つのレーンを書くと throw するので、あとでレーンを足したときに線の意味が黙って変わらない。`laneOrder` と併用できるのも `between` だけ。ただし `laneOrder` は境目を知らずに並べるので、矢印が入り組んだ図では 2 つのレーンを離して throw することが多い(境目の両側のレーンに `fixed: true` を付けるか、`laneOrder` を外す。`orderLanes` に隣り合う組を渡す案は残り)。`after` は、レーンが動かない図の短い書き方。
- 矢印にラベル(チップ)を付けると、境目の線の上に重なることがある(ブループリントの矢印はほぼ境目をまたぐ)。`labelAt` で線から外す(検査はしない)。
### D2: チップの分だけレーンを高くする
ラベルのある境目の両側のレーンは、レーン名(中央寄せ)がチップに触れないように、高さを「レーン名の高さ + チップの高さ + 4px」以上にする(チップの高さは `boundaryChipH(note)`)。レーンの高さが変わるので、境目を書いた図は、書かない図と高さが違う。**境目を書かなければ(`boundaries: []` も)出力は 1 バイトも変わらない**(origin/main との比較で確かめ、テストで守る)。
### D3: 検証
`after` / `between` のレーンがない・最後のレーンの後・隣り合っていない・同じ境目に 2 本・ラベルが空か文字列でない・`boundaries` が配列でない、は throw。`laneOrder` と `after` の併用も throw。名前は、**文字の幅を測って**、ラベル列の `labelW − 16 − 20`(チップの両端の余白 10px ずつ)に入らなければ throw(切れない 1 語でも)。`labelW` を書かなければ、ラベル列は既定の 128px と「一番長い名前 + 36px」の大きい方になる(境目の名前がなければ 128px のまま)。`labelW` を明示して足りなければ throw し、必要な幅を文に書く。`fit: 'shrink'` は、ラベル列を「一番長い名前 + 36px」より狭めない(列の幅が足りないときのエラーの文もそれに合わせる)。`after` と `between` の両方・どちらもない・`between` が 2 つの id でない・同じレーンを 2 回、も throw。
### D4: 帯は作らない
レーンの数・名前・線の本数は図ごとに違う(物的証拠を置かない、線を 2 本にする、実行線・受注浸透線を足す、など)。線を足すのは `boundaries` の本数を増やせば済む。
- 失敗点・待ち時間・所要時間は、手順の `tag` / `stamp` / `icon` で書く(記号の帯は作らない)。顧客の感情は `journeyMap()` の領域(swimlane では描かない)。
- **`serviceBlueprint()` にするきっかけ**: 失敗点・待ちに専用の記号、線ごとの見た目の違い、感情の行、のどれかを足したくなったとき。
- PPTX は swimlane と同じく画像で書き出す。

## 結果と残り
- 例 `examples/service-blueprint.ts`(golden と PPTX golden あり。`between`、手順の `tag` で待ち・失敗点)。テストは `test/swimlane-boundaries.test.ts`。
- Opus レビュー(1 巡目): 高 2・中 5・低 6 を受けて、`between`、文字幅での検査、shrink の下限、D4 の具体化、byte 同一のテストを入れた。(2 巡目): 中 2・低 5 を受けて、`labelW` 未指定のときの自動の広げ、`laneOrder` と `between` のエラーの文、`boundaries` の型の検査を入れた。
- 残り: 線ごとの見た目の違い(可視線だけ太く、など)、チップを右端に置く選択、矢印ラベルと線の重なりの検査(いまは書き手が `labelAt` で外す)、`reveal` で線を段階的に出す、名前を 2 行まで許す、境目のない swimlane の golden(出力が `main` と同じことを golden でも守る)、`laneOrder` が `between` の組を離さないようにする。要望があれば。
