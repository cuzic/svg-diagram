## 確かめて問題がなかったこと（指摘にしない）

- **`maxR` の候補:** `n = 2〜12` のどの値でも、`r = 1..maxR` から `perRow = ceil(n/r)` を求めると、`perRow` が重ならない。
  - `n = 10` で `r = 3` のとき、`perRow` は 4 で、段数も 3 になる。
  - D1 の「段数が `r` より少なくなる」場合も、`'auto'` では起きない（`r ≤ floor(n/3)` のため）。
- **D7 の表と schema:** `perRow` の上限が 8 なので、`perRow` を書けば 1 段は必ず 8 つ以下になる。
  - 整数の `rows`（2〜4）で `n ≤ 12` なら、1 段は 6 つ以下になる。
  - 9 つ以上で 1 段になる明示の指定は、`rows: 1` と指定なしだけ。表の 4 行目はどちらも捉えている。
  - 縦で 9 つ以上に `rows` を足した場合は、2 行目と 3 行目の両方の issue が出る。どちらも「横にする」の方向を指すので、矛盾しない。
- **spec の文字列と `\n`:** spec の文字列は改行を断る（`lib/spec-validation.ts:6`、`UNDRAWABLE`）。そのため、明示の `\n` の扱い（m12）は DSL だけの話。

## Minor

### m11. `'auto'` は 9〜12 個を 1 段に決めうる。D7 が明示の 1 段を断るのと食い違う

- 節: D3、D7 の `check` の表の 4 行目
- 根拠:
  - D3 の候補は `r = 1` から始まる。`n = 12` で文字が短く、幅が広ければ、段階 1 で `r = 1` に決まる。すると 12 個が 1 段に並ぶ。
  - 段階 3 で、どの `r` でも行数が同じになった場合も、同じなら小さい `r` を選ぶので `r = 1` になる。
  - 一方、D7 は、横の 9 つ以上で `rows` も `perRow` も無い場合と `rows: 1` の場合を issue にする。「1 段は 8 つまで」という意図に見える。
  - `rows: 'auto'` は issue にしない（m9）。そのため、同じ 12 個の 1 段が、`'auto'` からなら黙って出る。
- 直し方（どちらか）:
  - (a) 候補の下限を `rMin = ceil(n/8)` にして、`r = rMin..maxR` にする。`n ≤ 8` なら今と同じ。
    - `n = 9〜12` では `rMin = 2`、`maxR = 3〜4` なので、候補は空にならない。
  - (b) 「1 段 9 つ以上は、文字が折れなければ許す」と決め、D7 の表の 4 行目の理由を書き直す。
- (a) の方が D7 と揃う。

### m12. 「折れない」の定義「行数が明示の行の数と同じ」は、末尾の `\n` で必ず偽になる

- 節: D3「『折れない』の定義」
- 根拠: 試しで `wrapText` の行数を数えた。
  - `'abc\n'` は 1 行。`split('\n')` では 2 つになる。
  - `'ab cd\n'` も 1 行。
  - 行末の空白を落とすので（`lib/wrap.ts:168` の `trimEnd`）、末尾の空の行は残らない。
  - 一方、`'a\n\nb'` は 3 行で、`'\nabc'` は 2 行。これらは `split` の数と合う。
- 問題:
  - 末尾に `\n` を持つラベルが 1 つあると、どの `r` でも「同じ」にならない。
  - そのため、段階 1 と段階 2 が成り立たず、段階 3 に落ちる。
  - DSL でしか起きない端の場合だが、規則が字のとおりには実装できない。
- 直し方:
  - 「余分な行 = `max(0, 折った行数 − 明示の行数)`」と定義する。
  - 「折れない」は「余分な行が 0」と言い換える。段階 2 の「余分な行」も同じ定義を使う。
  - 明示の行数を `split('\n').length` で数えるとは書かないでおく。
