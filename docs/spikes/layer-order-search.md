# スパイク: causeTree の層の並びの探索(ADR 0073 Q3)

- 日付: 2026-11-22。基点: `main` = cb55027d(ADR 0073 の U5 の後)。
- 状態: **測定とプロトタイプだけ**。`lib/` は変えない(試作は `scripts/crt-u6-measure/q3-layer-order.patch`)。
- 決める人の指示(2026-11-22): スパイクを先に行い、ゲートを通ったときだけ ADR を書く。
- 規則: 利用者の実際の図のラベルは、リポジトリにも PR にも書かない。実ファイルは `REPORT_CRT` で数だけ測った。図は fixture の ID と座標でだけ指す。

## 作ったもの

試作は 2 つ(patch の中身。`lib/layer-order-spike.ts` が新規、`lib/graph-layout.ts` と `lib/toc.ts` が小さな差分)。

1. **層の並びの探索 `searchRows`**(`layoutLayered` の中の層ごとの並び。ダミー節を含む)。目的は「層の間の交差の数」。動かすのは同じ連結成分の中の隣り合う 2 つの入れ替えだけで、1 手の差は隣の層との辺の組だけで出る(U5 の版は毎回 O(E^2) で数え直していた)。種類は、(a) 焼きなまし(乱数で並びを崩した再出発を何回か。最良の並びを返す)、(b) 挿入のしぼり込み(sifting)、(c) 両方。仕上げに sifting をかける。
   - `andW`: 同じ AND の結果に入る 2 本の辺の交差の重み。
   - `freeze`: 同じ AND に入る辺の節は、種の並びの前後を変えない。
   - `k`: 再出発ごとの最良の並びのうち、違うものを `k` 個まで候補にする。
2. **候補として足す `toc.ts` の変更**。**図につき 1 回だけ**探索する(最初の `base` の配置の中で。配置のたびではない)。**既存の順序探索はそのまま最後まで走らせ**(main と同じ点列・同じ選び)、その後で見つけた並びを**強制した配置**を候補として足す。候補は既存と同じふるい(`inFrame`・高さのふるい)と同じ採点(AND の交差 → 組・交差・折れの窓 → 高さ)で選ばれる。
   - 並びを先に足す版(ループの前)は、探索の道筋を変えて、`cause-crossing` が増えた(#33)。**ループの後に足す**ことで、既存の選びが必ず候補に残る。
   - `post`: 探索が選んだ最良の順序から配置し直し、その層の並びを種にもう一度探索する(1 配置を足す)。
   - `ov`: 「4px 未満の重なり」(`parallelRuns(P, 4)`)が今の選びより増える候補は入れない。
   - 最終の選び(`pickFinal`)には、main が選んだ図(詳細な経路つき)も候補として残す。
   - 環境変数 `LO`(JSON)で入れる。`LO` が無ければ main と同じ(点列の hash が 300 + 150 枚と fixture で一致することを確認)。

## 使い方

```
git worktree add -b <branch> <dir> cb55027d && cd <dir> && git apply scripts/crt-u6-measure/q3-layer-order.patch && pnpm install
cd <scratch>; ROOT=<dir> S=<dir>/scripts/crt-u6-measure
$S/lo-run.sh base ''                         # main と同じ(300 枚 + canvas 150 枚、約 35 秒)
$S/lo-run.sh e1 '{"restarts":5,"moves":3000,"shuffle":true,"T0":2,"andW":6,"post":true,"ov":true}'
node $S/lo-compare.mjs base e1               # 合計・図ごとの増減・ゲート(cause-crossing と折れ)
$S/lo-bench.sh 120 plain 2 '<LO json>'       # 60/120 節の壁の時間(交互、最小値)
REPORT_CRT=<利用者のファイル> LO='<json>' node $S/fixture.ts $ROOT   # fixture と報告の図(数だけ読む)
```

### fixture と報告の図(ADR 0070 の基準)

e1 は fixture(既定・asap・wide・compact・canvas なし・minText 14/24)も、`examples/toc-*` も、報告の図も、**どれも変えない**(交差 5、折れ 52、`cause-crossing` 0、組 0 のまま。点列の hash が main と同じ)。ADR 0070 の基準は main と同じく満たす。

下限(層の間の交差 2)に届くのは、**`k`=3 かつ 10 回の再出発の版(k3・e2・c2)**だけ。

| 版 | 交差 | 折れ(合計 / 最大) | 高さ | `cause-crossing` | 組 |
|---|---|---|---|---|---|
| main = e1 | 5 | 52 / 4 | 1818 | 0 | 0 |
| e2(`k`=3) | **2** | **40 / 2** | 1818 | 0 | **1** |
| 報告の図の実ファイル(main = e1) | 5 | 52 / 4 | 1818 | 0 | 0 |
| 報告の図の実ファイル(e2) | **2** | 42 / 4 | 1818 | 0 | **1** |

e2 は、既定・canvas なし・minText 14・報告の図で、**倍率の線の間隔の組が 0 → 1**(ADR 0070 の基準「組 0」を満たさない)。crossings を減らす代わりに、組が 1 増える。採点は (交差) が (組) より先なので、既存の規則どおりの選びである。minText 24 は組 22 → 19、compact は 0 のまま。asap の fixture は(U5 と同じく)どの版でも変わらない(交差 9、`cause-crossing` 2)。

### 60 節のベンチマークで、強制しても利得が出なかった理由

U5 の測定(焼きなまし 10 回 x 4000 手、利得なし)の原因を追った。

- **層の間の交差の下限が 0 ではない**。60 節 plain で、焼きなました層の間の交差は 19(30 回 x 30000 手まで増やして 13)。AND あり 60 節で 19〜30。120 節 plain で約 60。乱数の CRT の小さな図(8〜19 節)では 0 だったが、リンクの多い大きな図には下限が無い。
- **経路の交差は層の間の交差より 6〜10 多い**(ポート・AND の弧・トラック)。main は 60 節 plain で 17、AND あり 26、120 節 plain で 59〜62 に既に届いていて、下限(13〜19、19〜30、約 60)とほぼ同じ。強制した並びの経路の交差は 19(plain)・31〜34(AND あり)で、main より悪い。
- つまり**大きな図では、層の並びを直しても、残っている交差は並びの選びではなく経路の構造から出ている**。U5 の「利得が出ない」は、探索の不足ではなかった。
- ただし AND あり 60 節では、e1 は AND の交差を採点が先に見る形で、**交差 26 → 22、折れ 168 → 160(canvas 164 → 156)**。k3 では 26 → 44(折れ 168 → 202)になる。AND の交差 1 → 0 と引き換えの交換を、採点が選ぶためである(`cause-crossing` が先)。折れの合計のゲートはサンプルで測ったもので、この 1 枚は +20% の図になる。

## 判定と推奨

- **ゲート: e1 は合格**(`cause-crossing` は合計・図ごとに増えない、折れ +0.2%/+0.7%、費用は最大 +27.5%)。120 節 plain の +27.5% は境界(機械の揺れの内)。
- **得るもの**: 乱数の CRT で交差 −19%、`cause-crossing` −22%〜−24%、組も合計で減る(−5%〜−11%)。fixture と報告の図は変わらない(交差 5 のまま)。
- **得られないもの**: 報告の図の点 1(交差 5 → 2)は、`k`=3 の版でしか出ず、その版は 120 節 plain で +41%、かつ組が 0 → 1 になる。ゲートの内では取れない。
- **推奨: ADR を書く**(範囲を e1 に絞る)。スパイクが通るのは「図ごとに悪くならず、合計で −19〜−24%」だが、報告の図の交差は減らない点を ADR に明記する。ADR で決めること:
  1. 候補を足す位置(ループの後。ループの前は不可)と、`pickFinal` に main の選びを残すこと。
  2. `ov` の保護(4px 未満の重なりを増やさない)を規則にするか。
  3. `k`=3 を入れるか(fixture 5 → 2 と引き換えに、120 節 plain の +41% と組 0 → 1)。推奨: 入れない。入れるなら、探索の予算(層の探索を 120 節では打ち切る、など)を ADR 0053 の枠で決める。
  4. 費用: 120 節 plain +27.5% が境界なので、探索を節数で刻む(例: 節が多い図は再出発を減らす)測定を実装の最初の仕事にする。
  5. 組が増える図(plain 9 枚、canvas 6 枚)を受け入れるか。採点上は (交差) が先で、規則どおり。
- **ADR を書かない場合**の理由になりうる点: 利得は乱数の CRT に限られる(報告の図は変わらない)。決める人の判断。

## 再現できない部分

- 壁の時間は共有機での最小値(2〜3 回)。CPU 時間も並べた。
