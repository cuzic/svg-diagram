## 指摘

### m5 (Minor): マウスでバーに動かしてから 400ms 以内に押すと、クリックが消える
- 場所: `lib/present/ui.ts:158`(`.nav.live{pointer-events:auto}`)、`lib/present/ui.ts:549-553`(`showNav`)、`lib/present/ui.ts:560`(`mousemove` → `showNav`)
- 問題: 400ms の遅れは、タッチだけでなくマウスにもかかる。デスクトップの閲覧者(1280×800、`hasTouch:false`)で試した。マウスを止めてバーが消えるのを待つ。そこから `＋` へ 3 歩で動かし、0ms 後か 150ms 後にクリックすると、target は `stage` になり、拡大率は 100% のまま。450ms 後なら `zin` に当たる。素早く押す人には、見えているボタンが 1 回目だけ効かないように見える。main ではすぐ効いていたので、これはこの PR で新しく起きた問題。
- 直し方: マウスで動かした時は、すぐ `live` にする。ただし `mousemove` では判定しない。iOS などはタップの後に互換の `mousemove` を送るので、M2 がまた起きる。代わりに `pointermove` の `pointerType` で分ける。
  ```js
  document.addEventListener('pointermove', function (e) { if (e.pointerType === 'mouse') { showNav(); $('nav').classList.add('live'); } });
  ```
  手元の ui.ts の写しで試した。マウスでは、動かしてから 0・150・450ms のどれでも `zin` に当たり、125% になる。タッチの M2 の結果(1 回目は `stage`、600ms 後は `zin`)は変わらない。`present-touch` の 7 つのテストも通る。
- テスト: デスクトップの閲覧者で、マウスを `＋` に動かしてすぐクリックすると 125% になる、を足す。

### m6 (Minor): 最大を越えてピンチしてから戻すと、指を閉じても、しばらく縮まない(1 を切ってから開くのも同じ)
- 場所: `lib/present/ui.ts:498`
- 問題: 拡大率を `pinch.z × d / pinch.d`(指を置いた時からの累積)にしたので、600% で止まった後も、目標の値は増え続ける。戻す時は、目標が 600% を切るまで反応しない。CDP の 2 本の指で、d0=40 から確かめた(1 手ずつ 40ms 待った)。
  - d=240 で 600%。340 まで開いてから閉じると、300 でも 240 でも 600% のまま。200 になってようやく 500% になる(340 から 240 までの 100px は反応しない)。
  - 20 まで閉じると 100%。そこから開いても、30 と 40 では 100% のまま。60 になって 150% になる。z0=3 から 100% まで閉じた場合は、比が 1/3 に戻るまで反応しない。
  - 1 手ずつ掛けていた前のコミットでは、どちらも戻した時にすぐ反応した。そのため、これはこの PR の後のコミットで新しく起きた問題。
- 直し方: 目標が範囲の外に出た時は、そこを新しい起点にする。1.01 の丸めの所(目標が 1.00〜1.01)では起点を変えないので、遅いピンチは直したままになる。
  ```js
  if (pinch.d > 0) { var want = pinch.z * d / pinch.d; zoomBy(want / zoom.z, pinch.m.x, pinch.m.y); if (want > MAX_ZOOM || want < 1) { pinch.z = zoom.z; pinch.d = d; } }
  ```
  写しで試した。同じ手順で 340 → 300 が 529%、240 が 424% と、すぐ縮む。20 → 30 は 150%、40 は 200% と、すぐ開く。横向きの遅いピンチを含む `present-touch` の 7 つのテストも通る。
- テスト: 最大を越えて開いてから少し閉じると、600% 未満になる、を足す。

### m7 (Minor、main から): スマホのダブルタップは拡大して、すぐ 100% に戻る
- 場所: `lib/present/ui.ts:517`(touchend のダブルタップ)、`lib/present/ui.ts:535`(`dblclick`)
- 問題: `touch-action:none` の要素では、Chromium(Android)が 2 回のタップの後に `dblclick` を送る。touchend の処理が 250% にした直後に、`dblclick` の処理が `zoom.z > 1` を見て `resetZoom()` する。CDP の本物のタップで、スライドの中心を 2 回タップした時の記録は次のとおり。
  - 間が 170ms: `touchend@186 → 250% → click → 100%`。
  - 間が 360ms: touchend の 300ms の判定からは外れる。それでも Chromium のダブルタップの判定には入るので、`dblclick` だけで 250% になる。
  - origin/main(git archive で取り出したもの)でも、同じ記録になる。そのため、この PR で新しく起きた問題ではない。ただ、この PR は「スマホで拡大する」ための修正で、ヘルプにも「ダブルタップ」と書いてあるので、ここで直すのを勧める。この PR で `#stage` 全体が `touch-action:none` になったので、黒の帯でも同じことが起きる。
- 直し方: タッチの直後の `dblclick` は無視する(マウスのダブルクリックは今のまま)。
  ```js
  // touchend の先頭で touchedAt = Date.now();
  $('stage').addEventListener('dblclick', function (e) { if (Date.now() - touchedAt < 1000) return; /* 今の処理 */ });
  ```
  写しで試した。170ms の間では 250% のままになり、360ms の間では何も起きない(1 回ずつのタップ)。デスクトップのダブルクリックの中心は (0.299, 0.599) のまま。
- テスト: CDP で同じ点を 2 回タップすると 250% になる、を足す。

### m8 (Minor、m3 の残り): バーが見えている時に、2 本目の指をバーに置いたピンチは拡大しない
- 場所: `lib/present/ui.ts:488-523`(touchstart/move/end が `$('stage')` にしかない)
- 問題: バーが `live` の時(タップした後の 2.5 秒)に、1 本目を (195, 400)、2 本目を `#pos` に置いて開いた。拡大率は 100% のままだった。ページは拡大されない(scale 1)。2 本目の `touchstart` が `nav` に行くので、`#stage` では `pinch` が作られない。逆の順(1 本目がバー、2 本目がスライド)なら 150% になる。`touch-action:none` でページが拡大しなくなったのはよい。ただ、聴き手から見ると「時々ピンチが効かない」ことになる。
- 直し方: 前の回の案のとおり、touchstart/move/end を `document` で受ける。`#overview` か `#help` が開いている間は何もしない。それ以外では `pinch` と `sx` を扱う。タップと `showNav` は、target が `.nav` の中でない時だけにする(ボタンのタップはボタンに任せる)。PR の範囲を広げたくなければ、ここは別の Issue にしてもよい。

### n3 (nit): ピンチの途中で発表者がスライドを替えると、新しいスライドが指を置いた時の拡大率で始まる
- 場所: `lib/present/ui.ts:235`、`lib/present/ui.ts:487`
- 追従中にスライドが替わると、`draw` が `zoom.z = 1` にする。それでも `pinch.z` は前のスライドの値(例えば 3)のまま。次の 1 手で、新しいスライドが 3 × 比の大きさに飛ぶ。めったに起きないので、`draw` でスライドが替わった時に `pinch = null` にすれば足りる。
