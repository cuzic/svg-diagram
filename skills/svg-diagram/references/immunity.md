# 免疫マップ（Immunity to Change）の図
（svg-diagram の入口は `../SKILL.md`）

Kegan & Lahey『Immunity to Change』（邦訳『なぜ人と組織は変われないのか』）の面談を、図にしながら進める。**専用の部品は無い**。既存の `row` / `group` / `table` / `causalLoop` / `cloud` で、段階ごとに別の図を作る（TOC が現状ツリー・クラウド…と図を分けるのと同じ）。1 枚に詰め込まない。1 図 1 問い、スライド 1 枚に載る大きさにする。

**対応づけについて**: マップ以外（ループ・雲）の使い方は、原典にある書き方ではなく、面談の道具として足した見せ方（出典のない対応）。案件の資料では、そう断って使う。

| 面談の段階 | 図 | 部品 | 例 |
|---|---|---|---|
| 1 マップ（目標・阻害行動・競合目標・固定観念） | 4 つの欄のワークシート | `row([group × 4])` | `examples/immunity-map.ts` |
| 2 固定観念の検証 | 検証の表 | `table` | `examples/immunity-tests.ts` |
| 3 阻害行動が不安を下げる仕組み | 自己調整のループ | `causalLoop` | `examples/immunity-loop.ts` |
| 4 目標と競合目標の対立 | 蒸発雲 | `cloud` | `examples/immunity-cloud.ts` |

## 1 マップ

- 欄は `group([...箱], {valign: 'top', title: '1 改善目標'})` を 4 つ並べ、`row([...])` に入れる。幅は同じになり、高さは最も高い欄にそろう。欄ごとに独立した列で、行どうしは対応しない。
- **`grid()` は使わない**。行優先に折り返して同じ行の高さをそろえるため、「阻害行動 i と競合目標 i」が 1 対 1 に読まれる（原典は欄ごとの箇条書き）。
- **不安ボックス**は、第 3 欄の先頭に置く。`box({title: '不安: …', dashed: true})`。**色（`tone`）は付けない**（凡例にない記法の警告 `legend-missing` が出る）。破線と「不安:」の語で示す。
- まだ聞いていない欄は `group([box({title: '(未記入)', frame: false})], {dashed: true, ...})`。**空の子を入れない**（`(未記入)` の箱には `id` を付けない）。
- 欄の間に矢印は引かない（原典のマップも欄の順に読む）。**`connect()` を書くなら**、既定の経路は箱を避けず build の検証で落ちるので `connect('x:left', 'y:right', {route: 'elbow', bend: 'auto'})` の形で書く。1 つの辺に複数の矢印が集まると矢じりが 1 点に重なる。`connect` が 3 本以上あると、`id` を持つのに矢印の端でない箱が `graph-orphan-node`（warn）になる（全部の箱を結ぶか、`id` を付けない）。
- 段階ごとに見せるなら `group` の `reveal` / `until`（欄単位）。

### 書き方（面談の質問）

| 欄 | 質問 |
|---|---|
| 1 改善目標 | 本気で変えたいことは何か。**1 つに絞る**（候補を書く段階では複数でよい） |
| 2 阻害行動 | その目標に反して、していること・していないことは何か |
| 3 不安と競合目標 | 欄 2 の逆をしたら、何が怖いか（不安）。その不安から守っているものは何か（「〜しないことに専心している」の形） |
| 4 強力な固定観念 | 競合目標を支えている思い込みは何か（「〜なら、〜になる」の形で、検証できる文にする） |

## 2 固定観念の検証（表）

- 行 = 1 つの検証。列は「試す固定観念」「すること」「集めるデータ」「安全か」「結果」「固定観念について分かったこと」。
- 検証は**改善ではなく調べること**（結果が固定観念を支えることもある）。安全で小さく、すぐ実行できるものにする。
- 「試す固定観念」の列は、id でなく固定観念の**文**を書く。

## 3 悪循環のように見えるもの（自己調整のループ）

- 免疫は不安から自分を守る自己調整（動的平衡）。不安 →(+) 守る力 →(+) 阻害行動 →(−) 不安。負が 1 つなので **B（バランス）ループ**になる（`causalLoop` が自動で B1 と表示する）。強化（R）と書かない。
- 目標が遠のくほど不安が増える強化（R）のループは、**別の図**に描く。`polarity` は作者が書く。

## 4 蒸発雲に置く

雲は A が共通の目的、B / C がニーズ、D / D' が対立する行動。目標と競合目標はどちらもニーズの側にあたる。

| 雲 | 免疫マップ |
|---|---|
| A | 両方を含む上位の目的 |
| B | 改善目標が満たすニーズ |
| C | 競合目標（自分を守る） |
| D | 改善の行動（欄 2 の逆） |
| D' | 阻害行動（欄 2） |
| `cd`（C → D'）の前提 | **強力な固定観念** |

- 固定観念は `assumptions: [{on: 'cd', text: '…'}]`。
- **`injection` に行動実験を入れない**。`injection` は「前提を偽にする変化」で、解決策に読まれる。原典の検証は改善でなく調べることなので、検証は表（段階 2）で扱い、雲の下に `caption` で添える。
- 割り当ては作者が決める（標準の対応ではない）。

## 検査

専用の検査は無い。`check --strict` で、凡例（`legend-missing`）・孤立（`graph-orphan-node`）・幅の問題だけが見られる。「阻害行動に競合目標が無い」「固定観念が検証されていない」は、面談の中で人が確かめる。
